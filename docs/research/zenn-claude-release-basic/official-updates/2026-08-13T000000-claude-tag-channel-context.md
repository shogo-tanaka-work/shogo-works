# 2026-08-13 Claude Tag のチャンネル文脈対応

## 公式内容の日本語要約

Claude Tag は Slack のチャンネルに Claude を参加させ、能動的な協働者として動かす機能である。@メンションで応答するほか、Claude 自身が有用と判断したときに自発的に発言する。

今回の更新で、**Claude が個々のメッセージを単独で評価するのをやめ、チャンネル全体の文脈を見るようになった**。従来はメッセージを孤立した単位で判断していた。これにメモリと常設の指示が組み合わさり、**いつ自発的に応答するか、いつしないかの判断が約 30% 改善**したとされる。

判断の出し方も細かくなった。短くて検証可能な答えならインラインで返す、複雑な問題ならスレッドを立てて調査する、既存のワークストリームへ振り分ける、あるいは黙っている、といった選択をする。

提供は Claude Teams と Enterprise で開始済み。**文脈拡張は追加費用なし**で、Claude が追加で処理する文脈は利用量や支出上限にカウントされない。

加えて、応答の受け付け表示が速くなった。従来は Claude の初期化中は無反応だったが、数秒以内に反応が返る。

## できるようになったこと

- Claude Tag がチャンネル全体の文脈を踏まえて発言要否を判断する
- インライン返信 / スレッド調査 / 既存ワークストリームへの振り分け / 沈黙を使い分ける
- 追加の文脈処理が利用量・支出上限にカウントされない
- 応答の受け付けが数秒以内に返る

## 影響範囲

- 対象ユーザー: Slack で Claude Tag を使うチーム
- 対象プラン: Claude Teams / Enterprise
- API / UI / 管理者機能: Slack 上の挙動。設定変更は不要

## 教材化メモ

- **「AI がいつ黙るべきか」を扱う教材の実材料になる。**チャットに常駐する AI の評価軸は、良い回答をするかどうかよりも、余計な発言をしないかどうかで決まる場面が多い。公式が「いつ応答しないか」の判断精度を成果指標にしている点は、この論点を裏づける。
- メッセージ単位の評価からチャンネル全体の評価への変更は、context engineering の観点で説明できる。**判断の質は入力の窓の取り方で決まる**という一般則の具体例。既存の context-window 系教材へ接続できる。
- 追加の文脈処理が利用量にカウントされない点は、コスト設計を扱う教材で注記に使える。ただしベンダー都合で変わりうる条件なので、教材本文で恒久的な前提にしない。
- 約 30% 改善という数字は公式の自己申告であり、測定条件は開示されていない。教材で引用するなら**出典と条件不明である旨をセットにする**。
