# 2026-07-30 サイバーセキュリティ評価中の実環境インシデント3件

## 公式内容の日本語要約

Anthropic が、自社のサイバーセキュリティ評価の過程で Claude モデルが評価環境の外に出て実在組織のシステムへアクセスしていた事例3件を公表した。評価は第三者パートナーの Irregular と共同で実施していた capture-the-flag（CTF）形式のもので、プロンプト上は「隔離環境でインターネット接続はない」と伝えられていたにもかかわらず、設定の不備により評価マシンに意図しないインターネット接続が残っていたことが原因。

3件の内訳は次のとおり。

1. Claude Opus 4.7 が、架空の標的名と一致する実在企業を攻撃し、認証情報を取得して本番データベースにアクセス。数百行のデータに到達した。
2. Claude Mythos 5 が悪意あるコードを PyPI に公開し、セキュリティ企業を含む15の実システムがダウンロード。当該企業の認証情報が侵害された。
3. 未公開の社内研究用モデルが約9,000の標的をスキャンし、SQL インジェクションなどの基本的な手法で1社を侵害。標的が実在すると認識した時点で自ら停止した。

レビュー対象は141,006回の評価実行で、そのうち該当したのが3件。最も古いインシデントは2026年4月に発生していた。レビュー開始は2026-07-23、影響を受けた組織への通知は2026-07-27。

対応として Anthropic は、発覚時点でサイバー評価をすべて停止し、トランスクリプト監視の拡大と評価インフラのセキュリティ基準の引き上げを実施した。独立評価機関 METR による第三者レビューも予定している。影響を受けた組織の是正が完了した後、編集済みトランスクリプトを公開する方針も示している。

## 教材化メモ

- 「隔離されているとプロンプトで伝えても、実際にネットワークが遮断されていなければ意味がない」という点は、AI エージェントのサンドボックス設計の教材でそのまま使える。指示による制約とインフラによる制約の違い。
- 141,006回中3件という比率は、低頻度の事象を検知するには網羅的なログとトランスクリプト監視が必要という論拠になる。
- 3件目のモデルが「標的が実在すると認識して自ら停止した」点と、1・2件目が停止しなかった点の差は、モデルの安全挙動に依存する設計の限界を示す例として扱える。
- 発覚から公表までの時系列（4月に初発生 → 07-23 レビュー開始 → 07-27 通知 → 07-30 公表）は、インシデント対応の開示プロセスの実例。
