# 2026-10-12 n8n の旧ライン backport（2.42.7 / 1.123.85）

## 公式内容の日本語要約

**2.42.7**（2026-10-12T07:34:44Z）の修正は2件である。

- **同時実行の credential test が1つの node type registry を共有しないようにする**（#40783）
- **skill が読み込んだ deferred tool のツール呼び出しを再開する**（#40747）

2件目は同日の **2.43.4（#40746）と同じ修正の backport** である。1件目は共有状態の分離で、同週の 2.43.6（webhook のリクエストボディごとに XML パーサーを生成）と同じ系統である。公式に security fix / breaking change のラベルは無い。

**1.123.85**（2026-10-14T08:38Z）は **1.x LTS ラインへの backport** だが、**GitHub Releases のページで changelog 本文が読み込みエラーになり、内容を取得できなかった。** 取得できたのはタグ名、日付、publisher（n8n-assistant）、commit 参照、Assets 4 のみである。**前週の 1.123.84 でも同じ症状が出ている**（週次サマリー 2026-10-12 に記録）。**内容未確認として扱い、推測で埋めない。**

## できるようになったこと

- 2.42 系で、同時実行の credential test の相互干渉と deferred tool の呼び出し再開不可が解消される
- 1.123.85: 内容未確認

## 影響範囲

- 対象ユーザー: 2.42 系に留まっている利用者、1.x LTS ラインの利用者
- 対象プラン: 記載なし
- API / UI / 管理者機能: core

## 教材化メモ

- **同じ修正が 2.43.4（#40746）と 2.42.7（#40747）で別 PR 番号で入っている。** backport の追跡は PR 番号ではできず、**修正内容の文面で突き合わせる必要がある**。バージョン追跡の実務上の注意点として使える。
- **1.x LTS の changelog 本文が2週連続で取得できない。** 「公式ページに情報はあるが到達できない」ケースで、**取得失敗を内容の不在と混同しない**という記録規律の実例になる。
- 同時実行で共有状態が壊れる修正が、2.42.7 / 2.43.6 / 2.44.0 の3ラインに散っている。**並行処理での状態共有は、ライン横断で出続ける種類の不具合**である。
