# 2026-09-22 n8n 2.41.0

## 公式内容の日本語要約

n8n `2.41.0` が 2026-09-22T07:32Z に **pre-release（beta 系列）**として公開された。**2.41 系列の最初のリリースで、変更点が多い。**

**権限まわりの追加が1件ある。** **プロジェクトロールへ「実行の閲覧」と「実行の削除」の権限を追加**した。実行履歴は入力データを含むため、**誰が見られるかを役割単位で分けられるようになった**という意味になる。

**AI 機能の追加。** **単体ノード実行を Workflow Builder / AI Assistant のツールとして呼べる**ようになり、agent builder に n8n Assistant パネルが統合された。

**ノードの拡張。** Microsoft Teams ノードが chat リソースと @mention に対応。MiniMax ノードは**ハードコードされた一覧ではなく API から利用可能モデルを取得**する。

**その他。** メールアドレス変更の確認フロー、Environments 設定からのインスタンス昇格操作。

**依存更新とセキュリティ関連。** **undici 7.29.1、vm2 3.12.2、Snowflake SDK 3.3.0** へ更新。**MCP OAuth アクセストークンの RFC 9068 準拠。** **生のインスタンスキーとして保存されたデータ暗号鍵の修復**（前週 2.40.3 / 2.39.8 と同系列）。

修正は AI Builder / Assistant、コア（停留ジョブ、公開失敗、トリガーの teardown）、OAuth2 資格情報テスト、エージェント実行の観測と状態報告、ノード別（S3 のファイル名、Databricks の強制、OpenAI の JSON パラメータ）、エディタ UI、IMAP トリガーの imapflow 移行に広く入っている。**公式リリースノートに breaking change の記載はない。**

## できるようになったこと

- プロジェクトロールで実行の閲覧・削除権限を分けられる
- 単体ノード実行を Workflow Builder / AI Assistant のツールとして利用
- Microsoft Teams ノードで chat リソースと @mention を扱える
- MiniMax ノードが API から利用可能モデルを取得
- MCP OAuth アクセストークンが RFC 9068 に準拠

## 影響範囲

- 対象ユーザー: n8n の beta チャネル利用者
- 対象プラン: プロジェクトロールは該当エディションの機能
- API / UI / 管理者機能: プロジェクトロールの権限項目が増える。依存ライブラリ（undici / vm2 / Snowflake SDK）が更新される

## 教材化メモ

- **実行履歴の閲覧権限を分けられるようになった**点は、統制として実務的に効く。**実行履歴にはワークフローを流れたデータそのものが残る。** 「ワークフローを編集できる人」と「実行結果を見られる人」を同じ権限で扱っていた組織は、**この分離を入れる前提で権限設計を見直せる。**
- **MiniMax ノードのモデル一覧をハードコードから API 取得へ変えた**のは、同週の GitHub Copilot のモデル追加・廃止ラッシュと同じ問題への対処である。**モデル名を実装に埋めると、外部の退役スケジュールに追随できない。** 小さな変更だが、設計原則の実例として強い。
