# 2026-11-03 n8n 3.1.0（pre-release）

## 公式内容の日本語要約

**3.x 系列の 3.1.0 が pre-release として公開された**（11-03 08:33Z）。同時刻帯に出た 2.47.0（08:36Z）と変更内容が大きく重なり、2.47.0 の項目に加えて 3.x 固有の項目が乗る構成になっている。

共通する主な内容は 2.47.0 と同じ（v3 移行レポートの改善、AI Agent ノードの非推奨案内、ai-builder の self-healing レビュー、**送信リクエストガードの既定ブロック IP レンジ拡張**、プロジェクトスコープの適用、エージェントサンドボックスのファイルサイズ上限、式ランタイム周りの多数の修正）。

3.1.0 側で目立つ項目として、community package の `supportedNodesApiVersion` v3 互換性、CLI からのワークフローの publish / unpublish、キュージョブを待機中のワーカーへ順番に1つずつ渡す変更、メモリガードのヒープ比率を old generation で測る変更、Sentry trace ヘッダー伝播の制限、waiting / queued 実行の resume 試行回数の制限などがある。

**pre-release であり、`beta` タグは 3.1.0 ではなく 2.47.2 を指している。**

## できるようになったこと

- 3.x 系列を pre-release として試せる（v3 移行の事前検証用）
- CLI からワークフローの publish / unpublish ができる（3.x 側）

## 影響範囲

- 対象ユーザー: v3 移行を検証中の self-hosted 利用者
- 対象プラン: self-hosted（pre-release のため本番前提ではない）
- API / UI / 管理者機能: **pre-release のため本番適用の対象ではない。** ただし 2.47.0 と同じ既定変更（送信リクエストガードの IP レンジ拡張、プロジェクトスコープ適用）を含むため、移行検証では**既存ワークフローが止まらないかの確認が主眼になる**

## 教材化メモ

- **2.47.0 と 3.1.0 がほぼ同時刻に、ほぼ同じ変更内容で出ている。** 2系列を並行メンテナンスする体制で、**同じ修正が両系列へ入る**形になっている。巡回側は「別のリリースだが中身は重複」という判定が要る。OSS の系列管理を説明する実例になる。
- **v3 移行レポートの改善が3リリース連続で入っている**（2.46.5 / 2.47.0 / 3.1.0）。移行支援ツール自体を繰り返し手直ししている状況で、**メジャー移行の本体はコードではなく「何が壊れるかを利用者へ伝える仕組み」**であることが読み取れる。移行計画の立て方を教えるときに使える。
- `beta` タグが 3.1.0 を指していない点は、**pre-release とタグが独立している**ことの確認になる。「beta を使えば次のメジャーが試せる」とは限らない。
