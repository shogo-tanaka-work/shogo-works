# 2026-09-30 n8n 2.41.4

## 公式内容の日本語要約

2.41 系列の修正版。**窓の終端時点で `stable` タグが指すのは 2.41.6** であり、**2.41 系列はこの窓の途中で beta から stable へ昇格している**（前週終端は `stable` = 2.40.7、`beta` = 2.41.3）。

**Bug Fixes**

- **trace context が不完全な場合の API 実行取り扱い**（2.42.1 と同内容の修正）
- **event-loop の遅延中に DB ping を成功として数えていた**問題を修正
- **キュージョブの結果を、そのプロセスが投入した実行の分だけ保存**するよう修正
- Assistant バナーのクレジット表示

**Features**

- 新規 Cloud サインアップ向けの n8n Assistant オンボーディング
- Assistant のクレジット CTA のルーティング改善

## できるようになったこと

- event-loop 遅延時に DB 死活判定が誤って成功しない
- マルチプロセス構成でキュージョブ結果が混ざらない

## 影響範囲

- 対象ユーザー: キューモードで複数 main を運用するセルフホスト環境、Cloud 利用者
- 対象プラン: 2.41 系列（窓終端時点で stable）
- API / UI / 管理者機能: DB 死活監視、キュー実行

## 教材化メモ

- **「event-loop が詰まっているのに DB ping が成功していた」**は、ヘルスチェック設計の失敗例としてそのまま使える。**プロセスが応答できない状態でも、死活確認だけは通ってしまう**——ヘルスチェックが測っている対象と、利用者が期待している対象のずれである。自社のヘルスエンドポイントが何を測っているかを点検する動機になる。
- **キュージョブの結果を自プロセス投入分に限定**した修正は、水平スケール時の状態共有の難しさの実例。**同じ修正が 2.41 系列と 2.42 系列の両方へ同日に入っている**点も、複数系列を並行保守するコストの具体例になる。
