# 2026-09-18 n8n 2.40.3（pre-release）

## 公式内容の日本語要約

**Bug Fixes が2件。窓の終端時点で `beta` タグが指している実バージョンである。**

**core: 生のインスタンス鍵として保存されたデータ暗号鍵を修復する**（#38910）。

**editor: AI Assistant でワークフロープレビューが空白になる問題を修正**（#38914）。

**暗号鍵の修復は 2.39.x 系でも継続している。** 前週の 2.39.1（09-09）が「旧形式のデータ暗号鍵を起動時に修復」だったのに続き、今週は 2.39.8 と 2.40.3 で**「生のインスタンス鍵として保存された」ケース**を扱っている。**同じ領域の修復が2週にわたって出ている。**

## できるようになったこと

- 生のインスタンス鍵として保存されていたデータ暗号鍵が起動時に修復される
- AI Assistant のワークフロープレビューが表示される

## 影響範囲

- 対象ユーザー: `beta` チャネルの利用者。過去の版で暗号鍵が誤った形式で保存された環境
- 対象プラン: 記載なし。pre-release
- API / UI / 管理者機能: 起動時の鍵修復、AI Assistant

## 教材化メモ

**暗号鍵の保存形式の修復が2週連続で出ている点を、教材では「データ層の移行は完了しない」という論点で扱う。** 鍵の形式変更は、**過去に保存されたレコードが残っている限り、修復コードを持ち続ける必要がある。** 1回のマイグレーションで終わらず、**修復器が製品に常駐する**形になっている。スキーマ移行を設計するときの現実的な想定として使える。

**運用上の注意は「起動時に黙って直る」こと。** 直ったこと自体はログにしか出ないため、**自環境が該当していたかどうかを後から知る手段が薄い。** 鍵まわりの修復が入ったリリースでは、起動ログを確認してから本番へ上げる、という手順が妥当である。
