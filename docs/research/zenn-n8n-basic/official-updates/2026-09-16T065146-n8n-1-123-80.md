# 2026-09-16 n8n 1.123.80（1.x backport）

## 公式内容の日本語要約

**1.x 系への backport。Bug Fixes は1件だけだが、内容は統制に直結する。**

**core: declarative ノードのリクエストに、資格情報の許可ドメイン（allowed domains）を適用する**（#38723）。

n8n の資格情報には**送信先ドメインを制限する機能**があるが、**declarative 方式で定義されたノードからのリクエストでは、その制限が適用されていなかった**ことになる。つまり、**ドメインを絞ったつもりの資格情報が、declarative ノード経由では絞られていなかった期間がある。**

翌日の **1.123.81 で「ドメイン制限付き資格情報が自分のノード内で動くようにする」（#38786）という追随修正**が入っており、**2日連続で同じ機能まわりを触っている。**

## 影響範囲

- 対象ユーザー: 1.x 系を使い続けているセルフホスト環境。**資格情報に許可ドメイン制限を設定している組織**
- 対象プラン: 1.x LTS 系列
- API / UI / 管理者機能: 資格情報のドメイン制限、declarative ノードの HTTP リクエスト

## 教材化メモ

**「設定した制限が、ある経路でだけ効いていなかった」という典型例である。** 管理者から見ると設定画面ではドメインが絞られており、**効いていないことに気づく手段が無い。** 同じ週に Claude Code 側でも `sandbox.excludedCommands` の glob が複合コマンド全体をサンドボックスから外していた問題（2.1.277）、組織ポリシーのキャッシュが切り替え後も再利用される問題（2.1.271）が修正されている。**統制設定は「入れた」で終わらず、「効いているか」を別の手段で確かめる必要がある**という主張の実例が、今週だけで3つ揃った。

**確認手段としては、許可していないドメインへ実際に出て失敗することを見る**のが確実である。設定画面の表示は、その経路で適用されている証拠にならない。
