# 2026-09-03 n8n 2.37.9

## 公式内容の日本語要約

2.37 系のパッチ。**式（expression）の中で `$json` のデータに対する破壊的な配列メソッド（mutating array methods）が使えなくなっていたのを復活させた**もの。`push` / `splice` / `sort` のように配列を直接書き換える種類のメソッドを指す。

**回帰の修正である。** どこかの版で `$json` が読み取り専用として扱われるようになり、既存のワークフローの式が動かなくなっていたと読める。

## できるようになったこと

- 式の中で `$json` のデータに破壊的な配列メソッドを再び使える

## 影響範囲

- 対象ユーザー: 式の中で配列を直接書き換えているワークフローを持つ環境
- 対象プラン: セルフホスト / クラウド
- API / UI / 管理者機能: 式エンジン

## 教材化メモ

- **既存ワークフローの式が動かなくなる種類の回帰**は、自動化基盤では被害が読みにくい。**式は単体テストの対象になっていないことが多く、壊れても実行されるまで気づかない。** 「動いていたものが動かなくなった」ことを検知する仕組みが無い、というのが本質的な問題である。
- **`$json` を読み取り専用にする**という変更自体は、設計としては真っ当な方向である（入力データを破壊しない）。それでも**既存の利用者を壊すなら回帰として扱われる。** 正しさと互換性が衝突したときにどちらを取るか——本件は互換性側へ戻した実例として使える。
- 自動化基盤の運用教材で、**式を含むワークフローも「コード」として扱い、更新前に検証環境で流す**という手順の必要性を裏づけられる。
