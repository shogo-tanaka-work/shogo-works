# 2026-08-12 n8n 2.34.5 / 2.35.1 / 1.123.70

## 公式内容の日本語要約

同日に3本のリリースが出た。いずれもバグ修正のみで、新機能はない。

2.34.5（stable、2026-08-12T08:04:40Z）は core の修正1件。プロキシ経由でリクエストを送る際に、TLS オプションがホップごとに適用されるようになった（#36017）。プロキシ環境下で TLS 設定が意図通り効かない不具合の修正である。

2.35.1（pre-release、2026-08-12T07:56:04Z）は core の修正2件。上記と同じ TLS のホップ単位適用（#36016）に加え、data-tables の resume 時に「Always allow」スコープを受け付けるようになった（#36080）。

1.123.70（2026-08-12T08:25:55Z）は 1.x 系のバックポート。

前日の 2.35.0（stable）が Agent Builder のテスト実行と HITL、Discord チャネル、カスタムロール API を含む機能リリースだったのに対し、今回は追随のパッチにあたる。

## できるようになったこと

- プロキシ経由のリクエストで TLS オプションがホップごとに正しく適用される
- data-tables の resume 時に「Always allow」スコープが通る（2.35.1）

## 影響範囲

- 対象ユーザー: セルフホスト運用者、特にプロキシ配下で n8n を動かしている環境
- 対象プラン: セルフホスト / クラウド共通
- API / UI / 管理者機能: core（HTTP リクエスト処理、data-tables）

## 教材化メモ

- 企業のプロキシ環境で n8n を動かす場合の落とし穴として使える。TLS 設定がホップ単位で適用されない実装だと、社内プロキシを挟んだ瞬間に証明書検証が想定通りに働かない。自動化基盤を社内に置く教材では、この種の「ネットワーク境界で壊れる」事例を1つ持っておくと説明が具体的になる。
- 2.35.0 の翌日にパッチが2本出ている点も、機能リリース直後の版を本番へ即時適用しない運用判断の実例になる。
