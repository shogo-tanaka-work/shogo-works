# 2026-09-17 n8n 2.40.2（pre-release）

## 公式内容の日本語要約

**Bug Fixes が2件。**

**core: ルールが例外を投げても breaking change 検出を継続する**（#38789）。**1つの検出ルールが落ちると、それ以降の検出が走らなくなっていた**ことになる。

**editor: 資格情報の入力欄で数値を数値として送信する**（#38880）。

同内容が **2.39.x 系にも 2.39.7 として同日にバックポート**されている（#38790 / #38881）。

## できるようになったこと

- 一部の breaking change ルールが失敗しても、残りのルールによる検出が続く
- 資格情報の数値フィールドが正しく送信される

## 影響範囲

- 対象ユーザー: n8n セルフホスト管理者、資格情報を設定する利用者
- 対象プラン: 記載なし。pre-release
- API / UI / 管理者機能: 起動時の breaking change 検出、資格情報エディタ

## 教材化メモ

**「検出器が静かに止まる」は、安全機構の失敗として最悪の形である。** 2.39.6 で v3 向けの検出ルールが増えたばかりで、**ルールを増やした結果、1つの例外で検出全体が止まるようになった**という順序になる。**チェックを増やすほど、チェック自体の堅牢性が要る**という一般則の実例で、**個々のルールを独立させて失敗を隔離する**という設計（現在の修正の形）が答えになる。

**同じ構図は CI や lint の設計でも起きる。** 1つのルールの実行時エラーでジョブ全体が落ち、**「通らないから一旦無効化」で検査そのものが外れる。** 検査の追加は、失敗時の振る舞いとセットで決める、という手順に落とせる。
