# 2026-09-10 n8n 2.39.2

## 公式内容の日本語要約

バグ修正とパフォーマンス改善のリリース。

**バグ修正2件**。`pairedItem` の祖先探索をメモ化してパフォーマンスを改善（#38212）。**フロー途中で訪問者が認証した場合に、既存の consent grant を再利用する**（#38248）。後者は、認証が途中で挟まったときに不要な再認証を求めていた挙動の修正である。

**パフォーマンス改善1件**。**ユーザーのワークフローを Instance AI サンドボックスへコピーしないようになった**（#38199）。メモリ使用量が減り、全体の性能が改善する。

公式には**破壊的変更の記載はない。**

## できるようになったこと

- フロー途中の認証で consent grant が再利用され、再認証を求められなくなった
- ユーザーのワークフローが AI サンドボックスへ複製されなくなり、メモリ使用量が減った

## 影響範囲

- 対象ユーザー: n8n 利用者全般（AI 機能を使う環境で効果が大きい）
- 対象プラン: セルフホスト / クラウド
- API / UI / 管理者機能: コア（実行エンジン・認証フロー）

## 教材化メモ

- **公式はパフォーマンス改善として書いているが、「ユーザーのワークフローをサンドボックスへコピーしない」変更はデータの取り回しの話でもある。** ワークフロー定義には接続先・認証情報の参照・業務ロジックが含まれる。**それが AI サンドボックスへ複製されていた期間があった**という事実は、セルフホストで機微なワークフローを扱っている組織にとって、性能より先に確認したい論点になる。公式の記載は最適化の文脈のみで、データ取り扱いへの言及は無い。
- **consent grant の再利用**は、OAuth 連携の実装でよく踏む落とし穴の実例。認証がフローの途中で挟まると状態が失われ、最初からやり直しになる設計は珍しくない。
- 記事化はしない（週次確認ソースのマイナーアップデート）。**ただしワークフローの複製に関する点は、次週以降に公式の追加説明が出ないか注視する。**
