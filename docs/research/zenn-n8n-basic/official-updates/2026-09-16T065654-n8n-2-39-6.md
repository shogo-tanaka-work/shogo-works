# 2026-09-16 n8n 2.39.6

## 公式内容の日本語要約

**Bug Fixes**: **Gateway クレジットの適格性が、誤ったサブノードに対して検証されていた**問題を修正（#38673）。

**Features**: ストレージディレクトリのリネームに関する **v3 の breaking change ルール**を実装（#38636）。**`N8N_DB_PING_TIMEOUT` 環境変数の非推奨警告**を追加（#38569）。

**v3 の breaking change ルールが 2.39.x に入り始めている**点が観測事項である。n8n は起動時に breaking change を検出して警告する仕組みを持っており、**次のメジャー（3.x）へ向けた検出ルールが前倒しで配られている**形になる。

## できるようになったこと

- Gateway クレジットの適格性が正しいノードに対して判定される
- ストレージディレクトリのリネームに関する v3 breaking change を起動時に検出する
- 非推奨の `N8N_DB_PING_TIMEOUT` を起動時警告で把握する

## 影響範囲

- 対象ユーザー: n8n セルフホスト管理者、Gateway クレジット利用者
- 対象プラン: 記載なし
- API / UI / 管理者機能: 起動時チェック、環境変数、クレジット判定

## 教材化メモ

**「メジャーアップグレード前に検出ルールだけ先に配る」という運用は、追随コストの下げ方として良い実例である。** 3.x が出てから調べるのではなく、**2.39.x の起動ログで先に警告を受け取れる。** 自社プロダクトで破壊的変更を出すときの手順としてそのまま真似できる形で、**「非推奨警告 → 検出ルール配布 → メジャー投入」の3段構え**として教材化できる。

**運用側の注意は、起動時警告を誰も読んでいないと意味がない点。** コンテナ運用では起動ログが流れて消える。**警告をログ基盤で拾ってアラートに乗せる**ところまでが対応になる。
