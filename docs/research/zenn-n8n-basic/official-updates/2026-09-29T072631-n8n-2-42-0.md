# 2026-09-29 n8n 2.42.0

## 公式内容の日本語要約

**2.42 系列の初版で、窓内で最大のリリース。** 窓の終端時点で `beta` タグが指すのは 2.42.2 であり、**2.42 系列は beta チャネル**である（`stable` は 2.41.6）。

**権限・資格情報まわりが中心である。**

- **インスタンス資格情報に対する view / use / manage のカスタムロール**を作成できる（`core`）
- **粒度の細かい資格情報共有の feature flag**（`core`）
- **資格情報を workflow runner に対して検証**（`core`）
- システムインスタンスロールから**半チェック状態の権限を除去**し、Member プリセットを復旧（`editor`、バグ修正）
- **quick-connect の OAuth 資格情報を、認可されるまで一覧に出さない**（`editor`、バグ修正）
- **token payload を検証してからユーザーを解決**（`core`、バグ修正）

**既定値とサインインの変更。**

- **Agents を既定で有効化**（`core`）。2.41.1（09-23、当時 beta）で入った変更が 2.42 系列にも入っている
- **SSO が有効なとき、SSO を主要なサインイン手段として表示**（`editor`）
- **保存 / 公開 / 実行の拒否時に、ポリシー違反をスコープ付きで表示**（`editor`）
- NDV の**制限付きノードパネル**に管理者連絡先と代替パスを表示（`editor`）

**ノードとエージェント基盤。**

- **Azure OpenAI Chat Model ノードを Azure AI Foundry Chat Model へ改称**し、project 入力と deployment 一覧取得に対応
- **Anthropic ノードの Message 操作で prompt caching** に対応
- **durable agent message queue の基盤**、共有 Agent コンテキストへのアクセス、agent preview セッションの所有者スコープ化（`core`）
- MCP connect-client ピッカーへ **Mistral Vibe** を追加（`editor`）
- AI Assistant から **MCP Registry の feature flag を除去**（`core`）

ほか、Public API spec、OpenTelemetry、Redis pubsub の再接続、binary-data の削除リトライなど多数の修正を含む。

## できるようになったこと

- インスタンス資格情報のカスタムロール（view / use / manage）
- Anthropic ノードの prompt caching
- Azure AI Foundry（旧 Azure OpenAI）の project / deployment 指定
- ポリシー違反のスコープ付き表示

## 影響範囲

- 対象ユーザー: セルフホスト / Cloud の n8n 管理者、ワークフロー作成者
- 対象プラン: beta チャネル（`beta` タグ）。**stable は 2.41 系列**
- API / UI / 管理者機能: **資格情報の権限モデル、Agents の既定値、SSO の表示順、ノード名の変更**

## 教材化メモ

- **資格情報の権限を「見える / 使える / 管理できる」の3段に割る**という設計は、AI ワークフロー基盤の統制の型になる。実行者に「使える」だけ渡して「見える」を渡さない、という分け方ができると、**資格情報を知らないまま自動化を回せる**。社内の AI 自動化の権限設計でそのまま使える粒度である。
- **`Azure OpenAI Chat Model` → `Azure AI Foundry Chat Model` の改称**は、既存ワークフローの手順書・スクリーンショット・教材が一斉に古くなる型の変更。**ノード名は仕様ではなくブランド名に従って変わる**ため、教材でノード名を見出しに使うと保守コストが上がる。
- **「半チェック状態の権限」をシステムロールから除去**したという修正は、権限 UI の設計上の失敗例として分かりやすい。中間状態を許す権限画面は、管理者が「何を許可したか」を言えなくなる。
