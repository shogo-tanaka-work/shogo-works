# 2026-10-16 n8n stable が 2.43.7 へ（2.43 系の stable 昇格）

## 公式内容の日本語要約

**moving tag の `stable` が 2.43.7（commit b7c5430）を指すようになった。** 前週の `stable` は 2.42.6 だったため、**この窓で stable チャネルが 2.42 系から 2.43 系へ移った**ことになる。`beta` は 2.44.3（commit bfbeea9）を指す。

**2.43 系は窓内に4版出ている。** 10-07〜10-09 の 2.43.1 / 2.43.2 / 2.43.3 は pre-release 扱いだったが、**2.43.4 以降は pre-release マークが外れている**。

- **2.43.4**（2026-10-12T07:23Z）— キュー モードでの Chat Hub セグメントの二重処理の修正（#40816）、**skill が読み込んだ deferred tool のツール呼び出しが再開されない問題の修正**（#40746）
- **2.43.5**（2026-10-14T08:15Z）— `chunk()` 式拡張の size 引数の検証（#40911）、モデルピッカーで **Gemini モデルを名前で表示し優先モデルを先頭に並べる**（#41016）
- **2.43.6**（2026-10-15T07:26Z）— **webhook のリクエストボディごとに XML パーサーを生成する**（#41113）
- **2.43.7**（2026-10-16T07:23Z）— **worker 停止時に実行中の production execution を suspend する**（#40944）

**公式に security fix / breaking change のラベルは付いていない。** ただし 2.43.6 の「リクエストごとに XML パーサーを生成する」は、**パーサーのインスタンスを複数リクエストで共有していた状態の是正**であり、同週の 2.42.7（同時実行の credential test が1つの node type registry を共有しない）と同じ系統の修正である。

10-17 / 10-18 / 10-19 のリリースは無い（週末）。

## できるようになったこと

- stable チャネルで 2.43 系を使える
- worker 停止時に実行中の production execution が suspend される（ジョブの取りこぼし低減）
- モデルピッカーで Gemini モデルを名前で判別できる

## 影響範囲

- 対象ユーザー: `stable` タグで追従している self-hosted 利用者
- 対象プラン: 記載なし
- API / UI / 管理者機能: core、webhook、エディタ（モデルピッカー）

## 教材化メモ

- **`stable` / `beta` が moving tag であるため、「stable を使っている」は特定バージョンを意味しない。** 今週 2.42.6 → 2.43.7 へ動いた。**タグ追従の自動更新を入れている環境では、マイナー跨ぎの変更が意図せず入る。** `source-catalog.md` の注意点どおり、タグが指す実バージョンを毎回確認する必要がある。
- **「リクエストごとにパーサーを作る」「registry を共有しない」型の修正が同週に2件**出ている。**共有状態のインスタンスを使い回す設計は、並行処理で壊れる**という一般論の具体例として2件並べられる。
- worker 停止時の suspend は、**エージェント/ワークフローの graceful shutdown 設計**の題材になる。停止時に実行中のものをどう扱うかは自作の自動化でも必ず出る論点である。
