# 2026-10-27 n8n 2.46 系と beta タグの移動

## 公式内容の日本語要約

**2.46.0（2026-10-27T08:39Z）が minor として出た。** 窓内に 2.46.1（10-28T07:18Z、pre-release）、2.46.2（10-29T08:49Z）、2.46.3（10-30T08:26Z）が続き、**`beta` moving tag は 2.45.3 → 2.46.3 へ動いた**（10-30T08:26Z、コミット `7cc7d2d`）。

**2.46.0 で目立つのは権限・資格情報まわりの引き締めである。**

- **実行データの読み取りに `execution:read` を要求する修正**が複数（Assistant の実行読み取り、Assistant の単発ノード実行、`execution:read` を持たない場合に retry レスポンスから実行データを除外）。実行データの redaction も Assistant 経路へ適用された。
- **draft の Agent 実行で、エージェントの read 権限と資格情報アクセスをチェックする**ようになった（#42152）。
- **エクスポートしたワークフロー JSON から資格情報の名前を除外**（#41691）。
- **JS task runner で Node Web Storage を無効化**（#41852）。
- **SAML ログインで、assert されたメールアドレスがリンク済みユーザーと異なる場合に報告**（#41506）。
- **アクセスキーを linting 上で secret な資格情報フィールドとして扱う**（CE-3601）。
- **public API の 401 すべてで OAuth resource challenge を広告**（#41829）。
- Webhook / MCP Trigger ノードを **trusted sources 経由で認証**する機能追加（#41455）。
- **granular credential sharing が常時有効になった**（#41376）。
- **非推奨ノードの利用を editor が防ぐ**ようになった（#31392）。

ほかに v3 マイグレーションレポート関連の拡充（プロジェクト別フィルタ、CSV エクスポート、ワークフロー編集者による findings のトリアージ、Edit Image ノードと Slack signature secret の v3 マイグレーションルール追加、「Executions might fail」インパクトの追加）、Microsoft Foundry のモデル対応（Claude デプロイを含む）、Agents SDK スパンへの OTel GenAI 属性追加、MCP registry servers への n8n Connect サーバー追加が入っている。

2.46.1〜2.46.3 は不具合修正が中心で、2.46.2 / 2.46.3 にも **`execution:read` の要求（workflow-scoped routes が実行データを読むとき）**、managed OAuth app の版選択、キュージョブの割り当て順の修正が含まれる。

## 影響範囲

- 対象ユーザー: n8n セルフホスト（`beta` チャンネル）、2.46 系へ上げる環境
- 管理者: 権限チェックの追加により、**これまで通っていた API 呼び出し・Assistant 経路が `execution:read` 不足で止まりうる**。granular credential sharing の常時有効化と非推奨ノードの利用禁止も挙動変更

## 教材化メモ

記事化しない（週次ソースの巡回記録）。**minor 1本に「今まで通っていた経路を止める」変更がまとまって入っている**のが要点で、機能追加ではなく権限チェックの追加が主役である。`execution:read` を持たないロールで運用していた自動化は 2.46 系で止まる。2.45.0 の「MCP ツール権限の全面見直し」（前週記録）からの連続で、**n8n は2週続けて権限の既定を締めている。**
