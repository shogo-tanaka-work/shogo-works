# 2026-11-03 n8n 2.47.0 系と moving tag の昇格

## 公式内容の日本語要約

窓内のリリースは **2026-11-03 と 11-04 に集中**し、11-05 以降は新規リリースが無い。安定版系列は2本動いた。

**2.47.0**（11-03 08:36Z）が本体。修正中心の大きめのリリースで、v3 移行レポートの改善（削除ノードと Edit Image の項目、行の詳細、アーカイブ済みワークフローを既定で隠す）、AI Agent ノードの非推奨エージェント種別の案内先の修正、ai-builder のチーム self-healing レビューへのインスタンス管理者の追加などが入る。**セキュリティに関わる既定変更として、送信リクエストガードの既定ブロック IP レンジが拡張された**（`core: Expand default blocked IP ranges for outbound request guard`）。ほかに execution の redaction を MCP ワークフロー実行エラーへ適用、フォルダ一覧クエリと MCP インスタンスコンテキストへのプロジェクトスコープ適用、エージェントサンドボックスのファイル書き込みをサンドボックスのサイズ上限内に収める修正、パッケージエクスポートパスでの危険な id のエスケープなど、**権限スコープと情報の漏れに関する修正が多い**。

**2.47.1**（11-04 13:30Z）は移行レポート関連の2件（アーカイブ済みワークフローを既定で隠す、レポート読み込みが長いときのメッセージ表示）。**2.47.2**（11-04 13:50Z）は `npm install` が全プラットフォームで通るようにする修正1件。

**2.46 系 backport** も同日に出た。**2.46.5**（11-04 09:37Z）は AI Agent ノードの非推奨案内、ノードパラメータ読み込み時の資格情報解決の改善、式での名前付き配列キーの読み取り、移行レポート関連2件。**2.46.6**（11-04 13:10Z）は 2.47.2 と同じ `npm install` の修正。

**moving tag の指す先**（取得時点）: **`stable` → 2.46.6**（11-04 13:10Z）、**`beta` → 2.47.2**（11-04 13:50Z）。`stable` はまだ 2.46 系に留まっており、2.47 系へは昇格していない。

## できるようになったこと

- v3 への移行レポートが読みやすくなった（アーカイブ済みを既定で隠す、長時間ロードの表示、削除ノードの詳細）
- `npm install` が全プラットフォームで再び通る（2.47.2 / 2.46.6）

## 影響範囲

- 対象ユーザー: self-hosted で n8n を運用している利用者、v3 移行を控えている利用者
- 対象プラン: self-hosted / Cloud 共通（タグ運用は self-hosted に影響）
- API / UI / 管理者機能: **送信リクエストガードの既定ブロック IP レンジ拡張は、これまで通っていた送信先が止まりうる既定変更である。** 内部ネットワーク宛てのリクエストを行うワークフローがある場合、2.47.0 へ上げる前に対象レンジを確認する必要がある。プロジェクトスコープの適用追加（フォルダ一覧、MCP インスタンスコンテキスト）も、**権限が狭まる方向の変更**であるため、見えていたものが見えなくなる可能性がある

## 教材化メモ

- **`stable` が 2.46 系に留まり、`beta` が 2.47.2 を指している点は、タグ運用の実例として重要である。** `stable` / `beta` は moving tag なので、**タグ名で固定しているデプロイは、ある日突然メジャー寄りの版へ動く**。本件のように `stable` が1つ前の系列に留まる期間もあるため、**タグが指す実バージョンを確認してから上げる**という手順が要る。巡回側でも「タグ 2本 + 実バージョン 6本」を別々に数える必要がある。
- **`core: Expand default blocked IP ranges for outbound request guard` は、SSRF 対策の既定強化である。** 自動化ツールは「任意の URL へリクエストする」機能を持つため、**内部ネットワークへの到達を既定で塞ぐ**のが定石になっている。一方で、社内 API を叩く正当なワークフローも同じ仕組みで止まる。**セキュリティの既定強化が既存の自動化を壊す**典型例で、前週の n8n 2.46 系の権限チェック追加と同じ系列である。
- **プロジェクトスコープの適用漏れ修正が複数ある**（フォルダ一覧、MCP インスタンスコンテキスト実行サマリー）。マルチテナントの権限モデルで、**一覧系クエリにスコープを掛け忘れる**のはよくある穴である。自作のマルチテナント実装を点検させる題材になる。
