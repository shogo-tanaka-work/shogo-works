# 2026-10-09 n8n 2.43.3

## 公式内容の日本語要約

**pre-release として公開され、moving tag の `beta` が本バージョンを指す。** **Features 2件**で、bug fixes の記載は無い。

**core**: **deprecated node を使うワークフローの作成・更新をブロックする**（#40706）。

**Google Gemini ノード**: 画像モデルの一覧へ **Nano Banana 2.1** と **Nano Banana 2 Lite** を追加（#40655）。

**同内容が 2.42.6（2026-10-09）へ backport され、その 2.42.6 が `stable` になった**（別メモ参照）。つまり **deprecated node のブロックは beta だけの話ではなく、同日に stable へも入っている。**

## できるようになったこと

- Gemini ノードで Nano Banana 2.1 / 2 Lite を画像モデルとして選べる

## できなくなったこと

- **deprecated node を含むワークフローを新規作成・更新できない**

## 影響範囲

- 対象ユーザー: n8n 利用者全般（stable へも同日に入ったため beta 限定ではない）
- 対象プラン: 記載なし
- API / UI / 管理者機能: ワークフローの保存・更新、Google Gemini ノード

## 教材化メモ

- **「Features」として告知された変更が、利用者側から見れば移行作業の締切である**という典型例。既存ワークフローの実行は止まらないが、**編集して保存する時点で弾かれる。** 自動化を運用している環境では、**更新前に deprecated node の棚卸しが必要**になる。
- **公式のリリースノートの分類（Features / Bug Fixes）を、利用者への影響の分類として読まない**という教訓になる。影響の大きさは節の名前では決まらない。
- Nano Banana 系の追加は、**ノードのモデル一覧がベンダーのモデル追加に追随する構造**の例である。モデル名をワークフローへ直書きしている場合、**ノードの更新とモデルの退役の両方を追う必要がある。**
