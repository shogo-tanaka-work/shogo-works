# 2026-08-28 Gemini Notebook の利用上限が柔軟化

## 公式内容の日本語要約

Google は 2026-08-28、**Gemini Notebook の利用上限を「計算量ベース（compute-specific）の柔軟な上限」へ変更する**と発表した。提供開始は **2026-09-02**、対象は**コンシューマーアカウントの web / モバイル**である。

従来は操作の種類にかかわらず一律のカウントだった。新方式では、**プロンプトの複雑さ、チャットの長さ、ソース数、使う機能**に応じて消費量が変わる。軽い操作は多く、重い操作は少なく回せる形になる。

**リセット間隔が日次から5時間ごとへ短縮**される。上限に当たっても翌日まで待つ必要がなくなる。

加えて、**生成物の先送り**ができるようになる。Video Overviews やスライドデッキのように生成が重いものは、上限を超えている場合に**後で自動生成させて通知を受け取る**形にできる。Notebook 側は使用状況を表示し、上限を超えそうなときは代替手段を提案する。

**具体的な数値上限は公式に明記されていない。** 有料ティアと無料ティアの区別についても記載がない。

## できるようになったこと

- 操作の重さに応じた消費量で上限を使える（軽い操作は回数を稼げる）
- 上限のリセットが5時間ごとになる
- 重い生成物を先送りして自動生成・通知させられる
- 現在の使用状況と代替手段を Notebook 上で確認できる

## 影響範囲

- 対象ユーザー: Gemini Notebook のコンシューマーアカウント利用者
- 対象プラン: コンシューマー向け（有料／無料の区別は公式に記載なし）
- API / UI / 管理者機能: UI 側の使用状況表示と生成キュー

## 教材化メモ

- **「回数」から「計算量」への上限設計の移行**は、AI プロダクトの課金・レート制限設計として押さえるべき変化。一律の回数制限は、**軽い操作しかしない人が損をし、重い操作を連打する人が得をする**構造になる。トークン／計算量ベースへ寄せるのは、API 側では当たり前だった発想がコンシューマー UI へ降りてきた例である。
- **リセット間隔を日次から5時間へ短くしたのは、上限そのものより体験を変える。** 「明日まで使えない」は離脱に直結するが、「数時間後に戻る」なら待てる。**制限の強さと、制限に当たったときの復帰時間は別のパラメータ**という設計論として教えられる。
- **重い生成を先送りしてキューへ入れる**設計は、同期処理を前提にした UI の限界を回避する定石。エージェント系のプロダクトを作るときも、**即応する処理と、後で通知する処理を分ける**判断は必ず出てくる。
- 数値が公開されていないため、記事化しても読者が自分の使い方に当てはめられない。上限値が明示されるか、有料プランでの扱いが出た時点で拾い直す。
