### 廃止・EOL と発効日の要点（`source-catalog.md` の GitHub Copilot 優先確認に基づく）

**今週の新規の廃止告知は1件で、それが予告期間ゼロだった。**

**1. JetBrains IDE 2025.1 のサポート終了（2026-10-10）。** プラグインの機能追加告知の末尾に「Support has ended for JetBrains IDE 2025.1. Users need JetBrains IDE 2025.2 or later」として置かれている。**公開日以外の発効日は示されていない。** 前週に記録した「同じベンダーの予告期間が1日から29日まで開く」という観察の続きだが、**今回は予告そのものが無い。** モデル廃止は29日の予告があったのに、IDE のサポート終了は即日である。**ベンダーの予告期間は「変更の重さ」ではなく「変更の種類」で決まっていない**ということであり、**予告を待つ運用は成立しない。** 対策は IDE / プラグインのバージョン分布を常に把握できる状態にしておく側にしかない。

**2. 同じ週に、IDE のバージョンを把握していないと困る別の案件が出た。** 「Copilot 利用メトリクスから agent 活動が欠落している」告知（2026-10-06）である。**IDE が agent セッションを Copilot SDK へ移したが、セッションが出自の IDE を申告しておらず、帰属が付かなかった。** **欠落したデータは遡って補填されない。** 修正版は VS Code 1.139.0 が提供済みで、Visual Studio 18.12 が 10月中、JetBrains が10月下旬、**Eclipse と Xcode は11月**の見込みである。**課金は影響しないが、Copilot CLI のメトリクスは逆に過大になっている。**

**この2件を並べると、IDE のバージョン統制がセキュリティ目的だけでなく「計測の正確さ」のためにも必要になったと言える。** 管理者の実作業は同じ一手（デバイス管理で最低バージョンを強制する）に収束する。公式も `totals_by_ide` の `last_known_ide_version` / `last_known_plugin_version` で古いクライアントを特定するよう案内している。

**3. 退役予告の継続案件2件に変化はない。** 10-19 の6モデル廃止（残7日）と 11-02 の `grok-imagine-image-quality` 退役（残21日）。後者は**退役後も同じ slug が応答し、出力品質だけ変わる**ため、**エラーにならずに結果だけ変わる**最も気づきにくい形である。3週連続で記録する。

**4. 10-22 の既定有効化（残10日）は今週も未処理のまま残っている。** GA 済みの Copilot 機能が Business / Enterprise で既定有効になり、**対象に MCP servers in Copilot ポリシーが含まれる。** 明示的に有効化・無効化している設定は上書きされないため、**10-22 までに AI Controls の「Default policy for new features」を3択（Enabled / Disabled / Let organizations decide）から選ぶ**のが実作業である。**残10日に入った。**

## 権限と統制（今週の最重要領域）

**今週は「エージェントの実行を落とす側の仕組み」が、ベンダー横断で同時に整備された週である。**

### 1. GitHub Copilot の local sandboxing が GA（2026-10-07）

Copilot が起動するコマンドとツールを、**ファイル・ネットワーク・資格情報・その他のシステム機能へのアクセスを制限した状態で実行する**仕組みが一般提供になった。基盤は **Microsoft eXecution Container（MXC）** で、共通のポリシー記述を Windows / macOS / Linux のネイティブ制御へ写す。**Copilot に追加費用なしで含まれる。** 対象は Copilot CLI、Copilot app、Agent Host を使う VS Code セッション。

**統制上の要点は2つある。** 1つは **enterprise-managed settings でサンドボックスを必須化し、開発者が弱められないポリシーを強制できる**こと。もう1つは **「ポリシーは Copilot がどのモデルを使っているかに関わらずツール実行へ適用される」**と明記されたことである。モデルの実行とツールの隔離が別々に扱われているためで、**モデルを差し替えても統制が崩れない構造**になっている。

**一方で既定が有効か無効かは告知に書かれていない。** GA を「何もしなくても安全になった」と読まず、自社で確認する必要がある。

### 2. Claude Code が hook の fail-closed 設定を入れた（2.1.295、2026-10-08）

command / HTTP hook を、**起動失敗・タイムアウト・想定外の終了コードのときに操作をブロックする**設定にできるようになった。**「ガードレールが落ちたとき、どちらに倒すか」を明示的に選べる**ようになったということである。

**同じ 2.1.295 で、権限 hook をすり抜けていたツール呼び出しが修正されている。** さらに 2.1.292 には**「PreToolUse hook の承認と auto mode が権限プロンプトを迂回していた」という明示のセキュリティ修正**があり、2.1.294 では**指示文として書いた prompt / agent hook が本来ブロックすべき操作を通していた**問題が直った。

**前週（2.1.284 / 2.1.289）は「ルールの判定がコマンドの書き方ですり抜けた」型だったが、今週はもう一段内側である。** 承認プロンプト自体が出なかった、hook の判定が誤った、hook をすり抜けた呼び出しがあった。**2週で合計7件、公式の修正として確定している。** **ガードレールを足すほど安全になるのではなく、ガードレール自体が検証対象になる。**

### 3. Copilot for JetBrains が MCP サーバーの自動起動を止められるようにした（2026-10-10）

**Copilot と Claude の MCP サーバーの自動起動を止める設定**が入り、利用者がいつ有効になるかを決められるようになった。あわせて **managed settings から enterprise の既定モデルを指定できる**ようになった。

**MCP サーバーが IDE 起動と同時に立ち上がる構成は、使っていない時間も外部サービスへの口が開いている。** 起動タイミングを握れるかは MCP の審査項目に入る。**同じ週に Claude Code 2.1.296 が `managed.policies[]` へ `code` キーを追加しており、両ベンダーで「管理側から拡張の起動を制御する」方向が揃っている。**

### 4. Cursor が「手元のマシンへ外から入る」口を足した（2026-10-06）

**remote control** により、ローカルで動いている agent を **Cursor の iOS アプリから閲覧・返信できる**ようになった。agent はコンピューター上に留まり、アプリがリモートから接続する形である。

**既定の状態が統制上の論点になる。** **Enterprise organization を除く全利用者で既定有効**で、**Enterprise 管理者だけが Org settings > Security and identity > Remote control で手動有効化する。** ペアリングはデスクトップアプリ側での承認が必要なので直ちに危険ではないが、**Business 相当以下の組織では、許可するかを決める前に機能が有効になっている。**

**前週に GitHub Copilot の computer use（画面と入力デバイスの操作）を記録したのと同じ系統である。** 「人間が使う画面・人間の手元のマシン」をエージェント経由で触る口が、ベンダー横断で増え続けている。あわせて **「Keep this computer awake」で常時起動を前提にする**点は、電力・画面ロック運用・物理的な持ち運びの前提を変える見落としやすいコストである。

### 5. n8n の資格情報カスタムロールが stable で使えるようになった（2026-10-09）

moving tag の **`stable` が 2.41.6 → 2.42.6 へ昇格**した（`beta` は 2.43.3）。**前週に「2.42 系列は beta チャネルのため stable では使えない。次の昇格後になる」と記録した統制機能が、1週で stable へ届いた。** 該当するのは、**インスタンス資格情報に対する view / use / manage のカスタムロール**、粒度の細かい資格情報共有、**資格情報を workflow runner に対して検証**、ポリシー違反のスコープ付き表示、SSO を主要サインイン手段として表示である。

**継続案件として残した判断が機能した。** moving tag を追う運用では、**「機能が出た日」と「stable で使える日」を別に記録する**必要がある。

## 課金と調達経路

**今週は「AI 機能の従量課金が、既定では個人の枠から引かれる」構造が明示された。**

**1. Copilot code review の課金先と実行者制限（2026-10-08）。** **既定では、レビュー要求は要求したメンバー自身の Copilot 枠に課金され、枠が枯渇するとレビューは失敗する。** organization owner は organization 課金へ切り替えられるが、**AI Credits の有償利用を有効化する必要がある**。あわせて「organization / enterprise 外のライセンス（個人ライセンスなど）でレビューを要求できなくする」制限が入り、**organization レベルで有効化するとリポジトリ管理者は外せない。**

**実務でいちばん効くのは既定値である。** CI にレビューを組み込んでいる場合、**特定メンバーの枠切れで落ちる**経路が既定のまま残る。**「誰の財布で動いているか」を自動化の前提条件として書き出す**必要がある。裏返しとして、**外部の個人ライセンスで組織リポジトリのレビューを要求できていた**という事実も読み取れる。**課金の経路が、そのままアクセスの経路になっている。**

**2. Secret Protection AI Credits（2026-10-07）。** 漏洩シークレット検出の専用モデルが投入され、**既存の AI 検出 Password アラートは自動的に新モデルへ切り替わった**（追加費用なし）。一方で **新しくクレジットを消費するチェックは既定で無効**で、**push protection の AI 検出は管理者が明示的に有効化する必要がある。** **課金は「数週間のうちに」開始**で具体日は示されていない。

**管理者の実作業は、Billing and licensing > Budgets and alerts で SKU 単位の予算を置き、「Stop usage when budget limit is reached」を有効化すること**である。**予算アラートだけでは使用は止まらない。** これは従量課金の AI 機能を採用するときの点検項目として、ツールを問わず流用できる。

**3. Copilot Credits の従量課金は継続案件（Q4 CY2026 展開、09-25 告知）。** 今週 **Viva Insights の Copilot Analytics に Cowork の採用状況と効果**が入った。**使用量を測る手段が、課金が従量へ移る直前に出てくる**順序になっている。
