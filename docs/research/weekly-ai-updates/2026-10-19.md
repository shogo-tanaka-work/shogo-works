### 廃止・EOL と発効日の要点（`source-catalog.md` の GitHub Copilot 優先確認に基づく）

**1. モデル廃止が2か月連続で走る。** 本日 2026-10-19 に6モデル（09-18 告知）が発効し、**28日後の 2026-11-16 に3モデル（Claude Opus 4.8 / Claude Opus 5 / GPT-5.6 Terra）が廃止される。** 影響面は Copilot Chat、インライン編集、ask / agent モード、コード補完で、**事実上すべての利用面**にかかる。

**2. 11-16 の廃止では、統制を強めている組織ほど手作業が増える。** 代替モデル（Opus 5.5 / GPT-6.1 Sol / GPT-6 Luna）は **default model enablement のもとでは自動的に有効**になるが、**グローバル既定を切っている組織・当該モデルを明示的に無効化している組織では自動で入らない。** モデルポリシーから手動で有効化する必要がある。**年額個人プランの契約者は Claude Opus 4.8 のアクセスを維持する**ため、この廃止の対象外である。

**3. 10-22 の既定有効化（残3日）が、ついに期限直前になった。** GA 済みの Copilot 機能が Business / Enterprise で既定有効になり、**対象に MCP servers in Copilot ポリシーが含まれる。** 明示的に有効化・無効化している設定は上書きされないため、**10-22 までに AI Controls の「Default policy for new features」を3択（Enabled / Disabled / Let organizations decide）から選ぶ**のが実作業である。**4週にわたり未処理のまま残日数だけが減っており、今週が最後の週である。**

**4. xAI の退役告知は、同じベンダー内で粒度が揃っていない。** `grok-voice-transcribe-1.0` は「2026-10-02 に EOL」と明示、`grok-imagine-image-quality` は「2026-11-02 に退役」と明示だが、**今週新規の `grok-voice-2.0` 非推奨には EOL 日付が無い。** 期日があるものは逆算でき、無いものは放置されやすい。**移行は `model` を 1行書き換えるだけで同価格のため、期日を待たずに済ませるのが妥当である。**

## 利用者側の対応が必要なもの（今週の最重要領域）

### 1. Microsoft 365 Copilot の trust-aware controls には CVE と管理者作業が紐づく（2026-10-13）

**間接プロンプトインジェクションへの対策として、取得コンテンツ（ツール出力）と主モデルの間に決定論的な強制レイヤーを置く。** 構成は4つ — **trust classification**（組織外からの外部メールなどを組織境界で untrusted に分類）、**quarantined processing**（untrusted を制約された経路に通し構造化表現へ変換、悪性と疑われる部分を落とす）、**provenance markers**（untrusted 由来の印を以降の処理へ反映）、**safer synthesis**（主モデルへは trusted はそのまま、untrusted は変換後の表現だけ渡す）。

**ここが本題である: 管理者の作業が2点ある。** **untrusted コンテンツを識別する Outlook の送信者設定を有効にする必要がある**（公式は設定名と場所を明示していない）。あわせて **MSRC の update guide にある CVE-2026-55145 の構成ガイダンスを確認する**よう案内している。**つまり機能告知の形をしているが、実質はセキュリティ対応依頼である。**

**見落としやすい理由が3つある。** (1) **`learn.microsoft.com` の release notes 側には未掲載**で、Tech Community blog にしか出ていない（release notes の最新見出しは 10-06 のまま）。(2) ロールアウト日・地域の時期が示されておらず、**提供状況と挙動はリリースチャネルとテナント環境によって異なる**とされる。(3) **ブロック・変換されたコンテンツのレポート・ログ・監査の手段が記載されていない**ため、効いているかを確認する手段が示されていない。

**公式が引く OWASP Top 10 for LLM Applications 2026 では、プロンプトインジェクションがアプリケーション層の最大リスクである。** 攻撃が**既存の権限の範囲内で成立する**ため、認証・アクセス統制・DLP では捕まらない。**権限統制を固めても止まらない種類の攻撃**であることが、この対策の存在理由である。

### 2. GitHub Copilot の managed settings が「確実に効かせる」方向へ2件同時に動いた（2026-10-12 / 10-13）

**10-13 の `forceRemoteSettingsRefresh` は、起動時にサーバー側の現行設定を取得させる。** server-managed / MDM-managed / ファイルベースのいずれでも設定でき、**一度 server-managed 値を受け取った後は、以降の起動で再取得が必須になる。** 有効な間は**キャッシュ応答では要件を満たせず、現行ポリシーを確認できないクライアントは fail closed で止まる。** 対応は Copilot CLI / VS Code / GitHub Copilot app。

**同じ告知に、`sandbox` キーによる最小クライアントバージョンの強制が入っている。** managed settings に `sandbox` を含めると、**GA 済みのローカルサンドボックス（10-07 記録）に対応した最小バージョン未満のクライアントはブロックされ、更新するまで使えない。** 公式は「今後、他のガバナンス向けキーにも最小バージョン要件を追加していく」と述べている。**古いクライアントの利用者が突然使えなくなるため、クライアント更新の周知を先に回す必要がある。**

**10-12 の telemetry 設定は、別方向の判断を発生させる。** `telemetry.capture.identity` を有効にすると、OpenTelemetry データへ **Copilot アカウント名・ローカル OS アカウント・ローカルマシン名**が付く。**既定は無効**で、取得クラス（プロンプト / レスポンス / ツール引数 / ツール出力 / ポリシー詳細）も**すべて既定オフ**である。旧 `captureContent` は5つの内容クラスの一括指定として機能するが、**identity は決して有効にしない。** 公式は「監査用途に必要なクラスだけを有効にする」よう明記し、**送信先を承認済みエンドポイントに限る**よう案内している。**監視の粒度を上げる機能は、同時に個人情報の取り扱い判断を発生させる。**

### 3. code scanning の agentic autofix GA で、無償機能が有償機能に置き換わる（2026-10-15）

**有効化すると、個別アラートの無償の「Generate Fix」が「Assign to Copilot」に置き換わる。** 動作は、関連ファイルを横断して調べ、修正を提案し、**CodeQL を再実行してアラートが閉じることを確認し**、draft PR を開く流れで、**最大25件のアラートを1 PR でまとめて修正**できる（REST API からも割り当て可能）。

**課金は AI Credits と Actions 分を消費する。** Code Security 予算の AI Credits を使い、消費は enterprise billing の「AI usage」配下「Advanced Security」製品として表示される。**SKU レベルの予算を設定できる。** **Generate Fix を日常的に使っているチームは、有効化前に消費見込みを見る必要がある。**

**対象は GitHub Enterprise Cloud の Code Security / Advanced Security 顧客に限られ、さらに既定ブランチ上のアラートだけが割り当て可能である。** PR や他ブランチにしか出ていないアラートは割り当てられない。**「PR 上で見つけた問題を自動で直す」という最も欲しい使い方ができない。**

### 4. n8n の `stable` が 2.42.6 から 2.43.7 へ動いた（2026-10-16）

**`stable` moving tag が 2.43.7（commit b7c5430）を指すようになった。** 前週の `stable` は 2.42.6 だったため、**この窓で stable チャネルが 2.42 系から 2.43 系へ移った。** `beta` は 2.44.3 を指す。**タグ追従の自動更新を入れている環境では、マイナー跨ぎの変更が意図せず入る。** 「stable を使っている」は特定バージョンを意味しない。

**同時実行で共有状態が壊れる修正が、3ラインに散って同週に3件出ている。** 2.42.7（**同時実行の credential test が1つの node type registry を共有しない**、#40783）、2.43.6（**webhook のリクエストボディごとに XML パーサーを生成**、#41113）、2.44.0（単一ノード実行に workflow create スコープを要求、テストとプローブにも credential policy を適用）。**公式に security fix のラベルは無いが、いずれも権限・分離に関わる修正である。**

**2.43.7 は worker 停止時に実行中の production execution を suspend する**（#40944）。停止時のジョブの取りこぼしに効く。

### 5. Grok Voice は「何もしなくても変わる」（2026-10 中、日付不明）

**`grok-voice-latest` が `grok-voice-3.0` を指すようになった。** 公式は「sessions that use the alias are upgraded automatically」と明記しており、**エイリアスを使っているセッションはコードを変えずにモデルが入れ替わる。** 価格は Grok Voice 2.0 と同じで、API も変わらない。**性能・品質の差分、対応言語、レイテンシの数値は記載が無い。**

**音声の声質・話し方が変わりうるため、エンドユーザー向けの音声体験を作っている場合は切り替わりを前提に検証する必要がある。** 品質差分の数値が公式に無いため、**移行の判断材料は自前の評価しかない。**

## 課金と調達経路

**1. agentic autofix の GA は「無償 → AI Credits」の置き換えである**（上記3）。SKU レベル予算が同時に提供されているのは、消費が読めないことが前提の設計である。

**2. Gemini 4 Argon は premium request の乗数が示されていない**（10-13）。公式は「usage-based billing のもとでプロバイダーのリスト価格で課金する」とし、モデルと価格のドキュメントを参照するよう案内している。**premium request の本数で見積る前提が崩れるため、利用実績ベースで測る必要がある。**

**3. HydraFusion Max は research preview で、価格・乗数・既定有効化の状態がいずれも記載されていない**（10-14）。**試用と本番導入を分ける判断が要る段階である。**

**4. Microsoft Copilot for legal はプラン階層・ライセンス要件が記載されていない**（10-15）。法務スキルは「世界中の Microsoft Copilot 顧客に一般提供」とされるが、**導入コストの見積りには問い合わせが必要である。**

**5. Copilot Credits の従量課金は継続案件**（Q4 CY2026 展開、09-25 告知、MC1479276）。今週の release notes 側に新しい動きは無い（最新見出しは 10-06 のまま）。
