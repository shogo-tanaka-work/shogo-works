# 2026-09-28 Manus 2.0

## 公式内容の日本語要約

**Manus 2.0 が公開された。** 公式は通常のバージョン更新ではなく「新しいアーキテクチャ、新しい製品、新しい機能」と位置づけている。Web・デスクトップ・モバイルで同時提供。

**Cascade agent harness（自社製ハーネスの刷新）。** 必要になったときだけ特化機能を読み込む方式で、プロジェクトの効率を保つ。公式が示す計測値は、ある構成で**トークン 23.2% 減、所要時間 28.2% 減、コスト 32% 減**（従来システム比）。

**Cloud Computer。** 常時稼働の環境を必要とするプロジェクト向けの専用環境。公式が挙げる用途は、サーバーが常に必要なマルチプレイヤーゲームと、継続実行する automations。

**Automations の拡張。** スケジュール実行だけでなく**イベント駆動**になった。トリガー例として「新着メール、広告パフォーマンスの変化、カレンダー予定、Slack メッセージ、Notion の更新」が挙がっており、**プロンプト1つで設定できる**とされる。

**Manus Studio（デスクトップアプリ）**に Video Editor と Game Dev の環境が加わり、ドキュメント・スプレッドシート・PDF・コードプロジェクトの扱いが強化された。

**新製品 Cue。** Web・デスクトップ・モバイル（iOS は App Store 審査中）で動く単体のパーソナルエージェントアプリ。早期アクセスは招待コード `MEETCUE` で先着。

**価格・クレジットについての記載はない。** 既存利用者の既定挙動が変わるかどうかも明示されていない。

## できるようになったこと

- Cascade ハーネスによるトークン・時間・コストの削減
- Cloud Computer での常時稼働プロジェクト
- イベント駆動の Automations（メール / Slack / Notion / カレンダー / 広告指標）
- Manus Studio での Video Editor / Game Dev
- 単体エージェントアプリ Cue の早期アクセス

## 影響範囲

- 対象ユーザー: Manus 利用者全般
- 対象プラン: 記載なし（価格・クレジットの言及なし）
- API / UI / 管理者機能: 新環境（Cloud Computer）、Automations のトリガー種別

## 教材化メモ

- **ハーネスの改善を数値で出してきた**点が重要である。トークン 23.2% 減・時間 28.2% 減・コスト 32% 減という提示は、**「ハーネス設計が性能とコストを決める」という主張をベンダーが自ら計測して示した**事例になる。ハーネスエンジニアリングの教材で、外部の裏づけとして引ける。
- **イベント駆動 Automations は、エージェントを「呼ぶもの」から「待つもの」へ変える。** メール受信や Slack メッセージで起動する構成は、**人間の承認が挟まらない実行経路**になりやすい。同じ週に GitHub Copilot も定期実行スケジュールを preview で出しており、**無人起動が複数ベンダーで同時に標準化している。** 承認フローの設計を先に決めるべき領域である。
- **価格・クレジットの記載が無いまま大型刷新が出た**という事実は、そのまま判断材料になる。Cloud Computer は常時稼働前提の環境であり、**課金条件が示されないまま常時稼働を選べる構造は、予算側から見れば未確定リスク**である。
