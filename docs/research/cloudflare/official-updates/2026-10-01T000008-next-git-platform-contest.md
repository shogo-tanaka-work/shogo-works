# 2026-10-01 次世代 Git プラットフォーム公募

## 公式内容の日本語要約

Cloudflare は、**Workers と Artifacts を使って「エージェント向けに最適化された次の Git プラットフォーム」を作る公募**を開始した。GitHub をエージェント向けに手直しするのではなく、**数百から数千のエージェントが同一コードベースで同時に協働する**状況に対応する新しい設計を求めている。

Artifacts 側の位置づけは「**Git を話し、数百万リポジトリへスケールするバージョン管理ファイルシステム**」であり、Workers バインディングによるリポジトリ操作、リポジトリ変更のイベント購読、データ所在（US / EU）の制御、メトリクスのダッシュボードを基盤として提供する。公募側は、その上の**協働とレビューの仕組み**に集中してほしいという立て方である。

**応募要件**: 5〜10分のデモ動画、オープンソースのコード（MIT / Apache / BSD）、利用手順。**締切 2026-10-14**。**上位3チームはサンフランシスコの Cloudflare Connect に招待**され、**1位には Cloudflare クレジット 25,000 ドル**と VIP ディナーが提供される。

Artifacts のオープンベータは Workers Paid プラン向けで、**課金開始は 2026-10-15 と本記事に記載がある**（changelog 側は 2026-10-14。**公式内で1日の差がある**ため、本メモでは差異として記録する）。

## できるようになったこと

- 公募への応募（締切 2026-10-14）

## 影響範囲

- 対象ユーザー: Workers / Artifacts を使う開発者・チーム
- 対象プラン: Artifacts オープンベータは Workers Paid
- API / UI / 管理者機能: 変更なし

## 教材化メモ

- **「エージェントが数千並列で同じコードベースを触る」前提でのバージョン管理**という問題設定そのものが教材価値を持つ。人間のレビュー速度がボトルネックになる構造を、どう作り替えるかという論点。
- **公募という手段で製品の使い道を外部に探させる**やり方。プラットフォーム事業者が「基盤は出した、上は任せる」と言うときの典型で、**基盤側がどこまでを自社の責任範囲とみなしているか**を読む材料になる。
- **締切が2週間という短さ**。既に作っているチームを拾う設計であり、新規参入を募る性格ではない。公募の設計意図を読む練習題材。
