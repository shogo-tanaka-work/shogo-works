# 2026-10-15 Cloudflare と OpenAI の AI 発見性パイロットの初期結果

## 公式内容の日本語要約

**Cloudflare と OpenAI が、2026年7月に開始した共同研究パイロットの初期結果を公表した。** 検証したのは「**Cloudflare のネットワークから得られるシグナルが、ChatGPT の利用者が新しいコンテンツをより効率的に見つける助けになるか**」である。

**役割分担が明示されている。** **Cloudflare はネットワークシグナルを提供**し、OpenAI の検索クローラーが有用なページを見つけやすくする。**OpenAI は独立にそれらのページを評価し、関連性と有用性でランク付けする。** つまり**シグナルは「見つけやすさ」に効き、順位付けは OpenAI 側の判断**である。

**規模と結果。** パイロットは **Cloudflare のネットワークの約1%の参加コホート**で行われ、**OpenAI が数億（hundreds of millions）の新規ページを発見・インデックスする助けになった**とされている。

**シグナルの中身は3種類が説明されている。**

- **フィルタリング**: 存在しないページの識別。ボットが繰り返し要求する URL、**ほぼどんなアドレスもトップページへリダイレクトするサイト**、重複コンテンツを見分け、無駄な取得を省く。
- **変更シグナル**: ページを再訪する価値があるときとないときを示し、不要な再クロールを減らす。
- **有害シグナル**: インデックスから外すべき**個別ページ**をフラグする。

**有害ページの扱いに設計意図がある。** **ドメイン全体ではなく、侵害された単一ページをフラグする。** 利用者を守りつつ**サイト運営者を連帯責任で罰しない**ためである。

**短期的にはクロールが増える可能性が明記されている。** 新しいページを見つける段階では、それらを評価するためにクロールが一時的に増えうる。目標は、発見を最新に保ちながら**全体のクロール作業を減らす**ことである。

**サイト運営者側の要点。** 開発者向けの具体的な手順は示されていない。運営者は **AI Crawl Control** で AI システムのアクセスを把握・管理できる。**シグナルはアクセス許可を与えるものではない**と明記されており、**アクセス制御は運営者の手に残る。**

**学習利用との線引きも明示されている。** この研究が使うのは**検索・発見のための Web に関するメタデータ**であり、**モデル学習のためのページ内容ではない。**

**次の段階**は、ページ選択の改善、より速く信頼できる変更シグナルの試験、発見された後に何が起きるかの計測である。発見性の改善が事業成果にどうつながるかも調べる予定とされている。

**パイロットへの参加方法・オプトインの説明はない。** 提供範囲は参加コホートに限られ、全顧客へ広げる時期は示されていない。

## できるようになったこと

- （パイロット参加コホートにおいて）OpenAI の検索クローラーが新規ページを従来より効率的に発見できる
- 侵害ページがドメイン単位ではなくページ単位でフラグされる
- サイト運営者は AI Crawl Control で AI システムのアクセスを把握・管理できる（シグナルの有無にかかわらずアクセス制御は運営者側）

## 影響範囲

- 対象ユーザー: Cloudflare を使うサイト運営者（パイロットは約1%のコホート）、ChatGPT の検索利用者
- 対象プラン: パイロットの参加条件・オプトイン方法は公式に記載なし
- API / UI / 管理者機能: AI Crawl Control（既存機能）。新しい設定項目の発表はない
