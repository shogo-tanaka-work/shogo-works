# 2026-09-28 Vinext 1.0

## 公式内容の日本語要約

Cloudflare が **Vinext 1.0** を公開した。**Next.js アプリケーションを Vite 上で動かし、Cloudflare Workers / Netlify / AWS Lambda など任意のプラットフォームへ移植可能にするフレームワーク**である。公式の表現は「Pages Router でも App Router でも、どちらで作られた Next.js アプリも任意の Web プラットフォームへデプロイできるように移植可能にする」。

**実験的プロジェクトから安定版へ昇格した。** テスト互換率は **cache components を除いて99%超**まで上がり、高トラフィックの本番アプリケーションで既に顧客が稼働させているとしている。

**対応する Next.js 機能**は、App Router と Pages Router の両方（両者が混在するアプリも含む）、React Server Components、Server Actions、middleware、レンダリング方式は SSR / 事前レンダリング / 静的エクスポート / ISR、OpenTelemetry と Sentry のトレーシング連携、認証・MDX・画像最適化といったエコシステムの定番パターン。

**Cloudflare Workers 固有の機構として cache warming がある。** ページの事前レンダリングをビルド時ではなく**本番デプロイ前の Cloudflare ネットワーク側へ移す**もので、大規模サイトのビルド時間を削減する。

**AI との関係が2段階で語られている点が特徴的である。** 元のプロジェクトは「エンジニア1人とトークンによる AI 駆動の実験」として始まった。そして **1.0 では継続的な保守そのものに AI エージェントを使っており、Next.js 側の変更を自動でレビューし、毎晩互換性テストを走らせている。**

## できるようになったこと

- Next.js アプリを Vite 上で動かし、Workers / Netlify / AWS Lambda へ移植
- App Router / Pages Router 混在アプリ、RSC、Server Actions、middleware の本番運用
- cache warming によるビルド時間削減（事前レンダリングを Cloudflare ネットワークへ移動）
- OpenTelemetry / Sentry によるトレーシング

## 影響範囲

- 対象ユーザー: Next.js を運用する開発者、Vercel 以外へのデプロイ先を検討している組織
- 対象プラン: Workers の通常課金に従う（Vinext 自体の追加課金は記載なし）
- API / UI / 管理者機能: ビルド・デプロイ基盤。cache components のみ互換率99%超の対象外
