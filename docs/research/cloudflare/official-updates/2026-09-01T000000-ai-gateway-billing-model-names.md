# 2026-09-01 AI Gateway の請求明細とモデル名

## 公式内容の日本語要約

AI Gateway の月次利用請求書（前月分を月初に発行）が、**モデルごとに単一の合計コストを表示する形式へ変わった。** 従来は入力トークンと出力トークンが別々の明細行に分かれ、それぞれの数量と単価が載っていた。

公式が挙げている例では、従来 `anthropic claude-haiku-4-5-20251001 Input Tokens`（40,000 トークン @ $0.000001 = $0.04）と `... Output Tokens`（24,000 トークン @ $0.000005 = $0.12）の2行だったものが、`anthropic/claude-haiku-4.5`: $0.16 の1行になる。

**あわせて、請求書とログの両方でモデル名が標準化された。** プロバイダー固有のバージョンサフィックス付きで表示されていたモデル名が、一貫した `provider/model` 形式の識別子になる。

**なお、この変更は AI Gateway のクレジット購入分の請求書には適用されない。**

## できるようになったこと

- 請求書上でモデル単位のコストを1行で把握できる
- 請求書とログでモデル名の表記が一致する（突き合わせが容易になる）

## 影響範囲

- 対象ユーザー: AI Gateway の従量課金利用者
- 対象プラン: 月次利用請求書のみ。クレジット購入分の請求書は対象外
- API / UI / 管理者機能: 請求書とログの表示形式の変更。**API の挙動や料金体系そのものは変わらない**

## 教材化メモ

- **明細の粒度を落とすことが、必ずしも利便性の向上ではない**という論点。入力/出力トークンの内訳が消えるため、**入力偏重か出力偏重かというコスト構造の分析が請求書からはできなくなる。** 内訳が必要ならログ側で取る必要がある——「どこで何を観測するか」の設計が要る、という一般則の実例。
- **モデル名の標準化は、地味だが集計コードに効く。** 請求書とログでモデル名が食い違っていると、突き合わせのために変換テーブルを持つ羽目になる。**識別子の一貫性は、後工程の複雑さを直接減らす。**
- 記事化は見送った（スコア5点）。請求書の表示形式変更で、読者の手順や判断が変わる範囲が狭いため。
