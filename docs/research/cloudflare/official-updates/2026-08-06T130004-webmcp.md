# 2026-08-06 Give any website a WebMCP interface

## 公式内容の日本語要約

WebMCP は、AI エージェントがサイトをスクレイピングするのではなく、サイト側が公開した「ツール」を呼び出して操作できるようにするブラウザ標準。Chrome 146 で実験的に搭載されており、ブラウザ上では `document.modelContext` として現れる。

Cloudflare の実装は2要素で構成される。1つは**エッジでの注入**で、HTMLRewriter を使って HTML レスポンスにブリッジスクリプトの参照を追加する。サイト側のコードは変更しない。もう1つは**ブラウザ側のブリッジ**で、WebMCP 対応を検出し、ツールパックを登録してエージェントから呼び出せるようにする。`data-packs` に列挙されたパックを1つのツールリストに合成し、それぞれを `.registerTool` で登録する仕組み。

開発者プレビューとして提供され、Cloudflare ダッシュボードの Agent Readiness > Labs からコード変更なしのワンクリックで有効化できる。初期のツールパックは2種類 — Content Credentials（画像の C2PA メタデータ）と Site MCP Server（既存 MCP サーバーへの接続）。ツールはすべて訪問者のブラウザ上、訪問者のオリジンとセッションで実行される。価格の記載はない。

## できるようになったこと

- サイトのコードを変更せず、ダッシュボード操作だけで WebMCP のツール面を配信できる
- Content Credentials / Site MCP Server の2パックをすぐ有効化できる
- 既存の MCP サーバーをサイト上のツールとしてエージェントへ露出できる

## 影響範囲

- 対象ユーザー: Cloudflare でサイトを配信している事業者
- 対象プラン: 開発者プレビュー（Agent Readiness > Labs）。価格記載なし
- API / UI / 管理者機能: ダッシュボード

## 教材化メモ

- 「エージェントにスクレイピングさせるか、ツールを渡すか」という対比は、MCP を学ぶ前段の導入として使いやすい。スクレイピングの脆さ（DOM 変更で壊れる）を先に体験させてからツール提供の話に入る構成が有効。
- ブラウザ標準（Chrome 146 で実験的）に依存するため、教材化は仕様の安定を待つべき。現時点では「そういう方向の標準が動いている」に留める。
- ツールが訪問者のセッションで動く点はセキュリティ上の重要論点。企業導入編で「サイトが提供するツールをエージェントが訪問者の権限で叩く」構図のリスク整理に使える。
