# 2026-11-13 Cursor セキュリティインシデントの調査結果

## 公式内容の日本語要約

2026-10-29 に公表した、Cursor の VS Code 拡張マーケットプレイスへ Anthropic の Claude Code 拡張の**悪意ある無許可コピー**が出た件について、2週間の調査結果が公表された（初報は `docs/research/zenn-cursor-basic/official-updates/2026-10-29T000000-cursor-marketplace-claude-code-extension-compromise.md`）。影響を受けた顧客には個別に連絡済みとしている。

公式が示した経路は次のとおり。

1. **発端は Fireworks**。Cursor が Fireworks へ発行していたアクセスキーが Fireworks 側で露出し、攻撃者がそれを使って、Cursor が Fireworks とデータを共有するための読み取り専用ストレージバケットからデータを複製した。そのバケットには Privacy Mode でないセッションのコーディングエージェントのトレース（大半が2025年のもの、モデル学習に利用を許諾されていたもの）が入っていた。**そのうち一部に、マスクされていない資格情報が含まれていた（API 資格情報が露出したのは顧客の 0.01% 未満）。** 攻撃者はそれを起点に Cursor が使う一部の SaaS ツールへ到達し、アーカイブ済みの非本番ソースリポジトリ（一部に業務上の連絡先情報を含む）、一部のサポートデータとメールのやり取り、製品利用メトリクスと連絡先、コーディングエージェント会話の要約、**サポート宛に利用者が送っていた資格情報**にアクセスした。
2. Cursor の監視が不正な活動を検知し、ベンダーのキーを無効化、資格情報の無効化とローテーション、追加の不正アクセスの捜索を実施した。念のため必要以上に内部・製品サービスを一時停止したため、一部機能が一時的に使えなくなった。
3. **2026-10-29、攻撃者は内部システムから盗んだ資格情報を使い、Cursor の VS Code 拡張マーケットプレイスの配信キャッシュへ、Claude Code 拡張の悪意あるコピーを直接置いた。** Anthropic がこれを公開したわけではなく、Anthropic 製品の脆弱性でもない。マーケットプレイスのソースである Open VSX にマルウェアは入っていなかった。**10-29 に特定のキャッシュ版を要求した最大 5,000 ユーザーが、悪意あるビルドを受け取った可能性がある。** 公開されていたのは約11時間。
4. 10-30 にブログと X で侵害指標（IoC）、修復手順、確認スクリプトを公開し、影響を受けたユーザーとチーム管理者へアプリ内通知とメールで連絡した。
5. **封じ込め済みと判断**。攻撃者の最後の活動は 2026-11-01 で、これはブロックされた。

## 利用者側の対応（必要）

- **露出期間中に Cursor の VS Code 拡張マーケットプレイスから `Anthropic.claude-code` の 2.1.312 または 2.1.313（改ざん版）をインストールまたは更新した場合は、Cursor のセキュリティ通知の手順に従う。拡張のアンインストールだけでは不十分な場合がある。**
- 資格情報が露出した場合は、チーム管理者へローテーション対象のキー一覧がメールで送られている。
- 通知が来ていなければ、トレースへの該当はないと公式は説明している。

## 影響を受けなかったもの（公式の明示）

- Privacy Mode 利用時のプロンプトとコード
- Privacy Mode 非利用でも、トレースが露出したのは利用者の 0.05% 未満（該当者には個別通知済み）
- 現在 Cursor へ送っているデータとライブトラフィック（露出したトレースは過去のオフライン分析用ストレージに限られる）
- Cursor を動かす本番システムとインフラ
- Cursor アプリとその公式アップデート

## 影響範囲

- 対象ユーザー: 10-29 に Cursor の拡張マーケットプレイス経由で該当拡張を取得した最大 5,000 ユーザー、API 資格情報が露出した 0.01% 未満の顧客、トレースが露出した 0.05% 未満の利用者
- 対象プラン: プラン横断
- 期限: 明示された期限はないが、**改ざん版を取得した可能性がある利用者の対応は未完了であれば即時**

## 教材化メモ

記事化しない（本Skillの記事化対象は Claude Code / Codex のロールアップのみ）。ただし週次サマリーの冒頭で扱う。**サプライチェーンの経路が3段（ベンダーのキー露出 → トレース内の未マスク資格情報 → SaaS ツール → 配信キャッシュ）になっている点が教材価値の中心である。** とくに「モデル学習用に共有していた過去のトレースに資格情報が残っていた」ことが起点になっており、**ログ・トレースのマスキングが侵入の深さを決めた**。AI エージェントのログ設計を教えるときに、保持方針とマスキングを同じ回で扱う根拠になる。加えて、**公式マーケットプレイスのソース（Open VSX）は無事で、配信キャッシュが汚染された**という形は、「上流が正しければ安全」と言えないことを示す。
