# 2026-09-02 Cursor Self-hosted machines

## 公式内容の日本語要約

**ツール実行を自社ネットワーク内に閉じ込める**機能が入った。公式表現は "keep tool execution entirely in your own network"。**コードベース、ビルド成果物、シークレットが社内インフラに留まったまま**、エージェントがツール呼び出しを処理する。

構成は次の4要素。

- **My Machines**: ノート PC や VM を1台アカウントへ接続する個人向けの使い方
- **Team Pools**: 名前付きのワーカーキュー。需要に応じて容量を動的にスケールし、アイドル時はマシンを休止させてコストを抑える
- **サンドボックス連携**: AWS Lambda、Coder、Cloudflare、Daytona、Modal、Namespace、Vercel、E2B に対応
- **Computer Use**: Linux と Mac で、エージェントが「クリック、入力、スクリーンショット取得、ブラウザ操作」を行える。デスクトップの観察や手動での操作引き取りも可能

対象プランと管理者側の具体的な設定要件は、公式ページには記載がない。廃止・期限の記載もない。

## できるようになったこと

- ツール実行を自社ネットワーク内のマシンで行う
- チーム向けにワーカープールを組み、需要に応じてスケール・休止させる
- Linux / Mac で Computer Use を動かし、必要なときに人が操作を引き取る

## 影響範囲

- 対象ユーザー: コードやシークレットを外部へ出せない制約を持つ組織
- 対象プラン: 公式ページに記載なし
- API / UI / 管理者機能: 実行基盤、サンドボックス連携

## 教材化メモ

- **「モデルは外、実行は内」という分割**が、この機能の本質である。推論そのものはベンダー側で行い、**ファイルに触る・コマンドを打つ・ブラウザを操作するといった副作用のある操作だけを自社側に置く。** データ持ち出しの懸念で AI コーディングツールの導入が止まっている組織にとって、この分割は交渉の材料になる。**「AI を使うか使わないか」ではなく「どこに境界を引くか」**という議論に持ち込める。
- ただし**プロンプトとして送られるコードは依然として外へ出る**点は誤解しやすい。「実行が内側」であることと「コードが出ない」ことは別である。**セキュリティ要件を満たすかは、境界の位置を正確に把握してから判断する**——導入検討の教材で最初に潰すべき誤解として使える。
- **アイドル時にマシンを休止させる**という設計は、自前実行基盤のコスト問題への現実的な回答。セルフホストは「安く済む」わけではなく、**遊休時間の扱いで総額が決まる。**
