# 2026-11-05 Cursor: Build Live Apps

## 公式内容の日本語要約

Cursor 内で Web アプリを作り、リンクで共有できるようになった。クラウドエージェントを起動してアプリを作りたいと伝えると、Cursor がアプリの雛形を作り、**必要に応じて Postgres データベースと Cursor SSO 認証を用意し、ホスティングをプロビジョニングし、自社システムへの接続に必要なシークレットを尋ねる**。公開時は一意のドメインを選ぶ。

**公開前に Cursor がセキュリティチェックを走らせる**（露出したシークレットなどの問題を検査）。**チェックが通り、利用者が明示的に公開操作を行うまで、何も公開されない。**

**チーム管理者の統制**として、全アプリとシークレットの閲覧、独自のセキュリティレビュールールの追加、ブロックされた公開の承認、アプリの非公開化ができる。共有範囲は特定の個人・グループ・チーム全体（Cursor サインインの背後）から選べ、**個人プランでは公開共有も可能**。スクリプトや Grok Bot 用に Cursor API キーを発行できる。

有料プラン全般（クラウドエージェント有効）が対象。デプロイ元は Cursor Origin と GitHub リポジトリに対応し、GitLab 対応は予定。

## できるようになったこと

- Cursor から DB・認証・ホスティング込みで Web アプリを立ち上げ、URL で共有できる
- 管理者がアプリとシークレットを一覧し、公開を承認・取り消しできる
- 公開前のセキュリティチェックに独自ルールを足せる

## 影響範囲

- 対象ユーザー: Cursor の有料プラン利用者（クラウドエージェント有効）
- 対象プラン: 全有料プラン。公開共有は個人プランでも可
- API / UI / 管理者機能: **開発ツールがホスティング事業者になる変更である。** シークレットを Cursor 側へ預ける構造になり、**チーム管理者はシークレットを閲覧できる**。社内システムへ接続するアプリを個人が立ち上げられるため、情シスから見た新しい統制対象が増える

## 教材化メモ

- **「開発ツールが DB・認証・ホスティングまで持つ」形が、Cursor でも始まった。** 作る側の摩擦は確実に下がるが、**社内システムの資格情報が開発ツールのベンダーへ渡る**構造になる。前週の Cursor Marketplace での偽拡張配布（2026-10-29）と合わせて読むと、**同じベンダーに預けるものが増えている**流れが見える。導入判断では「どこにシークレットが置かれるか」を必ず確認させたい。
- **公開前のセキュリティチェックと管理者承認は、設計として評価できる。** 「チェックが通り、かつ利用者が明示的に公開するまで何も出ない」という二段構えで、**既定で安全側に倒している。** 一方でチェックの網羅性は検証できないため、**自動チェックを通ったことを安全の証明と読まない**という注意はセットで要る。
- 管理者が**シークレットを閲覧できる**点は、便利さと内部統制の両面がある。「管理者なら見られて当然」ではなく、**誰がシークレットを見られるかを設計として意識する**題材に使える。
