# 2026-11-06 Cursor: Voice Chat with Agents

## 公式内容の日本語要約

エージェントとリアルタイムで音声通話できるようになった。対応は Agents Window、IDE、Web、Cursor for iOS。エージェントがアイドルで入力欄が空のときに出る波形ボタン（"Start voice chat"）から開始する。**iOS では「Hey Siri, call Cursor」で発信し、ロック画面からミュートや終話ができる。**

音声エージェントはコーディング作業をチャットエージェントへ引き渡せ、**作業が走っている間も質問に答えられる**（差分で何が変わったか、実行の状況など）。コーディングエージェント側は短い進捗を音声で伝え、終了時に簡単な要約を話す。

**基盤は Grok Voice**で、複数の音声から選べる。**Privacy Mode が有効な場合はゼロデータ保持で動作する。** 音声入力をチャット欄のテキストに変換する dictation とは別機能で、IDE での dictation の切り替えは従来どおり Cmd+Shift+Space。

## できるようになったこと

- エージェントと音声で対話しながら、作業の進捗や差分の内容を聞ける
- iOS から Siri 経由で発信し、ロック画面で操作できる
- Privacy Mode 下ではゼロデータ保持で音声機能を使える

## 影響範囲

- 対象ユーザー: Cursor の Agents Window / IDE / Web / iOS 利用者
- 対象プラン: 公式記載にプラン別の明記なし
- API / UI / 配慮事項: **音声は新しいデータ種別である。** 基盤が Grok Voice（xAI）であるため、**モデル提供元が Cursor 本体と別になる**。Privacy Mode でゼロデータ保持と明記されているが、Privacy Mode を使っていない組織では音声データの扱いを別途確認する必要がある

## 教材化メモ

- **「音声で進捗を聞く」は、エージェントの非同期化が進んだ結果である。** 作業が長時間走る前提になったからこそ、**走っている間に状況を問える経路**が要る。前週までの Cloud Agents / 並行セッションの流れと同じ方向で、**開発者の役割が「書く人」から「複数の作業を見る人」へ寄っている**ことを示す材料になる。
- **基盤が Grok Voice であることは、記録しておく価値がある。** 同じ週に `status.cursor.com` が `status.x.ai` へリダイレクトするようになった（本リポジトリの巡回で確認）。**Cursor と xAI の技術基盤の結合が進んでいる**と読める。利用者から見ると、**1つのツールを選んだつもりで複数ベンダーのサービスを使っている**状態になるため、データの流れ先の確認が要る。
- **音声データは議事録・会話ログと同じ機密性を持ちうる。** 「コードは Privacy Mode で守っている」組織が、音声を同じ基準で扱えているかは別問題である。新しい入出力経路が増えたときに**既存のデータ分類が追いついているか**を点検させる題材になる。
