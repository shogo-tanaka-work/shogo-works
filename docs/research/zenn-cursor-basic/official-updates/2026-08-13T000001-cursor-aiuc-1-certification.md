# 2026-08-13 Cursor の AIUC-1 認証取得

## 公式内容の日本語要約

Cursor が **AIUC-1 認証**を取得した。AIUC-1 は AI エージェントのセキュリティ・安全性・信頼性に関する新しい標準で、**組織的な統制の監査**と**製品そのものへの敵対的テスト**を組み合わせる点が特徴である。

Cursor は既存のセキュリティ認証との違いをこう説明している。従来の認証はデータがどう保存され、保護され、統制されているかを示すが、**エージェント自身がどう振る舞うか**の評価は薄い。「安全でないコードを書くよう指示されたら」「秘密情報を露出するよう求められたら」「拒否すべき操作を求められたら」エージェントは何をするのか、という問いに答えるのが AIUC-1 だとしている。

標準の成り立ちも示されている。Fortune 500 の CISO・リスク責任者 100 名超の意見を取り入れ、MITRE、Cloud Security Alliance、スタンフォードの研究者が技術的に寄与した。**NIST AI Risk Management Framework、MITRE ATLAS、OWASP の agentic threat taxonomy** といった既存フレームワークを、実際に動作する AI システムに対してテスト可能な要件へ翻訳している。コーディングエージェント向けには、**秘密情報の保護、安全なコード生成、MCP セキュリティ、エージェントの ID と権限**が要件に含まれる。

監査は **Schellman** が実施した。ANAB 認定の ISO 42001 認証機関として世界初であり、AIUC-1 の最初の認定監査人でもある。Schellman は文書化された統制を確認し、その背後にある AI ガバナンスの実践と実装を検証した。

加えて、数千のシナリオによる敵対的テストを実施した。対象は IDE とクラウドエージェントを含む主要なエージェント面で、代表的な企業設定を用いた。評価者は Cursor が持つ **rules、hooks、Auto-review** といったセーフガードを実際に動かし、コーディングエージェントが遭遇しやすいリスクのシナリオを試した。**2 ラウンド・数千シナリオを通じて、良性・敵対的の双方の条件でセーフガードが維持され**、要件を満たしたとしている。

継続性も特徴として挙げられている。認証の維持には**四半期ごとのテストと年次の完全監査**が必要で、AIUC-1 の要件自体も四半期ごとに更新される。エージェントの能力向上に合わせて基準が上がっていく設計である。

現在 **Fortune 500 の 70%** が Cursor を利用しているという数字も示されている。

## できるようになったこと

- 企業の調達・セキュリティレビューで、エージェントの挙動に関する第三者評価を証跡として使える
- rules / hooks / Auto-review といった既存の統制機能が、敵対的条件下で検証された事実を参照できる

## 影響範囲

- 対象ユーザー: Cursor を導入検討・運用中の企業のセキュリティ・調達担当
- 対象プラン: 記載なし。認証は製品全体に対するもの
