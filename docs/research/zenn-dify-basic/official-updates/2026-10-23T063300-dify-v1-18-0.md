# 2026-10-23 Dify 1.18.0

## 公式内容の日本語要約

**1.17.1（2026-09-10）から6週ぶりのマイナーリリース。** タイトルは「Release v1.18.0 — Smarter Agent Routing, Portable Apps, Deeper Workflow Visibility」。

**主な新機能**

- **Agent Output Routes**: Agent がワークフローの分岐を選べるようになり、選んだ経路が読み取り専用の `switch` 出力に出る。
- **`.ifpkg` 形式のポータブルパッケージ**: インラインの Agent / Skill / ファイルを含めてアプリをエクスポートできる。YAML エクスポートも引き続き利用可。
- **ネストしたワークフローのトレース**: Workflow Tool の実行が子グラフとして動き、その中のステップまで掘れる。
- **Agent Knowledge Base（Beta、opt-in）**: Agent 向けの知識空間。**別サービスと別データベースを前提とする。**
- **difyctl と OpenAPI**: CLI がサーバーのカタログからコマンドを発見する。Workflow / Chatflow アプリを管理できる。
- Agent トレース、OpenShell バックエンド、E2B 使用量収集。Plain Agent v2 ノードがテキストをストリーミング。

**破壊的変更（公式が breaking として列挙しているもの）**

- Agent Backend の `/runs` は composition v2 のみ受け付け、**v1 リクエストを拒否する。** 直接連携している実装は更新が必要。
- Agent 専用の AskHuman ツールと deferred resume 経路を**削除**（共有の Workflow Human Input ノードは引き続き動作）。
- Local Agent sandbox が**空でない認証トークンを必須化**（`DIFY_AGENT_LOCAL_SANDBOX_AUTH_TOKEN`）。
- ソースからのインストールは **Python 3.13 必須。**
- 新しい difyctl クライアントは v1 のログイン状態を再利用しないため、**再サインインが必要。**
- モード非依存の `/openapi/v1/apps/{app_id}:run` を、モードごとの操作へ置き換え。
- `GRAPH_ENGINE_MIN_WORKERS` と scale-up / scale-down の設定を削除。
- console の feedback エクスポートエンドポイントを削除。
- **`PASSWORD_PEPPER` の設定・変更・削除は既存のパスワードハッシュを無効化する。**

**セキュリティ修正・強化**

- API と webhook のエラーが、内部の例外テキストではなく固定の公開メッセージを返すようになった。
- CSRF の allowlist 照合が完全一致になった。
- ローカルサンドボックスは空の認証トークンを拒否する。Landlock のセットアップ失敗はジョブを中断する。
- **プラグインのインストールが、ポリシー未保存の場合に workspace owner と administrator だけの既定になった。**
- **新規の knowledge base が、RBAC 有効な環境で workspace メンバー全員を自動的に含めなくなった。**
- 依存更新に Weaviate（1.39.2 → 1.39.13）、Next.js、certifi、NLTK 3.10.4 を含む。**公式は「NLTK の更新だけでは全ての advisory を解消しない」と明記している。**

**アップグレード時の注意**（公式の要点）

- データベース、ベクターストア、アップロード済みファイル、Agent ストレージ、シークレット、env ファイルを**先にバックアップする。**
- API / workers / Agent Backend / Agent runtime のイメージを**一式で揃えて上げる。** 新しいトラフィックを通す前に旧 worker を退役させる。
- 1.17.1 からのアップグレードは **22 revision ＋ merge 2件**を適用し `b9d3f7a5c102` で終わる。新 worker 起動前に全チェーンを適用する。
- `PASSWORD_PEPPER` は、pepper 無しの既存環境では空のままにし、設定済みの値は変更しない。
- Nginx の前にロードバランサーや Cloudflare がある場合は trusted real-IP の設定を行う。
- KnowledgeFS は既定オフ。データベース・鍵・`/ready` チェックを整えてから有効化する。
- 公開済みの trigger subscription の再バインド、対象ドキュメントの再インポート／再インデックスが必要な場合がある。
- Weaviate 1.27 の環境は、先に 1.17.1 の段階的アップグレードを完了させる。

## できるようになったこと

- Agent がワークフロー分岐を選択でき、選択結果を後続で参照できる
- アプリを `.ifpkg` として Agent / Skill / ファイルごとエクスポートできる
- ネストしたワークフローの実行を子グラフとして掘れる
- difyctl から Workflow / Chatflow アプリを管理できる

## 影響範囲

- 対象ユーザー: Dify のセルフホスト運用者、Agent Backend `/runs` を直接叩いている実装、difyctl 利用者
- 対象プラン: 記載なし（OSS / self-hosted）
- API / UI / 管理者機能: Agent Backend API、OpenAPI、difyctl、プラグイン権限、knowledge base の RBAC 既定

## 教材化メモ

- **権限の既定が2か所で厳しくなった点が、この版でいちばん実務に効く。** (1) プラグインのインストールがポリシー未保存時に **workspace owner / administrator 限定**になり、(2) **新規 knowledge base が workspace メンバー全員を自動的に含めなくなった。** どちらも「今まで通りに動かない」方向の変更で、**アップグレード後に「権限が無くて操作できない」という問い合わせが出る**類のものである。緩い既定を締める変更は、セキュリティ上は正しく、運用上は摩擦を生む。この両面を同時に説明する教材素材になる。
- **`PASSWORD_PEPPER` の扱いは事故の作り方として分かりやすい。** 設定・変更・削除のいずれでも既存のパスワードハッシュが無効になる。つまり「設定を整えよう」として触ると全員がログインできなくなる。公式が「pepper 無しの既存環境では空のままにする」と明記しているのがその証拠である。
- **「NLTK の更新だけでは全ての advisory を解消しない」と公式が書いている**のは誠実な書き方である。依存更新の記載を見て「脆弱性は解消済み」と読むのが誤りである例として使える。
- 6週間リリースが無く、1本に破壊的変更9件とマイグレーション22 revision が溜まった。**更新頻度が低いツールほど、1回のアップグレードが重くなる。** 週次確認ソースへ置いた判断（更新検出が少ない）と、1回あたりの重さは別物である、という整理ができる。
