# 2026-09-10 Dify 1.17.1

## 公式内容の日本語要約

窓内の Dify リリースは 1.17.1 の1件。**セルフホスト運用者に、更新前の手作業が発生する。**

**最優先の警告（公式が WARNING として掲示）。同梱 Weaviate を使うセルフホスト環境は、1.17.1 を起動する前に段階的な手動アップグレードを完了させる必要がある。** 同梱 Weaviate が `1.27.0` から `1.39.2` へ、**マイナー12版ぶん**上がる。**マイナーを飛ばすのはサポート外**で、単に pull して再起動すると**ベクトル検索が無言のまま永続的に壊れうる。** 新規デプロイ、外部 Weaviate、他のベクトルストアは影響を受けない。

**新機能**。**ナレッジベース単位のスコープを持つ API キー**。従来、ナレッジベースのサービス API キーはワークスペース全体が対象で、1本のキーでテナント内の全ナレッジベースを読み書きできた。**特定のナレッジベースへ紐付けられる**ようになり、紐付けたキーは他データセットに対して（ドキュメント・検索とも）`403` を返す。**既存キーは未紐付けのままワークスペース全体の挙動を維持する**ため、更新しても挙動は変わらない。ほかにワークフローノード・コメントのキーボード移動、マーケットプレイスの作者プロフィールとトップページ刷新、Markdown フォームのフィールド名長を `MARKDOWN_FORM_FIELD_NAME_MAX_LENGTH` で設定可能に。

**バグ修正**。**エラーを出さずに文書内容を書き換えていた抽出バグの一群**が修正された。**更新後に該当ドキュメントの再取り込みが要る（インデックス済みのテキストは遡って修復されない）。** CSV が pandas の型推論を通っていた問題（`00123` → `123.0`、空セルが文字列 `nan`、`NA` / `NULL` が欠損値化）、Notion テーブルの列の増減と database プロパティの先頭セグメントでの切り詰め、`.xls` のダブルクォート、URL から読む PDF の `AssertionError` クラッシュ、内蔵 Web スクレイパーが本文ではなく Python のデータ構造を返していた問題など。

そのほか、**エージェント実行の保持期間が既定で3日から2時間へ短縮**（Redis の無制限な肥大化を防ぐため）、**エージェントスキルにおける SSRF ポリシー回避の修正**を含むセキュリティ強化、アクセシビリティ改善が入っている。

## できるようになったこと

- API キーを特定のナレッジベースへ紐付け、他データセットへのアクセスを `403` で拒否できる
- ワークフローのノード・コメントを矢印キーで移動できる（Shift で大きく、1操作＝1 undo）
- Markdown フォームのフィールド名長を環境変数で調整できる

## 影響範囲

- 対象ユーザー: Dify のセルフホスト運用者（特に同梱 Weaviate 利用者）、ナレッジベース連携を実装している開発者
- 対象プラン: セルフホスト（OSS）
- API / UI / 管理者機能: ベクトルストアの手動アップグレード、ナレッジ API キーのスコープ、エージェント実行の保持期間（既定変更）

## 教材化メモ

- **「pull して再起動すると無言で壊れる」という更新は、セルフホストの最悪のパターンである。** エラーが出ないため、壊れたことに気づくのはベクトル検索の品質が落ちてからになる。**リリースノートの WARNING を読まずに更新する運用が、そのまま事故になる**実例として強い。更新手順に「リリースノートの WARNING 節を読む」を明示的に入れる根拠になる。
- **API キーのスコープが「ワークスペース全体」だったという事実そのもの**が教材になる。1つのナレッジベースへ連携させるつもりで渡したキーで、全ナレッジベースが読めていた。**最小権限が設計に入っていないプロダクトは珍しくない**という前提で、連携先の権限モデルを確認する習慣につなげる。**しかも既存キーは未紐付けのまま**なので、更新しただけでは安全にならない。棚卸しが要る。
- **抽出バグ群は「AI が嘘をつく」前段の問題である。** `00123` が `123.0` になり空セルが `nan` になった状態でインデックスされていれば、RAG の回答は元データと違っていて当然である。**モデルの精度を疑う前に取り込み経路を疑う**という順序を教える具体例として、CSV の型推論はとりわけ分かりやすい。
- **エージェント実行の保持が3日→2時間**は、デバッグ運用の前提を変える。翌日に調べようとすると記録が消えている。
- 記事化はしない（週次確認ソースの通常更新）。ただし**セルフホスト運用者には更新前の作業が発生する**ため、週次サマリーで明示する。
