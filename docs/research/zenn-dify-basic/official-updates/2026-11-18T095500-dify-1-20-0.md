# Dify 1.20.0

## 公式内容の日本語要約

2026-11-18 に 1.20.0 が出た。Dify は週次確認ソースの中でも更新頻度が最も低い（91日で5回）ため、窓内の1件はこれのみ。

**期限が過ぎている対応事項がある。** Langfuse Cloud は**レガシーの ingestion エンドポイントを 2026-11-16 に廃止**し、セルフホストの Langfuse v4 も同エンドポイントへのイベントを拒否する。**それらの環境へトレースを送り続けるには 1.20.0 へ上げる必要がある。** 1.20.0 の Langfuse トレーシングは Langfuse v4 と現行の Langfuse Cloud ingestion に対応する（既存の Langfuse 設定はそのまま動く）。

**新 HITL（既定で有効、`NEXT_PUBLIC_ENABLE_HITL_IM=true`）**。承認フローをメールとチームが既に使っているメッセージングツールへ出せるようになった。共有チャンネル、集約された連絡先、通知テンプレート、検証付き承認フォームを導入し、受信者を一度設定すれば複数の Human Input ノードで再利用できる。対応 IM は Slack / Feishu・Lark / Microsoft Teams / DingTalk / WeCom。受信者は IM カード内でレビューするか単独フォームを開き、**Dify ログインまたはメール検証で本人確認**する。既存ワークフローの移行は opt-in。デプロイ要件は "Configuration and Integration Changes" に記載。

**ナレッジアップロードのマルウェアスキャン（`FILE_SCAN_ENABLED=true`）**。アップロードされたファイルを**抽出・索引の前に**スキャンする。ワークスペースの owner / admin が Integrations → File Security Scan でスキャナーを設定し、ナレッジベースごとに使い方を定義する。対応スキャナーは Cloudmersive / Scanii / OPSWAT MetaDefender Cloud / カスタムエンドポイント。スキャン不能時のフォールバック挙動を選べる。対象は従来のナレッジベース、RAG Pipeline のローカルファイルソース、Agent ナレッジベースのアップロード。ブロック理由はドキュメント一覧に出る。

**OpenTelemetry への汎用エクスポート**。新しい OpenTelemetry プロバイダーが、アプリと Agent のトレースを任意の互換コレクターへ送る。ベンダー固有の Dify 連携なしで、ワークフローのステップ・モデル呼び出し・ツール活動をまとめて追える。

**個人アクセストークン（PAT）**。Console セッションを共有せずに、スクリプト / CI / 個人のエージェントへ Dify OpenAPI のアクセスを与えられる。アカウントページで作成し、**ワークスペースとリソースにスコープを絞り、任意の有効期限を設定し、不要になれば失効**できる。

**その他**: Chatflow 内の Agent v2 ノードのツール活動をリアルタイム表示（`NEXT_PUBLIC_ENABLE_AGENT_V2_IN_CHATFLOW=true`）、GitHub ナレッジソースをツリーから選択、Goto Anything の検索スコープと小画面向けドロワー、ナレッジベース説明の文字数上限引き上げ、外部ナレッジ検索のメタデータ返却、DB・起動オーバーヘッドの削減。同梱 plugin daemon は 0.6.15-local へ。

## 影響範囲

- 対象ユーザー: Dify セルフホスト運用者。Langfuse を使っている環境は**更新しないとトレースが止まる**
- 対象プラン: セルフホスト（環境変数での機能制御が中心）
- API / UI / 管理者機能: PAT の発行・失効、File Security Scan の設定（owner / admin）、新 HITL が既定有効
