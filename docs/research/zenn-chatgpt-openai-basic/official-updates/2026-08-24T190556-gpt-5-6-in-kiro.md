# 2026-08-24 GPT-5.6 ファミリーが Kiro で利用可能に

## 公式内容の日本語要約

OpenAI が 2026-08-24、**GPT-5.6 モデルファミリー（Sol / Terra / Luna）を AWS の開発エージェント Kiro で利用可能にした**と発表した。Kiro は仕様駆動（spec-driven）でソフトウェア開発を進めるエージェントで、IDE / CLI / Web の3形態を持つ。今回の対応で、計画・実装・レビュー・テストという開発ワークフローの中で OpenAI のフラッグシップ系列を選べるようになった。

公式が強調しているのは価格性能比である。**Terminal-Bench 2.1 において、GPT-5.6 Terra は Kiro 上で成功タスクあたり約82%のコスト削減を記録した**と OpenAI は述べている。Kiro の仕様駆動アプローチが、要件・技術設計・タスク文脈をモデルに最初から与えるため、遠回りが減り結果として消費トークンが下がる、という説明である。OpenAI と AWS が共同で Kiro 環境と OpenAI モデルの最適化を行ったとも明記されている。

提供条件は Kiro 側の告知（`kiro.dev/blog/gpt-5-6/`）に詳しい。**Kiro Pro / Pro+ / Pro Max / Power の各プラン向けに experimental support として段階的ロールアウト**で、リージョンは AWS us-east-1（バージニア北部）と eu-central-1（フランクフルト）、クロスリージョン推論に対応する。3階層とも 272K のコンテキストウィンドウを持つ。Kiro のクレジット倍率は Sol が 2.4x、Terra が 1.2x、Luna が 0.6x。

本件は OpenAI モデルが Kiro に載る初めてのケースであり、Kiro にとっては Anthropic モデルと並ぶ選択肢が増えたことになる。

## できるようになったこと

- Kiro の IDE / CLI / Web で GPT-5.6 Sol / Terra / Luna を選択できる
- 3階層とも 272K コンテキスト。Sol は最難度の多段タスク、Terra は日常的なエージェント作業、Luna は高頻度・低コスト用途という位置づけ
- 対象は Kiro Pro / Pro+ / Pro Max / Power。experimental support の段階的ロールアウト
- 提供リージョンは AWS us-east-1 と eu-central-1、クロスリージョン推論あり

## 影響範囲

- 対象ユーザー: Kiro の有償プラン利用者（Pro / Pro+ / Pro Max / Power）
- 対象プラン: 上記4プラン。無償帯への言及なし
- API / UI / 管理者機能: Kiro のモデルセレクタ側の変更。OpenAI API 側の仕様変更ではない

## 教材化メモ

- **「モデルが速くなった」ではなく「同じ結果により少ないトークンで到達する」**という主張の立て方は、価格性能比を説明する教材の実例に使える。Terminal-Bench 2.1 で約82%のコスト削減という数字は、ベンチマークスコアではなく成功タスクあたりのコストで語られている点が肝である。
- **仕様駆動（spec-driven）がコスト削減の理由として挙げられている**点は、ハーネス設計の議論に直結する。要件と設計をあらかじめモデルに渡す構造が、結果としてトークン消費を下げる。プロンプト工夫ではなく作業環境の設計で効かせるという主張であり、本サイトのハーネスエンジニアリング教材と接続できる。
- ただし**本件は Kiro 利用者に閉じた話**で、日本の読者層での Kiro 利用は限定的である。速報記事にはせず、価格性能比・仕様駆動の題材として教材側に温存する判断とした。
