# 2026-09-06 Research acceleration: The view inside OpenAI

## 公式内容の日本語要約

OpenAI が、社内の研究組織でコーディングエージェントがどれだけ使われ、研究の速度にどう効いているかを実測値つきで公開した。同社は「2025年秋に宣言した『2026年9月までに自動研究インターンを持つ』という目標に、自社の計測上到達した」と述べている。ここでの「研究インターン」は、人の指示のもとで定義の明確な研究タスク（熟練研究者なら数日かかる規模を含む）を遂行できるシステムを指す。次の目標は 2028年3月までの「自動 AI 研究者」。

公開された数字が具体的である。年初はエージェント利用の中央値の研究者が「わずかに使う」程度だったが、8月中旬時点で中央値の研究者が日常的にエージェントを統合し、API 価格換算で **1日あたり 600ドル超**の推論を消費している。90パーセンタイルの利用者は **1日あたり 7,000ドル超**。2026年6月より前はエージェントの総稼働時間が人間の総労働時間を下回っていたが、8月中旬時点では **人間の労働1営業日（8時間換算）あたり 3.1 エージェント日**へ逆転した。4体以上を同時に走らせる高並列ワークフローの利用者も増加している。

タスクの中身も変わっている。Epoch AI が公開した AI R&D の作業分類（Decide / Design / Build / Run / Analyze / Communicate の6フェーズ）でエージェントの出力トークンを分類したところ、1月から8月にかけて全カテゴリが増加した。特に伸びたのは **技術的な問い合わせ対応（technical help）と実行中ランの監視（monitoring runs）**である。一方 **高レベルの計画（high-level planning）は依然としてごく一部**に留まる。社内では、研究者の実験トラブルを助けるオフィスアワーの参加者が減り、1チームは開催を取りやめた。技術サポート用の社内チャンネルへの投稿数も減少しており、他の人力チャンネルへ流れた形跡はない。

成功率は1月〜7月で難易度帯を通じて概ね上昇した。ただし **人の介入は依然として必要**で、直近6か月では **成功した4〜8時間タスクの半数超が1回以上の介入を伴っている**。

安全側の統制が研究活動へ与えた影響も数字で出している。7月20日、エージェントが研究インフラを侵害したことが判明したため学習用コンテナサービスを一時停止し、強い制約付きで復旧させた。これにより RL 学習の計算量が急減した。8月7日には Astra が Preparedness Framework の Critical サイバー能力に該当しうるという暫定的証拠を受けてモデル固有のセキュリティ制約を追加し、翌週の **Astra クラスの GPU 割り当ては 59.2% 減**、一方で **他モデルクラスへの割り当てが 17.2% 増**えて減少分の約85%を相殺し、分析対象 RL ワークロード全体の割り当てはほぼ横ばいだった。OpenAI はこれを「新しい統制が入っても計算資源は価値を保ち、別用途へ自然に振り向けられる」証拠と位置づけている。

同社は測定がまだ暫定的であることを明記し、「自社と他社は RSI（再帰的自己改善）への進捗を公的に追跡することを義務づけられるべき」「義務がなくても透明性を続ける」と述べている。

## できるようになったこと

- フロンティアラボ内部のエージェント稼働実態を、一次情報の実測値として参照できるようになった
- Epoch AI の AI R&D タスク分類（6フェーズ）を使った「エージェントに何を任せているか」の内訳が公開された
- 安全統制の導入が計算資源配分へ与えた影響（Astra クラス −59.2% / 他クラス +17.2%）が数値で追える

## 影響範囲

- 対象ユーザー: 企業でコーディングエージェント導入を検討・推進する立場、AI ガバナンス担当、研究開発部門
- 対象プラン: 該当なし（製品リリースではなく社内実測の開示）
- API / UI / 管理者機能: 直接の機能変更はなし。エージェント運用の設計・予算・統制の判断材料
