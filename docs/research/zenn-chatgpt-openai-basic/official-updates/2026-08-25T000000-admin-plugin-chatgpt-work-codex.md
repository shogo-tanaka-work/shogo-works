## 公式内容の日本語要約

ワークスペース管理者向けの **Admin プラグイン**が ChatGPT Work と Codex に追加された。公式ページの要旨は「ワークスペースの利用状況を分析し、メンバーと権限を管理し、上限を調整し、管理リクエストに対応する」。管理者は分析ダッシュボード・設定画面・各種レポートを行き来せず、**1つの会話の中で質問し、詳細を確認し、権限の範囲内で変更を加え、結果を確認する**という流れになる。

報道ベースで確認できる機能は次のとおり。ChatGPT Work と Codex をまたいだ**アクティビティとクレジット消費のレビュー**、メンバーの追加・削除、グループの更新、アクセス権限の管理、メンバー / グループ / ワークスペース単位の**利用上限の調整**、支出リクエストの承認・却下。

自動化の側面もある。保留中の利用リクエストを **Slack や Microsoft Teams へルーティング**して、権限を持つレビュアーがそこで承認・却下できる。あらかじめ定めた条件を満たす機能リクエストは自動で許可し、例外だけを手動レビューに回す、という運用が組める。

権限モデルについては、**プラグインは利用者自身の既存のロールと権限の範囲内で動作し、より広いアクセスを与えるものではない**とされている。管理者の指示を Admin Console 上の read / write アクションへ対応付け、構造化された結果を返す。影響範囲の大きい操作は適用前にレビューできる。

提供形態は ChatGPT ワークスペース設定から、または ChatGPT Work（web / デスクトップ）のプラグインディレクトリからのインストール。

## できるようになったこと

- 利用リクエストの Slack / Microsoft Teams へのルーティングと条件付き自動許可

## 教材化メモ

- **「管理コンソールを会話で操作する」形態そのものが教材の題材**になる。GUI で権限を触るのと、自然言語で指示して権限を変えるのとでは、**誤操作の性質が変わる**。GUI は画面を見ながら間違えるが、会話では「意図と違う対象に当たった」ことに気づきにくい。だからこそ「影響範囲の大きい操作は適用前にレビュー」という設計が入っている。ガバナンス教材で、AI に管理権限を渡すときの設計原則として提示できる。
- **「既存のロールと権限の範囲内で動作する」は、AI エージェントに権限を持たせる際の基本形**として教えられる。エージェントに専用の強い権限を与えるのではなく、**呼び出した人の権限を継承させる**。この設計にしておくと、権限設計を二重に管理せずに済む。Claude Code の managed settings や MCP のスコープ設計と並べて説明すると、共通の原則が見える。
- **承認フローを Slack / Teams へ逃がす設計は、「AI が判断する部分」と「人が判断する部分」の分離の実例**である。条件を満たすものは自動許可、例外だけ人へ。研修で「どこまで自動化するか」を扱うとき、全自動か手動かの二択ではなく**例外だけを人に回す**という第三の形を示す材料になる。
- **本件は「公式本文が読めない」まま扱った事例**でもある。二次報道は詳細だが、公式が何と書いたかの確認にはならない。**情報源の制約を明示したうえで扱う**という運用そのものが、AI 時代の情報検証の教材になる。
