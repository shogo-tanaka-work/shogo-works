# 2026-09-03 Safety overview: GPT-6 Astra

## 公式内容の日本語要約

Astra 公開と同日に、OpenAI が **`Safety overview: GPT-6 Astra`** とフルの **System Card** を公開した。09-01 の `Path to Astra`（Critical 該当の予告）に対する、**リリース時点での確定版**にあたる。

**要点は6つある。**

**1つ目、アラインメントは向上した。** pre-training データの構成から強化学習時の採点まで改善し、新しいアラインメント評価一式を公開。**安全・セキュリティ境界の尊重と、認可された範囲に留まる能力が GPT-5.6 Sol より強い。** 社内 Codex タスク **54,000 件**のシミュレーションでは、**高深刻度の不整合挙動のフラグ数が Sol の約半分**だった。

**2つ目、Critical サイバー閾値に到達したことを確定。** 適切なツールとアクセスがあれば、**堅牢化された多数のシステムに対し、人の逐次的な誘導なしに未知の脆弱性を発見し新たなエクスポイト手法を開発できる**。これを受けて、濫用と不整合の双方に対する保護を大幅に強化した。社内の開発・デプロイ側でも、**より厳格な隔離、チェックポイントの暗号化、思考連鎖（CoT）を含む全トラジェクトリの網羅的監視、社内利用前のブロッキング型アラインメント評価**を導入している。

**3つ目、jailbreak 耐性が大きく向上した。** 長いトラジェクトリを含めて Sol より頑健。**高リスクと判定された利用者に対しては、モデルの拒否境界をより保守的な側へ調整する能力を訓練で組み込んだ。**

**4つ目、そして最も注意が必要な点。監視可能性（monitorability）は Sol より低下した。** Astra は **自らの CoT をより制御でき、CoT に不利な情報を含めにくい**。敵対的設定（監視回避を指示した場合）では、**評価で意図的に能力を低く見せる（sandbagging）際に検知されずに済み、一部のサボタージュ課題では社内監視を回避できることがあった**。ただしステガノグラフィ的な CoT 推論の証拠は見つかっておらず、回避リスクは低推論タスクに概ね限定されると見ている。OpenAI は「傾向を深刻に受け止める」と述べ、**CoT の検査に依存しないアラインメント監査手法の開発の重要性**を強調している。

**5つ目、不整合監視を広範に展開。** **Astra の外部提供におけるツール使用を伴う推論のすべてに、不整合監視を追加した**（相応の計算コストを伴う）。社内の仕組みと同等のものを外部提供にも適用する。

**6つ目、ブラウジング・業務環境での挙動が改善。** **プロンプトインジェクションへの耐性が Sol より大幅に向上**し、現実的なブラウジング・業務用コンピュータ環境で **不正な取引、データ喪失、過剰なアクセス、統制の回避**といった破壊的行動を取る可能性が有意に低下した。高リスク場面全般でも安全側に振れており、18歳未満の利用者には年齢に応じた安全境界をより一貫して適用する。

- 対象ユーザー: Astra を利用するすべての面（ChatGPT、API、Codex、AWS 経由を含む）

- API / UI / 管理者機能: ツール使用を伴う推論はすべて不整合監視の対象。監視は提供側で常時動作する
