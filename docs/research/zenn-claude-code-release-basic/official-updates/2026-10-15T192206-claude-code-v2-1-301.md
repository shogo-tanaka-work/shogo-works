# 2026-10-15 Claude Code v2.1.301

## 公式内容の日本語要約

**usage limit 待ちの挙動に上限が入った。** retry mode で usage limit の解除を待つ際の**上限（retry-mode limit）**が設けられた。待ち続けて止まったままになる状況に区切りを付ける変更である。

**auto mode の分類判断が計測対象になった。** OpenTelemetry へ **auto mode の classifier decision を表すフィールド**が追加された。auto mode は入力に応じて処理方針を切り替えるため、**どう判断されたかが外から見えないと挙動を説明できない。** 前日の v2.1.300 で GenAI semantic conventions の属性とキャッシュ内訳が入ったのに続き、**OpenTelemetry へ出す情報が2日連続で増えている。**

**`claude-api` skill に OpenTelemetry トレーシングの案内が加わった。** スキル側のドキュメントが、Claude Platform 側のベータ提供（10-14）に追随した形である。

**エディタ操作の追加が2点。** Vim モードの **`%` モーション**（対応する括弧へ移動）と、mod のテキスト入力で**複数行の `rows`** を指定できるようになった。

**修正は実運用で踏みやすいものが並ぶ。** worktree のクリーンアップ確認、**モデルエイリアスのフォールバック**、ログインエラーメッセージ、検索エラーの報告、**Read ツールのバイナリファイル処理**、ターミナル描画の不具合。VS Code 拡張側では **LaTeX 数式のレンダリング**と usage limit のリンクが修正された。

## できるようになったこと

- retry mode が usage limit を待ち続ける際に上限で打ち切られる
- auto mode の分類判断を OpenTelemetry のフィールドとして収集できる
- Vim モードで `%` による対応括弧への移動が使える
- mod のテキスト入力を複数行にできる

## 影響範囲

- 対象ユーザー: Claude Code 利用者全般。auto mode を使う組織、mod 開発者、VS Code 拡張利用者に個別の追加あり
- 対象プラン: 記載なし
- API / UI / 管理者機能: CLI、OpenTelemetry 出力、mod API、VS Code 拡張

## 教材化メモ

- **単独記事にしない（判定D）。** バージョン番号付きリリースのため規約どおり週次ロールアップへ回す。
- **「auto mode の判断を計測できるようにする」という方向は、週次ロールアップの軸になる。** v2.1.300（GenAI 属性・キャッシュ内訳）と v2.1.301（classifier decision）、さらに Claude Platform の OpenTelemetry ベータ（10-14）が**3日で同じ方向へ揃っている。** 個別のリリースノートを1日ずつ見ていると、この流れは見えない。
- **retry mode の上限は、エージェント運用の教材で扱いやすい。** 「待てば回復する」前提の処理は、**待ち続けること自体が障害になる。** 上限を設ける設計判断は、自作の自動化にも一般化できる。
- **モデルエイリアスのフォールバック修正は、注意点として残す価値がある。** エイリアス指定は便利だが、**実際に何が動いたかは別途確認する必要がある**という話につながる。
