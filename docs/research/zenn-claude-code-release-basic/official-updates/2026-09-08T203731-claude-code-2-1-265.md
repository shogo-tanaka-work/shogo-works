# 2026-09-08 Claude Code v2.1.265

## 公式内容の日本語要約

CHANGELOG の v2.1.265 は、テレメトリ、プラグイン、ツール結果の扱いに関する変更を含む。

**テレメトリに `user.email` と `user.groups` のフィールドが追加**された。対象は Claude Desktop と Cowork の gateway セッションである。**`--plugin-dir` が子フォルダをプラグインとして読み込めるようになり**、追加・削除がライブで検出される。**ディスクへ保存するツール結果に 1 GB の上限**が設けられ、切り詰めが起きた場合はその旨が表示される。

修正としては、再開したサブエージェントとエージェント teammate でのプロンプトキャッシュ再利用の不具合、ツール実行中にプロセスがクラッシュした後のセッション再開、`/model opusplan[1m]` のモデル検証が挙がっている。ほかに UI 描画、ファイル権限、キーボードショートカットの修正が複数入っている。

## できるようになったこと

- `--plugin-dir` が**子フォルダをプラグインとして読み込む**（追加・削除をライブ検出）
- ツール結果のディスク保存に **1 GB 上限**と切り詰め表示
- Claude Desktop / Cowork gateway セッションのテレメトリに **`user.email` / `user.groups`**
- 再開サブエージェント・agent teammate の**プロンプトキャッシュ再利用の修正**

## 影響範囲

- 対象ユーザー: Claude Code 利用者、プラグインを配布する組織
- 対象プラン: 記載なし
- API / UI / 管理者機能: CLI + テレメトリ

## 教材化メモ

**単独記事にしない（バージョンリリースのため週次ロールアップへ）判断だが、2点は週次でまとめる際に落とさない。**

1つ目は**テレメトリへの `user.email` / `user.groups` 追加**である。組織で Claude Code を配布する場合、誰がどのグループでどれだけ使ったかを可視化できる一方、**個人識別情報が観測基盤へ流れる構成変更でもある**。導入企業側でプライバシー設計の確認が要る変更なので、週次では「便利になった」ではなく「確認事項が増えた」として書く。

2つ目は **`--plugin-dir` の子フォルダ読み込み**。プラグインを1ディレクトリにまとめて配る運用が成立するようになり、社内配布のパッケージングが単純化する。ハーネスエンジニアリング系の教材で、チーム全体へルールを配る手段として扱える。
