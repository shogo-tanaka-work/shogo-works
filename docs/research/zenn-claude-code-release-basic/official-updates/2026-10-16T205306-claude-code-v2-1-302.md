# 2026-10-16 Claude Code v2.1.302

## 公式内容の日本語要約

**追加された設定が2つある。** `CLAUDE_CODE_AUTO_MODE_MODEL` で、クライアント側 auto mode の分類器（classifier）が使うモデルを指定できる。もう1つは `/config` の **idle compaction 設定**で、前版（2.1.299）でターミナルに入った idle compaction の切り替えが設定画面に出た。

**既定の挙動が3か所変わった。** (1) permission mode を持たないサードパーティセッションは `default` モードで開始する。(2) ターミナル外では **fork subagent が既定で有効**になり、デスクトップアプリと VS Code の subagent は**バックグラウンドで動く**。(3) prompt hook と agent hook の**同時実行が12本に制限**された。

**`/design-sync` と `/design-login` が、standalone Claude Design の 2026-12-14 閉鎖を警告するようになった。** 閉鎖そのものは 2026-10-08 に告知済みで、本リポジトリでは `docs-slides-design-ga` として記事化済みである（新規の告知ではなく、CLI 側への反映）。

**修正は compaction と資格情報まわりが中心である。** compaction 中の "Prompt is too long"、セッション途中での Vertex / Bedrock 切り替え、後から読み込まれたツールによる prompt cache のミス、終了時に設定の書き込みが失われる問題。Read ツールは **128 MB を超える画像ソースを拒否**し、巨大画像をメモリへ丸ごと載せなくなった。

プラグイン側では、reftable ref 形式での marketplace の再 clone、PowerShell でのプラグイン `bin/` の扱い、`claude remote-control --help` の出力不正が直った。Cloud Sessions / Remote Control / Claude Tag の修正も多数含まれる（rewind、routine の実行状況報告、リポジトリ改名後の diff 表示、Slack の画像・返信整形）。Code Review のセットアップは、GitHub 接続後にリポジトリ選択から再開するようになった。

## できるようになったこと

- `CLAUDE_CODE_AUTO_MODE_MODEL` で auto mode の分類器モデルを選べる
- `/config` から idle compaction を設定できる
- 128 MB 超の画像を Read が拒否し、メモリを食い潰さなくなった
- prompt / agent hook の同時実行が12本で頭打ちになる（暴走時の保護）

## 影響範囲

- 対象ユーザー: Claude Code 利用者全般。ターミナル外（デスクトップアプリ / VS Code）の subagent 挙動が変わる
- 対象プラン: 記載なし
- API / UI / 管理者機能: CLI。Vertex / Bedrock 切り替え、Cloud Sessions / Remote Control / Claude Tag を含む

## 教材化メモ

- **「同時実行に上限を付ける」というhooks の変更は、エージェント設計の定番の落とし穴を説明する素材になる。** フックは1イベント1回に見えて、並列セッションでは簡単に数十本走る。**上限を決めずに外部コマンドを呼ぶ設計は、ある日マシンを止める。**
- **auto mode の分類器モデルを差し替えられる**点は、「エージェントの中に小さな判断モデルが埋まっている」構造を説明する具体例として使える。主モデルと分類器を別に選べることは、**コストと精度のつまみが1つではない**ことを示す。
- **ターミナル外で subagent がバックグラウンドになる**変更は、UI の制約が実行モデルを決める例。教材では「同じツールでも実行環境で既定が変わる」ことの注意喚起に使える。
- 本件は**バージョン番号付きリリースのため単独記事にしない**（判定D）。週次ロールアップ側で `2.1.299` 〜 `2.1.302` をまとめて扱う。
