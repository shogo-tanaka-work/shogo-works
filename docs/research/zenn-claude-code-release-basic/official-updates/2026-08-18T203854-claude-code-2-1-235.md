# 2026-08-18 Claude Code 2.1.235

## 公式内容の日本語要約

Claude Code の 2.1.235 がリリースされました。新機能は 1 件で、残りは修正と改善です。

追加されたのは任意の `spellcheck` 設定で、インストール済みの `aspell` / `hunspell` / `ispell` を使い、プロンプト入力中のスペルミスに下線を引きます。

実務上意味があるのは権限ダイアログ周りの改善です。表示テキストと「今後確認しない」の選択肢が、実際に許可される範囲と常に一致するようになりました。加えて、内容を完全に表示できない場合は「今後確認しない」自体を出さないようになっています。何を許可したのか分からないまま恒久的な許可を与えてしまう事故を減らす変更です。関連して、権限プロンプトのコメント欄で Shift+Tab を押すと編集が承認されセッション全体の編集許可まで付与されてしまう不具合も修正されました。

このほか、言語サーバーの切断・再接続でプロンプトキャッシュ全体が無効化される問題、ネスト 3 階層以上の Markdown リストの表示ずれ、複数行プロンプトでのハイライト位置ずれ、ノートブックのセル削除・置換の承認ダイアログが既存セル内容を黙って省略していた問題などが直っています。`/ultrareview` や `/autofix-pr` のようなクラウドセッションを背後で走らせている間のメモリと CPU 使用量も改善しました。

## できるようになったこと

- `spellcheck` 設定で、プロンプト入力中のスペルミスに下線表示（aspell / hunspell / ispell 利用）
- 権限ダイアログの表示と実際の許可範囲が常に一致。完全表示できない場合は「今後確認しない」を出さない
- Vim モードで transcript 切替やパネル閉鎖をしても NORMAL モードとカーソル位置を保持
- 埋め込み grep の改善（病的なパターンで即失敗、`-m N` と `-A/-C` の併用で正しい文脈出力）

## 影響範囲

- 対象ユーザー: Claude Code 利用者全般
- 対象プラン: 全プラン
- API / UI / 管理者機能: CLI / IDE 拡張の UI 改善と不具合修正

## 教材化メモ

- 権限ダイアログの「表示内容と許可範囲を一致させる」修正は、AI エージェントのガードレール設計の教材で使える。承認 UI が実際の権限より狭く見えることが、ユーザーが意図より広い許可を与えてしまう典型的な原因になる。
- 単体では記事化基準に届かない回だが、2.1.232〜2.1.235 を通してみると権限・サンドボックス・秘密情報のマスキング関連の修正が連続している。「エージェントの権限境界」をテーマにするなら、この期間のリリースをまとめて素材にできる。
