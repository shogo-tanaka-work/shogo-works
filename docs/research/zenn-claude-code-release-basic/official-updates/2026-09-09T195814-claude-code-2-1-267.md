# 2026-09-09 Claude Code v2.1.267

## 公式内容の日本語要約

v2.1.267 は、**設定による効率レベルの上限設定**と、**プロンプトキャッシュの安定化を狙った多数の修正**が中心のリリース。単発の目玉機能より、修正項目の総量が多い。

新規追加は2件。`maxEffortLevel` 設定（トップレベル、または `modelSettings` 配下のモデル別）で、**Bedrock / Vertex / Foundry を含むすべてのプロバイダーで効率レベルの上限を強制**できる。利用者はそれより低いレベルを選ぶことは可能。もう1件は `--system-prompt-snapshot off` で、会話に記録済みのシステムプロンプトを再利用せず、**毎リクエストで再生成**する（プロンプト文言の反復調整用）。

セキュリティ・統制系の修正が複数入っている。**マーケットプレイスのエントリパスにバックスラッシュを含めると macOS / Linux で封じ込めチェックを回避できた問題**を修正（2.1.265 のプラグインパス同種修正に続くもの）。管理設定の `allowedHttpHookUrls` / `httpHookAllowedEnvVars` / `allowedChannelPlugins` が**読み取れないときに「全許可」ではなく「全拒否」になる**よう修正。組織の管理設定がサンドボックスを要求する場合に Cowork のスケジュール実行がクラウドで起動失敗する問題も修正された。

プロンプトキャッシュ関連の修正が突出して多い。MCP サーバーの再送、セッション中のツール追加・消失、`/model` でのモデル切替、`-p` セッションの対話再開、コネクタのツール変更など、**「会話の前置き（prefix）が途中で書き換わってキャッシュを外す」経路**を系統的に潰している。あわせて拡張思考（extended thinking）が落ちる問題も同じ経路で修正された。

そのほか VS Code 拡張、Claude Code on the web、Claude Tag（Slack）向けの修正が並ぶ。

## できるようになったこと

- `maxEffortLevel` で全プロバイダー横断の効率レベル上限を設定できる
- `--system-prompt-snapshot off` でシステムプロンプトを毎回再生成できる
- 管理設定の許可リストが読めない場合に安全側（全拒否）へ倒れる
- 5MB 超の大規模セッション再開で並列ツール呼び出しとフック出力が失われなくなった
- `claude remote-control` がサーバー資格情報の期限切れ（起動から約30日）で全セッションを落とさなくなった

## 影響範囲

- 対象ユーザー: Claude Code 利用者全般、特に組織の管理設定を運用する管理者
- 対象プラン: 記載なし（CLI 全般）
- API / UI / 管理者機能: CLI 設定、管理設定、VS Code 拡張、Claude Code on the web、Claude Tag

## 教材化メモ

- **`maxEffortLevel` は、AI 利用コストの統制手段として教材化できる。** 効率レベルの上限を管理者側で固定でき、Bedrock / Vertex / Foundry を含む全プロバイダーに効くという点が重要。「利用者の自由度は残しつつ上限だけ縛る」という設計は、AI ツールのコストガバナンス一般の型として使える。
- **許可リストが読めないときの倒れ方**（全許可ではなく全拒否）は、セキュリティ設計の基本原則（fail-safe / fail-closed）の実例として短い教材素材になる。「設定ファイルが壊れたときにどちらへ倒れるか」を確認する観点は、AI ツールに限らず適用できる。
- **プロンプトキャッシュ修正の量そのものが論点。** 1リリースに10件以上のキャッシュ関連修正が入るということは、実運用でキャッシュミスが頻発していたということでもある。コンテキストエンジニアリングの教材で「キャッシュは前置きが一定であることに依存する」という原則を説明する際の裏付けに使える。
- 本リリースは**バージョン番号付きのため単独記事化しない**（`selection-rubric.md` の「日次リリース型ツールの扱い」）。週次ロールアップで 2.1.265〜2.1.267 をまとめて扱う。
