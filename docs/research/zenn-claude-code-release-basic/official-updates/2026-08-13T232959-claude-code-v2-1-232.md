# 2026-08-13 Claude Code v2.1.232

## 公式内容の日本語要約

機能追加、GitLab 対応、複数の権限バイパス修正を含む大きめのリリース。

**サブエージェントの fork が既定になった。**`subagent_type: "fork"` のサブエージェントは会話全体とプロンプトキャッシュを継承する。加えて、対話セッションでの teammate 以外のエージェント起動は、既定でバックグラウンド実行になった。エージェントの起動コストと待ち方が変わる挙動変更である。

**セッション間のやり取りが直接できるようになった。**プロンプトで `@` を打つと他の Claude セッションを名前で指名でき、Claude は `SendMessage` でそのセッションへ直接届ける。`SendMessage` は、生存中のセッション1つに一意一致する裸の名前へそのまま配送するようになった（従来は ref での確認を求めていた）。同一マシン上の対話セッションは名前が一意に保たれ、既存の生存セッションと同名で起動・改名すると `name-word-word` 形式の変種が割り当てられて通知される。`/config` に「Dialog expiry」と「Messages from your other sessions」（セッション間の受信を accept / hold / refuse）の行が追加された。

**GitLab 対応が入った。**シークレットの秘匿対象に GitLab のトークン群（`glrt-`、`gloas-`、`glptt-`、`glagent-`、`glimt-`、`glsoat-`、`glcbt-`、`glft-`、`glffct-`）が加わり、ルーティング可能な `glpat-` / `gldt-` は全体秘匿になった。`glab` CLI の設定ストアも `gh` と同じサンドボックスと認証情報パスの保護を受ける。プラグインマーケットプレイスは裸の `gitlab.com` リポジトリ URL（ネストしたサブグループ含む）を `github.com` と同様に clone できるようになった。

**セキュリティ修正が複数入っている。**PowerShell で変数を書き込むパラメータが `$PSDefaultParameterValues` を黙って上書きし、以降のコマンドのファイルアクセスを迂回させられた権限バイパスを修正。Windows で Git Bash が Cygwin 形式のシンボリックリンクを辿り、パス検証からは通常ファイルに見えていた権限バイパスも修正され、これを経由する書き込みは許可確認を要するようになった。ネストした git リポジトリが親ディレクトリの trust を継承していた問題も修正され、各リポジトリが個別の trust 確認を要するようになった。Gateway 側では、`managed.policies[].match.groups` / `admin.admin_groups` の空エントリと、不正な `email_domain` 値（空、`@` / 空白 / カンマを含むもの）が、**誰にもマッチしないか管理者権限を与えてしまう**状態を許していたが、起動時に失敗するようになった。

その他、Remote Control 関連の修正が厚い（クラウドセッション内のブリッジが transcript や認証情報を継承する問題、Desktop / IDE から開始したセッションが再開のたびに新規 claude.ai セッションとして現れる問題、削除済みセッションの再開失敗、v2.1.227 の退行）。mTLS クライアント証明書のローテーションが再起動不要になり、Bedrock / Vertex / gateway でのストリームアイドルタイムアウトが失敗ではなく回復するようになった。Fable 5 が `/advisor` のアドバイザーとして再提供された（Fable アクセスのある組織向け、`/model fable` で利用クレジットの同意を設定）。

なお v2.1.231（2026-08-13T08:38:50Z）は、Slack のように事前登録済み OAuth クライアントを使うサーバーで MCP OAuth のサインインが redirect URI 不一致で失敗する問題の修正1件のみ。v2.1.230 は欠番。

## できるようになったこと

- `@` で他の Claude セッションを名前指名し、`SendMessage` で直接やり取りできる
- サブエージェントの fork が既定で有効になり、会話全体とプロンプトキャッシュを継承する
- GitLab のプラグインマーケットプレイスを `github.com` と同様に使える
- GitLab トークンがシークレット秘匿の対象になった
- `/config` からセッション間受信の可否（accept / hold / refuse）を設定できる

## 影響範囲

- 対象ユーザー: Claude Code 利用者全般。GitLab 利用組織、Remote Control 利用者、Gateway 運用者への影響が大きい
- 対象プラン: 記載なし（バージョン更新）。`/advisor` の Fable 5 は Fable アクセスのある組織向け
- API / UI / 管理者機能: CLI、`/config`、Gateway の managed policy（起動時検証が厳格化）、Enterprise policy の `blockedMarketplaces`
