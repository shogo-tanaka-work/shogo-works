# 2026-10-14 Claude Code v2.1.300

## 公式内容の日本語要約

**OpenTelemetry 周りが2点強化された。** `api_request` イベントに **`cache_creation_5m_tokens` と `cache_creation_1h_tokens`** が入り、**キャッシュ書き込みを 5分 / 1時間の内訳で見られる。** さらにトレース span へ **GenAI semantic conventions の属性**（`gen_ai.provider.name`、`gen_ai.conversation.id`、`gen_ai.tool.name`、`error.type` など）が付くようになった。**同日に Claude Platform 側が OpenTelemetry エクスポートをベータ提供しており、属性の揃え方が両製品で同じ方向へ動いている。**

**`/advisor` が Claude Platform on AWS で使えるようになった。** 無効化は `CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1`。

**mod 向けの追加が多い。** プロンプト装飾の `virtualText`、`$.ui.view({ agentId })`（`$.ui.view({})` で戻る）、`Text` の `dir` prop（右から左へ書く言語向け）、`agent.spawn` mod フックでワークフローエージェントの `prompt` と `model` を書き換えられる機能、**`prompt.change` mod フック**。VS Code には `claudeCode.attachSelection` 設定が入った。

**Claude Tag（Claude in Slack）側**は、Slack Connect チャンネル対応（既定オフ）、コネクタ操作に対する**非公開の「Allow once / Deny」カード**、ボイスクリップ対応。

**修正は実運用で踏みやすいものが並ぶ。** `SessionEnd` フックがバックグラウンドコマンド実行中の終了時に走らないことがある問題、自動ツール検索（`ENABLE_TOOL_SEARCH=auto`）が会話の途中でオフになる問題、`forceLoginOrgUUID` で拒否されたログインが**拒否された組織のトークンを保存したままにする**問題、`/branch` が U+2028 / U+2029 を含むメッセージを落とす問題、API が MCP ツールの入力スキーマを拒否したときに会話が毎ターン 400 で失敗する問題、`claude remote-control` が一時的なサインインエラーで接続更新を諦める問題、`claude daemon stop --any` が停止していないサービスに対して "stopped" と表示する問題。

**Cowork のクラウドセッションで、Write / Edit / NotebookEdit がユーザー自身のマシン上のファイルに対して成功を報告していた問題**も修正された。**書けていないのに成功と返る挙動**であり、影響が見えにくい種類の不具合である。

## できるようになったこと

- OpenTelemetry でキャッシュ書き込みを 5分 / 1時間の内訳で計測できる
- トレース span が GenAI semantic conventions の属性を持つ（他プロバイダーのデータと並べやすくなる）
- Claude Platform on AWS で `/advisor` が使える
- mod が agent のトランスクリプトを表示でき、`prompt.change` フックを使える
- Claude Tag が Slack Connect チャンネルとボイスクリップに対応する

## 影響範囲

- 対象ユーザー: Claude Code 利用者全般。Claude Platform on AWS 利用者、mod 開発者、Claude in Slack 利用者に個別の追加あり
- 対象プラン: 記載なし
- API / UI / 管理者機能: CLI、OpenTelemetry 出力、mod API、VS Code 拡張、Slack 連携

## 教材化メモ

- **単独記事にしない（判定D）。** バージョン番号付きリリースのため規約どおり週次ロールアップへ回す。
- **OpenTelemetry の GenAI 属性対応は、同日の Claude Platform 側のベータ提供と並べて1つの話にできる。** 「CLI もプラットフォームも、同じ semantic conventions で span を出す方向へ揃えてきた」という読み方は、**個別のリリースノートを追っているだけでは出てこない。** 週次ロールアップの要点に向く。
- **キャッシュ書き込みの 5分 / 1時間内訳は、コスト分析の教材にそのまま使える。** 合計だけ見ていると分からない「どちらの TTL に書いたか」が取れる。
- **「成功と返るが書けていない」種類の不具合は、検証設計の教材として強い。** Cowork のクラウドセッションでの Write / Edit の修正がその例である。**戻り値を信じる設計の危うさ**という一般論へ展開できる。
