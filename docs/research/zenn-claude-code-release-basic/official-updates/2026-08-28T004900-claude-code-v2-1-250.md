## 教材化メモ

- **リリースノートが「バグ修正」1行だけの版が定期的に混ざる**という事実自体が、バージョン追跡の運用設計に効く。差分が読めない版は、**内容で判断しようとしても判断材料が無い**。これは「タイトルにバージョン番号が付くかどうかで機械的に記事化を判定する」という本プロジェクトの方針が正しく働く典型例で、中身で判定する方式ならこの版は毎回判断保留になる。
- 追跡精度を落とさないために、**内容が読めない版でも詳細メモは残す**。後から「この日に版が出ていたか」を履歴で引けることが目的で、要約の厚みは目的ではない。
