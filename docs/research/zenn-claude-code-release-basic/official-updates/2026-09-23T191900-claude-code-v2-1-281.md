# 2026-09-23 Claude Code v2.1.281

## 公式内容の日本語要約

Claude Code `v2.1.281` が公開された。前版 `v2.1.280`（2026-09-22）に続く日次パッチで、追加は9件、残りは修正が中心の大型リリースである。

**企業ゲートウェイ（Claude apps gateway）まわりの追加が目立つ。** Bedrock upstream に `assume_role` が入り、ゲートウェイが STS 経由で引き受けた IAM ロールとして Bedrock を呼べるようになった。別 AWS アカウントを指定でき、開発者ごとに1セッションを割り当てる運用も選べる。同じく Bedrock upstream の `guardrail: {id, version}` で、そのupstream を通る全リクエストに Amazon Bedrock のガードレールを適用できる（全 Bedrock upstream に設定するか、まったく設定しないかの二択）。`desktop` ポリシーブロックでは `blockReadsOutsideWorkingDirectories` と `disableBypassPermissionsMode` という新しい Claude Desktop キーがサポートされた。`telemetry.resource_attributes` で Claude Desktop と `/login` セッションのテレメトリに固定ラベルを付けられる。

**運用面では `settings.json` の `"attribution": false`** が加わり、コミットと PR の attribution をすべて隠せるようになった。古い CLI はこれを持つ設定ファイルを読み飛ばすため、バージョン混在の共有ファイルではオブジェクト形式を維持する必要がある。MCP 側では 2026-07-28 プロトコル接続で URL モードの elicitation に対応し、サーバーがブラウザベースのフローを開かせられるようになった。`claude plugin validate` は `.mcp.json` の取りこぼしエントリ、未宣言の `${user_config.*}` 参照、安全でない URL を報告する。

**権限・サンドボックス関連の修正も複数含む。** コマンド置換のみを対象にした再帰 `rm`（`rm -rf "$(pwd)"` など）が auto / `--dangerously-skip-permissions` で無確認実行されていた問題、NUL バイトを含む権限ルールがワイルドカードに展開されていた問題、macOS の `/.vol` / `/.nofollow` / `/.resolve` 配下のパスを承認前に読んでいた問題、`claude --bg` が信頼プロンプト未通過のディレクトリでプロジェクトフックを実行していた問題などが修正されている。

**バージョン番号が付いたリリースのため、`selection-rubric.md` の「日次リリース型ツールの扱い」に従い単独記事化はしない。** 権限・サンドボックス修正を含むが、機械的な線（タイトルにバージョン番号が付くか）で判定 D とし、週次ロールアップへ送る。

## できるようになったこと

- Bedrock upstream で `assume_role`（STS 経由の IAM ロール引き受け、別アカウント可）と `guardrail` を設定できる
- `desktop` ポリシーで `blockReadsOutsideWorkingDirectories` / `disableBypassPermissionsMode` を指定できる
- `settings.json` の `"attribution": false` でコミット・PR の attribution を全面的に隠せる
- MCP の URL モード elicitation に対応（2026-07-28 プロトコル接続）
- `claude plugin validate` が MCP サーバー設定の問題を検出する
- `/insights` が auto モードで削減できたはずの権限プロンプト数を推定して提案する

## 影響範囲

- 対象ユーザー: Claude Code 利用者全般。ゲートウェイ関連は企業導入の管理者
- 対象プラン: 全プラン
- API / UI / 管理者機能: `settings.json` / ゲートウェイ設定 / `desktop` ポリシーの各スキーマに追加。`--setting-sources` が派生セッション（teammates、`/bg`、`claude agents`、`--worktree --tmux`）へ転送されるようになった

## 教材化メモ

- **`"attribution": false` は、バージョン混在環境での設定ファイル互換性の実例として使える。** 古い CLI が「そのキーを持つ設定ファイルごと読み飛ばす」という挙動は、フラグを1つ足すだけで他の設定まで失われうるという話につながる。チーム共有の設定ファイルを扱う章で扱いたい。
- **Bedrock upstream の `assume_role` / `guardrail` は、「AI ゲートウェイを1か所に置く」構成の具体例。** 開発者ごとに認証情報を配らず、ゲートウェイがロールを引き受けて呼ぶ形。ガードレールを upstream 単位で強制する設計とあわせて、企業導入の標準構成として説明できる。
- **`rm -rf "$(pwd)"` が無確認で通っていた修正**は、「許可ルールは文字列として評価される」という原則を示す好例。コマンド置換の中身は実行時にしか決まらないため、静的な allow ルールでは守れない。権限設計の教材で使う。
