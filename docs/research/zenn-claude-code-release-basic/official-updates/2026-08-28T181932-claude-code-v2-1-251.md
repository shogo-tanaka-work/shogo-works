# 2026-08-28 Claude Code 2.1.251

## 公式内容の日本語要約

窓内では最大のリリースで、CHANGELOG の項目数は約80。柱は4つある。

**1. フックとステータス表示の追加。** `PreModelSwitch` / `PostModelSwitch` フックイベントが追加され、モデル切替をブロック・確認・注釈できるようになった。`SessionStart` の resume フックはセッションの陳腐化情報と再キャッシュの推定コストを受け取る。`/usage` に Spend limit バー、`/cost` にセッション単位のプロンプトキャッシュ行（ヒット率・ミス・再キャッシュしたトークン・warm/cold）が加わり、ステータスライン用に `rate_limits.spend_limit` と `prompt_cache` が公開された。

**2. サンドボックス・権限まわりの修正が複数。** 権限チェック後に作業ディレクトリ内でシンボリックリンクが差し替えられると、ファイルツール（Read / Write / Edit）が承認範囲外を読み書きしうる問題を修正。Grep / Glob がシンボリックリンク経由の探索パスに `Read(...)` の deny ルールを適用していなかった問題、マーケットプレイス記載のプラグインコマンドがプラグインディレクトリ外を指せた問題（パストラバーサルとして拒否）、プロジェクト設定から詳細ベータトレースや生 API ボディのログを有効化できた問題も修正された。Bash の権限チェックが算術代入（`OPTIND=1/0` 等）を自動承認していた件も塞がれている。

**3. 設定の昇格に承認を要求する変更。** サンドボックスの TLS 終端、サンドボックス通信の自前プロキシ経由、資格情報の注入、サンドボックス分離の弱体化を行うサーバー管理設定は、適用前に承認が必要になった。`ANTHROPIC_CUSTOM_HEADERS` も、資格情報・組織/テナント・ルーティング・API 挙動に関わるヘッダーを設定する場合は承認必須。プロジェクトの `.claude/settings.json` の `env` から `CLAUDE_CONFIG_DIR` / `CLAUDE_CODE_TMPDIR` / `TMPDIR` 系を設定できなくなった。

**4. 既定値の変更。** シート課金の Enterprise 契約の既定モデルが **Opus 5** になった（他の上位プランと同じ）。`/effort` はモデルごとに既定の effort を保存するようになり、`CLAUDE_CODE_SUBAGENT_MODEL` は「全部を上書き」から「サブエージェントの既定を決める」へ意味が変わった（エージェント定義の `model:` と明示指定が優先）。

## できるようになったこと

- `PreModelSwitch` / `PostModelSwitch` フックでモデル切替を制御できる
- `/cost` と `/usage` でプロンプトキャッシュ効率と支出上限を確認でき、ステータスラインからも参照できる
- フォアグラウンドのサブエージェントのツール呼び出しと結果を Remote Control クライアントへライブ配信できる
- `claude --help` から `attach` / `logs` / `stop` / `respawn` / `rm` を辿れる

## 影響範囲

- 対象ユーザー: Claude Code 利用者全般。設定を配布している管理者は承認要求の追加を要確認
- 対象プラン: シート課金 Enterprise は既定モデルが Opus 5 へ変更
- API / UI / 管理者機能: 管理者向けにサーバー管理設定の承認要求が追加

## 教材化メモ

- 記事化しないため、この節を残す。**権限チェックとファイル操作の間にある TOCTOU（time-of-check to time-of-use）**の実例として質が高い。「チェックしたパス」と「実際に開くパス」がシンボリックリンクの差し替えでずれる、という古典的な脆弱性パターンが、エージェント実行環境でそのまま再現している。AI エージェントに権限を与える設計を教えるときの具体例に使える。
- **「設定を書ける＝分離を弱められる」という構造**も論点になる。サンドボックスの TLS 終端やプロキシ経由化を設定で有効にできる状態は、設定ファイルを書ける立場が実質的に最高権限を持つことを意味する。承認を挟む変更は、その権限の格上げを可視化する対処にあたる。
- `selection-rubric.md`「日次リリース型ツールの扱い」により、バージョン番号が付いたリリースは内容にかかわらず単独記事にしない。権限モードやセキュリティ修正を含んでいても同じ扱いで、週次ロールアップへ送る。
