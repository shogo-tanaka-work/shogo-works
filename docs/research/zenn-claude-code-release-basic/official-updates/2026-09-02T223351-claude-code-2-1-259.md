# 2026-09-02 Claude Code 2.1.259

## 公式内容の日本語要約

Claude Code 2.1.259 が公開された。組織配布と無人実行に関わる追加が中心で、権限境界の修正も複数含む。**バージョン番号付きリリースのため、`selection-rubric.md` の「日次リリース型ツールの扱い」に従い単独記事にはしない（判定D、週次ロールアップへ）。**

**組織配布**: `managedMcpServers` で **HTTP/SSE の MCP サーバー**を全ユーザーへ配布できるようになった。あわせて `allowedMcpServers` の意味が変わり、**ユーザーが自分で追加したサーバーだけを対象とする**ようになった。フィルタリングには `deniedMcpServers` を使う。**既存の設定で意図した制限が外れうる変更**である。

**無人実行**: `--permission-prompts none` が追加され、権限プロンプトを自動的に拒否する。無人のヘッドレスホスト向け。

**権限境界の修正**（3リリース連続の流れの続き）: Bash の `Read()` 拒否ルールが、**オプションの値に含まれるファイル、git のオペランド、複合コマンド**にも及ぶようになった。管理設定が**パースできない場合は起動を拒否**する挙動になった。マーケットプレイスのリポジトリ URL の末尾スラッシュや余分な文字が、正しいクローン URL になるよう修正された。

**その他**: 並行セッションが互いの設定変更を巻き戻す不具合、拒否された thinking が以降のターンで繰り返し拒否される不具合、OAuth トークン更新でプロンプトキャッシュが無効化される問題、`CLAUDE_CODE_MAX_CONTEXT_TOKENS` が Vertex 形式のモデル版で無視される問題などを修正。GitLab のマージリクエストが `MR !N` として表示されるようになり、`claude plugin validate` に `--json` が付いた。

## できるようになったこと

- `managedMcpServers` による **HTTP/SSE MCP サーバーの組織配布**
- `--permission-prompts none` による**無人実行時の自動拒否**
- Bash `Read()` 拒否ルールの適用範囲拡大（オプション値 / git オペランド / 複合コマンド）
- 管理設定がパース不能なら**起動を拒否**
- `claude plugin validate --json`、GitLab MR 表示

## 影響範囲

- 対象ユーザー: Claude Code 利用者全般。特に**組織で MCP サーバーを配布・制限している管理者**
- 対象プラン: 全プラン
- API / UI / 管理者機能: **`allowedMcpServers` の意味変更**は管理者の設定見直しが必要になりうる

## 教材化メモ

- **`allowedMcpServers` の適用範囲が「ユーザー追加分のみ」へ変わった**のは、設定名から挙動が推測できなくなる典型例。**許可リストの対象が何かを明示しない設定名は誤解を生む**という設計上の教訓であり、既存設定を持つ組織は「今も意図どおり効いているか」を確認する必要がある。週次ロールアップで最初に触れるべき点。
- **権限境界の修正が 2.1.251 / 2.1.252 / 2.1.257 / 2.1.259 と4リリースにわたって続いている**。シンボリックリンク経由の境界、クラウドメタデータ資格情報（Containment Escape）、そして今回の Bash 拒否ルールの適用漏れ。**「拒否ルールを書いたのに抜け道があった」という形の修正が繰り返されている**点は、AI エージェントに権限制御を課すときの一般的な難しさとして扱える。
- **管理設定がパースできないときに起動を拒否する**という選択は、「壊れた設定で無防備に動き出すより止まる方が安全」というフェイルセーフの原則。設定を配布する仕組み全般に移せる。
