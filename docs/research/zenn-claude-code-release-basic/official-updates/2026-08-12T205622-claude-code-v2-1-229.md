# 2026-08-12 Claude Code v2.1.229

## 公式内容の日本語要約

機能追加と多数の修正を含むリリース。追加のうち実運用に効くのは3点である。

第一に、プラグインマーケットプレイスに `command` ソースが加わった。ローカルのコマンド（IDE など）がプラグインディレクトリを出力し、それがセッションごとに再解決されて再起動なしで適用される。`mode: "link"` を指定するとその場所をそのまま使う。

第二に、VSCode 拡張のサイドバーにセッショングループが入った。右クリックで作成・改名・削除でき、Cmd/Ctrl クリックや Shift クリックで複数セッションをまとめて移動できる。`/btw` のサイドクエスチョンパネルも境界ドラッグでリサイズできるようになった。

第三に、`/commit-push-pr` の挙動変更である。`--force`、`--amend`、`--no-verify` など危険なフラグを含む git / gh コマンドが自動承認されなくなった。これは既存の運用が黙って変わる種類の変更で、承認プロンプトが増える方向に働く。

セルフホストランナー関連の修正も多い。サーバー供給の Claude Code hook がセルフホストランナーのセッションでも使えるようになり（マネージド環境と同じ挙動）、`managed-mcp.json` がデプロイされている環境で起動時に落ちる問題、Git Credential Manager のプロンプトでリポジトリ準備がハングする問題が直った。Windows のセルフホストランナーは明示的な `--base-dir` が必須になった（Windows には既定のチェックアウト先を置かない方針）。

性能面では、ワークフローのファンアウトで同じプレフィックスを持つ兄弟エージェントの起動をずらし、後続エージェントがキャッシュ済みプロンプトプレフィックスを読めるようにした（`CLAUDE_CODE_WORKFLOW_PREFIX_STAGGER_MS=0` で無効化）。また CPU 制限付きコンテナ内の動的ワークフローが、ホスト機のコア数ではなくコンテナの CPU 制限を見るようになった。

その他、Vertex / Bedrock 上流での長考中のアイドルタイムアウト切断を防ぐ SSE キープアライブ、`ListAgents` での offline / cloud ラベル表示、サンドボックスの IPv6 リテラル対応（`[::1]:443` 形式、曖昧な表記は fail-closed で `/doctor` が指摘）などが入った。

## できるようになったこと

- IDE などのローカルコマンドからプラグインディレクトリを解決し、再起動なしで反映できる
- VSCode サイドバーでセッションをグループ分けして整理できる
- ワークフローのファンアウトでプロンプトキャッシュを効かせ、トークンの再支払いを減らせる
- セルフホストランナーでサーバー供給の hook を使える

## 影響範囲

- 対象ユーザー: Claude Code 利用者全般。セルフホストランナー運用者への修正が厚い
- 対象プラン: 記載なし（バージョン更新）
- API / UI / 管理者機能: CLI、VSCode 拡張、セルフホストランナー、サンドボックス設定

## 教材化メモ

- `/commit-push-pr` で危険フラグが自動承認されなくなった点は、既存の教材やハーネス手順が「承認なしで通る」前提で書かれていると齟齬が出る。権限モデルを扱う教材では、自動承認の範囲は版によって縮小されうるものとして説明する。
- ワークフローのプレフィックススタガーは、マルチエージェントのコスト設計を扱う教材の実例になる。同じ system prompt を持つ兄弟エージェントを同時に投げるとキャッシュが効かない、という具体的な失敗形が公式の修正として現れた。
- コンテナの CPU 制限を見るようになった修正も同系統で、「並列度をどこから決めるか」の話題に接続できる。
