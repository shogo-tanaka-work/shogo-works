# 2026-08-11 Claude Code v2.1.228

## 公式内容の日本語要約

大半がバグ修正のリリースだが、セキュリティと挙動変更がいくつか含まれる。

claude.ai から同期されたスキルがハードニングされた。同期スキルはローカルのコマンドや MCP プロンプトを上書きしなくなり、説明文はサニタイズのうえラベル付けされる。利用者のマシン上では、同期スキルの本文から `!` コマンドの実行と `@` によるファイル展開が行われなくなった。

Write ツールの挙動が変わった。新しいモデルは、そのセッション中に読んでいないファイルでも上書きできるようになり、Edit ツールのルールと揃った。古いモデルは従来どおり事前の読み取りを必要とする。

self-hosted runner 関連の修正が2件入った。1つは、セッションが push しないリポジトリで `checkout` フックが失敗すると、新しい runner のたびにセッションが落ちていた問題で、該当リポジトリは警告付きでスキップされるようになった。もう1つは、バックグラウンドタスクの完了から次のターン開始までの隙間でセッションが終了してしまう問題である。

このほか、Remote Control の `/resume` が接続中のセッションへ再開元の会話タイトルや履歴を漏らす問題、セッションのクリーンアップがプロジェクトの memory フォルダ内を削除する問題、Vertex AI の期限切れ認証情報で数分間リトライし続ける問題が修正された。Pro / Max / Team の初回利用通知から、auto mode セッションのコストがやや高くなるという古い注記が削除された。

## できるようになったこと

- claude.ai 同期スキルがローカルのコマンド / MCP プロンプトを上書きせず、`!` 実行と `@` 展開も行わなくなった
- 新しいモデルは未読ファイルを Write ツールで上書きできる（Edit と同じルール）
- `checkout` フック失敗時、該当リポジトリをスキップして self-hosted runner のセッションを継続できる
- Vertex AI の認証情報が無効な場合、数分待たずに数秒で失敗する

## 影響範囲

- 対象ユーザー: Claude Code 利用者全般、self-hosted runner を運用する組織
- 対象プラン: 全プラン
- API / UI / 管理者機能: CLI 本体

## 教材化メモ

- claude.ai 同期スキルのハードニングは、「外部から持ち込んだスキルをどこまで信用するか」を扱う具体例。同期スキルがローカルコマンドを上書きできてしまう状態が修正前に存在した、という事実そのものが教材の導入に使える。
- Write ツールの挙動変更はモデル世代で分岐する。教材で「Write の前に必ず Read が要る」と書いている箇所は、新しいモデルでは前提が崩れるため、断定を避ける書き方へ改める必要がある。
- 自動承認や自動編集を扱う章では、`!` 実行と `@` 展開が「スキル本文から実行されうる経路」だったことを、権限設計の実例として引用できる。
