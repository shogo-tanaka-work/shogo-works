# 2026-08-31 Claude Code 2.1.252

## 公式内容の日本語要約

Claude Code の stable リリース `v2.1.252` が公開された。**バグ修正とセキュリティ修正が中心**で、新機能の追加は含まれない。

**セキュリティ修正**として、ファイルツールにおける**シンボリックリンク経由で承認済みの場所の外を読み書きできてしまう問題**にパッチが当たった。あわせて**プラグインのパストラバーサル攻撃**が遮断された。また、**算術評価を伴うシェル変数代入で権限チェックが回避される**問題も修正されている。

**不具合修正**は次のとおり。一部の Mac で Bash コマンドが `task output swap refused (tasks dir moved or linked)` を出して失敗する問題。`.claude/settings.local.json` が無いプロジェクトで「always allow」が保存されない問題。claude.ai への接続が劣化している状況で Remote Control セッションがツール完了後に停止する問題。失敗時の出力が大きいバックグラウンドタスク通知が API リクエストのサイズ上限を超える問題。

**前バージョン 2.1.251（08-28）でもシンボリックリンク関連の読み取り拒否ルール回避が修正されており、2リリース連続で同系統の問題に対処している。**

## 影響範囲

- 対象ユーザー: Claude Code 利用者全般。特に macOS 利用者、プラグイン利用者、Remote Control 利用者
- 対象プラン: プラン非依存
- API / UI / 管理者機能: ファイルツールの権限境界、プラグイン読み込み、シェル実行時の権限チェック

## 教材化メモ

- **AIニュース単独記事化は見送り（週次ロールアップへ）。** `selection-rubric.md`「日次リリース型ツールの扱い」により、バージョン番号が付いたリリースは内容にかかわらず単独記事にしない。セキュリティ修正を含んでいても判定は変わらない。
- **週次ロールアップの「今週の要点」冒頭で、対応要否を明示すること。** 2.1.251 と 2.1.252 で**2リリース連続してシンボリックリンク経由の権限境界の逸脱**が修正されている。これは「承認済みディレクトリの外は読み書きされない」という前提に依存した運用（機密ディレクトリを承認範囲外に置くだけで安全とみなす設計）が、実際には破れていた期間があったことを意味する。**アップデートを止めている環境ほどリスクが残る**ため、バージョン固定運用をしている組織には明示的な更新推奨が要る。
- 教材的な核心は、**「権限境界はパスの文字列ではなく実体で判定しなければならない」**という一般則。シンボリックリンク、パストラバーサル（`../`）、算術評価を伴う変数代入——今回修正された3つは、いずれも**「入力を正規化する前に権限判定してしまった」**という同じ構造の異なる現れ方である。AIエージェントに権限を与える設計を扱う回で、そのまま教材にできる。
- `.claude/settings.local.json` が無いと「always allow」が保存されない不具合は、**設定ファイルの存在を前提にした書き込み処理の典型的な抜け**。ハーネス設計の文脈で「設定の初期状態を必ず作る」という設計原則の実例として使える。
