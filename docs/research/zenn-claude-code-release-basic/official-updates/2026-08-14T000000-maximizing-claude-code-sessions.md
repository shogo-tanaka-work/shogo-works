# 2026-08-14 Maximizing the value of your Claude Code sessions

**これは製品変更の告知ではなく、公式が出した運用ガイダンス記事である。**新機能・新バージョン・仕様変更はいずれも含まれていない。既存の機能をどう使うとトークン消費を抑えられるかを Anthropic 自身が説明したもの。

## 公式内容の日本語要約

コストが決まる要素として3点が挙げられている。

- **モデル選択**
- **入力トークンと出力トークンの価格差**: 出力は入力の約5倍
- **プロンプトキャッシュの挙動**: キャッシュ読み出しは入力価格の 0.1 倍。キャッシュは約1時間で失効する

そのうえで、具体的な操作として次が示されている。

- **関係のないタスクの間で `/clear` を使う**。無関係な文脈を積み上げないため
- **モデルと effort はセッション冒頭で決める**。会話の途中で変えるとプロンプトキャッシュが壊れる
- **パスを打つ代わりにファイルを @-mention する**。余分な Read 呼び出しを減らせる
- **出力の多いコマンドには quiet フラグを付けるか、サブエージェントに回す**。ノイズで会話が膨らむのを防ぐ
- **新しいセッションで `/context` を実行する**。不要に読み込まれているものを見つけて外す
- **休憩の前に `/compact` を実行する**。プロンプトキャッシュは1時間で失効するため

想定読者は、サブスクリプションまたは API キーで Claude Code を使っていて、消費を意識している利用者である。

## 教材化メモ

- **`src/content/knowledge/ai-tools/claude-code/daily-operations.mdx` への最小反映が妥当**。速報として単発で出すより、日常運用の教材に「トークンの使われ方」として組み込む方が読者に残る。公式が数値（出力は入力の約5倍、キャッシュ読みは 0.1 倍、キャッシュ1時間）を明示しているため、根拠付きで書ける。
- **`/clear` の位置づけが変わる。**「文脈が混ざって精度が落ちるから区切る」という理由で説明されることが多いが、公式はコストの観点から同じ操作を勧めている。**同じ操作に理由が2つある**ことを示すと、なぜやるかが定着する。
- **プロンプトキャッシュが1時間で失効する**という仕様は、教材で明示されることが少ない。「休憩前に `/compact`」という具体的な操作へ落ちる点まで含めて、キャッシュの挙動は運用に直結する知識として扱う。
- **モデルと effort をセッション冒頭で決める**理由が「途中変更でキャッシュが壊れるから」である点は、`new-commands-2026.mdx` の `/effort` 記述と接続できる。コマンドの存在ではなく、いつ使うかを教える材料になる。
- 出力の多いコマンドをサブエージェントへ回す話は、`subagents.mdx` の動機づけとして使える。サブエージェントは「並列化のため」と説明されがちだが、**親の文脈を汚さないため**という理由の方が日常運用では効く。
