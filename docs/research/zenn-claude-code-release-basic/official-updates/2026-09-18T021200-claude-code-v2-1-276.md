# 2026-09-18 Claude Code v2.1.276

## 公式内容の日本語要約

**変更点が1行しかないホットフィックスである。** `ANTHROPIC_BASE_URL` がプロキシまたはゲートウェイを指している環境で、**全リクエストが `400 … Input tag 'advisor_20260301'` で失敗する**不具合を修正した。

changelog に **「2.1.275 regression」と明記されている**。前日（2026-09-17T22:33Z）に出た v2.1.275 で作り込まれたもので、**発生から約3時間40分で修正版が出ている**。

**影響を受けるのは、Anthropic API を直に叩かずゲートウェイ経由にしている構成に限られる。** 企業で LLM ゲートウェイを挟んで利用ログや費用を集約している場合が該当し、個人が公式エンドポイントへ直接つないでいる構成では発生しない。**該当環境では「一部が遅い」ではなく全リクエストが落ちる形**だったため、v2.1.275 を掴んでしまった環境は 2.1.276 以降への更新が必要である。

## できるようになったこと

- ゲートウェイ / プロキシ経由（`ANTHROPIC_BASE_URL` 指定）の環境で、v2.1.275 以降も Claude Code が利用できる

## 影響範囲

- 対象ユーザー: `ANTHROPIC_BASE_URL` でプロキシ・ゲートウェイを指定している利用者（主に企業の集中管理構成）
- 対象プラン: プラン非依存
- API / UI / 管理者機能: API リクエストの送信経路

## 教材化メモ

**単独記事にしない（バージョンリリースのため規約により週次ロールアップへ）。**

教材素材としては「**集中管理構成のほうが先に壊れる**」という点が使える。ゲートウェイを挟む構成はガバナンス上は正しいが、**ベンダーの検証が薄い経路でもある**。標準構成から外れるほど、リグレッションを最初に踏む確率が上がる。企業導入の章で「集中管理は統制と引き換えに、ベンダーの想定外経路を踏むリスクを取る」という形で扱う。

**バージョン固定運用との組み合わせも論点になる。** 全リクエストが落ちる種類の障害は、更新を止めている環境ほど復旧が遅れる。**「更新を止める」と「壊れたら更新して直す」は両立しない**という当たり前を、3時間40分で修正版が出たこの事例で具体化できる。
