# 2026-10-08 Claude Code v2.1.295

## 公式内容の日本語要約

大きめのリリースで、主要な追加・変更は次である。

**新機能**: command / HTTP hook を、**起動失敗・タイムアウト・想定外の終了コードのときに操作をブロックする**（fail-closed）設定にできるようになった。Program Status Protocol（OSC 7501）対応ターミナルで、Claude Code が作業中 / 入力待ち / 完了のどれかを表示できる。`/copy` のピッカーが `>` の引用記号なしで下書きをコピーできる。`claude plugin` / `marketplace` 系コマンドが、書き込み先の設定ファイルが読み込まれない場合に警告する。`claude -p` が最終ターン後も開いたままのとき、stderr が端末なら待機理由を出す。Claude apps gateway が**クラウド upstream のストリーム開始までのタイムアウト**に対応（超過でフェイルオーバーまたは 502）。gateway が **upstream ごとのモデル一覧（ワイルドカード対応）**を受け付け、フェイルオーバー時にも適用する。gateway の監査イベントと成功レスポンスに upstream ID / リクエスト ID が入る。mods に通知 API とボタンの子要素、429 / 529 時の無人リトライの最大待ち時間設定が追加。

**権限・安全性**: fail-closed の hook が操作をブロックするようになった。Bash の権限チェックが、glob 展開を伴う読み取り専用コマンド・zsh 固有の変数挙動・glob を回す for ループについて厳格化された。read の deny ルールと作業ディレクトリ外の読み取りブロックが、**シンボリックリンク経由のファイルや Bash のワイルドカードオプション**にも適用される。これまで権限 hook をすり抜けていた、または無視されていたツール呼び出しと割り込みが処理されるようになった。plan モードと auto モードの境界ケースも修正。

**修正**: `[1m]` モデルで gateway やクラウドプロバイダーが context-1m beta を拒否した場合、beta なしで再試行する。リモート MCP サーバーが障害後に再接続し、切断が続く場合はバックオフする。Bash ツールが `command_description` を受け付ける。Claude in Chrome がポート80の deny ルールを平文 HTTP ページにも適用する。worktree / SendMessage / task-stop 周りのバックグラウンドサブエージェントとチームメイトの挙動、ターミナル表示・入力、セッション再開 / rewind / `/loop` / スケジュールタスク復旧の多数の修正。

**変更**: tool search 経由の MCP ツール説明の切り詰め上限が拡大。16 MiB 超の WebSocket メッセージは接続を閉じる。サブエージェントのスキル事前読み込みは最大32件。バックグラウンド `/loop` の Ctrl+C / Esc の挙動変更。

## 影響範囲

- 対象ユーザー: Claude Code 利用者全般。gateway / mods / hook を使う構成はとくに影響大
- 対象プラン: Claude Code 全般
- API / UI / 管理者機能: CLI と gateway。**権限チェックの強化により、これまで通っていた Bash 呼び出しが拒否される可能性がある**

## 教材化メモ

- **hook の fail-closed 設定は「落ちたときどちらに倒すか」の設計判断の教材になる。** hook が起動に失敗したとき、操作を通す（可用性優先）か止める（安全性優先）か。**この分岐を明示的に選べるようになった**こと自体が、セキュリティ設計の説明材料として使える。
- **権限チェックの抜け穴の実例が具体的である。** シンボリックリンク経由の読み取り、glob 展開、zsh の変数挙動、for ループ。**「拒否リストを書いた」だけでは守れない**という典型を、公式の修正履歴で示せる。
- **gateway の upstream ごとのモデル一覧とタイムアウトは、社内 LLM ゲートウェイを設計する際の要件リストとして流用できる。** モデルの許可リスト、フェイルオーバー、監査 ID の紐付けは、自社で作る場合も同じ項目が必要になる。
