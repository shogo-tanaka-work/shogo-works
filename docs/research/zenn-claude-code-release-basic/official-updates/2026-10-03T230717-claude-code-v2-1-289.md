# 2026-10-03 Claude Code v2.1.289

## 公式内容の日本語要約

バグ修正中心のパッチリリース。新機能は `agent.spawn`（teammates 向け）と、plugin hook イベントをまたいで同一の agent id を持つ仕組み、`$.agent.list()` への idle / waiting 状態の追加の3点のみ。

**修正の中心は2つの領域に分かれる。1つめは権限ルールの取りこぼしである。** 複合シェルコマンドの入れ子部分に付いた deny / ask ルールが、管理対象マシンでユーザーがインストールした mod の承認に対して効かなくなっていた問題、環境変数を前置した破壊的コマンド（公式例は `TZ="$HOME"` 付きのビルド成果物削除）がサンドボックスの自動許可下で deny / ask を素通りしていた問題、裸の変数代入がコマンドの前に来た場合に同じく素通りしていた問題、`Read` の deny ルールがシンボリックリンク経由で IDE から @ 参照・変更・選択されたファイルに適用されていなかった問題——いずれも「ルールは書かれているが効いていない」型の抜け穴である。

**2つめは plugin / mod の描画と安定性である。** mod の `ui.render` フックが書いた値で行が例外を投げるとセッションが「unrecoverable interface error」で終了していた、高さゼロの plugin リージョンが伸び続けるとセッションが終了していた、plugin の on-screen ハンドラが非同期に例外を投げると supervised / background セッションが終了していた、ターミナルが知らない枠線スタイルの Box を描こうとすると起動時にフリーズまたは強制終了していた——プラグイン側の不具合がセッション全体を落とす経路を個別に塞いでいる。

**組織管理との境界に関わる修正も1件ある。** ユーザーがインストールした plugin が、組織管理下の MCP サーバーのサインインツールの説明文を書き換えられてしまう問題を修正した。

その他、`plugin list` / `plugin eval` / `plugin update` がローカルフォルダ marketplace 由来の plugin の古いコピーを表示する問題、`claude plugin validate` がフォルダに marketplace マニフェストがあると plugin を飛ばす問題、アップグレード後の最初のセッションで mods が読み込まれない問題、公開済み artifact ページが未閉鎖の `<script>` タグを多く含む短いコードブロックで閲覧者のブラウザタブをフリーズさせる問題などを修正している。

## できるようになったこと

- `agent.spawn`（teammates 向け）の追加、plugin hook イベント間で一貫した agent id、`$.agent.list()` の idle / waiting 状態
- 権限ルールの抜け穴3件の解消（複合コマンドの入れ子部分、環境変数前置、裸の変数代入）
- `Read` deny ルールがシンボリックリンク経由の IDE 参照にも適用される
- plugin / mod の不具合でセッション全体が落ちる経路の個別封鎖（描画例外、高さゼロ領域、非同期例外、未知の枠線スタイル）
- ユーザー plugin による組織管理 MCP サーバーのツール説明文の書き換えを防止

## 影響範囲

- 対象ユーザー: Claude Code 利用者全般。**権限ルール（deny / ask）を運用で使っている組織と、plugin / mods を自作している利用者に影響が大きい**
- 対象プラン: 記載なし（CLI のパッチリリース）
- API / UI / 管理者機能: 管理対象マシンの権限ルール適用、組織管理 MCP サーバーの保護、plugin / mods の実行安定性

## 教材化メモ

- **「ルールは書いてあるが効いていない」という失敗の形。** v2.1.289 の権限修正3件はすべて、deny / ask ルール自体は設定済みなのに、コマンドの書き方（複合コマンドの入れ子、環境変数の前置、裸の変数代入）で判定をすり抜けていた。**権限設定を入れた時点で安全だと考える運用は危ない**という具体例として使える。ルールを書いたあとに「すり抜ける書き方」を試す検証工程が要る、という話につなげられる。
- **シンボリックリンクが権限境界の穴になる**という定番の論点。`Read` deny ルールがシンボリックリンク経由では効いていなかった。ファイルパスで境界を切る仕組み全般（コンテナのマウント、CI の成果物制限、Web サーバーの静的配信）に共通する弱点として一般化できる。
- **プラグインの不具合がホストを落とす構造**。本リリースは「plugin / mod が例外を投げたらその部分だけ失敗させ、セッションは生かす」方向へ一貫して寄せている。拡張機構を自作するときの設計方針（障害の隔離境界をどこに置くか）の実例として使える。
- **ユーザー拡張が組織管理設定を上書きできてしまう問題**。plugin が管理下 MCP サーバーのサインインツールの説明文を書き換えられた、という修正は、**「管理者が決めたものをユーザー側の拡張が変えられるか」という権限モデルの検証項目**を示している。社内で AI ツールを統制する際のチェックリストに入る観点。
