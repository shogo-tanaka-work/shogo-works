# 2026-09-03 Claude Code 2.1.260

## 公式内容の日本語要約

Claude Code **2.1.260** が公開された。**バージョン番号付きリリースのため単独記事にはせず、週次ロールアップへ送る**（`selection-rubric.md`「日次リリース型ツールの扱い」）。以下は追跡用の要点である。

**追加された主な機能。** フルスクリーンで会話の横に開き、Claude の編集に合わせて未コミット差分を表示する **diff パネル**（`/diff` でトグル）。`/cost` とステータスラインの `prompt_cache` に **プロンプトキャッシュのミス理由**（ツール定義やシステムプロンプトの変更、TTL 超過のアイドルなど）を表示。ヘッドレスセッションでの `/reload-plugins`、デスクトップ / Remote Control / ヘッドレス向けの **テキスト版 `/advisor`**。

**権限まわりの修正が今回の中心である。** 記録として重要なものを挙げる。

- **括弧を含むパスの `Edit`/`Write`/`Read` 権限ルールが無効として捨てられ、Bash サンドボックスから無視されていた。** その結果「読み取り専用」のはずのフォルダが**書き込み可能なまま残っていた**
- コンパイル不能なパターン（閉じていない `[` など）を含むルールが1つあると、**全ファイル編集が `Invalid regular expression` で失敗**していた
- **zsh の `REPORTTIME` / `REPORTMEMORY` / `DIRSTACKSIZE` 代入にコマンド置換を隠した場合、Bash 権限チェックが自動承認していた**。承認プロンプトを出すよう修正
- macOS で `permissions.blockReadsOutsideWorkingDirectories` がサンドボックス化された git からユーザーの git config を隠していた問題
- 管理された `skillOverrides` のエイリアス指定が効かない、`Skill(name)` の deny ルールが `<dir>:name` 形式のネストしたスキルを覆わない問題

**そして 2.1.259 の変更が1つ撤回されている。** **`Read()` の deny ルールを Bash 引数へ適用する変更を revert した。** 理由は明快で、`Read(./**/build/**)` 配下で **`npm run build` が全モードで拒否され**、`cd … && grep` が auto モードでもプロンプトを出すようになっていたため。

**その他**では、Bedrock でのモデル検出・トークンカウント・AWS SSO/STS が社内ルート CA を OS ストアにのみ持つ環境で失敗する問題、claude.ai Enterprise/Team ユーザーで古い API キーが残っていると管理設定が読み込まれない問題、Fable 5.1 まわりの複数修正（`/model` ピッカーに出ない、ツール結果後のコンテキストがキャッシュされず毎ターン再送される、`[1m]` タグ無視）などが修正された。1M コンテキストモデルの auto-compact 改善、Claude in Chrome の組織管理設定への追従も入っている。

## できるようになったこと

- `/diff` による未コミット差分のサイドパネル表示
- プロンプトキャッシュのミス理由の可視化（`/cost`、ステータスライン）
- ヘッドレス / デスクトップでの `/advisor`、`/reload-plugins`

## 影響範囲

- 対象ユーザー: Claude Code 利用者全般。**特に権限ルールで読み取り専用領域を定義している組織**
- 対象プラン: 全プラン
- API / UI / 管理者機能: 権限ルールの解釈が複数箇所で変わる。**2.1.259 で `Read()` deny を Bash 引数へ広げた挙動は撤回された**

## 教材化メモ

- **「読み取り専用のつもりが書き込み可能だった」という修正**は、権限設計の教材として素直に使える。**設定を書いたことと、それが効いていることは別**。括弧を含むパスという、ごく普通の記法で無効化されていた点が重要で、**権限ルールは書きっぱなしにせず、実際に拒否されるかを試す**という運用習慣に落とせる。
- **2.1.259 → 2.1.260 の revert** は、**セキュリティ強化が実務を壊した実例**として価値がある。`Read()` deny を Bash 引数へ広げた結果、`npm run build` という日常的なコマンドが全モードで止まった。**「厳しくすれば安全」ではなく、誤検知のコストを見積もる**という話に接続できる。1日で撤回された点も含めて、変更の可逆性を保つ設計の例。
- **zsh の変数代入にコマンド置換を隠すと自動承認されていた**件は、**シェルの構文解釈の差がセキュリティ境界の穴になる**という具体例。bash と zsh でパースが違うという前提を持っていないと防げない種類のバグ。
- **プロンプトキャッシュのミス理由の可視化**は、コスト最適化の教材に使える。**キャッシュが効いていない原因を推測で潰す作業**が減る。ツール定義やシステムプロンプトの変更が原因になるという点は、エージェント設計の実務知識としても有用。
