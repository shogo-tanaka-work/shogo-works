## 補足メモ

- **source-catalog の GitHub Releases 取得コマンドに、クラウド実行時の代替経路を明記すべきである。** カタログは `gh api -X GET 'repos/<owner>/<repo>/releases?per_page=100' --paginate` を正としているが、**前日は 403、本日は `gh` / `curl` 自体が使えず、2日連続でそのまま使えなかった。** 実際に機能した経路は次の3つで、いずれも WebFetch のみで到達できる。カタログ側へ「クラウド実行時は以下を使う」として追記することを推奨する。
  - Claude Code: `https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md`（最も安定）
  - Claude Code / Codex のリリース日時: `https://github.com/<owner>/<repo>/releases.atom`
  - Cloudflare: `https://developers.cloudflare.com/changelog/rss/index.xml` と `https://blog.cloudflare.com/rss`
- **「リリース本文が空なら翌日 changelog を再確認する」という Codex 固有の運用パターンを記録する。** 2026-10-06 の `rust-v0.161.0` はリリース本文が空で「内容不明」として通過した。**翌日（本日）に `learn.chatgpt.com/docs/changelog` へ内容が掲載され、GPT-6.1 Sol 既定化・Bedrock GovCloud 対応という重い内容が判明した。** GitHub Releases だけを一次情報にすると、Codex は内容不明のまま通過する日が出る。**`learn.chatgpt.com/docs/changelog` を「翌日の追補確認先」として source-catalog に位置づけておくべきである。**
- **`help.openai.com` の 403 は新規の死角として監視が必要である。** `openai.com/news/` の 403 は15日続いており既知だが、**本日 ChatGPT Release Notes の主ソースも 403 になった。** 両方が落ちると ChatGPT アプリ本体（モデル提供、利用枠、UI 機能追加）が観測できない。明日も 403 が続く場合は、`learn.chatgpt.com/docs/changelog` のアプリ側エントリ（ChatGPT for iOS / Android / デスクトップ）を主ソース扱いに格上げするか、二次ソース（`neowin.net` / `releasebot.io`）からの一次逆引きを定常手順に組み込むかの判断が必要になる。
- **ユーザー認識ギャップに該当する事項は、本日は発生していない。**
