## 補足メモ

- **ユーザー認識ギャップ該当なし。** 本日の実行で `perception-gaps.md` への追記事項は発生していない。
- **【推奨】source-catalog の「GitHub Releases取得コマンド」節に代替経路を追記する。** 本セッションでは `gh api` が対象リポジトリで 403 を返し、カタログに書かれたコマンドがそのまま使えなかった。**クラウド実行環境では GitHub アクセスがリポジトリ単位で付与されるため、外部リポジトリの API 取得が通らないことがある。** 代替として **(1) `https://github.com/<owner>/<repo>/releases.atom` の WebFetch**（タグ名・timestamp・本文が取れる）、**(2) `raw.githubusercontent.com` の CHANGELOG**（Claude Code は本文が最も詳しい）を明記しておけば、次回以降の迷いがなくなる。**pagination が使えない点だけが atom の弱みだが、日次の窓（24h）では十分である。**
- **【推奨】Claude の巡回経路の優先順位を入れ替える。** 本日の Claude 3件は**すべて `claude.com/resources/articles/` と `anthropic.com/news` 側**で、`support.claude.com` の Release Notes は 09-28 から動いていない。**Release Notes を起点にする順序は、開発者向け・企業向けの発表を構造的に後回しにする。** 巡回順を **`claude.com/blog`（= `claude.com/resources/articles/`）→ `anthropic.com/news` → `platform.claude.com` API リリースノート → `support.claude.com` → AWS 逆引き** とする方が、検出が早い。
- **【推奨】Anthropic / Claude の個別ポストは必ず一覧ページから href を取る。** 本日 `anthropic.com/news/` の個別ポスト URL を2回スラッグ推測で踏んで 404 になった。**正しい URL は一覧ページの href にしかない。** また `claude.com/blog` の個別ポストは **`claude.com/resources/articles/<slug>`** で、一覧ページの URL（`claude.com/blog`）とパスが違う。**OpenAI について既に「URL のスラッグは推測しない」という運用ルールがあるが、同じルールを Anthropic 側にも適用する必要がある。**
