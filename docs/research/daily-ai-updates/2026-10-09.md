## 補足メモ

- **source-catalog の GitHub Releases 取得コマンドは、3日連続でそのまま使えていない。** 10-07 は `gh api` が 403、10-08 は `gh` / `curl` 自体が不可、本日は**外部リポジトリのみ 403（自リポジトリは成功）**。環境条件が日によって違うため、**カタログ側へ「クラウド実行時の代替経路」を明記すべきである。** 実際に機能した経路は次のとおり。
  - Claude Code の変更内容: `https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md`（最も安定）
  - Claude Code / Codex のリリース日時: `https://github.com/<owner>/<repo>/releases.atom`
  - Codex の変更内容: `https://learn.chatgpt.com/docs/changelog`（リリース本文が空の場合の正本）
  - Cloudflare: `https://developers.cloudflare.com/changelog/rss/index.xml` と製品別 RSS
  - **open PR の確認: `gh api 'repos/{owner}/{repo}/pulls?state=open'`（REST）。`gh pr list` は GraphQL のため 403。**
- **`platform.claude.com/docs/en/release-notes/api` は、WebFetch の10万字制限で後半が読めていない。本日の追補2件はこのページ由来である。** 10-06 の `capabilities.server_tools` と 10-07 の `web_fetch` 事前文脈制限は、いずれもこのページの date-only エントリで、**2日・3日前の日付のまま未記録だった。** 取りこぼしが2件同時に出たことを踏まえ、**次の2点を運用へ入れることを推奨する。**
  1. **このページは毎回 `offset: 100000` で後半も取得する**（残り約2.3万字。1回の追加呼び出しで済む）。
  2. **直近3日ぶんの日付節について、記録済み URL / フィールド名との差分を機械的に確認する。** 本日は `grep -rl "server_tools"` と `grep -rl "url_not_in_prior_context"` で未記録を確定させており、**この確認が追補の発見に直結した。**
- **「過去記事を確認してから判定する」手順が、本日は実際に判定を変えた。** Ultrafast の件は、**既存記事 `chatgpt-openai/gpt-6-1-sol-and-ultrafast-tier`（2026-09-29）に「Sol Ultrafast は近日」と記録されていた**ため、新設ではなく履行として扱えた。**確認しなければ「Ultrafast ティア新設」として二重に記事化していた。** さらにその過去記事が「速度倍率と単価は報道の突き合わせで再構成」と制約を明記していたため、**今回 `developers.openai.com/api/docs/pricing` で一次確認を取る動機になった。** 結果として全ティアの単価を一次情報で確定できた。**過去記事の「制約の明記」が、後続の実行で精度を上げる形で効いた事例として記録する。**
- **未マージ PR の扱いは、本日の手順がそのまま再利用できる。** PR #475 が着手時点で open だったため、(1) REST で変更ファイル一覧を取得して作成済み記事を控える、(2) PR ブランチから前日サマリーを取得して `window_end` を継承する、(3) 既出の更新は「見送り（既出・未マージPR #番号）」として残す、の3段で処理した。**実行時刻 -24h の代替は使わずに済んだ。** **なお PR #475 は本実行中（00:14:19Z）にマージされたため、滞留は解消している。** ただし**着手前の確認は時点のスナップショットである**という点は残るため、**PR 作成直前の再確認を手順へ入れることを推奨する。**
