### 選別の考え方

窓内の記事化候補は8件で、**本数上限（4本）が実質的に効いた日**である。今回は5位（Admin プラグイン、8点）が記事化基準（6点以上）を満たしており、**上限が無ければ記事化していた**。この点は前日（5位・6位とも基準未満）と状況が異なる。

**Claude のメモリ統合、ChatGPT Work のサインイン付きサイト対応、定期タスクのイベント起動が9点で並んだ。** 3件とも「重要度2・持続性2・実務影響2・既存教材影響1・公式情報の十分性2」で、いずれも組織側の判断か情シスの承認が必要になる。同点3件はすべて記事化したため、順位付けの必要は生じなかった。

**メモリ統合（9点）は、Team / Enterprise で管理者が組織単位の可否を握っている点が効いている。** 許可しなければ個人側でもオンにできないため、**方針を決めていない状態が事実上の禁止として機能する**。加えて「保存されない」と「送信されない」の区別を曖昧にしたまま社内説明すると後で認識のずれが出る、という説明責任上の論点がある。

**サインイン付きサイト対応（9点）は、提供範囲の逆転が最大の論点である。** Enterprise / Edu では使えず、Plus / Pro では使える。**組織として禁止しているはずの機能が、社員の個人契約では動く**という構造で、シャドー IT の入り口になりうる。あわせて告知された Site tools（WebMCP）は、中期的には「サイト側が AI 向けツールを定義する」という設計思想の転換点になる可能性がある。

**定期タスクのイベント起動（9点）は、逆に統制が効く設計である。** Slack チャンネルへの ChatGPT アプリ追加、GitHub 接続アプリのリポジトリアクセスが前提のため、個人が勝手に始められない。**同じベンダーの同じ日の発表で統制構造が正反対**という点は、それ自体が示唆的である。

**Claude Code 2.1.246（8点）と Admin プラグイン（8点）が同点で、上限の境目に来た。** 同点処理の順序は「1. 期限や発効日が決まっているもの → 2. 管理者の作業が発生するもの → 3. 利用者の操作フローが変わるもの」だが、**1 はどちらも該当せず、2 は両方該当する**（2.1.246 は既存の Bash allow ルールの是正作業、Admin プラグインは導入判断と権限設計）。そこで決め手にしたのは次の2点である。

- **2.1.246 は「既に配ってある設定が意図より広いかもしれない」という是正作業**で、新規導入の判断より緊急度が高い。起動時警告は流れて消えるため、気づいて対応する人がいなければ状態は変わらない
