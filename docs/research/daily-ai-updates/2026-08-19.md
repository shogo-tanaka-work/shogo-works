## 補足メモ

- **OpenAI の `openai.com/index/<slug>/` 個別ポストが取得できない状態が続いている。**今回、ChatGPT for Teens と Pacing model development の2本について、WebFetch は HTTP 403、Exa の `web_fetch` は livecrawl タイムアウトで本文を取れなかった。一方で **CodeAI のポストは Exa 経由で本文を取得できた**ため、恒常的に不可というわけではなく、ページごと・タイミングごとに結果が変わる。`openai.com/news/` 一覧は Exa 経由で安定して取得できるので、**一覧で存在と日付を押さえてから個別ポストを試す**手順が有効。
- 個別ポストが取れない場合の代替として、**Exa の `web_search` が有効**だった。ChatGPT for Teens は AP / BBC / ABC / Engadget / Fox Business が公式ブログと OpenAI 担当者の発言を引用しており、突き合わせで内容を再構成できた。ただし二次ソース由来であることは記事本文に明記する。
- **OpenAI の公式 URL に表記ゆれがある。**Pacing のポストは `openai.com/news/` 一覧上のリンクと、Exa が返した正規 URL（`openai.com/index/pacing-model-development-cyber-capabilities`、末尾スラッシュなし）が異なる。CodeAI も `partnering-with-codeai/` が正規で、一覧のアンカーテキストから推測した `partnering-with-codeai-to-prepare-the-first-ai-generation/` では 404 になる。**スラッグは推測せず、検索または一覧から実 URL を取る**。
- **n8n の `stable` / `beta` タグは moving tag。**今回 `beta` が `n8n@2.36.0`、`stable` が `n8n@2.35.3`（2026-08-14）を指していた。`gh api .../releases` の `published_at` だけを見ると `stable` タグ自体が窓内に見えるため、**タグが指す実バージョンと channel を必ず確認する**。
- ユーザー認識ギャップに該当する事例は今回なし。
