## 補足メモ

- **ユーザー認識ギャップ該当: なし。** 本日の実行では `perception-gaps.md` への新規エントリは発生していない。
- **本日の最も実務的な発見は「既定値と展開スケジュールの組み合わせ」である。** Gemini の MCP コネクタは、**既定で有効**かつ **Rapid / Scheduled 両ドメイン即日**という2条件が重なっている。**通常の Workspace 機能には段階展開ぶんの猶予（数日〜2週間）があり、告知を見逃しても対応の時間が取れた。** 今回はそれが無い。**機能の説明より先に「既定値」と「展開スケジュール」を読む**という読み方が、そのまま実害の有無を分ける。日次巡回の価値が最も直接的に出る形の更新である。
- **Cloudflare の自動移行は「設定が黙って読み替えられる」ケースとして記録に値する。** 旧「Block AI Bots」→ 新3設定への移行は、**旧設定より緩い方向**である。**利用者が何も操作していないのに、意図した防御水準が下がる。** 移行の事実そのものは公式に明記されているが、**設定画面を開かない限り気づかない。** 「自動移行された設定は移行後の状態を確認する」という運用則を、教材化メモ側に残した。
- **同じ日に「AI に学習させない設定」（Cloudflare）と「AI に業務データを繋ぐ設定」（Gemini MCP / Salesforce in Claude）が並んだ。** 方向は逆だが、**どちらも「既定値をどこに置くか」が論点**である点は共通している。Cloudflare は既存設定を緩い側へ移行し、Google は新機能を有効側に倒した。**AI 関連の既定値が「開く方向」に倒れる傾向**は、単一ベンダーの方針ではなく業界的な流れとして観察しておく価値がある。
- **`blog.cloudflare.com` の URL スラッグ推測が 404 になった件を、失敗として明記しておく。** 記事タイトルからスラッグを組み立てた（`give-every-teammate-and-agent-the-right-level-of-access-to-your-workers`）が、実際は `workers-granular-authorization` だった。**Cloudflare の blog はタイトルと無関係な短いスラッグを使うことがある。** `source-catalog.md` は OpenAI について「URL のスラッグは推測しない」と定めているが、**この原則は Cloudflare にも当てはまる。** 一覧または検索で実 URL を特定してから記録する。
- **Claude Code `v2.1.273` の判定について、前日と同じ構図が再現した。** この版には **LLM ゲートウェイ向けヘッダー**（組織のコスト可視化に直結）、**Bedrock / Vertex / Foundry の 401/403 修正**、**Bash の複合シェル構文に対する権限判定漏れの修正**が含まれ、内容で判断すれば単独記事の候補になる。**しかし規約どおり機械的な線を維持した。** 2日連続で「内容は重いがバージョンリリースなので D」という判定になっており、**週次ロールアップ側の要点が厚くなっている。** 週次の実効性が、この規約の前提条件である。
