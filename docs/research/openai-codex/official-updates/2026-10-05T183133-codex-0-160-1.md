# 2026-10-05 OpenAI Codex CLI 0.160.1

## 公式内容の日本語要約

Codex CLI の stable 版 **0.160.1** が 2026-10-05T18:31:33Z に公開された。内容は **Bug Fixes 1件のみ**である。

リモート stdio MCP サーバーを、リモート環境変数を明示設定して起動する際に **`SYSTEMROOT` / `TEMP` / `TMP` を保持する**よう修正した。これにより **Unix ホストから Windows のエグゼキュータを使う構成で、Windows 側の起動時環境を維持できる。** changelog では PR #51121 が「Backport Windows remote MCP environment preservation to 0.160」として挙げられており、**0.162 系（alpha）で入った修正の 0.160 系への backport** である。

`learn.chatgpt.com/docs/changelog` 側も同日付で 0.160.1 を掲載しており、内容は一致する。

**窓内の alpha は3本**（`0.162.0-alpha.14` 2026-10-05T02:17:14Z、`alpha.15` 13:23:38Z、`alpha.16` 21:50:17Z）で、規約どおり件数のみ計上し詳細メモは作成しない。

## できるようになったこと

- Unix ホスト + Windows エグゼキュータ構成で、リモート stdio MCP サーバー起動時に `SYSTEMROOT` / `TEMP` / `TMP` が保持される

## 影響範囲

- 対象ユーザー: Codex CLI で**リモート stdio MCP サーバー**を使い、かつ Windows 実行環境を併用している利用者
- 対象プラン: Codex CLI（stable チャネル）
- API / UI / 管理者機能: CLI（MCP サーバー起動時の環境変数引き継ぎ）

- 教材として押さえるべきは「MCP サーバーの起動環境は、クライアントの環境をそのまま継ぐわけではない」という一点である。**今回のように OS 固有の環境変数が落ちると、原因が MCP 側か CLI 側か切り分けにくい症状になる。** MCP を扱う教材では、環境変数の引き継ぎ範囲を最初に確認させる手順を入れておくとデバッグが早くなる。
