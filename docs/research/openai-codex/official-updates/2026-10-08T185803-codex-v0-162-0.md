# 2026-10-08 OpenAI Codex rust-v0.162.0（stable）

## 公式内容の日本語要約

stable リリース。GitHub Releases では 2026-10-08T18:58:03Z、`learn.chatgpt.com/docs/changelog` にも同日付でエントリが掲載されている（**前版 0.161.0 でリリース本文が空だった問題は、今回は発生していない**）。

**追加**: **managed Git worktree ツール**。Command Center での**タスクの固定（pinning）**。トランスクリプトのコピーとスクロールの改善。URL のクリック対応。**カスタムプロバイダーの capability 設定**。Code Mode での **opt-in のランク付きツール検索**。

**修正**: サンドボックス起動、`apply_patch` での CRLF 保持、リトライのタイミング、Windows インストーラのチェックサム。ほかに多数の内部変更が列挙されている。

**実務面で目を引くのは2点である。** 1つは **managed Git worktree ツール**で、エージェントが複数の作業を並行させるときに作業ツリーを分ける操作を、エージェント側の道具として持つことになる。本リポジトリの `branch-management.md` が worktree を例外手段として位置づけているのと対照的に、エージェント運用では worktree の管理コストが下がる方向へ動いている。もう1つは **カスタムプロバイダーの capability 設定**で、自前・社内プロキシ経由のモデルを使う構成で、どの機能を使えるかを宣言できるようになる。

同日に **GPT-6.1 Sol の Ultrafast モード**が Codex でも使えるようになったが、こちらはバージョンリリースとは別の独立告知として扱う（詳細メモは ChatGPT / OpenAI 側）。

## 影響範囲

- 対象ユーザー: Codex CLI 利用者
- 対象プラン: Codex CLI 全般
- API / UI / 管理者機能: CLI。Windows 利用者はインストーラのチェックサム修正が該当

## 教材化メモ

- **「エージェントに worktree を管理させる」という運用の実例として記録する価値がある。** 人間の運用では worktree は並行作業が必要なときの例外手段だが、**エージェントが複数タスクを並行させる前提だと、作業ツリーの分離は標準装備に寄る。** 人間向けの運用ルールとエージェント向けの運用ルールが分岐する具体例である。
- **カスタムプロバイダーの capability 設定は、社内プロキシ経由で LLM を使う構成の教材に使える。** 「このプロバイダーはツール呼び出しに対応しない」を宣言できないと、失敗してから気づく。**能力の宣言を設定に持たせる**という設計は、自社のラッパーを書くときにも効く。
- **`apply_patch` の CRLF 保持は、Windows 混在チームの地味な落とし穴の実例である。** 改行コードが勝手に変わるとレビューの差分が膨らむ。
