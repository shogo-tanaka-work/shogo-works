# 2026-10-09 OpenAI Codex CLI 0.162.1

## 公式内容の日本語要約

バージョン番号付きリリースのため**単独記事化はせず**、週次ロールアップへ送る。本リリースは **Bug Fixes のみ**の2件である。

1. **TUI のクラッシュ修正。** 非同期の質問が複数行にまたがるとき、ターミナル UI がクラッシュしなくなった。改行とハイパーリンクの完全な宛先が保持される（PR #51866）。
2. **起動失敗の修正。** 稼働中のバックグラウンドサーバーの feature 設定が CLI の既定値と異なるとき、起動に失敗しなくなった。**互換性チェックの対象を、コマンドラインで明示的に渡された feature override だけに限定**した（PR #52648）。

2番目は、前日の 0.162.0 で入った managed Git worktree まわりの機能追加のあと、**バックグラウンドサーバーを立てたまま CLI を更新した利用者が起動できなくなる**経路を塞ぐものである。日次運用で CLI を頻繁に上げる使い方では当たりやすい。

同じ窓の中で alpha も進んでいる（`rust-v0.163.0-alpha.4`、`rust-v0.163.0-alpha.5`）。alpha は規約どおり件数のみ計上し、詳細ファイルは作らない。

## できるようになったこと

- 複数行の非同期質問を含むセッションで TUI が落ちなくなった
- バックグラウンドサーバーを残したまま CLI を更新しても起動できる

## 影響範囲

- 対象ユーザー: Codex CLI の stable 利用者
- 対象プラン: 全プラン
- API / UI / 管理者機能: CLI（TUI / 起動シーケンス）

## 教材化メモ

- **「互換性チェックの範囲を明示指定だけに絞る」という修正は、設定の比較設計の教材になる。** 既定値まで含めて厳密一致を要求すると、片方だけ更新したときに必ず壊れる。**比較すべきは「ユーザーが意図的に指定した差分」だけ**という原則の実例である。
- **日次でツールを更新する運用の落とし穴**として扱える。バックグラウンドプロセスを残したままクライアントだけ上げる構成は、バージョン境界の不一致を生む。
