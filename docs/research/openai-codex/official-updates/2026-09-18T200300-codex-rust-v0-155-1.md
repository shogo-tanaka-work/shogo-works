# 2026-09-18 OpenAI Codex rust-v0.155.1

## 公式内容の日本語要約

**Bug Fixes が1項目だけの stable リリースである。** 内容は「**ローカルの新規 TUI セッションで reasoning summary を既定で無効にする**」で、**reasoning summary に対応していないプロバイダがリクエストを拒否していた**問題の修正にあたる。PR のタイトルは "Restore none as the TUI reasoning summary default" で、**既定値を `none` へ戻す**という位置づけである。

**明示的に reasoning summary を設定している場合は、その設定が引き続き尊重される。** 影響を受けるのは既定値のまま使っている新規ローカル TUI セッションに限られる。

**前日 stable 化した rust-v0.155.0（2026-09-17T23:14Z）のリグレッション修正**と読める形である。0.155.0 は実験的な `/voice`、TUI の推論サマリー、MCP の Touch ID 検証を含む9日ぶりの stable だった。**推論サマリーまわりの既定値変更が、対応していないプロバイダ側で拒否を引き起こしていた**ことになる。**約21時間で修正版が出ている。**

**alpha は窓内に5件**出た（`rust-v0.156.0-alpha.1` 〜 `alpha.4`、`rust-v0.155.0-alpha.9.2`）。規約どおり alpha は詳細ファイル化せず、日次サマリーで件数のみ記録する。

## できるようになったこと

- reasoning summary に非対応のプロバイダ（OpenAI 以外のエンドポイント、自社ゲートウェイ等）を Codex TUI から使える状態へ戻った

## 影響範囲

- 対象ユーザー: Codex CLI の TUI を、reasoning summary 非対応のプロバイダに向けて使っている利用者
- 対象プラン: プラン非依存
- API / UI / 管理者機能: TUI の既定設定

## 教材化メモ

**単独記事にしない（バージョンリリースのため規約により週次ロールアップへ）。**

**「既定値の変更が互換性を壊す」という典型例として扱える。** 機能追加そのもの（推論サマリー）は問題なく、**それを既定で有効にしたこと**が非対応プロバイダで全拒否を生んだ。教材では「新機能をオプトインにするかオプトアウトにするか」という設計判断の章に置く。

**Claude Code v2.1.276 と並べると効果が高い。** 同じ窓の中で、**両ツールとも「非標準のエンドポイント経由で使っている構成」が先に壊れて即日修正されている。** ゲートウェイや代替プロバイダを挟む構成は統制上は正しいが、**ベンダーの検証が薄い経路である**という共通の教訓が、2社の独立した事例で裏づけられる。
