# 2026-09-03 OpenAI Codex rust-v0.153.0

## 公式内容の日本語要約

Codex の stable **`rust-v0.153.0`** が公開された。**バージョン番号付きリリースのため単独記事にはせず、週次ロールアップへ送る**（`selection-rubric.md`「日次リリース型ツールの扱い」）。

**新機能**は次のとおり。

- **Vim モードで `u` による undo と `Ctrl+R` による redo をサポート。** 貼り付けた内容や添付を含め、ドラフト全体が保持される
- **プラグイン CLI が、リモートマーケットプレイスからのプラグインの一覧・インストール・削除に対応した**
- **自動 recap を無効化**しつつ、手動の `/recap` は残す設定が可能になった
- ターミナル UI の履歴で、**パッチ全体、バックグラウンドターミナルの入力、完了した個々のコマンド**を表示するようになった
- **Plus / Team ユーザーへ、残枠が半分を切ったときの警告が約5時間前倒しで出る**ようになった

**バグ修正**では、Guardian（ガードレール）まわりの挙動変更が目立つ。

- 外部 app-server の切断後、**TUI セッションが自動再接続**し、ドラフトとトランスクリプトを保持する
- **Full Access では確認のみの操作に対する Guardian レビューをスキップ**し、**承認モードではバックグラウンドの Guardian スコアリングをスキップ**する
- **Guardian のレビュー履歴が、コンパクション・再起動・ユーザー作成のフォークを越えて保持される**（ロールバック境界は尊重）
- **MCP のツール承認が、選択したアプリアカウント単位にスコープされる**ようになった。macOS で相対パスの MCP 実行ファイルがより確実に起動する
- ロールアウト圧縮が共有履歴を含むようになり、`codex exec resume` が圧縮済みロールアウトを正しく扱う

## できるようになったこと

- Vim モードでの undo / redo
- リモートマーケットプレイスからのプラグイン管理（CLI）
- 自動 recap のオフ設定
- 残枠警告の前倒し（Plus / Team）

## 影響範囲

- 対象ユーザー: Codex CLI 利用者全般。**MCP のツール承認スコープが変わるため、複数アカウントを繋いでいる環境は再確認が必要**
- 対象プラン: 全プラン。残枠警告の変更は Plus / Team
- API / UI / 管理者機能: Guardian レビューのスキップ条件が Full Access / 承認モードで変わる

## 教材化メモ

- **Guardian レビューのスキップ条件が権限モードごとに違う**という設計は、**「安全機構は一律に掛けるとコストが見合わない」**という実例として使える。確認のみの操作にまでレビューを掛ければ遅くなる。**リスクの段階に応じて検査の深さを変える**という考え方は、CI やコードレビューの設計にもそのまま転用できる。
- **MCP のツール承認がアプリアカウント単位にスコープされた**点は、**承認の粒度**の話。「このツールを許可した」が「どのアカウントで」まで含まないと、意図しないアカウントに権限が及ぶ。**権限は主体と対象の組で考える**という原則の具体例。
- **Guardian のレビュー履歴がコンパクション・再起動・フォークを越えて残る**という修正は、**エージェントの監査ログは会話の圧縮とは別のライフサイクルを持つべき**という設計の話。会話を縮めたら承認履歴も消えた、では監査にならない。
- **残枠警告の前倒し（半分を切った時点、約5時間前）** は小さいが、**限界に達してから知らせても手遅れ**という UX 原則の例。業務システムのアラート設計に読み替えやすい。
