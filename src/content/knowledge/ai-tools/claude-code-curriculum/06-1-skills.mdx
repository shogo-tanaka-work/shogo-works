## このレッスンでわかること

第5章では「指示の質を上げる方法」を学びました。この章では一歩進めて、**その指示を毎回書かなくて済むようにします**。

- 同じ指示を何度も書いている状態から抜け出せる
- 自分専用の手順を `/週報` のように短く呼び出せる
- 呼び出さなくても、必要な場面で自動的に使わせられる
- チームで手順を共有する方法がわかる

## なぜ必要か：あなたはもう同じ指示を何度も書いている

ここまでのレッスンを進めてきた方は、こんな経験があるはずです。

- 4-1 の営業レポートを、毎月同じ指示文を打ち直して作っている
- 3-3 のデータ整理を、ファイルが届くたびに同じ手順で頼んでいる
- 「元ファイルは変更しないで」「作業前に件数を教えて」を毎回書いている

**指示が良くなるほど、指示は長くなります。**そして長い指示ほど、毎回書き直すのが面倒になる。ここで多くの人が「面倒だから短く雑に書く」方向へ戻ってしまい、せっかく学んだ精度が落ちます。

**Skills** は、この問題を解決する仕組みです。長い指示を1回だけ書いてファイルに保存し、以降は短い名前で呼び出せます。

## CLAUDE.md との違い

5-1 で学んだ CLAUDE.md と混同しやすいので、先に整理します。

| | CLAUDE.md | Skills |
|---|---|---|
| いつ読まれるか | **毎回、自動で** | **呼び出したとき、または必要と判断されたとき** |
| 何を書くか | いつも守ってほしいルール | 特定の作業の手順、判断の基準 |
| 例 | 「金額は必ず税込で書く」 | 「週報を作る手順一式」「見積書の書き方」 |

**「常に効かせたいこと」は CLAUDE.md、「そのときだけ使いたいこと」は Skills** と覚えてください。両方を組み合わせると、指示がぐっと短くなります。

## 作ってみる：週報 Skill

実際に作ります。やることは「決まった場所にファイルを1つ置く」だけです。

### ステップ1：置き場所を作る

作業フォルダの中に `.claude/skills/` を作り、**Skill ごとにフォルダを1つ**作ります。そのフォルダ名がそのまま呼び出す名前になります。

**対話画面に入力**してしまうのが早道です。

```text
このフォルダに .claude/skills/weekly-report というフォルダを作ってください。
```

> **先頭のドットについて。** `.claude` のように**ドットで始まるフォルダは、Finder やエクスプローラーでは初期状態だと見えません**。「作ったのに見当たらない」と焦らないでください。Claude Code からは普通に見えています。

### ステップ2：中身を書く

そのフォルダの中に `SKILL.md` という名前でファイルを作ります。**名前は固定**です。

**対話画面に入力**します。

```text
.claude/skills/weekly-report/SKILL.md を作ってください。中身は次のとおりです。

---
description: 今週の営業週報を作る。売上CSVから商品別・担当者別に集計し、前週比を出す
---

指定されたファイルを読んで、今週分の営業週報を作ってください。

【手順】
1. 元ファイルは変更せず、読み取りだけにする
2. 集計する前に、対象データの件数を教える
3. 商品別・担当者別の売上を集計する
4. 前週と比べて増減が大きい項目を3つ挙げる

【成果物】
- report-今週の日付.md として保存
- 集計値は本文にも数字で書く（グラフだけにしない）

【注意】
- 数字が合わない箇所があれば、勝手に補わず質問する
```

上の `---` で囲まれた部分を **フロントマター** と呼びます。ここに書く `description` が、後で効いてきます。

### ステップ3：呼び出す

`.claude/skills/` の下に置いたファイルは、すぐ反映されます。**対話画面に**こう入力してください。

```text
/weekly-report sales.csv
```

さきほど書いた長い指示が、そのまま実行されます。**これだけです。**

**フォルダ名がコマンド名になります。**`weekly-report` というフォルダを作ったので `/weekly-report` になりました。

うまくいかないときは `/help` でコマンド一覧を表示し、`weekly-report` が載っているか確認してください。

## 呼ばなくても使わせる

ここからが Skills の本領です。

さきほどは `/weekly-report` と明示的に呼びました。しかし**呼ばなくても、Claude Code が自分で「今これを使うべきだ」と判断して使ってくれます**。

その判断材料になるのが `description` です。

### 試してみる

`/weekly-report` とは言わずに、**対話画面に**こう頼んでみてください。

```text
sales.csv から今週の営業週報を作ってください。
```

さきほど書いた手順（件数を先に報告する、前週比の上位3件を出す、など）がそのまま適用されていれば成功です。返答の中に、どの Skill を使ったかが表示されます。

### だから description が最重要

**`description` が曖昧だと、必要な場面でも呼ばれません。**

| Bad | Good |
|---|---|
| `description: 週報のルール` | `description: 今週の営業週報を作る。売上CSVから商品別・担当者別に集計し、前週比を出す` |

**「いつ使うものか」が読み取れるように書いてください。**キーワード（週報、売上、集計、前週比）を含めるのがコツです。

## 何を Skill にすべきか

迷ったときの目安です。

**Skill 向き**

- **他の人に説明したことがある**もの（新人への引き継ぎ内容がそのまま候補）
- **間違えられると困る**もの（金額・宛名・締め日）
- **自分の会社や業界に固有**のもの

**Skill 向きでない**

- 一度きりの作業（そのまま指示すればよい）
- **常に必ず守ってほしいこと** → 5-1 の CLAUDE.md

### 手順だけでなく「判断の基準」も預けられる

非エンジニアの業務では、**手順よりも判断の基準のほうが多い**はずです。

- 「この取引先は敬称を『御中』ではなく『様』にする」
- 「請求書の日付は締め日基準、納品書は納品日基準」
- 「社外向け文書では『弊社』、社内向けでは『当社』を使う」

こういうものは、いつ必要になるか事前に分かりません。その都度説明するか、毎回間違いを直すかの二択だったはずです。**Skill にしておけば、必要な場面で自動的に効きます。**

たとえば「見積書の書き方」を Skill にしておくと、「A社向けの見積書を作って」と頼んだだけでルールが適用されます。

## どこに置くかで共有範囲が変わる

置き場所によって、誰が使えるかが決まります。

| 置き場所 | 使える範囲 |
|---|---|
| `作業フォルダ/.claude/skills/` | **そのフォルダで作業する全員**。チームで共有される |
| `ホームフォルダ/.claude/skills/` | **自分だけ**。どのフォルダで作業しても使える |

「経理フォルダ専用の締め処理」は前者、「自分がいつも使う議事録整形」は後者、という使い分けになります。

チーム共有については 11-2 で改めて扱います。

## 最初から入っている Skill もある

自分で作らなくても、Claude Code には最初からいくつかの Skill が入っています。`/help` で一覧を見ると、自分が作った覚えのないコマンドが並んでいるはずです。

**まず `/help` を眺めて、使えそうなものがないか確認する**習慣をつけてください。自分で作る前に、既にあるかもしれません。

## よくあるつまずきと対処法

### Skill が一覧に出てこない

3つ確認してください。

1. **フォルダ構成は合っているか** — `.claude/skills/<名前>/SKILL.md` という形です。`.claude/skills/<名前>.md` では認識されません
2. **ファイル名は `SKILL.md` か** — 大文字です
3. **場所は合っているか** — 対話画面で「.claude/skills の中身を見せて」と頼めば確認できます

### 呼べばできるが、自動では使われない

`description` の問題です。「いつ使うか」が読み取れる文になっているか見直してください。

確認のしかたとして、**対話画面で直接聞く**のが早道です。

```text
いま使える Skill を一覧で教えてください。
どんなときに weekly-report が使われますか？
```

意図と違う答えが返ってきたら、`description` を書き直します。

### 逆に、使ってほしくないときにも使われる

`description` の範囲が広すぎます。「文書を作るときのルール」のように広く書くと、関係ない場面でも引っ張られます。**対象を具体的に絞ってください。**

### 実行したら想定と違うことをした

Skill の中身は「そのまま実行される指示文」です。**曖昧な部分があれば、毎回ぶれます。**5-2 で学んだ5大原則をそのまま適用して、書き直してください。

うまく動いた Skill は、**そのまま資産になります**。育てる価値があります。

> **※ Skills の仕様は変化が早い分野です。**うまくいかないときは公式ドキュメント（code.claude.com/docs）で最新の書き方を確認するか、エラー内容をそのまま対話画面に貼って聞いてください。

## 補足：`.claude/commands/` を見かけたら

古い記事や社内の資料で、`.claude/commands/` にファイルを置く「カスタムスラッシュコマンド」という書き方を見かけることがあります。

**これは Skills に統合されました。**公式ドキュメントには次のように書かれています。

> Custom commands have been merged into skills.（カスタムコマンドは Skills に統合されました）

`.claude/commands/` に置いた既存のファイルは**今も動きます**が、これから作るなら Skills を使ってください。公式も Skills を推奨しています。同じ名前が両方にある場合は Skills が優先されます。

## やってみよう

1. **棚卸し**：ここまでのレッスンで自分が書いた指示のうち、「2回以上似た内容を書いた」ものを1つ選びましょう
2. **Skill 化**：それを `.claude/skills/<名前>/SKILL.md` として保存し、`/名前` で呼び出して同じ結果になるか確認してください
3. **自動起動を試す**：Skill 名を出さずに関連する作業を頼み、自動で適用されるか確認しましょう
4. **description を壊してみる**：`description` をわざと「ルール集」だけに書き換えて、**自動では呼ばれなくなること**を確認してください。確認したら元に戻します
5. **既存の Skill を見る**：`/help` で最初から入っている Skill を眺め、使えそうなものを1つ試してみましょう

演習4は、`description` が仕組みの心臓部だと体感するための練習です。

## まとめ

- 良い指示ほど長くなる。**長い指示を毎回書き直さないための仕組み**が Skills
- 実体は `.claude/skills/<名前>/SKILL.md`。**フォルダ名がそのまま呼び出す名前**になる
- `/名前` で呼び出せるうえに、**呼ばなくても必要な場面で自動的に使われる**
- **`description` が最重要。**「いつ使うか」が読み取れないと自動では呼ばれない
- CLAUDE.md は「常に効くルール」、Skills は「そのときだけ使う手順・判断基準」
- 作業フォルダに置けばチーム共有、ホームフォルダに置けば自分専用
- **他の人に説明したことがある内容**は、そのまま Skill の候補になる
- 古い `.claude/commands/` は今も動くが、これから作るなら Skills

## 理解度チェック

**Q1. CLAUDE.md と Skills の使い分けとして、最も適切なものはどれでしょう？**

1. CLAUDE.md は無料プラン用、Skills は有料プラン用
2. CLAUDE.md は毎回自動で読まれるルール、Skills はそのとき必要な手順や判断基準
3. CLAUDE.md は個人用、Skills はチーム用
4. どちらも同じ機能で、書き方が違うだけ

<details>
<summary>答えを見る</summary>

**正解：2**

CLAUDE.md はセッション開始時に自動で読み込まれ、その作業中ずっと効き続けます。Skills は `/名前` で呼び出すか、Claude Code が必要と判断したときに使われます。「金額は税込で書く」のような常時のルールは CLAUDE.md、「週報を作る手順一式」のような特定作業は Skills が向いています。共有範囲はどちらも置き場所で決まるため、3 は誤りです。

**Q2. 作った Skill が、呼び出せば動くのに自動では使われません。最初に見直すべき箇所はどれでしょう？**

1. `description` に「いつ使うものか」が書かれているか
2. 本文の文字数が足りているか
3. ファイルサイズが大きすぎないか
4. Skill の数が多すぎないか

<details>
<summary>答えを見る</summary>

**正解：1**

Claude Code は `description` を読んで、その場面で使うべきかを判断します。「週報のルール」のように曖昧だと、どの場面で必要なのか判断できず呼ばれません。「今週の営業週報を作る。売上CSVから商品別・担当者別に集計し、前週比を出す」のように、対象とキーワードを含めて具体的に書いてください。

</details>
