このシリーズが目指すのは、**「AIは危険だから使わない」でも「大手の製品だから安全」でもない状態** だ。リスクがどこにあるのかを分解し、使う人自身が毎回判断できるようにする。

[AI導入ガバナンス解説](/knowledge/ai-governance/guide/) がルールを **作る側**（統制・法律・組織設計）の話であるのに対し、こちらはルールの **中で日々AIを使う側** の話になる。対になる位置づけとして読める。

## 5つの確認点 — これがシリーズの骨格

AIの利用で「何が危険か」を漠然と考えても判断はできない。確認する場面を5つに分けると、自分が何を見ればよいかが具体的になる。

| # | 問い | 見る場面 |
|---|---|---|
| ① | **どのAIか** | 使う前 |
| ② | **何を入れるか** | 入力するとき |
| ③ | **何を見られるか** | AIが社内データを読むとき |
| ④ | **回答は正しいか** | 返ってきたとき |
| ⑤ | **使ってよいか** | 成果物として使うとき |

5つは順番に並んでいる。**前を飛ばすと、後ろだけでは事故は防げない**。①を確認しないまま④の検証だけを丁寧にやっても、そもそも情報が社外に出てしまっていれば手遅れになる。

## 安全性は3層で決まる

安全は積み上げで成立する。どの層が欠けても事故は起きる。

1. **提供元の層** — 基盤側のデータ保護・暗号化・アクセス制御
2. **会社の層** — 承認するAI、情報分類、アクセス権、監査・保持のルール
3. **利用者の層** — 何を入力するか、回答をどこまで信用するか、最後に何を人が決めるか

このシリーズが扱うのは主に **3番目の層** だ。2番目の層をどう設計するかは [AI導入ガバナンス解説 第2回](/knowledge/ai-governance/guide/02-governance/) が担う。

なお、AI利用は既存の情報管理に **入出力の経路が一本増えたもの** と考えるのが実務的に扱いやすい。AI専用の別世界のルールを作る話ではない。

## このシリーズの前提

- **一律禁止にしない** — 「AIに顧客情報を絶対に入れるな」では業務が回らない。必要性・環境・保存先の3段階で判断する
- **製品名で覚えない** — 新しいサービスが出るたびに判断できなくなる。承認・アカウント・保護条件・入力情報・ログという確認軸で覚える
- **断定しない** — 「学習されないから安全」「一切追跡できない」のような言い切りは、どちらも判断を誤らせる。範囲を限定して理解する

具体例には **Microsoft Copilot**（旧 Microsoft 365 Copilot）を使うが、第3回・第4回・第6回の大半は製品を問わず成立する。

なお Microsoft は 2026年8月時点で、**Microsoft 365 Copilot を Microsoft Copilot へ、Microsoft 365 Copilot Chat を Microsoft Copilot Chat へ改称** している。移行期のため、画面やライセンス表記に旧名称が残っている場合がある（セキュリティ・コンプライアンス・プライバシーの扱いに変更はない）。

仕様は更新されるため、判断が分かれるものは自社の管理者・責任部門と、最新の公式ドキュメントで確認してほしい。
