## 要約

ChatGPT Release Notes の 2026-08-20 付見出し「Codex and ChatGPT feature updates」に6件が掲載されました。機能の性質としては**「ChatGPT が端末上のより多くのデータに触れる」方向の更新が2件**と、**Codex の共有まわりが1件**、Site 機能が2件、同期が1件という構成です。

最も注意を要するのが **Apple Messages プラグイン**です。Apple silicon の Mac で、ChatGPT デスクトップアプリが iMessage / SMS / RCS の会話を**読み取り・検索**し、Messages 経由でメッセージを**作成・送信**できます。ChatGPT Work と Codex の両方で使えます。既定では送信前に本文と宛先の承認を求める設計です。

ここで重要なのは、公式ドキュメント側に**承認を永続化した場合のリスク、権限の取り消し手順、承認プロンプトを無効化したタスクに関する既知の問題**が明記されている点です。つまり「承認は既定でオンだが、外すこともでき、外した場合に想定外の挙動がありうる」と公式が認めている状態です。個人利用と業務利用が同じ端末で混在している場合、この機能の扱いは事前に決めておくべきものです。

**Computer History の欧州提供**も同じ系統の変更です。EEA・スイス・英国で提供が始まりました。macOS のデスクトップアプリ向けで、既定はオフ、Memories が前提です。ここで help.openai.com と `learn.chatgpt.com` の記載に差があり、前者は「Pro ユーザー向け」、後者は「Pro / Business / Enterprise 向けで、Business・Enterprise は管理者が先に有効化する必要がある」としています。**管理者作業が発生するのは後者の記述**なので、法人で使う場合は `learn.chatgpt.com` 側を見るのが安全です。GDPR 圏で提供が始まったこと自体、データ保護の観点で整理が付いた結果と読めます。

**Codex スレッドの読み取り専用共有**は、macOS デスクトップアプリからローカルの Codex スレッドのスナップショットを共有する機能です。スナップショットは静的で、ツール呼び出しやシェルの入出力は含まれません。**個人アカウントのリンクは URL を知っている全員が開ける**一方、**ワークスペースアカウントのリンクは同一ワークスペースのメンバーに限定**されます。既知のシークレットパターンは伏字化されますが、公式は**パス・差分・画像に機微情報が残りうるため共有前に確認するよう**注意しています。リンクの確認と失効は、データ制御の Shared links から行えます。

残りの3件は ChatGPT Site とアプリの使い勝手です。**Site の URL 変更**は Plus / Pro のオーナー向けで、再デプロイ不要。旧アドレスはルートとクエリパラメータを含めてリダイレクトされ、カスタムドメインは別扱いで変更されません。**Site の共同編集**は同一ワークスペースのアクティブメンバーをエディターとして招待する仕組みで、オーナーが公開範囲・設定・分析・所有権・バージョン復元・エディター管理を保持します。**ピン留めチャットの同期**はデスクトップと iOS が対象で、Android は含まれません。

## 何が変わったか

- **Apple Messages プラグイン**: Apple silicon Mac の ChatGPT デスクトップアプリで iMessage / SMS / RCS を読み取り・検索し、Messages 経由で作成・送信。ChatGPT Work と Codex で利用可。既定で送信前に本文と宛先の承認を要求
- 公式ドキュメントに**承認の永続化リスク、権限の取り消し手順、承認プロンプトを無効化したタスクの既知の問題**を明記
- **Computer History を EEA・スイス・英国で提供**（macOS、既定オフ、Memories 前提）。Business / Enterprise は**管理者が先に有効化**する必要がある
- **Codex スレッドの読み取り専用スナップショット共有**。ツール呼び出しとシェル入出力は含まれない。個人リンクは URL を知る全員が閲覧可、ワークスペースリンクは同一ワークスペース限定。データ制御の Shared links から失効可能
- **ChatGPT Site の URL 変更**（Plus / Pro、再デプロイ不要、旧 URL からリダイレクト、カスタムドメインは別扱い）
- **Site の共同編集**（同一ワークスペースのアクティブメンバーをエディターに招待。オーナーが権限を保持）
- **ピン留めチャットのデスクトップ / iOS 同期**（Android は対象外）

## 業務インパクト（一般企業向け）

**Apple Messages プラグインは、BYOD ポリシーの見直し対象です。** 業務用の Mac で ChatGPT を使っている場合、その端末の iMessage には私用のやり取りが混ざっているのが普通です。プラグインを有効にすると、その会話を ChatGPT が読み取り・検索できる状態になります。逆に、私用 Mac で ChatGPT Work にログインしている場合は、業務の文脈で私用メッセージにアクセスできる状態になります。**「端末の所有者」と「アカウントの所属」が食い違う構成で問題が起きやすい**ため、どちらのパターンが自社に存在するかを先に把握してください。

そのうえで決めるべきは**承認プロンプトの扱い**です。公式が「承認の永続化に伴うリスク」と「承認プロンプトを無効化したタスクの既知の問題」を明記しているということは、承認を外す運用が可能で、かつそこに未解決の問題があるということです。**社内ルールとしては「承認プロンプトを無効化しない」を既定にする**のが妥当だと考えます。有効化そのものを禁止するかは業務内容次第ですが、送信の自動化だけは止めておくほうが事故のコストに見合います。

**Computer History の欧州提供は、管理者作業が発生します。** Business / Enterprise では管理者が先に有効化しない限りメンバーは使えません。裏を返せば、**有効化しなければ現状のままで問題ない**ということでもあります。有効化を検討する場合、Memories が前提である点、既定がオフである点、そして「PC の操作履歴を AI が参照する」という機能の性質を、従業員向けにどう説明するかまでセットで用意してください。GDPR 圏での提供開始は、ベンダー側の整理が付いたことを意味しますが、自社での利用の適法性は別途の判断です。

**Codex スナップショット共有は、既定の共有範囲を確認してください。** 個人アカウントのリンクは URL を知っている全員が開けます。業務のコードについて相談したスレッドを個人アカウントで共有すれば、実質的に公開です。**ワークスペースアカウントを使えばリンクは同一ワークスペースに限定される**ので、法人利用ではワークスペースアカウントの利用徹底が対策になります。シークレットの伏字化は「既知のパターン」に対するもので、社内の独自形式のトークンやサーバーのホスト名、内部パスは残ります。共有前レビューを運用に組み込むか、そもそも共有機能を使わない方針にするかを決めておくべきです。データ制御の Shared links から失効できるので、**定期的に棚卸しする担当を決めておく**と実効性が上がります。

## 副業・個人活用視点

Apple Messages プラグインは、**クライアントとのやり取りが iMessage / SMS に散っている人**には効きます。「あの案件の見積もり、いつ送ったか」を検索して拾い、返信の下書きまで作らせる、という使い方が成立します。ただし**送信の承認は必ず残してください**。宛先を間違えたメッセージは取り消せません。個人事業で相手が少数だからこそ、1件の誤送信の影響が大きいという考え方をしたほうがよいでしょう。

Codex のスナップショット共有は、**成果物の説明手段として使えます**。受託開発で「どう実装したか」を説明するとき、コードだけ渡しても意図は伝わりません。スレッドのスナップショットは、判断の経緯が残った形で渡せます。ただしツール呼び出しとシェルの入出力は含まれないので、実行ログを見せたい用途には向きません。そして**個人アカウントのリンクは URL を知る全員が開ける**ため、クライアントの機密が入ったスレッドをそのまま共有しないよう注意が要ります。共有前に自分で開いて、パスや差分に何が写り込んでいるかを見る手間は惜しまないほうがよいです。

**ChatGPT Site の URL 変更**は、小さいですが実務的な追加です。試作段階で付けた URL を、案件が本決まりになった段階で変えられます。再デプロイ不要で旧アドレスからリダイレクトされるので、既に共有済みのリンクも生きます。カスタムドメインは別扱いなので、独自ドメインを当てている場合は影響しません。Site の共同編集は同一ワークスペース内が条件なので、外部のクライアントを直接エディターに招く用途には使えません。

Computer History は、**個人の Pro ユーザーであれば EEA・スイス・英国でも使えるようになりました**。日本在住なら直接の変化はありませんが、欧州のクライアントと仕事をしている場合、相手側が使えるようになったという前提の変化はあります。既定オフで Memories が前提という点は、勧める側として説明できるようにしておくとよいでしょう。
