## 要約

OpenAI は 2026-10-22、**Decisions API** を一般提供としました。アプリやエージェントが業務の途中で行う「分類する」「どこへ回すか決める」「次に何をするか選ぶ」といった**小さな判断**に特化した API です。モデルは **GPT-6 Luna** で、専用のエンドポイントから使います。

公式は、Responses API 経由の GPT-6 Luna と比べて**最大10倍速い**と説明しています。

## 何が変わったか

- **使い方**: 質問と許される答えを定義し、文脈をテキスト、画像、ネイティブ JSON で渡す
- **答えの3形式**: `predicate`（条件が真である確率）、`choice`（用意した選択肢のどれか。確率と確信度も返る）、`score`（段階評価の重み付き平均）
- **公開ベータからの追加**: GPT-Live とのネイティブ連携、再利用する文脈のプロンプトキャッシュ、米国・EU のデータ所在地指定、JSON 入力、質問への画像添付
- **上限**: 1リクエストで最大400問（従来の2倍）。アジアの複数リージョンで処理能力も追加
- **GPT-Live 連携**: 音声セッションの `session.triggers` に設定すると、会話中の発話から判断結果のイベントが返る。顧客対応で「聞き返す・振り分ける・エスカレーションする」を決める用途を公式は挙げる
- **公式が示した顧客の数値**: Box は証明書類の振り分けで約5倍速く同等精度、Datadog はコマンドのリスク採点で p95 が40倍速く同等精度、Ramp は AI 費用の割り当てで4倍速く30%安価、Sierra は p95 280ms 未満で約3倍速く呼び出し単価90%減

## 業務インパクト（一般企業向け）

**問い合わせの振り分け、書類の仕分け、承認の要否判定のような定型の判断が、会話型モデルより軽い部品に置き換えられる可能性があります。** 現在、そうした判断に大きなモデルを使っているなら、待ち時間と費用の見直し候補になります。

導入前に確認する点は3つです。(1) 自社の分類データで精度が出るか。公式の数値は顧客各社の評価です。(2) 確信度が低いときに人へ回す設計にするか。Box の事例も、低確信度は担当者へ回しています。(3) データ所在地。米国・EU の指定が追加されましたが、日本の要件は本文に記載がありません。

## 副業・個人活用視点

**自作の自動化に「判断の部品」として差し込むと効きます。** たとえばメールを「返信が必要か」「後回しでよいか」に分ける、領収書の画像を勘定科目の候補に分ける、といった処理です。選択肢と確信度が返るため、確信度が低いものだけ自分で見る運用が組めます。

受託の案件では、既存の自動化のうち LLM の呼び出しが遅い箇所を洗い出し、置き換えの提案にできます。ただし料金は本文で確認できていないため、見積もりの前に公式の料金表で確かめてください。
