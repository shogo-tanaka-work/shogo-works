## 要約

OpenAI は2026-10-29、モデルの望ましい振る舞いを公開している **Model Spec** の更新を発表しました。今回の変更は、細かな規則の追加ではなく、**ガイダンス全体を5つの価値で組み直した**ことが中心です。

- **人の意図への忠実さ**: 指示を文字通りに守るだけでなく、OpenAI・開発者・ユーザーが何を大切にしているかを理解し、理解が不完全なときは賢明に動く
- **害の最小化**: 越えない境界を守り、行動の予見できる結果を考慮する
- **誠実さと透明性**: 知っていること、していること、不確かなことについて正直であること
- **人の主体性の支援**: 人が自分で理解し、選び、行動する力を強める
- **配慮**: 影響を受ける人の状況に目を向け、社会的・職業的な規範に従い、頼れる仕事をする

Spec は、これらの価値を実務の指針に落とし込む文書です。守るべき境界は固く定め、それ以外は、ユーザーや開発者が上書きできる既定の振る舞いとして書かれています。

## 何が変わったか

- **新設**: 「人の意図への忠実さ」の節。chain of command（どの指示が適用され、衝突をどう解くか）を更新し、**会話、メモリ、その他の文脈を意図の手がかりとして慎重に扱う**小節（consider context carefully）を追加した
- **追加された既定**: 人の主体性を支える、関連する社会的規範に従う、**副作用の制御と伝達**（既存の指針を拡張）
- **廃止**: 文体に関する詳細な規定の大半。文体は集団・言語圏・個人の好みに合わせ、ユーザーの反応と文脈を証拠にして適応させる。一方、「質問に客観的に取り組む」といった強い既定は残る。特定の視点を取らせたいときは、ユーザーや開発者が明示すればよく、モデルが「聞きたいことを言っているだけ」と推測して寄せてはならない
- **表記**: Spec 内でモデルを「the assistant」ではなく「GPT」と呼ぶ
- **今後**: 価値を理解して適用できるようにする新しい訓練手法を探索中で、結果は後日共有する予定

OpenAI は、**「現在のモデルはこの Spec をまだ十分には反映していない」**と明記しています。Spec は目指す姿の記述であり、現行の挙動の保証ではありません。

## 業務インパクト（一般企業向け）

**まず押さえたいのは、これは製品の機能追加ではなく、挙動の方針の変更だという点です。** 今日から ChatGPT や API の出力が変わると決まったわけではありません。ただし、方針が変われば、数か月かけてモデルの訓練と既定の挙動に反映されていきます。

**社内で ChatGPT のカスタム指示や、API 経由のシステムプロンプトを整備している場合は、次の2点を確認する価値があります。**

- **文体の細かい指定を既定に頼っていないか。** 文体の細則が減るため、トーンや書式を揃えたいなら、自社のプロンプト側で明示するほうが安全になる
- **「副作用を説明させる」要件を入れているか。** エージェント的な作業を任せる場合、副作用の制御と伝達が既定の指針に加わった。承認フローや監査ログの設計で、この前提を使える

**ガバナンスの観点では、5つの価値と chain of command が、AI 利用方針を社内で書く際の参照になります。** OpenAI が公開した枠組みを、そのまま社内ルールにする必要はありませんが、「誰の指示が優先されるか」「何は上書きできないか」を整理する出発点になります。

**注意点**: 本記事は OpenAI の発表文に基づいており、Spec 本文の個々の条文までは確認していません。具体的な既定の変更点は、Spec 本文で確認してください。

## 副業・個人活用視点

**受託や講座で AI の使い方を教えているなら、「AI に指示を出す」ことの説明が変わる点に注意してください。** これからは、指示の文面だけでなく、**文脈（会話、メモリ、添付資料）が意図の読み取りに使われる**ことを前提に教えるほうが実態に合います。

**自分の GPT やプロンプトを配布している人は、既定に任せていた部分を見直しましょう。** 文体や視点の既定が弱まる方向なので、トーン・立場・書式は、明示しておくほうが再現性が上がります。

**公式の言い回しは、そのまま営業や研修の資料に使えます。** 「忠実さ、害の最小化、誠実さ、主体性、配慮」の5語は、AI 活用の社内ルールを説明する際の整理軸として便利です。ただし、Spec は目標であって保証ではない（公式が明記）ことも、併せて伝えてください。
