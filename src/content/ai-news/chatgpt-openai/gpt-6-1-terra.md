## 要約

OpenAI は 2026-10-26、新モデル **GPT-6.1 Terra** を発表しました。公式は「視覚推論と精密なコンピューター操作に、より明快で自然な文章を組み合わせた、速く効率的なモデル」と説明しています。提案書の下書き、技術図面の読み取り、フォーム入力、動画編集のような、仕事の時間の大半を占める作業が想定用途です。

提供範囲は2系統あります。ChatGPT Work と Codex では、Plus / Pro / Business / Enterprise / Edu のユーザーにモデル一覧から選べる形で順次展開されます。API では `gpt-6.1-terra` として使えます。

## 何が変わったか

- **価格**: 標準 API 価格は入力 $1、キャッシュ入力 $0.05、出力 $5（100万トークンあたり）。公式は、GPT-5.6 Terra と GPT-6.1 Sol の標準価格より50%低いとしています。
- **利用枠**: ChatGPT Work と Codex では、同じ利用枠で GPT-5.6 Terra より多くのタスクをこなせ、GPT-6.1 Sol や GPT-6 Astra よりは大幅に多くなると説明されています。プラン全体の上限自体は変わりません。
- **コンピューター操作**: 公式の Agents' Last Exam で、中程度の推論設定では GPT-5.6 Terra より15ポイント高く、コストは約3分の1です。GPT-6 Astra と同等の水準を、トークン単価で約10分の1で出すとしています。タスク完了は GPT-6 Astra や GPT-6.1 Sol の3倍以上速いとされています。
- **コーディング**: Terminal-Bench 4.0 の最大推論設定で 50.3%。GPT-5.6 Terra の公表値 21.5% の2倍超です。ただし最も複雑なコーディングには、引き続き GPT-6.1 Sol と GPT-6 Astra が適すると公式が明記しています。
- **事実性**: 誤りを誘発するプロンプトでの誤り率は、低推論設定で 53.6% から 16.7% に下がりました。最大推論設定では 4.3% です。

数値はすべて OpenAI の自社評価です。条件が異なる他社モデルとの比較（公式は Claude Opus 5.5 との比較も載せています）は、自社の業務データで再確認する前提で読んでください。

## 業務インパクト（一般企業向け）

最も影響が出るのは、**量が多く、1件あたりの価値が小さい業務**です。公式の例は、届いた請求書を読んで会計ソフトに入力する処理です。この種の処理は精度よりも単価と速度で採算が決まるため、入力 $1 / 出力 $5 という価格帯は、これまで人手や安価な旧モデルで回していた領域にエージェントを入れる判断材料になります。

導入判断で押さえる点は3つです。

1. **Sol / Astra の置き換えとは限らない**。公式が最も複雑なコーディングには Sol と Astra を勧めている以上、Terra は「上位モデルを使うほどではない大半の作業」を引き受ける位置づけです。用途ごとに使い分ける前提で、現在 Sol を既定にしている処理から棚卸しします。
2. **ChatGPT Work の既定が変わる場合がある**。ヘルプセンターには、Plus と Pro の一部で、Work の既定の Power プリセットが「Sol の Light」から「Terra の Medium」に表示される場合があると書かれています。利用者から「モデルが変わった」という問い合わせが出る可能性があるため、管理者は周知の文面を用意しておくと安全です。
3. **制約を確認する**。UAE の推論レジデンシーには対応しません（推論が実行される場所に基づく制限で、利用者の所在地ではありません）。また、Preparedness Framework のサイバー領域で Critical 閾値に該当するモデルとして扱われます。規制や社内ポリシーで地域指定がある組織は、導入前に確認してください。

Enterprise では、展開は順次で、ワークスペースの設定やリージョンによって表示時期が異なります。

## 副業・個人活用視点

個人にとっての利点は、**同じ Plus / Pro の利用枠で、試せる回数が増える**ことです。ChatGPT Work や Codex で重めのモデルを使うと枠の減りが早く、作業が途中で止まる経験をした人は多いはずです。日常的な書類作成、フォーム入力、資料の下書きを Terra に寄せ、難しい設計やデバッグだけ Sol / Astra に切り替えると、同じ契約で回せる量が増えます。

API で自作ツールや受託の自動化を組んでいる場合は、請求書、領収書、問い合わせメールの仕分けのような定型処理を `gpt-6.1-terra` で組み直す価値があります。顧客に見せる提案としては、「現行モデルのまま」「Terra へ置き換え」の2案を、実際のサンプル50〜100件の精度とコストで並べるのが現実的です。公式のベンチマーク値は参考に留め、**顧客自身のデータでの測定結果を根拠にする**と説明が通りやすくなります。
