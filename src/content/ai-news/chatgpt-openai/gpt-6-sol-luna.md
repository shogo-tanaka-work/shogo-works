## 要約

OpenAI は 2026-09-22、**GPT-6 Sol** と **GPT-6 Luna** を公開しました。9月初旬に出た GPT-6 Astra と同系統の学習手法で作られた、より速く安いモデルです。

公式の位置づけは「Astra の到達点を、**日常業務の規模・リズム・予算**へ配るためのモデル」。Astra は引き続き最上位として残り、「最良の結果と妥協のない体験が欲しいときに選ぶもの」とされています。

**この発表の中心は性能ではなく価格です。**

| モデル | 入力 | 出力 |
| --- | --- | --- |
| GPT-5.6 Sol → **GPT-6 Sol** | $4 → **$2** | $20 → **$10** |
| GPT-5.6 Luna → **GPT-6 Luna** | $0.20 → **$0.10** | $1.20 → **$0.50** |

（per 1M tokens）

公式の説明は明快です。「**キャッシュと推論をより効率的にし、その節約分を直接お渡しする**」。GPT-5.6 のプロモーション価格と比べて、Sol / Luna とも **API 価格を50%引き下げた**としています。Luna の出力は $1.20 から $0.50 なので、下げ幅は実際には58%です。

**そして同じ日、Anthropic も Claude Opus 5.5 を Opus 5 比20%安で出しました。** モデル価格の前提が、1日のうちに両陣営で動いたことになります。

## 何が変わったか

**性能面は「前世代より上、Astra より下」という位置づけです。**

業務ワークフローを測る **AutomationBench 1.0.6**（営業・マーケ・オペレーション・サポート・財務・人事にまたがる47ツールを使ったエンドツーエンドのタスク）では、GPT-6 Sol の xhigh effort が **33.2%・タスク単価 $0.27**。公式はこれを、Claude Opus 5（max）の 26.9% を **Opus 5 の9%のコスト**で上回った、と表現しています。GPT-6 Astra の low effort（30.3%）も上回ったとしています。

Luna は high effort で前世代比 5.4 ポイント改善、タスク単価は58%低いとしています。

長期的な専門業務を測る **Agents' Last Exam V1** では、Sol の max effort が 56.4%。公式は Claude Opus 5 の同評価での最高スコアを、60%低いタスク単価で上回ったとしています。

コーディングでは、**DeepSWE v1.1** で Sol（max）が 68.8%。Claude Fable 5（xhigh）の 69.9% と1.1ポイント差で、**タスク単価は約80%低い**としています。Luna（max）は 66.6% で、Claude Opus 5 および Fable 5 の medium effort と同程度としています。マージ可能性まで採点する FrontierCode 1.1 Main でも、Sol が GPT-5.6 Sol から大きく改善し、Claude Fable 5.1 の xhigh に低コストで並んだとしています。

**ベンチマークの読み方には注意が要ります。** これらは OpenAI が自社で選んだ比較条件です。公式自身、AutomationBench の Claude Fable 5.1 のデータ点について「**約40%のタスクで発生した Opus 5 フォールバックのコストを含んでいないため、実際のコストを過小評価している**」と注記しています。誠実な注記ですが、裏を返せば比較条件は各社の都合で動く、ということでもあります。

**事実性の改善は、ベンチマークより信用できる形で示されています。** 利用者が実際に「誤りだ」と報告した de-identified な会話をもとにした社内評価で、**GPT-6 Sol の誤りは前世代の約半分**。Astra 水準の信頼性へ近づいたとしています。Luna も高 effort では GPT-5.6 Sol と同等に達し、**コストは約100分の1**としています。公式は「この評価は誤りを誘発する会話の集合で、通常利用を代表しない」とも明記しています。

**提供範囲は当日から広いです。** ChatGPT Work と Codex で Plus / Pro / Business / Enterprise / Edu へロールアウト。API でも Sol / Luna とも利用可能。**Free と Go のユーザーはデスクトップアプリで GPT-6 Luna を試せます。** 利用上限も引き上げられました。

## 業務インパクト

**今日やるべきことは1つです。API を使っているアプリの原価を計算し直してください。**

入力・出力とも半額になったので、モデル名を差し替えるだけでコストが半分になる処理が大量にあるはずです。**特に Luna 帯は桁が変わる水準です。** 出力 $1.20 が $0.50 になったということは、「1リクエストあたり数円」で組んでいた見積もりが「1円台」になるということです。**これまで採算が合わないと判断して見送った自動化が、採算に乗る可能性があります。**

判断の軸を整理します。

**GPT-5.6 Sol / Luna を使っているなら、移行は検討ではなく作業です。** 同系列の後継で、性能は上、価格は半分。移さない理由がありません。ただし**出力の傾向は変わります**。プロンプトを細かく調整して形を固定していた処理は、移行後に出力を突き合わせてください。特に**事実性が改善されたということは、以前なら断定していた場面で留保を付けるようになる可能性がある**ということです。パース処理を挟んでいるなら影響します。

**Astra を使っているなら、そのまま残すべき処理を見極めてください。** 公式は「最も要求の厳しい重要なプロジェクトは引き続き Astra の深さを必要とする」と書いています。全部を Sol へ落とすのではなく、**タスクごとに必要な深さを測って振り分ける**のが正しい形です。AutomationBench で Sol の xhigh が Astra の low を上回った、というのは「effort の設定次第で順位が入れ替わる」という意味でもあります。

**effort レベルの設計が、これまで以上にコストに効きます。** Sol の xhigh、Luna の high、というように、公式の比較はすべて effort とセットで語られています。**モデルを選ぶことと effort を選ぶことは、別々の意思決定です。** 単価が下がった分、「high で回して精度を取る」という選択が現実的になった処理もあります。

**コーディングエージェントの運用コストは、ここ数か月で最も動いた領域です。** 公式は自社の内部利用について、API 価格換算で**日次トークン利用が研究者の中央値で $600 超、90パーセンタイルで $7,000 超**という数字を出しています。これは「エージェントを本気で使うとこの規模になる」という参考値です。**Codex を業務へ入れる際の予算感を、この桁で考えておく必要があります。**

**そして最も重要なのは、価格が半年ごとに半分になる前提で設計することです。** Anthropic が同日に20%、OpenAI が50%下げました。**今日の単価を固定値として埋め込んだ設計は、半年後に見直しコストを生みます。** モデル名と単価は設定として外に出しておいてください。

## 副業・個人活用視点

**Free / Go ユーザーがデスクトップアプリで Luna を試せるようになったのは、入口として大きいです。** 「まず触ってみる」の対象が上位世代になりました。人に勧めるときの導線が短くなります。

**個人開発者にとっては、Luna の単価が最大のニュースです。** 入力 $0.10 / 出力 $0.50 per Mtok というのは、**個人の趣味プロジェクトでも課金を気にせず回せる水準**です。自分用の要約ボット、メモの整理、コードレビューの下書き——これまで「動くけど毎月数千円かかるから止めた」ものが、数百円の領域へ落ちます。

**受託・副業では、見積もりの作り直しが仕事になります。** GPT-5.6 系で原価計算した提案書は今日から古い。**原価が半分になったことを顧客へ伝えるか、利幅として持つかは経営判断**ですが、知らずに古い単価で出し続けるのは避けてください。逆に、**すでに納品済みの案件で「月額のAPI費用」を見積もっている場合、こちらから連絡して下げる**のは信頼を作る動き方になります。

**提案の幅も変わります。** 「予算的に無理」で流れた話を、もう一度持っていける。特に**大量処理系（全件の分類、全ログの要約、全問い合わせの一次応答）**は、単価が支配的なので効きが大きい領域です。

**ただし、安くなったから雑に使ってよいわけではありません。** 単価が下がると総使用量は増えます。**上限を設けずに回すと、半額になったはずが総額は増える**という結果になりがちです。処理件数の上限、リトライの回数、入力トークンの長さ——この3つは単価と無関係に効きます。

**情報発信の題材としては、「同じ日に OpenAI と Anthropic が両方値下げした」という事実そのものが語りどころです。** 推論効率の改善が価格へ戻される流れが常態化しているなら、**読者に伝えるべきはモデルの優劣ではなく、「単価は下がり続けるので、単価前提の設計は寿命が短い」という構造の話**です。
