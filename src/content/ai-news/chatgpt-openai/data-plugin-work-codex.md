## 要約

OpenAI は 2026-09-10、ChatGPT Release Notes で **Data プラグイン** を公開しました。ChatGPT Work と Codex から、**接続済みの業務データを分析する** ためのプラグインです。

使い方は単純です。プラグインディレクトリから Data をインストールし、会話で **`@Data`** を指定して話しかけます。ビジネス上の問いを投げる、数字の変化の原因を調べる、インタラクティブなダッシュボードやレポートを作らせる、といった用途が公式に挙げられています。一度で終わらせる必要はなく、**フォローアップの質問で分析を絞り込めます。**

この機能で注目すべき点は、分析能力そのものより **2つの設計判断** にあります。

**1つ目は、チーム固有のメトリクス定義とビジネスコンテキストを持ち込めること。** 「売上」「アクティブユーザー」「解約率」といった指標の定義は組織ごとに違います。会計基準の違い、計上タイミングの違い、除外するセグメントの違い。**この差異を吸収できなければ、LLM が出す数字は「それっぽいが自社の定義ではない数字」になります。** Data プラグインは、その定義を明示的に渡せる設計になっています。

**2つ目は、クエリが接続アカウントの既存権限で実行されること。** 公式に明記されています。プラグインが独自に権限を広げるのではなく、**接続元のアクセス制御がそのまま効きます。** 見えないはずのデータは、プラグイン経由でも見えません。接続先によっては別途セットアップや認可が必要です。

**この2点は、業務データに LLM を当てるときに必ず問題になる箇所です。** 「定義が合わない」と「権限が漏れる」は、社内導入が止まる二大理由と言っていい。そこに最初から答えを用意してきた、という位置づけの機能です。

## 何が変わったか

- **Data プラグイン**がプラグインディレクトリから利用可能に（ChatGPT Work / Codex）
- 会話内で **`@Data`** を指定して起動する
- 接続済み業務データに対する質問、変化の原因調査、**インタラクティブなダッシュボード・レポートの生成**
- **フォローアップ質問**による分析の絞り込み
- **チームのメトリクス定義・ビジネスコンテキストの持ち込み**に対応
- **クエリは接続アカウントの既存権限で実行される**（プラグインが権限を拡張しない）
- 接続先によっては別途セットアップ・認可が必要

## 業務インパクト（一般企業向け）

**まず効くのは、BIツールへの「軽い依頼」が減ることです。**

多くの組織で、データ分析の依頼は2層に分かれています。ダッシュボードとして作り込む重い依頼と、「先月これ何で落ちたんだっけ」という軽い問い合わせ。後者はダッシュボードにするほどでもなく、しかしデータ担当者の時間を確実に削っています。**Data プラグインが刺さるのはこの層です。**

一方で、導入前に**メトリクス定義の棚卸し**が必要になります。プラグインが定義を持ち込める設計になっている以上、**持ち込む定義が存在しなければ効果は出ません。** 「うちの売上の定義はこれ」と言える状態になっているかどうかが、そのまま出力精度になります。定義が部署ごとにバラバラな組織では、プラグイン導入より先にその整理が仕事になります。

**情シス・セキュリティの審査論点は、接続アカウントの権限設計に集約されます。** プラグインが権限を広げない仕様なので、審査すべきは「どのアカウントで接続するか」です。ここで広い権限を持つ管理者アカウントを使うと、**プラグインの仕様が安全でも運用で穴が空きます。** 接続用に最小権限のアカウントを用意する、という定石がそのまま当てはまります。

監査面では、**「誰がどのデータに何を聞いたか」のログがどこに残るか**を確認しておく必要があります。公式リリースノートはこの点に触れていないため、導入時に確認する項目として立てておくのが安全です。

## 副業・個人活用視点

**個人やスモールチームでは、「ダッシュボードを作らない」という選択が現実的になります。**

副業や個人事業の規模だと、売上・原価・稼働時間のデータはスプレッドシートやSaaSに散らばっているのが普通で、BIツールを立てるほどの量はありません。かといって毎月手で集計すると、それ自体が時間を食う。**`@Data` で聞いて答えが返るなら、ダッシュボードを作る工程を丸ごと省ける可能性があります。**

案件としては、**「メトリクス定義の整理」が単体で売れる仕事になりえます。** プラグインを入れるのは顧客側でもできますが、指標の定義を揃える作業は業務理解が要ります。AIツール導入支援の文脈で、「ツールを入れる前にやること」として提案できる形です。

教える立場では、**`@Data` は「権限を超えないAI」の分かりやすい実例** です。「AIに社内データを渡すと何でも見えてしまうのでは」という質問は研修で必ず出ますが、この機能は接続アカウントの権限に従うと公式に明記されています。**仕様の話として説明できる材料が増えたことの価値は、機能そのものとは別にあります。**
