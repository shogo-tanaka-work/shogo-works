## 要約

OpenAI は 2026-09-10、**ChatGPT Library の接続先に Box、Dropbox、SharePoint を追加**しました。従来の Google Drive に3つが加わった形です。

接続すると、利用可能なファイルとフォルダを **ブラウズおよび検索** でき、**`Add from Library`** または **`@メンション`** で会話に持ち込めます。**再アップロードは不要です。**

対応形式のファイルは **会話の横にプレビューを開いたまま** 作業でき、引用から出典へ辿れます。ファイルを開いたまま、要約・分析・比較・そこからの新規作成を ChatGPT に依頼できる、というのが公式の説明です。

**フォルダ単位の指定にも対応しています。** フォルダを選んで「この配下のファイル全体に対して作業して」と指示できます。ファイルは元のソースに紐づいたままなので、原本へ戻るのも容易です。

### 提供範囲

Web 版の **Chat / Work 両方** で、**Go、Plus、Pro、Business、Edu、Healthcare、Enterprise** へ順次展開中です。**モバイル対応は後日** とされています。

そして統制上の重要点として、**既存のファイル権限とワークスペース統制がそのまま適用されます。**

## 何が変わったか

- ChatGPT Library の接続先に **Box / Dropbox / SharePoint** を追加（既存の Google Drive に加えて）
- ファイル・フォルダの **ブラウズと検索**
- **`Add from Library`** / **`@メンション`** による会話への取り込み（**再アップロード不要**）
- 会話の横での **ファイルプレビュー** 表示と、引用から出典への遡及
- **フォルダを選んで配下ファイル全体** を対象にした指示
- ファイルは **元のソースに紐づいたまま**
- 対象: Web 版の Chat / Work、**Go / Plus / Pro / Business / Edu / Healthcare / Enterprise**（順次展開）。モバイルは後日
- **既存のファイル権限とワークスペース統制が適用される**

## 業務インパクト（一般企業向け）

**この更新が本当に効くのは、シャドーIT対策としてです。**

ChatGPT に社内ファイルを読ませたいとき、これまで多くの人がやっていたのは **「SharePoint からダウンロードして、ChatGPT にアップロード」** でした。この操作には2つの問題があります。1つは、ファイルが管理下のストレージから離れて個人の端末を経由すること。もう1つは、**アップロードされた時点で元の権限設定が切れる**ことです。共有範囲が限定された資料でも、アップロードしてしまえば会話の中では自由に扱えてしまう。

**今回の対応は、この経路を正面から塞ぎます。** 再アップロードが不要で、かつ既存のファイル権限がそのまま効くのであれば、**「わざわざダウンロードする理由」がなくなります。** 禁止して守らせるのではなく、正規の経路を用意して不要にする形です。

**情シスの論点は、追加の権限設計ではなく既存権限の棚卸しへ移ります。** ChatGPT 側で新しい権限を設計する必要はありません。代わりに、**SharePoint や Box の既存権限がそのまま AI 経由の可視性になります。** 「実は全社公開になっていた共有フォルダ」のような設定ミスは、これまで気づかれずに済んでいたかもしれませんが、AI で横断検索されると顕在化します。**接続前に既存権限を見直す価値は、接続そのものより大きい可能性があります。**

**フォルダ単位の指示は、業務フローを変える力があります。** 「このプロジェクトフォルダ配下の議事録を全部読んで論点を整理して」という依頼が成立します。1ファイルずつ渡していた頃とは作業の粒度が違います。

**モバイル未対応である点は、展開計画に入れておく必要があります。** 外出先での利用を前提にした運用設計は、現時点ではまだ組めません。

## 副業・個人活用視点

**個人事業では、Dropbox 接続の価値が最も分かりやすいはずです。**

フリーランスや小規模事業者は、顧客ごとの資料を Dropbox や Google Drive で管理していることが多く、**そのまま ChatGPT の作業対象にできる**のは工数が直接減ります。過去の提案書を参照しながら新しい提案を書く、といった作業が1つの会話で完結します。

**顧客データを扱う場合、「元のソースに紐づいたまま」という仕様は説明材料になります。** 顧客の資料をAIに読ませることへの抵抗は根強くありますが、**「ファイルはコピーせず、既存の共有設定がそのまま効く」**という説明は、単なる「安全です」よりはるかに具体的です。ただしこれは ChatGPT 側にデータが渡らないという意味ではないので、**言い過ぎないように書く**必要があります。

**教える立場では、「再アップロードで権限が切れる」という論点が教材になります。** これは ChatGPT に限らず、あらゆるSaaS連携で起きる一般的な問題です。**ファイルをコピーした時点でアクセス制御が元を離れる**という構造は、情報管理の基礎として教える価値があります。今回の更新はその逆パターン、つまり **コピーせずに参照する設計** の実例として使えます。

**副業の受注文脈では、「AI導入前の権限棚卸し」が仕事になりえます。** 接続は簡単ですが、繋いだ瞬間に既存の権限ミスが露出します。**繋ぐ前に見直す**という工程を提案できるかどうかは、ツールに詳しいだけの支援と、業務を分かっている支援の差になります。
