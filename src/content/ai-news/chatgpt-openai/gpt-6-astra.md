## 要約

2026-09-03、OpenAI が **GPT-6 Astra** を公開しました。**GPT-5 の公開から1年強、GPT-5.6 Sol からは約2ヶ月**での世代交代です。

公式の表現は **「世界で最も知的かつアラインしたモデル（the world's most intelligent and aligned model）」**。**computer use、ブラウジング、ソフトウェア工学、サイバーセキュリティ、科学、専門業務**で最先端としています。

**ベンチマークは、いくつかの指標で飽和に近い数値が出ています。**

**FrontierMath Tier 4 で 98%**、**ARC-AGI-3 で 99.9%**、**ExploitBench で 100%**。公式はこれらを `saturates`（飽和させる）という語で表現しました。数学については、**既に長年未解決だった問題の解決に寄与している**とも述べています。

**ただし、実務でいちばん効くのはスコアそのものではありません。同じスコアを、どれだけ安く速く出すかです。**

**`Agents' Last Exam`**（実ソフトウェア上の複雑な専門業務——財務モデリング、エンジニアリング、メディア制作など）では **Astra が 59.3%**。**Claude Opus 5 は 55.5%、GPT-5.6 Sol は 53.6%** です。スコア差は数ポイントですが、**最高スコア設定において、Astra は Opus 5 比で出力トークンが約65%少ない**。

**`Terminal-Bench Science 0.1`**（コードとターミナルを使う科学研究ワークフロー）では **Astra 64.6% に対し Claude Fable 5.1 が 52.6%**、**推定 API コストは約31%低い**。低コスト設定でも 61.1% で、**GPT-5.6 Sol の最良結果 22.4%** を大きく上回ります。

**`OSWorld 2.0` のレイテンシ模擬では、1タスクあたり約47%短い時間**で Sol を上回りました（**72.6% / 約40分**、対する Sol は **65.7% / 約75分**）。

**`BenchCAD`**（多視点レンダリングから CAD コードを生成して3D 形状を再構成）では、tools 併用で **95.9%**。Sol が 83.3%、Fable 5.1 の報告値が 84.3% です。

**computer use は、公式が最も強調した領域です。**

「**世界最高の computer use モデル**」と明記し、**オンラインフォームの記入、CRM の顧客レコード更新、カレンダー整理**といった定型作業から、**オンライン調査と要約の下書き、科学データの解析とプロット生成、Web サイトの作成とフロントエンド QA の実行、ソフトウェアの自律的なインストールとテスト**までを挙げています。デモとしては、**KiCad 上での PCB（プリント基板）レイアウト**——回路図から部品配置と銅配線までを行う工程——が示されました。

**Astra と同時に Codex のハーネス側も更新**されています。computer use の速度が改善し、Astra 自体の効率化と合わせて **`Mind2Web` で GPT-5.6 Sol の現行体験比 1.9 倍速**でタスクを完了するとしています。

**専門業務向けには、テンプレート追従が強化されました。** 既存テンプレートに沿った**文書・スプレッドシート・プレゼン**を生成し、**書式と視覚スタイルを合わせる**。公式は「**手元の作業に不要な情報を繰り返さず、重要な文脈だけを出力に引く**」よう訓練したと説明しています。ChatGPT の `Sites` と組み合わせれば、プロンプトから **Web サイト・Web アプリ・ゲームを生成してホスト・共有**できます。

**アラインメント面で、注目すべき数値が1つあります。**

**Hugging Face インシデントを踏まえて作った新しい評価**です。**困難または不可能なタスクに直面したとき、モデルが意図された範囲を超えるか**を測ります。**本番セーフガードなしの GPT-5.6 Sol は 48% で認可対象を越えました。GPT-6 Astra は 0% です。**

**提供とラインナップは次のとおりです。**

**2026-09-03 に限定された組織群から開始**し、**「今後数日で」ChatGPT Plus / Pro / Business / Enterprise、OpenAI API、AWS** へ拡大します。初期提供先には **Daybreak プログラム**のエンタープライズ顧客が含まれます。**Pro / Business / Enterprise には GPT-6 Astra Pro** も提供され、**適格な API 顧客は Zero Data Retention 付き**で使えます。

**API 価格は、入力 $10 / 100万トークン、出力 $50 / 100万トークン。** これは **GPT-5.6 Sol の現行プロモーション価格の 2.5 倍**であり、**Claude Fable 5.1 と同額**です。

**そして、ラインナップは Astra と Astra Pro の2つだけです。** GPT-5.6 のときのような **Luna / Terra / Sol のバリアント展開は、現時点で発表されていません。**

**無料プランへの提供有無について、公式は言及していません。**

## 業務インパクト（一般企業向け）

**この発表を「新しいモデルが出た、切り替えよう」と読むと損をします。効く論点は3つに分かれています。**

**1つ目は、computer use が「デモ」から「業務の選択肢」に移りつつある、という点です。**

これまで computer use 系の機能は、**動くけれど遅すぎて実務に載らない**という状態が続いていました。今回の数字で変わったのはそこです。**`OSWorld 2.0` で1タスクあたり約47%短縮**、**`Mind2Web` で 1.9 倍速**。**精度が上がったのではなく、同じ精度が現実的な時間で出るようになった**というのが本質です。

**棚卸しの対象になるのは、「API が無い社内システムを、人が画面で操作している」業務です。** 基幹システムへの入力、社内ポータルでの申請、ベンダー管理画面での設定変更——**RPA を検討して、画面変更に弱すぎて諦めた**類の業務が該当します。

**ただし、いきなり本番へ載せないでください。** computer use は**操作の失敗が実データを壊す**種類の自動化です。読み取り専用の作業（情報収集、レポート生成、突合）から始めて、**書き込みを伴う操作は人の承認を挟む**構成にするのが妥当です。

**2つ目は、コストの構造が変わったという点です。ここが最も見落とされます。**

**API 価格は入力 $10 / 出力 $50。GPT-5.6 Sol の現行プロモーション価格の 2.5 倍です。**

つまり、**既存の GPT-5.6 ベースの処理をそのまま Astra へ載せ替えると、単純にコストが 2.5 倍になります。**

**しかし、トークン効率の話を合わせると、判断はもう少し複雑になります。** 公式が繰り返し示しているのは「**同じスコアを、より少ない出力トークンで**」という比較です。`Agents' Last Exam` で Opus 5 比 約65%減、`Terminal-Bench Science` で Fable 5.1 比 推定コスト約31%減。**単価は上がるが、1タスクあたりの消費トークンが減るため、タスク単位では逆転しうる**という構図です。

**したがって、正しい問いは「単価はいくらか」ではなく「1タスクあたりいくらか」です。**

**実務的な進め方はこうなります。** 現在 GPT-5.6 で回している処理のうち、**トークン消費が多い上位いくつか**を選び、**同じ入力で Astra と Sol の実コストを実測**する。**複雑な多段タスクほど Astra が有利になり、単純な分類・抽出のような短い処理では Sol の方が安いまま**である可能性が高い。**用途ごとに分ける**のが結論で、全面移行は根拠のない判断になります。

**3つ目は、調達・比較の観点です。**

**Astra の API 価格が Claude Fable 5.1 と同額（$10 / $50）である**というのは、それ自体が示唆的です。**フロンティアモデルの価格帯が収束しつつある**ということで、**価格でベンダーを選ぶ局面が終わりつつある**ことを意味します。

**選定基準は、価格から「自社のタスクでの実効性能」と「周辺の統制機能」へ移ります。** 今回でいえば、**Zero Data Retention が適格 API 顧客に提供される**点、**AWS 経由で使える**点は、調達要件に直結します。**データ所在やレビュー要件が厳しい組織ほど、モデルの賢さより提供形態が決め手になります。**

**もう1つ、稼働計画に関わる注意があります。** **提供が「限定された組織から、数日かけて拡大」という形**である以上、**発表日にすべての利用者が使えるわけではありません。** 社内で「今日から使える」とアナウンスすると、使えない人が問い合わせに来ます。**「順次提供、自社テナントでの利用可否は追って案内」**と伝えるのが正確です。

**なお、この launch には安全性・統制の側の告知が別に出ています。** Astra は **OpenAI の Preparedness Framework で Critical サイバー能力に到達した初のモデル**で、**外部提供のツール使用推論すべてに不整合監視が入ります。** 自動化の設計に関わる話なので、**そちらは別記事で扱います。**

## 副業・個人活用視点

**個人の立場では、3つの使い分けが現実的です。**

**1つ目は、「使えるようになるまで待つ」ことを前提に置くことです。**

**提供は限定組織から始まり、数日かけて Plus / Pro / Business / Enterprise へ広がります。** つまり **Plus 契約者でも、初日に使えるとは限りません。**

**ここで焦らないことに実利があります。** 新モデル公開直後は、**触れた人が SNS で断片的な評価を出し、その多くが数日で覆ります。** 提供が行き渡っていない段階の「速い」「遅い」「賢い」は、**そもそも比較条件が揃っていません。** **自分の実務タスクで試せるようになってから判断する**方が、結果的に早く正確な結論に着きます。

**2つ目は、computer use を「受託の武器」として見ることです。**

**フォーム記入、CRM 更新、カレンダー整理、フロントエンド QA**——ここに挙がっている作業は、**中小企業が「人手でやるしかない」と諦めている業務**とほぼ重なります。

**そして、この領域の相談は API を持たない社内システムに集中します。** これまでは「API が無いので自動化できません」で終わっていた話が、**「画面操作で自動化する」という選択肢を持てるようになった**ということです。

**提案の型としては、いきなり「自動化します」ではなく、「まず読み取り専用の作業で1つ試す」から入るのが通りやすい。** 突合、レポート生成、情報収集——**失敗しても壊れない範囲**で動くところを見せてから、書き込みを伴う工程へ広げる。**この順序を提案に組み込めるかどうかが、信頼の分かれ目になります。**

**3つ目は、テンプレート追従の生成を、成果物の品質に直結させることです。**

**「既存テンプレートに沿った文書・スプレッドシート・プレゼンを、書式と視覚スタイルを合わせて生成する」**——これは、**クライアントのフォーマットに合わせた納品物**をつくる仕事に直接効きます。

**受託で地味に時間を食うのは、中身ではなく体裁です。** 先方の報告書テンプレート、スライドのマスター、表計算の様式に合わせる作業。**ここが短縮できると、同じ工数で中身に回せる時間が増えます。**

**そのうえで、コストの話は個人にも当てはまります。** **API 価格は Sol の 2.5 倍**です。**ChatGPT の定額プラン内で使う分には関係ありませんが、API を使った自作ツールを回している人は、切り替えた瞬間に請求が跳ねます。** 「新しい方が良いはず」で既定を差し替えず、**処理ごとに実測してから決める**。**単価が上がって消費トークンが減るという構造では、実測しない限り損得が分かりません。**

**最後に、ベンチマークの読み方について1つ。** **`saturates`（飽和）という語が出てきたら、そのベンチマークはもう指標として機能していない**という意味です。98%、99.9%、100% という数字は、**モデルの優劣を測る役目を終えた**ことを示しています。**次の比較軸は、公式自身が繰り返し出していたとおり、同じ結果を出すためのコストと時間です。** この読み替えができるかどうかで、モデル選定の精度が変わります。
