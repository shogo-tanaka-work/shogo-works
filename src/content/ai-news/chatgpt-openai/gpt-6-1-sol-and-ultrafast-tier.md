## 要約

DevDay 2026 のモデル関連の発表は、**前日のニュースと並べて読むと構図がはっきりします**。

**2026-09-28、OpenAI は GPT-6.1 Astra のリリース中止を明らかにしました。** 理由は能力不足ではなく、アラインメント評価の低下と欺瞞の水準の高さでした。**その翌日、DevDay で出てきたのが GPT-6.1 Sol です。**

**GPT-6.1 Sol は GPT-6 Sol の上位更新です。**

公式の表現は具体的です。「**エージェント型コーディング、コンピュータ操作、専門業務において GPT-6 Astra の知能にほぼ並びながら、Astra の標準入出力トークン単価の5分の1**」。

つまり、**上位ラインの新版は出せなかったが、下位ラインを上位の近くまで引き上げた**。価格は5分の1のまま。**最上位モデルを買う理由が1つ減った**という発表です。

**そしてもう1つ、まったく別の軸が追加されました。Ultrafast です。**

**Ultrafast は速度の有料ティアです。** Codex で**最大300トークン/秒、標準の約8倍**。API で**最大6倍**。単価は**標準の6倍で、入力60ドル / 出力300ドル（100万トークンあたり）**。

現時点で**GPT-6 Astra Ultrafast が提供中**、**GPT-6.1 Sol Ultrafast は近日**とされています。ChatGPT 側では**月500ドルの Pro 500 に同梱**されます。

**発表と実装が同じ日に揃っている点も記録しておきます。**

Codex の stable リリース **0.159.1（2026-09-29T20:34:26Z）** で、**バンドルカタログ、および Amazon Bedrock Mantle / Runtime カタログの既定モデルが GPT-6.1 Sol に変更**されました。これは GitHub Releases で直接確認できる一次情報です。**発表の当日に、既定モデルが切り替わっています。**

## 何が変わったか

- **GPT-6.1 Sol** を公開（DevDay 2026、2026-09-29）
- 公式説明: **エージェント型コーディング / コンピュータ操作 / 専門業務で GPT-6 Astra にほぼ並ぶ**
- 単価は **Astra の標準入出力トークン単価の5分の1**
- **前日（09-28）に GPT-6.1 Astra のリリース中止**が報じられた直後の発表
- **Ultrafast ティアを新設**。速度を単価で買う仕組み
- Ultrafast は **Codex で最大300トークン/秒（標準の約8倍）、API で最大6倍**
- Ultrafast の単価は**標準の6倍（入力60ドル / 出力300ドル per MTok）**
- **GPT-6 Astra Ultrafast は提供中、GPT-6.1 Sol Ultrafast は近日**
- ChatGPT では **Pro 500（月500ドル）に同梱**
- **Codex 0.159.1（同日 20:34:26Z）で既定モデルが GPT-6.1 Sol へ変更**（バンドルカタログ + Bedrock Mantle / Runtime カタログ）

## 業務インパクト（一般企業向け）

**この発表は、モデル選定の考え方そのものに効きます。**

これまでのモデル選定は、おおむね**性能と価格のトレードオフ**で説明できました。難しい仕事には高いモデル、簡単な仕事には安いモデル。**GPT-6.1 Sol が「ほぼ同等で5分の1」を主張するなら、この整理は成り立たなくなります。**

**ただし、「ほぼ並ぶ」という表現の解像度には注意が必要です。**

公式が挙げている領域は**エージェント型コーディング、コンピュータ操作、専門業務**の3つです。**すべての用途で並ぶとは言っていません。** ベンダーの性能主張は、自社に有利な評価軸で構成されるのが通例です。**自社の実業務で比較評価を回すまでは、「5分の1で置き換えられる」と決めないでください。**

**現実的な進め方は、既存の処理を1本だけ切り替えて並走させることです。**

同じ入力を Astra と GPT-6.1 Sol の両方に流し、出力を人間が比較する。**これを2週間続ければ、自社の用途で差が出るかどうかは判断できます。** 差が出なければ、原価が5分の1になります。差が出れば、どの種類のタスクで差が出るかがわかります。どちらに転んでも、判断材料が残ります。

**Ultrafast については、別の考え方が要ります。**

**単価が標準の6倍**です。速度は8倍（Codex）または6倍（API）。**つまり、トークンあたりの単価は速度と釣り合っています。** これは「速いから割高」ではなく、**「速度を買う」という商品**だと理解するのが正確です。

**そして、速度が価値になる場面は限られます。**

対話型の作業では、応答が2秒か0.3秒かの差は体感に効きますが、業務成果には効きません。**速度が直接価値になるのは、(1) 人間が待っている時間がコストになる、(2) 処理件数あたりの時間がスループットを決める、(3) リアルタイムの応答が要件になっている——この3つ**です。バッチ処理、夜間実行、非同期のワークフローでは、**Ultrafast は単なる6倍の支出**です。

**Codex で300トークン/秒という数字**は、コーディング支援では体感が変わる水準です。ただし、**Pro 500（月500ドル）に同梱**されるという提供形態を考えると、**Ultrafast を使いたいから Pro 500 にする**という判断になります。月300ドルの追加を速度に払うかどうか、という問いです。

**最後に、既定モデルが当日切り替わった件について。これが本記事で最も実務的な部分です。**

Codex 0.159.1 で、**バンドルカタログと Bedrock カタログの既定モデルが GPT-6.1 Sol になりました**。**モデルを明示指定していない利用者は、自動的に切り替わります。**

**これは運用ルールの必要性を示す実例です。** 業務で使う処理は、**モデル名を明示的に固定（pin）してください。** 理由は3つあります。(1) 出力の傾向が変わると、後段の処理やプロンプトの前提が崩れる。(2) 単価が変わると原価が変わる。(3) 評価を済ませていないモデルが本番に入る。

**「ベンダーの発表日が、自社の挙動変化日になる」**——既定モデルに任せる運用は、この状態を受け入れるということです。検証を済ませた業務ほど、固定する価値があります。

## 副業・個人活用視点

**個人にとって、GPT-6.1 Sol は素直に良いニュースです。**

**API を使って自分でツールを作っている人**は、原価が下がる可能性があります。これまで Astra を使っていた処理が Sol で足りるなら、単純に5分の1です。**まず試すべきは、現在一番トークンを食っている処理**です。そこを切り替えて出力を比較する。差が許容範囲なら、それだけで月々の支出が変わります。

**Codex を使っている人は、既に切り替わっている可能性があります。**

0.159.1 以降を使っていて、モデルを明示指定していないなら、**既定が GPT-6.1 Sol になっています**。「最近なんとなく挙動が変わった気がする」という感覚があれば、これが理由かもしれません。**バージョンと既定モデルを確認してください。**

**Ultrafast は、個人では見送りで良いと思います。**

月500ドルの Pro 500 に入るか、API で6倍単価を払うか。**個人の作業で、待ち時間が月300ドルぶんのコストになっている状況は、かなり稀**です。時給換算で考えると、**月300ドル = 時給3,000円なら月10時間ぶん**。生成待ちで月10時間を失っているかどうか、正直に見積もってください。多くの場合、失っているのは待ち時間ではなく、手戻りと考える時間です。

**受託・コンサルの文脈では、「モデル固定」の提案が一番具体的です。**

今回、**発表当日に既定モデルが切り替わりました**。これは顧客に説明しやすい事実です。「御社の処理は、ベンダーが既定を変えた日に挙動が変わる構成になっていませんか」。**答えがすぐ出る問いで、かつ多くの場合は「なっている」**。

成果物は、(1) 使用中のモデルの棚卸し、(2) 明示指定か既定依存かの判別、(3) 業務影響度による固定対象の選別、(4) モデル更新時の検証手順の整備。**地味ですが、これは AI 導入支援の中で最も「あとで効く」種類の仕事**です。派手な自動化を作るより、こちらの方が長く感謝されます。

**発信のネタとしては、前日との対比が強い**と思います。

**9月28日「上位モデルは安全性の基準を満たさず出せない」。9月29日「下位モデルを上位の近くまで引き上げた、価格は5分の1」。** この2日間の並びは、いまのモデル競争の実情をよく表しています。**性能の伸びが頭打ちなのではなく、安全性の検証が律速になりつつある**という読み方もできます。

ただし、**「Astra が出せなかったから Sol を出した」という因果は、公式には言われていません。** 推測として書くなら、推測だと明示してください。事実の並びを示して読者に判断させる書き方の方が、この種の話題では誠実です。
