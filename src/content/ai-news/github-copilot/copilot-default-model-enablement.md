## 要約

GitHub が Copilot Business / Copilot Enterprise 向けに、一般提供（GA）になったモデルを既定で有効にするポリシーを導入しました。これまで新モデルは管理者が手動で有効化する必要がありましたが、今後は GA になったモデルが既定でオンになります。

スケジュールは2段階です。現時点から 2026-08-25 までは、ポリシーの設定はできるものの発効しません。この期間中はモデルの利用可否が現状のまま変わらないため、影響を確認しながら方針を決められます。2026-08-26 にポリシーが発効し、明示設定のないモデルは「継承された既定値（inherits default）」の扱いになります。

組織が選べるのは2択です。「既定で有効」は、自動ロールアウトを許容できる場合に GitHub が推奨している設定です。「無効」は、2026-08-26 より前と同じく手動承認方式を維持したい場合の選択になります。なお管理者が個別のモデルについて明示的に設定していれば、その選択は常に保持されます。すでに承認済み・拒否済みと明示したモデルが勝手に変わることはありません。

自動有効化の対象外も明示されています。DeepSeek や Kimi K2.7 のようなオープンウェイトモデル、および GitHub のデータ保持契約の対象外となるモデルは、このポリシーによって自動的に有効化されることはありません。

この変更が実務的に大きいのは、直前までの前提が反転する点です。2026-07-28 に Grok 4.5 が Copilot へ追加された際も「Business / Enterprise では管理者がポリシーを有効化する必要があり、デフォルトはオフ」という案内でした。それから1か月後には、GA モデルは黙っていれば使えるようになる、という逆の状態になります。

## 何が変わったか

- GA になったモデルを既定で有効にするポリシーが Copilot Business / Enterprise に導入された
- 現時点から 2026-08-25 まではポリシー設定は可能だが未発効（モデルの利用可否は変わらない）
- 2026-08-26 にポリシーが発効し、明示設定のないモデルは「継承された既定値」の扱いになる
- 組織は「既定で有効」（GitHub 推奨）か「無効」（手動承認方式の維持）を選択できる
- 管理者が個別モデルに明示設定していれば、その選択は常に保持される
- 自動有効化の対象外: オープンウェイトモデル（DeepSeek、Kimi K2.7 など）、GitHub のデータ保持契約の対象外モデル
- 対象は Business / Enterprise のみ（Pro 系は対象外）

## 業務インパクト（一般企業向け）

まず、これは期限のある実務タスクです。2026-08-25 までに方針を決めないと、既定値の側に倒れます。「決めていないので現状維持」が成立しない設計なので、Copilot を Business / Enterprise で運用している組織は、この1か月のうちに管理者間で結論を出す必要があります。

判断の軸は、モデルのベンダー審査を都度やるかどうかです。ここ最近の Copilot は、Gemini 3.6 Flash（07-21）、Claude Opus 5（07-24）、Grok 4.5（07-28）と1週間強で3つのモデルを追加しています。この頻度で個別承認を回し続けるのは現実的ではありません。GitHub が「既定で有効」を推奨しているのは、そうした運用実態を踏まえた提案でしょう。実際、審査が追いつかずに全部オフのまま放置され、開発者が古いモデルを使い続けるという状態が最も望ましくありません。

一方で、コードやプロンプトの送信先が増えることを審査せずに許容できない業種もあります。金融・医療・公共系で、ベンダーごとのデータ取扱い契約を確認してから使うことが手続き上求められる場合は、「無効」を選んで手動承認を維持するのが妥当です。その場合、モデル追加のペースに対して審査プロセスをどう回すかを別途設計しなければ、結局は使えないまま放置されます。

現実的な折衷案は、「既定で有効」を選んだうえで、許容できないベンダーのモデルを個別に明示的に無効化しておくことです。明示設定は保持されると明記されているため、この組み合わせは意図どおりに機能します。ベンダー単位の可否を先に決め、モデル単位の判断は自動に任せる、という運用に落とせます。

オープンウェイトモデルとデータ保持契約対象外モデルが除外されている点は、GitHub 側がリスクの高い区分を先に切り分けていることを意味します。逆に言えば、自動有効化される範囲は「GitHub がデータ保持契約でカバーしている商用モデル」に限られます。審査の観点を整理するとき、この境界は使えます。

## 副業・個人活用視点

Copilot Pro / Pro+ / Max といった個人プランは対象外なので、個人利用者に直接の影響はありません。個人プランではもともと管理者ポリシーの制約がなく、GA になったモデルはモデルピッカーから選べます。

ただし、企業に業務委託で入っている場合は影響を受けます。8月26日以降、クライアント側の組織で急に選択できるモデルが増えることがあります。案件のルールとして「このモデルを使う」と決めている場合、選択肢が増えたことに気づかず別のモデルで作業してしまう可能性があるため、モデルピッカーの表示が変わったら一度確認する習慣を持っておくと安全です。

もう一つの視点は、この変更が示す運用課題そのものが仕事になり得るという点です。モデル追加のたびに管理者が判断を求められる状態を、ベンダー単位の許可方針として整理する作業は、多くの組織で手が回っていません。8月26日という期限があるため、Copilot を導入済みの企業に対しては「今やるべきこと」として提案しやすいタイミングです。AI ツールのガバナンス設計を支援する立場なら、具体的な相談の入口になります。
