## 要約

Claude Code **v2.1.235** が 2026-08-18 に公開されました。前日の v2.1.234 に続くリリースで、**新機能は1点、残りは修正と改善**という構成です。

新機能は **`spellcheck` 設定**です。任意設定で、有効にするとプロンプト入力中に綴りの誤った単語へ下線が付きます。判定にはローカルにインストール済みの **`aspell` / `hunspell` / `ispell`** を使うため、入力内容を外部の校正サービスへ送る必要はありません。逆に言えば、これらが入っていない環境では機能しません。

修正で重要なのは**権限まわりの2件**です。1件目は、権限プロンプトのコメント欄で **Shift+Tab を押すと、欄を閉じる代わりに編集を承認し、さらにセッション全体の編集権限まで付与していた**不具合です。コメントを書きかけて閉じようとした操作が、意図しない権限付与になっていました。2件目は、権限ダイアログの**表示文と「don't ask again」の対象範囲が、実際に付与される権限と常に一致する**ようになった点です。あわせて、内容を完全に表示できない場合は「don't ask again」の選択肢自体を出さないようになりました。**何に同意したのか分からないまま恒久的な許可を出す余地**を潰す変更です。

**クラウドセッション実行中の負荷も下がりました**。`/ultrareview` や `/autofix-pr` をバックグラウンドで動かしている間、イベントストリームを更新のたびに再走査・再描画していた処理をやめ、メモリと CPU の使用を抑えています。

ほかの修正としては、言語サーバーがセッション途中で切断・再接続したときにプロンプトキャッシュ全体が無効化される問題、ターミナル UI で深さ3以上のネストしたマークダウン箇条書きがずれる問題、複数行プロンプトで入力ハイライト（スラッシュコマンド・キーワード・メンション）が数文字ずれる問題、`ctrl+t` で開くタスク一覧がセッション再開時に常に閉じた状態から始まる問題などが直っています。

改善では、macOS / Linux ネイティブビルドの内蔵 `grep` が**病的なパターンでメモリを食い潰さず即座に失敗する**ようになり、`-m N` と `-A/-C` の併用で正しい文脈行を出すようになりました。コンテキスト上限エラーは、auto-compact が無効になっている場合にその旨を伝え、`/config` から再有効化できることを案内します。

## 何が変わったか

- **`spellcheck` 設定を追加**（任意、ローカルの `aspell` / `hunspell` / `ispell` を使用）
- **権限プロンプトのコメント欄で Shift+Tab がセッション全体の編集権限を付与していた不具合を修正**
- **権限ダイアログの表示と付与範囲を一致**させ、完全に表示できない場合は「don't ask again」を出さない
- `/ultrareview` / `/autofix-pr` のバックグラウンド実行時のメモリ・CPU 使用を削減
- 言語サーバーの切断・再接続でプロンプトキャッシュ全体が無効化される問題を修正
- 内蔵 `grep` が病的なパターンで即座に失敗するように。`-m N` と `-A/-C` 併用時の文脈行を修正
- コンテキスト上限エラーが auto-compact 無効を明示し `/config` を案内
- Vim モード: transcript 切り替え（ctrl+o）やパネル閉鎖時に NORMAL モードとカーソル位置を維持
- `SendMessage` がセッション間配送に大きすぎるメッセージを事前に拒否（従来は黙って破棄）

## 業務インパクト（一般企業向け）

**権限まわりの2件は、更新を急ぐ理由になります**。特に Shift+Tab の不具合は、コメント欄を閉じるつもりの操作がセッション全体の編集権限付与につながっていたもので、操作した本人が権限を渡したと認識しないまま進む種類の問題です。エージェントに編集を任せる範囲を組織のルールで決めている場合、ルールの前提が崩れていたことになります。

**「don't ask again」の扱いが厳密になった点も、統制の観点では意味があります**。表示内容と付与範囲が一致するようになり、全容を表示できないときは恒久許可の選択肢を出さなくなりました。開発者が内容を確認しないまま許可を積み上げる経路が1つ減ります。権限の運用ルールを文書化している組織は、この挙動を前提に記述を見直せます。

**クラウドセッションの負荷改善は、並行作業の多い環境で効きます**。`/ultrareview` のような長時間動く処理をバックグラウンドに回しながら手元の作業を続ける使い方では、これまでイベントストリームの再描画が積み重なっていました。開発端末のスペックが揃っていない組織ほど体感差が出る部分です。

`spellcheck` は業務影響としては小さいものの、**外部サービスへ送らずローカル辞書で完結する**設計です。入力内容の外部送信を禁じている組織でも、辞書ツールを配布すれば使えます。

## 副業・個人活用視点

副業で複数案件を並行して回している場合、**クラウドセッションの負荷改善が最も体感しやすい**変更です。レビューや自動修正をバックグラウンドに投げたまま別案件の作業を続けても、端末が重くなりにくくなりました。

**権限ダイアログの修正は、個人利用でこそ効きます**。組織のようなレビュー体制がない分、「よく分からないまま don't ask again を押す」ことのリスクを自分で負うことになります。表示と付与範囲が一致するようになったので、内容を読んで判断できるようになりました。逆に、全容が表示できないケースでは恒久許可が出せなくなるため、都度確認する場面が増えるかもしれません。これは安全側への変更として受け止めるのが妥当です。

`spellcheck` は、クライアントへ渡す文面や仕様の説明をプロンプトに書く機会が多い人には便利です。使うには `aspell` / `hunspell` / `ispell` のいずれかをローカルに入れておく必要があるため、有効にしても下線が出ない場合はまず辞書ツールの有無を確認してください。

`SendMessage` が大きすぎるメッセージを事前に拒否するようになった点も、地味ですが確実な改善です。従来は黙って破棄されていたため、送ったつもりで届いていない状態が起こり得ました。
