## 要約

Claude Code 2.1.239 が 2026-08-21T19:54Z（JST 2026-08-22 04:54）にリリースされました。前版 2.1.238 の約23時間後で、**変更点は60項目を超えます**。大半は修正ですが、コスト表示・移行支援・プラットフォーム対応に実務上の意味がある追加が含まれます。

最も確認が必要なのは **コスト見積もりの修正** です。US-only inference を使うデータレジデンシー構成のワークスペースでは、実際の課金に **1.1倍のプレミアム**が乗ります。これまで Claude Code 内に表示される見積もりはその係数を含んでいなかったため、**表示額と請求額がずれていました**。今回それが反映されます。データ所在地の制約で US-only を選んでいる組織にとっては、これまで見ていた数字が実際より約1割低かったということです。予算の消化率をこの表示で追っていた場合、前提を確認してください。

**`/claude-api upgrade` が追加されました。** Python プロジェクトを `anthropic` 0.x から 1.x へ移行するコマンドです。SDK のメジャーバージョン移行という、手作業だと差分の洗い出しに時間がかかる作業を Claude Code 側から実行できます。1.x では HTTP 層が `httpx` から `httpx2` へ移り、レガシーな Text Completions API や Messages メソッドの `temperature` / `top_p` / `top_k` が削除されているため、移行対象は決して小さくありません。

**Windows でセッション横断メッセージングが利用可能になりました。** これまで macOS / Linux に限られていた機能で、`SendMessage` による複数セッションの連携が Windows でも組めます。あわせて `ListAgents` が自セッションの名前を返すようになり、稼働中のチームメイトも一覧に出るようになりました。Windows を標準環境にしている組織では、これまで使えなかった並行運用のパターンが選択肢に入ります。

プラットフォーム対応では、**Bedrock / Vertex / Foundry など、これまで対象外だった構成でもフルスクリーンレンダラーの案内が出る**ようになりました。**Alpine / musl ビルド**では画像ペースト・クリップボード・音声キャプチャのアドオンが読み込まれるようになり、ビルド種別による機能差が縮んでいます。コンテナ内で musl ベースのイメージを使っている環境に効きます。クラウドセッションでは、claude.ai から同期されたプラグインが `name@synced` として表示されるようになりました。

修正側で目に留まるものを挙げます。**HTTPS プロキシ配下で Bedrock と SSO プロファイルを併用したときの起動ハング**、プロキシが Content-Type ヘッダーを落とす環境での **Bedrock ストリーミング**、**`WebFetch` が期限切れページをセッション中ずっとメモリに保持する問題**、会話が約64KBを超えると**カスタムセッションタイトルが `/resume` から消える**問題。JetBrains IDE のターミナルで Edit / Write が約5秒止まる問題、`PreToolUse` フックで遅延したツール実行が OpenTelemetry のトレースを分断する問題も直っています。

## 何が変わったか

- **データレジデンシー構成（US-only inference）のコスト見積もりに 1.1倍プレミアムが反映**される
- **`/claude-api upgrade`** を追加。Python プロジェクトを `anthropic` 0.x → 1.x へ移行
- **Windows でセッション横断メッセージングが利用可能**に
- `ListAgents` が**自セッション名と稼働中のチームメイト**を返す。自分宛の `SendMessage` はその旨を返す
- **Alpine / musl ビルド**で画像ペースト・クリップボード・音声キャプチャのアドオンが読み込まれる
- Bedrock / Vertex / Foundry など従来対象外だった構成にも**フルスクリーンレンダラーの案内**が出る
- クラウドセッションで claude.ai 同期プラグインが **`name@synced`** 表示に
- 月次上限到達時のメッセージに**セッション／週次上限のリセット時刻**が出る
- 主な修正: HTTPS プロキシ＋Bedrock＋SSO プロファイルでの起動ハング / Content-Type を落とすプロキシ配下の Bedrock ストリーミング / `WebFetch` の期限切れページ保持 / 約64KB超でカスタムセッションタイトルが `/resume` から消える / JetBrains ターミナルで Edit・Write が約5秒停止 / `PreToolUse` フック遅延時の OpenTelemetry トレース分断
- 永続リトライは、組織の支出上限超過とクレジット切れでは即座に失敗するよう変更
- Claude Code on the web: anthropic.com の非 API ホストへのリクエストがネットワークプロキシ経由に

## 業務インパクト（一般企業向け）

**コスト見積もりの修正は、放置できない種類の変更です。** データレジデンシー要件で US-only inference を選んでいる組織は、これまで表示されていた見積もり額が実際の課金より約1割低かったことになります。月次の予算消化率をこの表示で追っていたなら、**過去の実績値をそのまま来期の見積もりに引き写さない**でください。特に、AI 利用のコストを部門別に配賦している場合、配賦の基準にしていた数字がずれていた可能性があります。金額の絶対値が大きい組織ほど、確認の優先度は上がります。

**「見積もりに係数が入っていなかった」という事象そのものが、教訓として読めます。** ツールが表示する数字は、その時点でツールが知っている前提でしか計算されません。請求書と突き合わせる習慣がなければ、ずれは検出されないまま蓄積します。**AI 利用のコスト管理では、ツールの表示ではなく請求実績を正とする**という原則を、この機会に運用ルールに落とし込む価値があります。

**プロキシ配下の修正群は、企業ネットワークで使っている組織に効きます。** HTTPS プロキシと Bedrock と SSO プロファイルの組み合わせで起動がハングする、プロキシが Content-Type を落とすとストリーミングが壊れる。どちらも「社内ネットワークだから起きる」タイプの不具合です。この種の問題は原因の切り分けが難しく、**ツール側の不具合なのか自社のプロキシ設定の問題なのか判断がつかないまま時間を使いがち**です。導入がうまくいっていない環境がある場合は、バージョンを上げてから再度切り分けてください。

**Windows のセッション横断メッセージング解禁は、標準環境が Windows の組織にとって選択肢の追加です。** 複数の Claude Code セッションを並行させ、相互に連携させる運用パターンが、これまで macOS / Linux 利用者に限られていました。ただし、機能が使えることと運用に載せるべきかは別の問題です。**並行セッションの連携は、誰がどのセッションを止めるかという統制の設計とセット**で考えてください。

`PreToolUse` フックで遅延したツール実行が OpenTelemetry のトレースを分断していた問題は、**AI エージェントの実行をテレメトリで監視している組織**には重要です。承認ゲートとしてフックを置いている構成では、まさにその承認待ちの実行が計測から欠けていたことになります。監視の穴が塞がる修正なので、テレメトリのデータを根拠に何かを判断していた場合は、**修正前後で数字が変わる可能性**を織り込んでください。

## 副業・個人活用視点

個人にとって直接効くのは **`/claude-api upgrade`** です。Anthropic の Python SDK を使った小さなツールやスクリプトを持っているなら、0.x のまま止まっているものがあるはずです。1.x では HTTP 層が `httpx` から `httpx2` へ移り、`temperature` / `top_p` / `top_k` といったパラメータが Messages メソッドから削除されています。**手作業だと差分を洗い出すだけで消耗する作業**で、後回しにされがちです。コマンド1つで着手できるなら、動かなくなる前に済ませておく価値があります。

**Alpine / musl ビルドの機能差解消**は、コンテナで作業環境を作っている人に効きます。イメージを小さくするために Alpine を選ぶと、画像ペーストやクリップボードが動かないという制約がありました。**イメージサイズと機能のトレードオフが1つ減った**ということです。開発環境を Docker で固めて案件ごとに切り替える使い方をしているなら、ベースイメージの選択を見直せます。

`WebFetch` が期限切れページをセッション中ずっとメモリに保持していた修正は、**長時間セッションを開きっぱなしにする使い方**をしている人に効きます。前版 2.1.238 でも長時間セッションのメモリリークが修正されており、**2版続けて同じ方向の修正が入っている**ことになります。1日中同じセッションで作業する運用が想定利用に入っている、という信号として読めます。裏返せば、バージョンを上げずに使い続けると既知の問題を踏み続けるということでもあります。

受託の観点では、**コスト見積もりの係数漏れは提案の材料になります。** クライアントに AI 利用の運用費を提示している場合、「ツールの表示ではなく請求実績で突き合わせる」手順を運用設計に含めておくと、こういう事象が起きたときに検出できます。**監視の設計を提案に含める**という一般則の、具体的で説明しやすい実例です。
