## 要約

v2.1.221 の翌日に公開された v2.1.222 は、新機能の追加がほぼなく、修正と挙動変更で構成されています。ただし内容は軽くありません。分離と権限まわりで、運用の前提に触れる修正が 2 件入っています。

1 つ目は **worktree 分離の穴**です。worktree で隔離したセッションと、そこから起動したサブエージェントが、メインのチェックアウトに対して破壊的な git コマンドを実行できていました。worktree を「本体を触らせないための隔離」として使っていた場合、その想定が成立していなかったことになります。修正後は、分離がファイル編集と Bash の両方に、かつ全セッション種別に適用されます。

2 つ目は **PreToolUse の auto-allow hook** です。バックグラウンドエージェントのタスク（要約、compaction、リネーム）で、auto-allow hook がツール制限を迂回していました。hooks でツールの利用範囲を絞っている組織にとっては、制限が効いていない経路が存在していたということです。

安全側の強化も入りました。auto mode では、`SendMessage` で他のエージェントセッションへ送るメッセージが、送信前に permission classifier で評価されるようになりました。エージェント間の連携が増えるほど、「メッセージ経由で制限を回避する」経路が問題になるため、その手当てと読めます。あわせて、`disable-model-invocation` が付いた skill を Claude が呼ぼうとしたときの拒否メッセージが変わり、ワークフローを自前で再現するのではなくユーザーに実行を依頼するよう指示されるようになりました。

運用面で影響が大きいのが **Remote Control の自動起動設定**の変更です。repo 内の `.claude/settings.json` / `.claude/settings.local.json` から**オンにできなくなりました**（オフにすることは引き続き可能）。有効化は `/config` によるユーザースコープ設定のみです。リポジトリ設定で配布していた場合は経路の作り直しが必要になります。

そして **ultraplan 機能が削除**されました。

## 何が変わったか

- worktree 分離を全セッション種別のファイル編集と Bash に適用（隔離セッションとサブエージェントがメインチェックアウトへ破壊的 git コマンドを実行できた問題の修正）
- PreToolUse の auto-allow hook が、バックグラウンドエージェントのタスク（要約 / compaction / リネーム）でツール制限を迂回していた問題を修正
- auto mode で `SendMessage` の内容を送信前に permission classifier が評価
- `disable-model-invocation` の skill を呼ぼうとしたときの拒否メッセージを改善（ワークフローの自前再現ではなく、ユーザーへの実行依頼を促す）
- Remote Control の自動起動は repo-local 設定からオンにできなくなり、`/config` のユーザースコープのみに（オフにするのは repo-local でも可能）
- **ultraplan 機能を削除**
- `/usage` の MCP サーバー按分を修正（呼び出し後の全ターンではなく、実際にツール結果を消費したリクエストのみ）
- `/usage-credits` が Team / Enterprise で、過去のリクエストを却下されたメンバーに「すでに申請済み」と誤表示していた問題を修正
- HTTPS プロキシ配下で起動時の接続チェックがハングして失敗する問題を修正（API リクエストと同じ proxy 対応トランスポートを使用し、明確なメッセージでタイムアウト）
- `ANTHROPIC_BASE_URL` のゲートウェイで、サーバーの keep-alive ping が届いていてもストリームのアイドルタイムアウトが発火する問題を修正
- 組織制限下で `model: opus` 系のサブエージェント / teammate 別名が親モデルへ落ちていた問題を修正（家族内で最新の許可モデルへ段階的に下がる挙動へ）
- claude.ai コネクタが、セッショントークン無効時に「認可が必要」と誤表示される問題を修正（`/login` のヒント表示へ）
- `/diff`、Remote Control のワークスペース diff、web セッションのファイル編集差分が raw git blob を使用（diff driver / textconv を無視）
- ブランチ push 後に作成した PR とセッションが紐づかない問題、実際には完了したレスポンスに「Connection closed mid-response」が出る問題などを修正

## 業務インパクト（一般企業向け）

最優先で確認すべきは worktree 分離です。Claude Code を組織導入する際、「worktree に隔離すればメインの作業ツリーは守られる」という説明で稟議を通しているケースは珍しくありません。この前提が成立していなかった以上、更新は待たずに配布計画へ入れるべき類の修正です。特に、サブエージェントを併用している環境では影響範囲が広がります。

PreToolUse の auto-allow hook の修正も、統制の観点で同じ重さがあります。hooks でツール制限をかけている組織は、「制限が効いていた」ことを前提に監査記録を扱っているはずです。バックグラウンドタスクという、利用者が意識しない経路で迂回が起きていたため、記録の解釈にも影響します。既に運用中の組織は、この修正を単なるバージョンアップではなく、統制の再確認の機会として扱うのが適切です。

Remote Control の設定変更は、配布方法の作り直しを伴います。リポジトリの `.claude/settings.json` に書いて全員に有効化させていた場合、その手が使えなくなります。オフにする方向は引き続き repo-local で可能なので、「組織として一律オフ、必要な人だけ `/config` でオン」という設計に寄せる形になります。方針としてはむしろ整理された変更ですが、既存の配布ドキュメントは書き換えが必要です。

ultraplan の削除は、使っていた組織には手順書の修正が発生します。廃止告知の猶予期間なしにリリースで消えているため、依存していた運用がある場合は代替の検討が要ります。

`/usage` の按分修正は、社内でツール利用実績を MCP サーバー単位で集計している場合に数値が変わります。過去の集計と比較する際は、バージョンの境目を意識する必要があります。

## 副業・個人活用視点

worktree 分離の修正は、複数案件を同じマシンで並行して回している個人にこそ効きます。「案件 A の worktree で作業していたつもりが、メインのチェックアウトに影響した」という事故は、他人のリポジトリを預かっている状況では致命的です。すぐ更新する価値があります。

Remote Control の有効化がユーザースコープのみになった点は、案件ごとの設定を repo に置いている人には手順変更です。ただしクライアントのリポジトリに自分の運用設定を書き込む必要がなくなる、と考えれば整理です。納品物に個人的な設定が混ざるのを避けられます。

HTTPS プロキシ配下の起動時ハング修正は、企業常駐やプロキシ経由の環境で作業する人には実利があります。原因が分かりにくいハングは、それだけで作業時間を溶かします。

`/usage` の按分修正は、時間単価ではなくトークン実費で請求している人には請求根拠の精度に関わります。MCP サーバーを多用する構成では数値が変わる可能性があるため、請求書を出す前に一度確認しておくのが安全です。

ultraplan を実演やワークフローに組み込んでいた場合は、そのまま資料が使えなくなります。講座や記事で紹介していたなら、削除された旨の追記が必要です。
