## 要約

Claude Code v2.1.223 が 2026-08-06 に公開されました。新機能の追加より、**権限まわりの修正**が目を引くリリースです。

修正された内容は具体的で、いずれも「承認ダイアログを回避される」種類の問題にあたります。第一に、細工した Bash コマンドが自身の一部を権限チェックから隠せる問題。関連して、タブや不可視 Unicode を詰めたコマンドが承認ダイアログ上で一部を隠せる問題も塞がれました。**承認画面に表示された内容と、実際に実行される内容が食い違いうる状態だった**ということです。権限承認を運用の砦にしている組織にとって、これは前提が崩れる話なので、更新の優先度は高いと考えるべきです。

さらに、ワークフロースクリプトが動的 `import()` を使ってワークフローサンドボックス外のコードを実行できた問題、エージェント定義の `bypassPermissions` モードが組織の bypass 無効化ポリシーを無視していた問題も修正されました。後者は、管理者が組織全体で禁止したはずの設定が、エージェント定義側から迂回できていたことになります。

管理機能では実用的な追加があります。`strictKnownMarketplaces` と `blockedMarketplaces` に所有者ワイルドカード（`"owner/*"`）が使えるようになり、GitHub org 配下のマーケットプレイスリポジトリを一括で許可・禁止できます。リポジトリを個別列挙する運用は、増えるたびに設定変更が必要で現実的ではありませんでした。また、サーバー配信の管理設定がマシンローカルの `managed-settings.json` や MDM プロファイルの env ブロックを無効化していた問題も修正され、管理者 env はキー単位でマージされるようになりました。

コンテキスト制御にも変更があります。`CLAUDE_CODE_DISABLE_1M_CONTEXT` の対象が「固定リスト」から「1M ネイティブウィンドウを持つすべての Claude モデル」へ拡張されました。新しいモデルが出るたびにリストが追いつかない、という問題への対応です。未知のモデル ID のセッションも想定ウィンドウ内に収めるよう auto-compact が働くようになり、以前の挙動に戻したい場合は `CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1` を指定します。auto-compaction が 200K に抑えられていない場合は起動時に警告が出ます。

コマンド体系では `/review` が `/code-review` のエイリアスになりました。`/code-review` は現在の差分または PR（`/code-review <level> <pr#>`）をレビューし、深いクラウドレビューは `/code-review ultra` です。effort level を省略すると前回指定した level を再利用します。似た名前のコマンドが並立している状態が整理された形です。

そのほか、ワークフローエージェント・フォークしたスキル・スラッシュコマンド・再開したバックグラウンドエージェントが要求したサブエージェントモデルが制限されていて親モデルで動く場合に警告が出るようになり、クラウドセッションでは `claude --teleport <session id>` でローカル継続する方法を示す `/teleport` ヒントが追加されました。ゲートウェイのモデル検出が `vertex_ai/claude-*` や `bedrock/anthropic.claude-*` のようなプロバイダ接頭辞付き ID を隠していた問題も修正されています。

## 何が変わったか

- Bash 権限チェックの回避（コマンド一部の隠蔽）を修正
- タブ・不可視 Unicode による承認ダイアログの表示偽装を修正
- ワークフロースクリプトが動的 `import()` でサンドボックス外を実行できる問題を修正
- エージェント定義の `bypassPermissions` が組織の bypass 無効化ポリシーを無視する問題を修正
- `strictKnownMarketplaces` / `blockedMarketplaces` で `"owner/*"` ワイルドカード指定が可能に
- サーバー配信の管理設定がローカルの `managed-settings.json` / MDM プロファイルの env を無効化する問題を修正（管理者 env はキー単位でマージ）
- `CLAUDE_CODE_DISABLE_1M_CONTEXT` が 1M ネイティブ対応の全 Claude モデルに適用されるように
- 未知のモデル ID でも auto-compact が想定ウィンドウを維持（戻すには `CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1`）
- `/review` が `/code-review` のエイリアスに統合。level 省略時は前回値を再利用
- サブエージェントモデルが制限され親モデルで動く場合に警告表示
- クラウドセッションに `/teleport` ヒント（`claude --teleport <session id>`）
- `vertex_ai/claude-*` / `bedrock/anthropic.claude-*` などプロバイダ接頭辞付き ID がモデル検出に出るよう修正
- 中断系の不具合修正（`/cd` 後のセッション再開が空になる、フォークしたバックグラウンドエージェントが「already resuming」で固まる、不正な診断添付を含む履歴でセッションが毎ターン失敗する、`git push` 出力の解析でまれにハングする）

## 業務インパクト（一般企業向け）

このリリースの受け止め方は、Claude Code の権限運用をどう設計しているかで変わります。

**承認ダイアログを人が確認する運用を採っている組織は、優先度を上げて更新すべきです。** 表示されたコマンドと実行される内容が食い違いうるということは、その運用が守っていたつもりの範囲が実際には守られていなかった可能性がある、ということです。承認する人がどれだけ注意深くても、表示自体が欺かれていれば防げません。更新のアナウンスと、必要なら過去の実行ログの確認まで含めて対応を考える範囲です。

`bypassPermissions` の修正も、管理者にとっては同種の話です。組織ポリシーで禁止したはずの設定が、エージェント定義側から迂回できていたことになります。ポリシーを設定して終わりにせず、実際に効いているかを確認する運用が要る、という一般的な教訓としても読めます。

一方、マーケットプレイスのワイルドカード指定は素直に作業を軽くします。プラグインの利用を組織で管理している場合、リポジトリを個別列挙する方式は追加のたびに設定変更が必要で、運用が追いつきません。`"owner/*"` で org 単位を許可・禁止できるようになれば、「社内 org は許可、それ以外は禁止」という単純な方針をそのまま設定に落とせます。ポリシーが単純であるほど守られやすい、という点でも意味があります。

管理者 env のマージ挙動の修正は、MDM でマシン固有の設定を配っている環境で効きます。これまではサーバー配信の設定がローカルの env ブロックを丸ごと無効化していたため、意図せず設定が消えていた可能性があります。MDM を併用している組織は、更新後に実際の env を確認しておくとよいでしょう。

コマンド面では `/review` の統合が地味に効きます。似た名前のコマンドが複数あると、社内手順書とチームの習慣がずれます。統合されたことで、手順書の記述を `/code-review` に寄せられます。

## 副業・個人活用視点

個人利用でも、権限修正は他人事ではありません。**むしろ承認する人が自分しかいない環境ほど、表示の信頼性は重要です。** 受託でクライアントのリポジトリを扱っている場合はなおさらで、更新は早めに済ませるべきです。

実用面では `/code-review` への統合が効きます。effort level を省略すると前回の指定を再利用するようになったので、`/code-review high` を一度打てば以降は `/code-review` だけで同じ深さのレビューが回ります。納品前のチェックをルーチンにしている人は、キーストロークが減る分だけ実行頻度が上がります。深いレビューが要る場面では `/code-review ultra`、PR 単位なら `/code-review <level> <pr#>` と使い分けられます。

`/teleport` のヒント表示は、クラウドセッションを使っている人向けの導線改善です。外出先で軽く指示を出しておき、`claude --teleport <session id>` で自席のローカル環境に引き継ぐ、という流れが取りやすくなります。作業場所が固定されない働き方をしている人には実際に使える機能です。

サブエージェントモデルの制限警告も、地味ですが役に立ちます。指定したモデルが使えず親モデルで動いていた場合、これまでは黙って実行されていました。結果の質が想定と違う理由が分からない、という状況が減ります。

コンテキスト制御の変更は、長時間セッションを回す人が知っておくべき箇所です。未知のモデル ID でも auto-compact が想定ウィンドウを維持するようになったため、以前の挙動を前提にしたワークフローがある場合は `CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1` で戻せます。ただし、これは基本的に安全側への変更なので、明確な理由がなければそのまま使うのが妥当です。
