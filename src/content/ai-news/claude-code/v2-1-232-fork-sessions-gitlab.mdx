## 要約

Claude Code **v2.1.232** が 2026-08-13 に公開されました。機能追加、GitLab 対応、権限バイパス修正が同時に入った大きめのリリースです。

最も影響が大きいのは**サブエージェントの fork が既定になった**ことです。`subagent_type: "fork"` のサブエージェントは、会話全体とプロンプトキャッシュを継承します。あわせて、対話セッションでの teammate 以外のエージェント起動が、既定でバックグラウンド実行になりました。エージェントの起動コストと、結果を待つ姿勢の両方が変わる挙動変更です。

**セッション同士が直接やり取りできる**ようになりました。プロンプトで `@` を打つと他の Claude セッションを名前で指名でき、Claude は `SendMessage` でそのセッションへ直接届けます。`SendMessage` は、生存中のセッション1つに一意一致する裸の名前へそのまま配送するようになりました（従来は ref での確認を求めていました）。同一マシン上のセッションは名前が一意に保たれ、既存の生存セッションと同名で起動・改名すると `name-word-word` 形式の変種が割り当てられて通知されます。`/config` には「Dialog expiry」と「Messages from your other sessions」（セッション間の受信を accept / hold / refuse）の行が追加されました。

**GitLab 対応**も入りました。シークレット秘匿の対象に GitLab のトークン群（`glrt-`、`gloas-`、`glptt-`、`glagent-`、`glimt-`、`glsoat-`、`glcbt-`、`glft-`、`glffct-`）が加わり、ルーティング可能な `glpat-` / `gldt-` は全体秘匿になりました。`glab` CLI の設定ストアも `gh` と同じサンドボックスと認証情報パスの保護を受けます。プラグインマーケットプレイスは裸の `gitlab.com` リポジトリ URL（ネストしたサブグループを含む）を `github.com` と同様に clone できます。

そして**権限バイパスの修正が4件**あります。PowerShell で変数を書き込むパラメータが `$PSDefaultParameterValues` を黙って上書きし、以降のコマンドのファイルアクセスを迂回させられた問題。Windows で Git Bash が Cygwin 形式のシンボリックリンクを辿り、パス検証からは通常ファイルに見えていた問題。ネストした git リポジトリが親ディレクトリの trust を継承していた問題。そして Gateway 側で、**不正な `email_domain` 値（空、`@` / 空白 / カンマを含むもの）が管理者権限を与えてしまう**状態を許していた問題です。最後のものは起動時に失敗するようになりました。

なお v2.1.231（同日）は、Slack のように事前登録済み OAuth クライアントを使うサーバーで MCP OAuth のサインインが redirect URI 不一致で失敗する問題の修正1件のみです。v2.1.230 は欠番でした。

## 何が変わったか

- `subagent_type: "fork"` が既定で有効になり、会話全体とプロンプトキャッシュを継承する
- 対話セッションでの非 teammate エージェント起動が、既定でバックグラウンド実行になった
- プロンプトの `@` で他の Claude セッションを名前指名でき、`SendMessage` で直接届く
- 同一マシン上のセッション名が一意に保たれ、重複時は `name-word-word` の変種が割り当てられる
- `/config` に「Dialog expiry」と「Messages from your other sessions」が追加
- GitLab トークン群がシークレット秘匿の対象になり、`glab` CLI 設定が `gh` と同等の保護を受ける
- プラグインマーケットプレイスが `gitlab.com` の URL（ネストしたサブグループ含む）を clone できる
- `additionalMarketplaces` / `allowedMarketplaces` が既存設定の別名として使える
- 権限バイパス修正4件（PowerShell、Windows の Cygwin symlink、ネスト git repo の trust 継承、Gateway の不正 `email_domain`）
- Gateway の `desktop:` オーバーレイが Desktop の全設定を受け付け、起動時に Desktop 側スキーマで検証される
- Remote Control 関連の修正多数（ブリッジの transcript / 認証情報の継承、セッション再アタッチ、履歴復元）
- mTLS クライアント証明書のローテーションが再起動不要に
- Fable 5 が `/advisor` のアドバイザーとして再提供（Fable アクセスのある組織向け）

## 業務インパクト（一般企業向け）

このリリースは**2つの異なる理由で急ぐ価値があります**。

1つ目はセキュリティです。**Gateway の不正な `email_domain` 値が管理者権限を与えうる状態だった**という修正は、内容として軽くありません。管理者グループの判定に使う値が壊れていたとき、誰にもマッチしないか、あるいは管理者権限が広がるか、どちらかに倒れていました。Gateway を運用している組織は、更新前に自分の managed policy を確認しておくべきです。**更新後は不正値があると起動に失敗する**ため、気づかないまま放置していた設定が突然ブロッカーになる可能性があります。これは事故ではなく設計どおりの挙動ですが、更新のタイミングは選んだ方がいいでしょう。

PowerShell と Windows の権限バイパスも、Claude Code に許可制御を任せている前提が崩れる類のものです。**Windows 環境で運用している組織は優先度を上げてください。**ネストした git リポジトリの trust 継承も同様で、親ディレクトリを信頼しただけで子リポジトリが自動的に信頼されるのは、モノレポや vendored な構成では想定外の広がり方をします。

2つ目は挙動変更です。**サブエージェントの fork 既定化とバックグラウンド実行の既定化**は、既存のワークフローの体感を変えます。fork が会話全体とプロンプトキャッシュを継承するということは、サブエージェントに渡す文脈を明示的に組み立てていた運用では、渡り方が変わるということです。バックグラウンド実行が既定になった点も、これまで結果を待つ前提で書いていた手順とかみ合わない場面が出ます。更新後に「動きが変わった」と報告が上がる可能性があるので、**チームで使っているなら事前に周知しておく**のが無難です。

GitLab 対応は、該当する組織にとってはまとまった前進です。トークンがログに残らなくなり、プラグインの配布経路として GitLab が使えるようになりました。これまで GitHub 前提の運用を強いられていた部分が解消されます。

セッション間メンションは、使いどころが分かれる機能でしょう。複数のセッションを並行で走らせている人にとっては、手動でのコピー&ペーストが減ります。ただし `/config` に受信の可否（accept / hold / refuse）が用意されていることからも分かるとおり、**割り込みを歓迎しない使い方もある**という前提の設計です。まずは refuse か hold から始めて、必要になったら開ける方が落ち着きます。

## 副業・個人活用視点

個人で使っている場合、体感が最も変わるのは**バックグラウンド実行の既定化**です。エージェントを投げてから待つのではなく、投げて別の作業に移る流れが標準になります。これまで「終わるまで待つ」前提でリズムを作っていた人ほど、最初は違和感があるはずです。

サブエージェントの fork 既定化は、**プロンプトキャッシュを継承する**という点でコスト面に効きます。同じ文脈を持つエージェントを複数立てるとき、キャッシュが効かないと文脈の再送分をそのまま払うことになります。前バージョン（v2.1.229）でもワークフローのファンアウトでプレフィックスをずらす改善が入っており、**マルチエージェントのコスト構造を詰める方向の変更が続いています**。並列でエージェントを走らせる使い方をしているなら、実効コストは下がる方向でしょう。

セッション間メンションは、副業の作業だと使いどころが見えやすいかもしれません。調査用のセッションと実装用のセッションを分けて走らせ、調査結果を `@` で実装側へ渡す、という流れが素直に組めます。これまでは人間が中継していた部分です。

GitLab 対応が効くのは、**クライアントが GitLab を使っている案件**です。受託だと GitHub とは限らず、そこで「トークンが秘匿されない」「プラグインを配れない」という差が出ていました。今回でその差はかなり埋まります。

案件として拾うなら、**セキュリティ修正を起点にした更新支援**が切り口になります。権限バイパス4件と Gateway の管理者権限の話は、放置していい種類のものではありません。とくに Gateway を運用している組織は、更新すると設定不備で起動しなくなる可能性があるため、**更新前の設定確認とセットで提案する**と価値が明確です。単なるバージョンアップ作業ではなく、事前確認込みの作業として組み立てられます。

発信のネタとしては、fork 既定化の前後で並列エージェントのコストがどう変わるかの実測が読まれるでしょう。**公式が「継承する」と書いていることと、実際にどれだけ請求が変わるかは別**なので、数字を出せると差別化になります。
