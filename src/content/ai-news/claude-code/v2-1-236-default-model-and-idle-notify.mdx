## 要約

Claude Code 2.1.236 が 2026-08-19T20:02Z（JST 2026-08-20 05:02）にリリースされました。前版 2.1.235 の翌日で、機能追加は3件、残りは修正と改善です。

**既定モデルの外部指定**として `ANTHROPIC_DEFAULT_MODEL` 環境変数が追加されました。これまで既定モデルは設定ファイルか `/model` での選択に依存していましたが、環境変数で与えられるようになりました。チーム配布のシェル設定や CI のジョブ定義に書けるため、「人によって既定モデルが違う」状態を解消できます。

**セッション横断の `SendMessage` に `notify_when_idle`** が追加されました。別セッションがアイドル状態になったときに通知を受け取れます。複数セッションを並行させる運用で、相手の完了をポーリングで待つ必要がなくなります。

**macOS のサンドボックス**では、ワイルドカードを使った read-deny ルールの扱いが改善されました。読み取り拒否の指定が意図どおりに効くようになる、権限設計側の修正です。ワイルドカードで広く拒否する書き方をしている場合、これまで期待どおりに効いていなかった可能性があります。

このほか `auto` モードの改善が複数入りました。Monitor の allow ルールの扱いが強化され、複数のクラウドプロバイダー上での挙動も改善されています。`/usage` の表示は Team / Enterprise メンバー向けに変更され、`/goal` のアイドルセッション判定タイミング、`/model` ピッカーのハイライト挙動、slash コマンドのエラー処理も変わりました。

**print / SDK モードでの SIGTERM の扱いが変更されている点**は、CI やスクリプトから呼ぶ側に影響します。タイムアウトで外から終了させる構成にしている場合は、挙動を確認しておく価値があります。

修正は広範囲です。ディレクトリ削除後のクリップボードコピーとバックグラウンド処理、フルスクリーンレンダラーのフォールバック、`/model` ピッカーの描画、`SendMessage` の閉じタグ不正、サブプロセス失敗時の未処理 Promise 拒否、ターミナルリサイズ後のフルスクリーン表示、managed-settings の承認プロンプトのタイミング、tmux でのターミナルタブタイトルの跳ね、git status チェックの設定処理などが直っています。起動時のセッションカウンターの性能も改善されました。VSCode ではトランスクリプトのスクリーンリーダー対応が入っています。

## 何が変わったか

- `ANTHROPIC_DEFAULT_MODEL` 環境変数で既定モデルを指定可能
- セッション横断 `SendMessage` に `notify_when_idle` を追加。別セッションのアイドル通知を受け取れる
- macOS サンドボックスのワイルドカード read-deny ルールの扱いを改善
- `auto` モードが Monitor の allow ルールを扱えるよう強化。複数クラウドプロバイダー上での挙動も改善
- **print / SDK モードでの SIGTERM の扱いを変更**
- `/usage` の表示を Team / Enterprise メンバー向けに変更
- `/goal` のアイドルセッション判定タイミング、`/model` ピッカーのハイライト挙動、slash コマンドのエラー処理を変更
- Remote Control のセッション状態更新を強化。`SendMessage` のメッセージサイズ検証を改善
- VSCode でトランスクリプトのスクリーンリーダー対応を追加
- 起動時のセッションカウンターの性能改善、managed-settings の承認プロンプトのタイミング修正、tmux のタブタイトル跳ね修正ほか多数

## 業務インパクト（一般企業向け）

`ANTHROPIC_DEFAULT_MODEL` は、チーム利用の運用が一段整理できる変更です。これまで既定モデルを揃えるには各自の設定ファイルに依存するしかなく、新しく入った人が違うモデルで作業している、という状態を検出する手段がありませんでした。環境変数であれば、開発環境のセットアップスクリプトや devcontainer の定義、CI のジョブ定義に書けます。**「どのモデルを既定にするか」をチームの決定として扱い、それを配布経路に乗せられるようになった**、というのが実務上の意味です。

managed-settings を使って設定を配布している組織は、今回の承認プロンプトのタイミング修正も確認対象です。承認ダイアログが出るタイミングが変わっているため、配布設定と組み合わせた挙動をテストしてから展開するのが安全です。

**print / SDK モードの SIGTERM 挙動変更は、CI に組み込んでいる場合に効きます。**ジョブのタイムアウトで外部から終了させる、あるいはスクリプトから子プロセスとして起動して制御している構成では、終了時の後処理が変わる可能性があります。CI が落ちてから調べるより、パイプラインを1本流して確認しておくほうが早く済みます。

macOS のサンドボックスでワイルドカードの read-deny ルールを書いている場合は、修正後に実際の拒否範囲を確認してください。**これまで意図どおりに効いていなかったものが効くようになる**方向の修正なので、これまで通っていたアクセスが止まる可能性があります。逆に言えば、これまで塞げていたつもりの範囲が塞げていなかった、ということでもあるため、セキュリティレビューの観点では確認する価値があります。

`auto` モードの Monitor allow ルール対応と複数クラウドプロバイダー上での改善は、自動実行を業務パイプラインに組み込んでいる組織向けの強化です。VSCode のスクリーンリーダー対応は、アクセシビリティ要件を持つ組織にとって導入判断に関わる項目になります。

## 副業・個人活用視点

`notify_when_idle` は、複数セッションを並行させて作業している人にとって効き目が大きい追加です。これまでは「別のセッションが終わったか」を確認するために自分で見に行く必要がありました。通知を受け取れるようになったことで、**長い処理を投げておいて別の作業に移り、終わったら戻る**という進め方が実際に成立します。副業として夜間や隙間時間に作業している場合、待ち時間をそのまま別作業に回せるのは大きい差になります。

`ANTHROPIC_DEFAULT_MODEL` は個人でも使いどころがあります。案件ごとにディレクトリを分けていれば、`direnv` などと組み合わせて「この案件では常にこのモデル」を自動で切り替えられます。コストの重い案件と軽い案件で既定を分けたい場合に、毎回 `/model` を叩く必要がなくなります。

CI から Claude Code を呼ぶ構成を組んでいる場合は、SIGTERM 挙動の変更を先に確認してください。個人開発の CI は失敗しても誰にも迷惑がかからない代わりに、原因調査に時間を取られます。バージョンを上げるタイミングで1回流しておくのが安上がりです。

なお Claude Code は 2.1.234 以降ほぼ毎日リリースが出ています。すべてを追う必要はありませんが、**環境変数・サンドボックス・SIGTERM のように「自分の設定と噛み合う変更」だけは拾う**という読み方をすると、負担を抑えつつ事故を避けられます。
