## 要約

Claude Code **2.1.237**（2026-08-20T00:54Z / JST 09:54）と **2.1.238**（同日 20:33Z / JST 翌 05:33）が、約20時間差で相次いでリリースされました。片方は小さく、もう片方は組織運用に関わる変更を含みます。

**2.1.237 の中身は2点だけです。** ひとつは、**LLM ゲートウェイやカスタム base URL を使うセッションでプロンプトキャッシュが効いていなかった問題の修正**です。これは金額に直結します。ゲートウェイ経由で Claude Code を使っている組織は、キャッシュが効いていれば節約できたはずのトークンを払い続けていた可能性があります。企業では監査・コスト集約・モデル切り替えのためにゲートウェイを挟む構成が珍しくないので、該当する組織は少なくないはずです。

もうひとつは、組み込みの **「Concise」出力スタイル**の追加です。結果を先に出し、前置きや実況を省く応答スタイルで、設定から選べます。従来はカスタム出力スタイルを自分で書く必要があった挙動が、既定の選択肢として入りました。

**2.1.238 は、プラグイン配布と MCP の統制に踏み込んでいます。** プラグインマーケットプレースが **`headersHelper` に対応**しました。URL 形式のマーケットプレースやカタログエントリに対して、HTTP ヘッダーを発行するコマンドを指定できます。つまり**認証が必要な社内マーケットプレースをホストできる**ということです。カタログエントリ側の `headersHelper` は、そのプラグインをインストールまたは更新するときだけ実行されます。

同じリリースで、**MCP 側の `headersHelper` には制限が加えられました**。プロジェクトの `.mcp.json` に書かれた `headersHelper` とインラインの MCP サーバー定義は **workspace trust が必須**になり、さらにプロジェクトの `.mcp.json`・プラグイン・エージェントファイル由来の `headersHelper` は**認証情報の環境変数を継承しない**よう絞られました。方向が逆に見えますが、そうではありません。**配布側（自組織がホストする経路）には手段を与え、受信側（リポジトリに紛れ込んだ設定）には信頼の確認を挟む**、という整理です。

運用系では **`claude self-hosted-runner --defer-shutdown-max-min <分>`** が追加され、実行中のジョブを打ち切らずにランナーを落とせるようになりました。あわせて **`--proxy-authorization-command` / `--proxy-authorization-file`** が加わり、プロキシ認証を外部コマンドやファイルから供給できます。

**長時間の対話セッションでメモリが無制限に増える問題**も修正されました。1日中同じセッションを開いたまま使う運用では、これまで再起動でしのぐしかなかった可能性があります。あわせて、**カスタム・プロジェクト・プラグインの出力スタイルがセッション途中で既定の声色に戻ってしまう問題**も直っています。

このほか、`keybindingFlavor` 設定（`"readline"` にすると `Ctrl+W` が直前の空白まで削除）、`claude mcp list` / `get` での無効サーバーの `⊘ Disabled` 表示、Remote Control が短時間の HTTP 403 を3分間許容するようになった点、macOS で `claude` の起動が速くなった点などが含まれます。

## 何が変わったか

**2.1.237**

- **LLM ゲートウェイ / カスタム base URL 経由のセッションでプロンプトキャッシュが効かない問題を修正**
- 組み込みの **「Concise」出力スタイル**を追加（結果を先に出し、前置きと実況を省く）

**2.1.238**

- プラグインマーケットプレースが **`headersHelper`** に対応。URL マーケットプレースやカタログエントリで HTTP ヘッダーを発行し、**認証付きの社内マーケットプレース**をホストできる
- カタログエントリの `headersHelper` は、そのプラグインのインストール／更新時にのみ実行される
- **MCP の `headersHelper`**: プロジェクト `.mcp.json` 由来とインライン MCP サーバーは **workspace trust が必須**に
- プロジェクト `.mcp.json`・プラグイン・エージェントファイル由来の `headersHelper` は、**認証情報の環境変数を継承しない**
- **`claude self-hosted-runner --defer-shutdown-max-min <分>`** を追加（猶予付きシャットダウン）
- **`--proxy-authorization-command` / `--proxy-authorization-file`** を追加
- **長時間の対話セッションでメモリが無制限に増える問題を修正**
- カスタム・プロジェクト・プラグインの**出力スタイルがセッション途中で既定へ戻る問題**を修正
- **`keybindingFlavor`** 設定を追加（`"readline"` で `Ctrl+W` が直前の空白まで削除）
- `claude mcp list` / `claude mcp get` が無効サーバーを **`⊘ Disabled`** と表示
- Remote Control が**短時間の HTTP 403 を3分間許容**するようになり、接続の粘りが改善

## 業務インパクト（一般企業向け）

**ゲートウェイ経由のキャッシュ修正は、コストの再確認を促す変更です。** 監査ログの集約、コストの部門別集計、モデルの切り替えといった理由で LLM ゲートウェイを挟む構成は、企業では標準的な選択です。その構成でプロンプトキャッシュが効いていなかったのなら、**同じ作業に対して払っていた金額が実際より高かった**ことになります。バージョンを上げた前後で、1セッションあたりの費用がどう変わるかを1〜2週間観測してみてください。差が出るなら、その差はこれまで無駄に払っていた分です。

**プラグイン配布を社内に閉じる構成が、正式な手段として揃いました。** `headersHelper` で HTTP ヘッダーを発行できるということは、認証をかけた社内マーケットプレースをホストできるということです。これは統制の観点で大きい変更です。公開マーケットプレースからプラグインを自由に入れられる状態は、**サプライチェーンの入口が組織の外にある**ということを意味します。社内ホストへ移せば、何を配るかを組織が決められます。導入を検討するなら、**まず現状で誰がどのプラグインを入れているかの棚卸し**から始めてください。配布経路を絞る前に、絞ったときに困る人を把握しておく必要があります。

**MCP 側の絞り込みは、リスクの向きを理解して読むべきです。** プロジェクトの `.mcp.json` は、リポジトリに含まれてクローンされます。つまり**リポジトリを開くだけで、そこに書かれた `headersHelper` コマンドが実行されうる**構造でした。workspace trust を必須にし、認証情報の環境変数を継承させないという変更は、この経路を塞ぐものです。外部のリポジトリや、社外から受け取ったコードを開く機会がある組織では、**このバージョン以降を必須とする運用ルール**を検討する価値があります。

**`--defer-shutdown-max-min` は、セルフホストランナーを普通のワーカーとして扱えるようにする変更です。** スケールインやデプロイでランナーを落とすとき、実行中のジョブをどうするかは CI の設計と同じ問題です。猶予を持たせて落とせるようになったことで、**AI エージェントの実行基盤にも通常のインフラ運用の作法を適用できます**。`--proxy-authorization-command` / `--proxy-authorization-file` は、プロキシ認証情報を設定ファイルに直書きせず外部から供給する手段で、認証情報の取り扱いルールがある組織には必要な部品です。

**長時間セッションのメモリリーク修正は、使い方の想定を示しています。** 1日中同じセッションを開いたまま使う運用が想定利用に入っている、ということです。翌日の 2.1.239 でも `WebFetch` が期限切れページを保持し続ける問題が修正されており、**2版続けて同じ方向の修正**が入っています。開発者の作業スタイルとして「セッションを閉じない」が前提になりつつある、と読めます。

## 副業・個人活用視点

**「Concise」出力スタイルは、地味ですが日々の体感に効きます。** 結果を先に出し、前置きと実況を省く応答は、慣れた利用者ほど価値があります。「これから〜します」「〜が完了しました」といった説明は、最初の数週間は安心材料ですが、その後は読み飛ばす対象になります。読み飛ばすものが出力されているということは、**そのぶんのトークンを払っている**ということでもあります。カスタム出力スタイルを自分で書く必要がなくなったので、試すコストはほぼゼロです。

**個人でも LLM ゲートウェイを挟んでいるなら、キャッシュ修正は金額に効きます。** 複数のプロバイダを切り替えるため、あるいは利用状況を自分で記録するためにゲートウェイを立てている人は一定数います。該当するなら、更新前後でトークン消費を比べてみてください。

**`headersHelper` によるプラグイン配布は、小規模チームやコミュニティ運営でも使えます。** 自分が作ったプラグイン群を、認証をかけたマーケットプレースとして配る。有償の会員向けにツール群を配布する、といった形も技術的には成立します。個人がツールを売る形態として、**「単体のスクリプトを売る」から「更新され続けるプラグイン群へのアクセスを売る」へ移す**選択肢が出てきた、と読めます。

`keybindingFlavor` の `"readline"` は、シェル操作に慣れた人ほど効く変更です。`Ctrl+W` の削除範囲がシェルと揃うだけですが、日に何十回も押すキーの挙動が環境ごとに違う状態は、地味に集中を削ります。

自分の作業環境が「セッションを開きっぱなし」型なら、**メモリリーク修正のために更新する理由は十分にあります**。動作が重くなったら再起動する、という対処で回していた場合、その症状の一部は既知の不具合だった可能性があります。
