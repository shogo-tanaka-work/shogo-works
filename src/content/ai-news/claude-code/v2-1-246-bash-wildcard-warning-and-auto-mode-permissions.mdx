## 要約

Claude Code 2.1.246 が 2026-08-25 に公開されました。**直近では最大級の変更量**で、権限・セキュリティ・プラグイン・表示・メモリの各領域に手が入っています。ここでは、実際に手を動かす必要があるものから順に見ていきます。

**最も対応が必要なのは、Bash allow ルールへの起動時警告です。** `Bash(git * main)` のように**サブコマンドの前にワイルドカードを置いたルール**に対して、警告が出るようになりました。理由は公式が明記しています——**この書き方は、サブコマンドの前に挿入されたオプションにもマッチしてしまう**からです。

これは新機能ではなく、**既存の設定が意図より広い可能性を知らせる警告**です。つまり、今日まで動いていた設定が、実は想定より多くのコマンドを許可していたかもしれない。**警告が出る組織は、設定を書いた時点の意図まで戻って確認する必要があります。**「動いていたから正しい」は、許可ルールでは成り立ちません。

権限まわりではもう2つ。**`/permissions` に Auto mode タブが追加**され、auto mode の classifier ルールを画面上で閲覧・編集できるようになりました。これまで auto mode の判定基準は実質ブラックボックスでしたが、**中身を見て直せるようになった**という意味で、統制の質が変わります。また、**末尾に `&&` や `||` がぶら下がった不正なコマンドは、常に承認を要求する**よう修正されました。パース漏れを利用した回避を塞ぐ変更です。

**セキュリティ修正が2件あります。** 1つは、**第三者ゲートウェイ（`ANTHROPIC_BASE_URL`）向けに設定した API キーが、Anthropic 宛のテレメトリ・メトリクス要求に載って送信されていた**という不具合です。修正後は、**資格情報は自分のホストにのみ送られます**。社内プロキシや API ゲートウェイ経由で Claude Code を使っている組織は、この修正の対象です。もう1つは、`apiKeyHelper` が短命 JWT を返す構成で、アイドル後の最初のプロンプトに API エラーが見えていた問題。期限切れトークンは送信前に更新され、401/403 は静かにリトライされるようになりました。

**メモリと表示の改善も、体感に直結します。** フルスクリーンおよび Ctrl+O のトランスクリプト表示で、**セッションが長くなるほどメモリが増えていた問題**が修正されました。原因は、描画された各行がトランスクリプト全体のツールルックアップの完全なコピーを保持していたことです。また、**base64 文字列のような極端に長い1行を含む diff で、トランスクリプトが極端に遅くなる問題**も解消しました（そうした行は切り詰めてマーカー表示されます）。長時間セッションを回す使い方をしている人には、地味に効く修正です。

**挙動が変わったものが2つあります。** `/cd` は、**移動先のプロジェクト設定・hooks・`.mcp.json` サーバー（通常の承認プロンプト経由）・skills・agents が、`--resume` を待たずに移動直後から有効**になりました。これまで「`/cd` したのに設定が効かない」という状態があったのが解消されます。サブエージェントは、`maxTurns` の上限に達した場合、**完了したように見せるのではなく「部分的」と明示して返し、`SendMessage` で継続できるヒントを添える**ようになりました。**上限で止まったことが分かるようになった**、という変更です。

そのほか、非対話セッション（`-p`、SDK、クラウドセッション）がサーバーエラーや接続断で途中終了した応答を**自動的に継続**するようになり、プラグイン関連の修正が多数入っています（キャッシュの SHA 名ディレクトリ重複、`<plugin>:` 接頭辞の二重表示、BOM 付き `plugin.json`、`/reload-plugins` が `skills/*/SKILL.md` 形式のスキルを0件と報告する問題など）。

## 何が変わったか

- **サブコマンド前ワイルドカードの Bash allow ルール（例 `Bash(git * main)`）に起動時警告**。サブコマンド前に挿入されたオプションにもマッチするため
- **`/permissions` に Auto mode タブ**を追加し、auto mode の classifier ルールを閲覧・編集可能に
- 末尾に `&&` / `||` がぶら下がった**不正なコマンドは常に承認を要求**
- **修正: 第三者ゲートウェイ（`ANTHROPIC_BASE_URL`）向け API キーが Anthropic 宛テレメトリ要求に載っていた**問題。資格情報は自ホストにのみ送信されるように
- 修正: `apiKeyHelper` の短命 JWT 構成で、アイドル後の初回プロンプトに API エラーが見えていた問題（期限切れトークンは送信前に更新、401/403 は静かにリトライ）
- 修正: フルスクリーン / Ctrl+O のトランスクリプト表示で**セッション長に比例してメモリが増える**問題
- 修正: base64 のような**極端に長い1行を含む diff でトランスクリプトが極端に遅くなる**問題（切り詰めてマーカー表示）
- **`/cd` 後、移動先の設定・hooks・`.mcp.json`・skills・agents が即時反映**（`--resume` 不要）
- **サブエージェントが `maxTurns` 到達時に「部分的」と明示**して返し、`SendMessage` での継続を案内
- 非対話セッション（`-p` / SDK / クラウド）が、中断された応答を**自動継続**
- ターン終了時に**完了時刻を表示**（例 `✻ Sautéed for 23s · done 6:05 PM`）
- プラグイン関連の修正多数（キャッシュの重複ディレクトリ、`<plugin>:` 接頭辞の二重表示、BOM 付き `plugin.json`、`/reload-plugins` の `skills/*/SKILL.md` 認識）

## 業務インパクト（一般企業向け）

**今日やるべき作業が1つあります。managed settings で Bash allow ルールを配っている組織は、ワイルドカードの位置を点検してください。** `Bash(git * main)` のような書き方をしているなら、それは**サブコマンドの前に挿入されたオプションにもマッチします**。何が通ってしまうかは、実際のルール次第です。**「今まで問題が起きていない」は、範囲が正しいことの証明にはなりません。**問題が起きていないだけかもしれません。

**この警告の設計自体が示唆的です。** Anthropic はルールを無効にしたのではなく、**警告を出すに留めました**。既存の設定を壊さないための判断ですが、裏を返せば**警告を無視すれば広い許可はそのまま残ります**。起動時のメッセージは流れて消えます。**誰かが気づいて対応するまで、状態は変わりません。**設定を配布している組織は、この点検を作業として誰かに割り当ててください。放っておいて直るものではありません。

**`/permissions` の Auto mode タブは、統制の質を一段上げます。** auto mode を有効にしている組織にとって、判定基準が見えないことは監査上の弱点でした。**classifier ルールを閲覧・編集できるようになったことで、「なぜこの操作が自動承認されたのか」を後から説明できます。**auto mode を採用しているなら、まず一度このタブを開いて、既定のルールが自社の方針と矛盾していないか確認する価値があります。

**第三者ゲートウェイへの資格情報送信の修正は、該当する組織にとっては重い話です。** 社内プロキシや API ゲートウェイを経由させている構成では、**そのゲートウェイ用の API キーが Anthropic 宛のテレメトリ要求に載っていました**。修正されたのは良いことですが、**修正前の期間に送信されていた事実は消えません。**該当する組織は、そのゲートウェイのキーをローテーションするかどうかを判断してください。**判断した結果「しない」でも構いませんが、判断はしてください。**

**サブエージェントの `maxTurns` 到達が明示されるようになった点は、無人実行を組んでいる組織に効きます。** これまでは、上限で止まったサブエージェントが**完了したように見えていました**。つまり、**中途半端な結果を「これで全部です」として受け取っていた可能性がある**ということです。自動化パイプラインの中でサブエージェントを使っているなら、**過去の実行結果が完全だったかを疑う根拠になります。**「失敗を失敗として報告させる」という設計原則が守られていなかった箇所が、1つ塞がりました。

**`/cd` の即時反映は、モノレポや複数プロジェクトを行き来する現場で効きます。** これまで「`/cd` したが移動先の hooks が効いていない」という状態が発生しえました。**設定が効いていないことに気づかないまま作業を続ける**のは、ガードレールを敷いている組織ほど問題になります。プロジェクトごとに異なる権限設定を配っているなら、この修正は実質的なセキュリティ改善です。

## 副業・個人活用視点

**個人で使っている人も、Bash allow ルールの点検はやってください。** 自分で書いた `~/.claude/settings.json` に `Bash(npm * install)` のような書き方があるなら、それは意図より広い可能性があります。**個人環境だから被害が小さい、とは限りません。**むしろ個人環境のほうが、本番の認証情報や公開鍵が同じマシンに置かれていることが多い。**5分で終わる点検なので、警告が出たら後回しにしないでください。**

**メモリ増加とトランスクリプト遅延の修正は、長時間セッション派には実利があります。** 1つのセッションを何時間も回す使い方をしていると、後半で明らかに動作が重くなる現象がありました。**原因が特定されて直った**ので、これまで「重くなったら `/clear`」で対処していた人は、その頻度を下げられます。文脈を維持したまま長く作業できることは、そのまま作業効率です。

**非対話セッションの自動継続は、自動化を組んでいる人には大きい変更です。** `-p` や SDK で回している処理が、サーバーエラーや接続断で途中終了していた場合、これまでは**中途半端な結果が返っていました**。自動継続が入ったことで、**一時的なネットワーク障害でパイプラインが壊れる確率が下がります。**夜間バッチのように人が見ていない実行ほど、この修正の恩恵が大きい。

**支援先へ Claude Code を導入している立場なら、Bash allow ルールの点検は今すぐ提供できる作業です。** 「起動時に警告が出ていませんか」から入って、設定ファイルを一緒に読み、ワイルドカードの位置を直す。**技術的には難しくありませんが、警告の意味を理解している人が少ない**ので、価値のある支援になります。あわせて `/permissions` の Auto mode タブを開いて、classifier ルールが方針と合っているかを確認するところまでやると、**「設定を配って終わり」ではない運用**の実例として見せられます。

**`maxTurns` の部分結果明示は、ハーネス設計の教訓として説明の材料になります。** 「エージェントが黙って途中で止まる」という失敗モードは、AI 自動化を組むときに必ず考慮すべきものです。**公式ツールですらこの問題を抱えていて、修正されたのが今日である**——という事実は、自作の自動化を点検する動機として、抽象的な注意喚起よりずっと強く働きます。
