## 要約

Claude Code は 2026-08-20 から 2026-08-23 の4日間で 2.1.237 / 2.1.238 / 2.1.239 / 2.1.240 / 2.1.241 の5版をリリースしました。バージョンごとに追うと粒度が細かすぎるため、この期間をひとまとめにして整理します。

**変更の中心は 2.1.239（2026-08-21T19:54Z）**で、CHANGELOG に60項目以上が並びます。2.1.240 と 2.1.241 はいずれも `Bug fixes and reliability improvements` の1行のみで、個別項目は公開されていません。大型版の直後に追随修正が2版続いた形なので、**2.1.239 の変更を検証する場合は 239 で止めず 241 まで上げてから確認する**のが実務上は効率的です。

この期間で最も金額に直結するのは、**ヘッダーを削るプロキシ配下で Bedrock のストリーミングが壊れていた問題**です。レスポンスの `Content-Type` ヘッダーを落とすプロキシを経由していると、Claude Code がストリーミング失敗と判断して毎ターンを非ストリーミングで再実行しており、**API 課金が黙って倍になっていました**。エラーとして表面化せず請求だけが増えるタイプの不具合なので、企業プロキシ経由で Bedrock を使っている組織は、気づかないまま払い続けていた可能性があります。

もう1つの課金まわりの変更が、**データレジデンシー（US-only inference）ワークスペースの 1.1 倍割増をコスト見積もりに反映**したことです。`/cost`、ステータスライン、`--max-budget-usd` のいずれもこれまで割増分を含んでおらず、表示と実請求がずれていました。`--max-budget-usd` で上限を設けている場合、**設定した上限より実際の請求が多かった**ことになります。

配布・運用面では、2.1.238 でプラグインマーケットプレースに `headersHelper` が入りました。短命トークンなどの HTTP ヘッダーを都度生成できるため、**認証をかけた社内マーケットプレース**が組めます。ヘッダーヘルパーが動くのはインストール／更新時だけで、実行前にユーザー確認が入ります。2.1.239 では claude.ai から同期されたプラグインが cloud セッションで `name@synced` として扱われ、ローカルにインストールした同名プラグインを上書きしなくなりました。

安定性では、2.1.238 で**長時間の対話セッションのメモリリーク**が解消しました。表示ウィンドウから外れたサブエージェントのツール結果を解放するようになったもので、「開きっぱなし」運用の実害が消えます。セキュリティ寄りでは、2.1.239 で**ログインコード欄などマスク入力の内容が Ctrl+Y で他所に貼り付けられたり、二重 Esc で消したときにプロンプト履歴へ保存される**問題が直りました。組織ポリシーで拒否されたリクエストが、拒否表示より先に再送されていた問題も修正されています。

なお 2.1.237 の `Concise` 出力スタイル（前置きと実況を省いて結果から述べる組み込みスタイル）と、LLM ゲートウェイ／カスタム base URL 利用時のプロンプトキャッシュ修正も、この期間の変更に含まれます。後者もコストに直接効く修正です。

## 何が変わったか

**課金・コスト**

- ヘッダーを削るプロキシ配下で Bedrock のストリーミングが壊れ、毎ターンを非ストリーミングで再実行して API 課金が倍になっていた不具合を修正（2.1.239）
- データレジデンシーワークスペースの 1.1× 割増を `/cost`・ステータスライン・`--max-budget-usd` に反映（2.1.239）
- LLM ゲートウェイ／カスタム base URL 利用時のプロンプトキャッシュを修正（2.1.237）
- 月次上限を使い切ったときのメッセージが、セッション上限・週次上限のリセット時刻も表示（2.1.239）

**プラグイン配布・エンタープライズ**

- プラグインマーケットプレースに `headersHelper` を追加。短命トークン等のヘッダーを生成でき、認証付き社内マーケットプレースが組める（2.1.238）
- cloud セッションの同期プラグインが `name@synced` 表記になり、ローカル同名を上書きしない（2.1.239）
- マーケットプレースの `metadata.pluginRoot` が効いていなかった問題を修正（2.1.239）
- セルフホストランナーに `--defer-shutdown-max-min`、egress プロキシ向けの認可対応を追加（2.1.238）
- Bedrock で SSO プロファイル＋`awsAuthRefresh` の構成が HTTPS プロキシ配下で起動時ハングする問題を修正（2.1.239）

**安定性・セキュリティ**

- 長時間対話セッションのメモリリークを解消（2.1.238）
- マスク入力（ログインコード等）が Ctrl+Y や履歴経由で復元できた問題を修正（2.1.239）
- 組織ポリシーで拒否されたリクエストが、拒否表示より先に再送されていた問題を修正（2.1.239）
- WebFetch のキャッシュがセッション中ずっと保持されていた問題を修正（本来は15分）（2.1.239）
- Linux サンドボックスで `extensions.worktreeConfig` 設定のリポジトリの git コマンドが全滅していた問題を修正（2.1.239）

**環境・プラットフォーム**

- Alpine/musl ビルドで画像ペースト・クリップボード・音声キャプチャが動作（2.1.239）
- Windows でセッション横断メッセージング（`SendMessage` / `ListAgents`）が利用可能に（2.1.239）
- JetBrains ターミナルで Edit / Write が約5秒停止する問題を修正（2.1.239）
- `/claude-api upgrade` で Python プロジェクトを `anthropic` 0.x → 1.x へ移行（2.1.239）
- 組み込み出力スタイル `Concise` を追加（2.1.237）

## 業務インパクト（一般企業向け）

**まず確認すべきは Bedrock の二重課金です。** 企業で Claude Code を Bedrock 経由で使う場合、社内プロキシを挟む構成はよくあります。そのプロキシがレスポンスの `Content-Type` を削っていると、この不具合の条件に当たります。厄介なのは、**利用者側には何のエラーも出ず、動作も正常に見える**点です。増えるのは請求だけなので、月次のコストレビューで「思ったより多い」と感じても、原因を Claude Code のバージョンに求めるのは難しい構造でした。

対応は2段階です。1つはバージョンを上げること。もう1つは、**過去の請求を疑うこと**です。プロキシ構成に心当たりがあるなら、2.1.239 の前後で1ターンあたりの API 呼び出し数がどう変わるかを1日分でも計測すれば、過去にどれだけ乗っていたかの目安が取れます。金額次第では調達・経理側への説明が必要になります。

**データレジデンシー割増のコスト反映は、予算管理の前提が変わる変更です。** US-only inference のワークスペースを使っている組織は、これまで `/cost` や `--max-budget-usd` が割増前の金額を出していました。`--max-budget-usd` を「ここで止まる」と信じて設定していた場合、**実際にはその 1.1 倍まで使われていた**ことになります。バージョンを上げると表示金額が上がりますが、これは値上げではなく表示が正確になっただけです。社内で「Claude Code の費用が上がった」という報告が上がってきたときに、この区別を説明できる状態にしておくと余計な調査が減ります。

**`headersHelper` は、プラグイン配布の統制を考えている組織にとって選択肢を増やす追加です。** これまで社内マーケットプレースを立てる場合、認証をかけるとインストール時にトークンを渡す手段がなく、実質的に無認証で置くか配布を諦めるかの二択でした。短命トークンをヘルパーで生成できるようになったことで、**社内ネットワークの外からでも認証付きで配布できる**構成が取れます。実行タイミングがインストール／更新時に限定され、ユーザー確認が挟まる設計なので、統制側にとっても説明しやすい形になっています。

`name@synced` の扱いも配布運用に効きます。claude.ai 側で配ったプラグインと、開発者がローカルで入れた同名プラグインが衝突しなくなったため、**「全社配布」と「個人の検証環境」を同居させられます**。これまでは名前が被った時点でどちらかが潰れていました。

**セキュリティレビューの観点では、マスク入力の修正と組織ポリシー拒否の修正の2件が対象になります。** 前者は、ログインコードのようにマスクして入力させていた値が、Ctrl+Y やプロンプト履歴から復元できていたという内容です。監査上「マスクしているから安全」という前提を置いていた場合、その前提は 2.1.239 より前のバージョンでは成立していません。後者は、ポリシーで止めたはずのリクエストが拒否表示より先に再送されていたもので、統制の実効性に直接関わります。**どちらも「設定はしていたが効いていなかった」型の問題**なので、設定の存在ではなく効果を検証する運用に切り替える根拠として使えます。

2.1.240 と 2.1.241 に個別項目が公開されていない点は、変更管理の面では扱いにくい部分です。差分が分からないため、リリースノートベースで承認フローを回している組織は判断材料がありません。この期間については、**2.1.239 を基準に検証を組み、241 まで上げてから通す**という運用が現実的です。

## 副業・個人活用視点

個人で使う場合、この期間で効き目が大きいのは**長時間セッションのメモリリーク修正**です。Claude Code を開きっぱなしにして作業する使い方をしていると、時間が経つにつれて重くなる現象がありました。2.1.238 でサブエージェントのツール結果が解放されるようになったため、**1日開きっぱなしにしても実用に耐える**方向に変わっています。副業として夜に数時間だけ触る、あるいは平日の隙間時間に少しずつ進める使い方では、毎回立ち上げ直す手間が減ります。

**コスト面では、LLM ゲートウェイやカスタム base URL を経由している人は 2.1.237 を最低ラインにしてください。**プロンプトキャッシュが効いていなかったため、同じ作業でも余分に払っていた可能性があります。個人の従量課金は金額が小さい分、異常に気づきにくいのが問題です。自前のゲートウェイを立てて複数プロジェクトから叩く構成にしている人ほど影響が出ます。

`Concise` 出力スタイル（2.1.237）は、慣れてきた人ほど価値があります。前置きと実況を省いて結果から出す組み込みスタイルで、**作業内容は変わらず出力だけが短くなります**。トークン消費が減るので、従量課金で使っている場合は実質的なコスト削減にもなります。カスタムの出力スタイルを自分で書いていた人は、組み込みで足りるか一度比べてみる価値があります。

環境面では、**Alpine/musl 対応と Windows のセッション横断メッセージング**が新しい選択肢を作ります。前者は軽量コンテナで Claude Code を動かす構成で、画像ペーストやクリップボードが使えるようになったということです。VPS 上の小さいコンテナで開発環境を持ち歩くやり方をしている人には効きます。後者は Windows でも複数セッションを連携させられるようになったもので、macOS / Linux と同じ運用が組めます。

`/claude-api upgrade` は、Anthropic の Python SDK を 0.x のまま使っているプロジェクトを持っている人向けです。移行は後回しにされがちですが、コマンド1つで着手できるなら、案件が動く前に済ませておくほうが安全です。特にタイムアウトの指定が `httpx.Timeout` から `anthropic.Timeout` に変わる点は、手作業だと見落としやすい部分です。

なお Claude Code は 2.1.234 以降ほぼ毎日リリースが出ています。全部を追う必要はありませんが、**課金・認証・サンドボックスに関わる変更だけは拾う**という読み方にすると、負担を抑えつつ金銭的な事故を避けられます。今回の Bedrock 二重課金は、まさにその読み方でしか拾えない種類の変更でした。
