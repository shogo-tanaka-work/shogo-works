## 要約

Claude Code **v2.1.234** が 2026-08-17 に公開されました。50項目を超える大型リリースです。

いちばん影響が大きいのは、**claude.ai の利用上限がリセットされたときにセッションを自動で継続する**挙動が入ったことです。**既定で有効**で、`/config` の「Continue automatically at usage limit」で切れます。これまでは上限に当たると作業が止まり、リセット後に人が戻ってきて再開する必要がありました。

セキュリティでは、**Windows NT namespace パス（`\??\`）の拒否対象が拡大**しました。v2.1.233 で **NTLM 認証情報の漏洩ベクトル**を塞いだのと同じ話の続きで、今回は**残っていた事前承認前のファイルアクセス経路**が対象です。具体的にはリモートファイルの読み取り、セッション復元、CLAUDE.md の include、workflow スクリプト、ファイルアップロード。**1回のリリースで塞ぎきれていなかった**わけです。

あわせて **MCP 診断が解決済みのシークレットを表示していた問題**が直りました。スコープ競合の警告は設定された `${VAR}` の形で表示され、接続失敗の詳細はサーバーのオリジンだけを出すようになります。権限プレビューのマスキングが**承認者からコマンドやパスや宛先を隠してしまう**問題も修正されました（隠されたら承認の意味がないので、これは正しい方向の修正です）。`strictKnownMarketplaces` の allowlist が、git が実際に接続するホストと異なる SCP 形式の git ソースを通していた問題も塞がれています。

運用面では **`/permissions` と `/add-dir` が作業中に開ける**ようになりました。権限ルールの変更は**現ターンの残りから有効**になります。`/autocompact`、`/theme`、`/help`、`/config`、`/advisor` もフルスクリーン TUI でターン途中に開けます。

`/goal` にも手が入り、回復不能なエラー（認証の失効、クレジット残高の枯渇、コンテキスト溢れ）でターンが落ちたときに**通知を出して自動解除**されるようになりました。armed のまま残らないということです。バックグラウンドタスクで30分以上待たされる場合は Claude が状況を確認しにいきます（`CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0` で無効化）。

コスト面では、**組み込み `claude-api` skill の読み込みコストが約200k+トークンから約25kへ削減**されました。参照ドキュメントを必要時に読む方式へ変えたものです。

## 何が変わったか

- **利用上限リセット時のセッション自動継続**（既定 on、`/config` の「Continue automatically at usage limit」で off）
- NT namespace パス（`\??\`）の拒否を、リモートファイル読み取り・セッション復元・CLAUDE.md の include・workflow スクリプト・ファイルアップロードまで拡大
- MCP 診断が解決済みシークレットを表示していた問題を修正（`${VAR}` 形式で表示、失敗詳細はオリジンのみ）
- 権限プレビューのマスキングが承認者からコマンド・パス・宛先を隠す問題を修正
- `strictKnownMarketplaces` が SCP 形式の git マーケットプレイスソースを取りこぼす問題を修正
- **`/permissions` と `/add-dir` を作業中に実行可能**（ルール変更は現ターンの残りから有効）
- `/goal` が回復不能エラーで自動解除、30分以上のバックグラウンド待ちで状況確認（`CLAUDE_CODE_GOAL_CHECKIN_MINUTES=0`）
- **`claude-api` skill の読み込みコストを約200k+トークンから約25kへ削減**
- GitLab リモートと認証済み `glab` CLI がある repo で、フッターとステータスラインに MR バッジ（`!N`、draft/pending/green）を表示
- `CLAUDE_CODE_PROJECT_DIR_NAME` でプロジェクト別 transcript ディレクトリ名を短縮
- `selection:clear` キーバインドでアプリ内テキスト選択を解除（agents ビューでも動作）
- Remote Control の effort 選択がスマホ / claude.ai/code からターミナル・Desktop・VS Code ホストのセッションへ反映
- アカウント email を本人確認以外の目的で外部サービスへ送らないよう Claude へ指示
- 自動生成のセッションタイトルが短い名前（「Login button bug」）になり、依頼文の言い換え（「Fix the login button on mobile」）ではなくなった
- 自分のプロンプトも返信と同じように markdown レンダリングされるようになった
- `/config` から「Default teammate model」設定を削除（チームメイトは spawn 時指定がなければリーダーのモデルを使う）

## 業務インパクト（一般企業向け）

**まず自動継続です。これは設定を変えていなくても挙動が変わります。**

上限に当たって止まるという挙動には、**意図せず安全弁として機能していた側面**があります。夜間に流したタスクが上限で止まっていたから、翌朝に気づいて確認できた。コスト管理の観点でも、上限が実質的な上限として働いていました。**自動継続が既定 on になると、この安全弁が外れます。**

止まらなくなること自体は改善です。上限を挟んだだけの中断で作業が分断されるのは、単に不便でした。ただし**「上限で止まる」を前提に組んだ運用があるなら、前提が崩れます。**該当しそうなのは、夜間や休日に長時間タスクを走らせる運用、上限到達を利用量の目安にしている運用、リセット後に人が確認してから再開する手順を組んでいる運用です。**該当するなら `/config` で切ってください。**該当しないなら、そのままの方が快適でしょう。

**セキュリティ修正の読み方**も、今回は実務的です。v2.1.233 で NTLM 認証情報の漏洩ベクトルを「塞いだ」と告知され、今回その**残りの経路**が塞がれました。つまり前回の告知の時点では、リモートファイル読み取り・セッション復元・CLAUDE.md の include・workflow スクリプト・ファイルアップロードの経路は開いたままだったということです。

これは Anthropic を責める話ではなく、**リリースノートの読み方の問題**です。「修正した」という記述は、その脆弱性クラスが全経路で閉じたことを意味しません。**同じ脆弱性クラスに対する修正が複数バージョンにまたがるのは普通のこと**です。Windows 環境で Claude Code を使っている組織は、**v2.1.234 まで上げて初めてこのベクトルが閉じる**と理解してください。

**MCP 診断のシークレット表示は、地味ですが実害のある種類のバグでした。**診断出力は共有されやすいものです。トラブルシューティングのときにログを貼る、サポートに送る、チャットに流す。そこに解決済みの値が出ていれば漏れます。**MCP サーバーの接続でトラブルシュートした履歴があるなら、その出力が残っている場所を確認しておく価値があります。**該当する値はローテーションを検討してください。

**権限プレビューのマスキングが承認者から情報を隠していた**件も同種です。承認を求める画面で肝心のコマンドや宛先が見えないなら、承認は形骸化します。**マスキングは強すぎても機能を壊す**という例です。

**`claude-api` skill のコスト削減は、数字が大きいので効きます。**約200k+トークンから約25kへ、8分の1です。この skill を読み込むセッションでは、これまで最初から200k以上のコンテキストが埋まっていたことになります。**Claude API を扱う作業をしている組織は、v2.1.234 に上げるだけで使えるコンテキストが増えます。**参照ドキュメントを必要時に読む方式への変更なので、機能が減るわけではありません。

**`/permissions` を作業中に開けるようになった**のは、日々の摩擦を確実に減らします。これまでは、権限で止まったら一度ターンを終えて設定を変えて、また依頼し直す必要がありました。今回から**現ターンの残りに適用される**ので、止まった場所から続けられます。

## 副業・個人活用視点

個人利用でいちばん体感が変わるのは、やはり**自動継続**でしょう。上限に当たって作業が止まり、リセット時刻を待って戻ってくる、という往復がなくなります。

ただし**個人こそコスト管理の観点で一度考えた方がいい**とも思います。上限で止まっていたから、それ以上使わなかった。その歯止めが外れます。従量課金ではないプランなら実害はありませんが、**「今日はここまで」の区切りが自動でつかなくなる**ことは意識しておいて損はありません。作業時間の管理を上限に任せていたなら、切っておく選択もあります。

**`claude-api` skill のコスト削減は、個人利用の方が恩恵が大きい**かもしれません。コンテキストが200k埋まった状態から始まるのと、25kから始まるのとでは、長い作業の持ちが変わります。API を触る作業をしているなら、更新する理由としてはこれだけで十分です。

**`/goal` の自動解除**も地味に効きます。認証が切れたりクレジットが尽きたりしてターンが落ちたとき、goal が armed のまま残っていると、次に何かした瞬間に意図しない動きをします。**通知を出して解除される**なら、少なくとも気づけます。バックグラウンドタスクで30分以上待つと状況を確認しにいくのも、放置事故を減らす方向です。

**GitLab の MR バッジ**は、前の2版から続く GitLab 対応の流れの一部です。v2.1.232 でプラグインマーケットプレイス、v2.1.233 で `--worktree` と `claude agents` ビューの MR URL 対応、今回でフッターとステータスラインの表示。**3版かけて GitLab が GitHub と同等の扱いに近づいています。**受託で GitLab を使う案件があるなら、この3版はまとめて価値があります。

案件として拾うなら、**「上限で止まる前提の運用棚卸し」**が具体的な切り口になります。自動継続が既定 on になったことで、夜間バッチやコスト管理の設計を見直す必要が出る組織があります。**設定ひとつの話ですが、影響範囲を洗い出すのは手間**なので、そこは仕事になります。

発信のネタとしては、**「セキュリティ修正は複数バージョンにまたがる」**という論点が書きやすいでしょう。v2.1.233 と v2.1.234 で同じ NTLM のベクトルを段階的に塞いだ実例があります。**「修正済み」という記述をどう読むか**は、更新の判断をする人全員に関係する話です。
