## 要約

2026-09-01、**Claude Code の週次利用上限 +50% プロモーションが 2026-09-13 まで延長されました。**

**公式ヘルプセンター記事が更新され、期間の記載が「2026-05-13 から 2026-09-13 まで」に書き換えられています。** 記事には明示的に、**「We've extended this promotion. Increased weekly limits now run through September 13, 2026.」** と書かれています。

**当初の期限は 2026-08-31 23:59 PT（= 2026-09-01 15:59 JST）でした。つまり、期限当日に延長が発表された形です。**

**内容は従来どおりです。**

**週次の利用上限が標準の +50%。** 5時間ごとの利用上限には適用されません。**対象は Pro / Max / Team および旧来のシート課金型 Enterprise プラン。** Free と従量課金型 Enterprise は対象外です。**2026-09-13 を過ぎると標準水準に戻り、課金内容の変更はありません。**

**そして、この記事で最も重要なのは、公式に「書かれていないこと」です。**

**一部で「2026-09-14 から恒久的に +25% になる」という情報が流れていますが、公式ヘルプセンター記事にその記載は一切ありません。**

**確認した範囲を明示します。** 公式ヘルプセンター記事、`anthropic.com/news`、`claude.com/blog`——**いずれにも、09-14 以降の恒久的な増枠に関する告知は出ていません。**

**公式が明示しているのは2点だけです。** **(1) 09-13 までは +50%。(2) その後は標準水準へ復帰。**

**この差は、運用上は決定的です。** 「9月中旬に一度下がるが、その後は今より25%高い水準で安定する」と「9月中旬に下がって、それで終わり」——**この2つでは、9月以降の作業計画がまったく変わります。**

**現時点で公式に裏付けられているのは後者だけです。**

## 何が変わったか

- **週次上限 +50% の適用期間が 2026-09-13 まで延長**（従来は 2026-08-31）
- 公式記事の記載: **「From May 13, 2026 through September 13, 2026, your weekly usage limit in Claude Code is 50% higher.」**
- 延長の明示: **「We've extended this promotion. Increased weekly limits now run through September 13, 2026.」**
- **適用範囲は週次上限のみ。5時間ごとの上限には適用されない**
- **対象: Pro / Max / Team / 旧シート課金型 Enterprise**
- **対象外: Free、従量課金型 Enterprise**
- **2026-09-13 経過後は標準水準へ復帰。課金内容の変更はなし**
- **追加の申請や設定は不要**（対象プランの利用者に自動適用）
- **「2026-09-14 から恒久 +25%」は、公式ヘルプセンター記事・`anthropic.com/news`・`claude.com/blog` のいずれにも記載がない**

## 業務インパクト（一般企業向け）

**まず、9月中旬までの計画は現行の枠で立てられます。** これが実務上の直接的な意味です。

**チームで Claude Code を使っている組織にとって、週次上限は実際に効く制約です。** 大きめの改修、リファクタリング、移行作業——**エージェントを長時間走らせる作業を計画するときに、週次の枠が足りるかどうかは現実的な検討事項です。**

**その枠が2週間分延びました。** 8月末に「9月からは枠が減る前提で計画を絞ろう」と決めていた組織は、**その判断を見直せます。**

**次に、2026-09-13 の扱いです。**

**カレンダーに入れてください。** そして、**それ以降は標準水準に戻る前提で計画を組んでください。**

**「延長されたのだから、また延長されるだろう」という期待で計画を立てるのは危険です。** 実際に一度延長されたという事実は、次も延長されることを意味しません。**公式が示しているのは 09-13 までです。**

**具体的な備えとしては、2つあります。**

**1つ目は、現在の消費量の把握です。** **標準水準に戻ったときに、いまの使い方が枠に収まるかどうか**——これは測ればわかります。`/usage` で消費を確認できるので、**「+50% の枠のうち、どのくらい使っているか」を把握しておけば、標準水準に戻ったときの影響が予測できます。**

**現在 +50% の枠の3分の2以内に収まっているなら、標準水準でも問題ありません。** 超えているなら、**9月中旬以降は作業の配分を変えるか、プランを見直すかの判断が要ります。**

**2つ目は、9月中旬に集中する作業を避けることです。** 枠が切り替わるタイミングで大きな作業を計画すると、**想定より早く枠を使い切る可能性があります。** 大きな改修は 09-13 より前か、切り替わって消費ペースが読めるようになってからにするのが無難です。

**そして、社内での情報の扱い方についてです。**

**「09-14 から恒久 +25%」という未確認情報を、社内の計画に織り込まないでください。**

**この種の情報は、SNS 経由で速く広がります。** そして、**速く広がった情報ほど、出典を確認されないまま前提になります。** 「来月から枠が増えるらしいので、それを見込んで計画しましょう」と会議で言われたときに、**「公式には記載がありません」と言える人がいるかどうか**が、後の混乱を左右します。

**確認の仕方は単純です。公式ヘルプセンター記事を見る。** そこに書かれていないなら、**現時点では存在しない**と扱う。**それだけです。**

## 副業・個人活用視点

**Pro / Max プランで Claude Code を日常的に使っている個人にとって、これは素直に良い知らせです。**

**週次上限は、実際に作業を止める制約です。** 特に Max プランで長時間のエージェント作業をしていると、週の後半で枠が近づいてくるのを意識する場面があります。**その枠が2週間分延びました。**

**やることは1つで、2026-09-13 をカレンダーに入れることです。**

**そして、それまでに自分の消費ペースを把握してください。** `/usage` で確認できます。**「+50% の枠でどのくらい使っているか」がわかれば、標準水準に戻ったときにどうなるかが予測できます。**

**もし現在の使い方が標準水準を超えるなら、選択肢は3つです。** プランを上げる。使い方を変える。**作業の配分を変える。**

**使い方を変える余地は、実は大きい。** 同日公開の Claude Fable 5.1 は、**effort を Low / Medium に落としても前世代の High 相当の結果が出ます。** **すべての作業に最高設定を使う必要はありません。** 定型的な修正や既存パターンの適用を Medium で回すだけで、消費は変わります。

**枠が減ることへの対処は、「使う量を減らす」だけでなく「同じ作業を安く済ませる」でも成立します。** こちらの方が、実務上は現実的です。

**受託をしている人は、もう1つ注意点があります。**

**顧客に「Claude Code の枠が増えています」と説明するときは、期限を必ず添えてください。** **09-13 までです。** 期限を言わずに枠の話をすると、**9月中旬以降に「話が違う」となります。**

**そして、「09-14 から恒久 +25%」を顧客に伝えないでください。** 公式に記載がありません。**顧客に伝えた未確認情報が外れたときの信頼の失い方は、伝えなかった場合の機会損失よりずっと大きい。**

**この判断基準は、AI 関連の情報を扱う仕事全般に当てはまります。** **公式ソースに書かれているか。書かれていないなら、「まだ確認できていない」と言う。** SNS で速く流れる情報ほど、この確認が抜けます。**出典を確認する習慣そのものが、この領域では専門性として機能します。**
