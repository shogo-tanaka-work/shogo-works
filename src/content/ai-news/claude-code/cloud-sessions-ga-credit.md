## 要約

Claude Code の **cloud sessions が research preview を抜けて一般提供**になりました。cloud sessions は、Claude Code を自分のマシンではなく Anthropic 側のインフラで動かす仕組みです。**ノートPCを閉じてもセッションが動き続け、別の端末から進捗を見たり指示を出したりできます。**

公式ドキュメント `code.claude.com/docs/en/claude-code-on-the-web` から research preview の表記が外れ、**対象は Pro / Max / Team、および premium seat か Chat + Claude Code seat を持つ Enterprise 利用者**と明記されました。

**この記事を今出しているのは、期限があるからです。** 発表は2026年9月23日で、当サイトの日次巡回では拾えていませんでした。**請求期限の10月7日まで残り9日です。**

**実務上の変更点は2つあります。**

**1つ目は CLI フラグです。** 正本が **`--cloud`** に変わりました。ドキュメントは "The older `--remote` spelling still works as a deprecated alias for `--cloud`" と記載しています。**`--remote` を書いたスクリプトや手順書は当面動きますが、非推奨です。** なお `--remote-control` はこれとは別機能（ローカルセッションを claude.ai から操作する）で、`--cloud` とは無関係である点もドキュメントが明示しています。**名前が似ているので混同しやすい箇所です。**

**2つ目は課金の構造です。** ドキュメントの Limitations には **"There is no separate compute charge for the cloud VM"** とあります。**cloud VM そのものには追加課金が無く、モデル利用は他の Claude / Claude Code 利用と同じレート制限を共有します。** 並列でタスクを走らせれば、その分だけ枠を消費します。**「クラウドで動かすと別料金」ではなく「いつもの枠をクラウドからも使う」**という理解が正確です。

**そして期限付きのクレジットがあります。** 公式 @ClaudeDevs アカウントの2026年9月23日の告知によると、**既存の Pro 加入者に $100、Max 加入者に $250 の一回限りクレジット**が付きます。**アカウントごとに1つ、cloud sessions にのみ使えます。** 請求は CLI の `/claim-credit` か告知内のリンクから行い、**GitHub 連携が必須**です。**請求期限は2026年10月7日**、報道ベースでは未使用分の失効は**2026年11月4日**とされています。

告知直後に「cloud sessions は別料金になったのか」という混乱が生じ、Anthropic 側が約4時間半後に補足しています。**クレジットは通常のプラン枠より先に消費されるバッファであって、別建ての従量課金ではありません。** 請求しなくても cloud sessions は使えます。**請求すると、通常枠を使い始める前にクレジットから消費される**という関係です。

**情報源の制約を明記します。** GA であること、フラグの変更、課金構造は**公式ドキュメントの本文から直接確認**しました。**一方、クレジットの金額・請求期限・失効日は公式 X アカウントの告知と複数報道が出所で、公式ドキュメントや公式ブログには記載が見つかりません。** 金額と日付は、公式アカウントの文言と複数報道が一致する範囲に限って記載しています。**請求前に、CLI で `/claim-credit` を実行して表示される条件を必ず確認してください。**

## 何が変わったか

- **cloud sessions が research preview を脱して一般提供**。対象は Pro / Max / Team、および premium seat か Chat + Claude Code seat の Enterprise 利用者
- **CLI の正本フラグが `--cloud` に変更**。`--remote` は非推奨エイリアスとして当面動作
- `--remote-control` は別機能（ローカルセッションの遠隔操作）で、`--cloud` とは無関係
- 起動元はブラウザ（claude.ai/code）、モバイルアプリの Code タブ、デスクトップアプリ、ターミナル、routines
- **cloud VM 自体への追加課金は無し**。モデル利用は通常のプランのレート制限を共有
- **Pro に $100、Max に $250 の一回限りクレジット**（cloud sessions 専用、アカウントにつき1回）
- **請求期限は2026年10月7日**。未使用分の失効は2026年11月4日（報道ベース）
- 請求には **GitHub 連携が必須**。`/claim-credit` またはリンク経由
- クレジットは通常のプラン枠より先に消費されるバッファ。請求しなくても cloud sessions は利用可能

## 業務インパクト（一般企業向け）

**まず着手すべきは `--remote` の棚卸しです。** CI スクリプト、社内手順書、オンボーディング資料に `--remote` が残っていないか検索してください。**非推奨エイリアスは動きますが、いつ外れるかはアナウンスされていません。** 動いているうちに書き換えるのが安い対応です。**「壊れてから直す」にすると、壊れる先が CI の場合は影響範囲が読めません。**

**次に、組織側の可否設定を確認する話があります。** cloud sessions は組織のポリシー `allow_remote_sessions` で制御されます。加えて**注意が必要な制約が2つ**あります。**Zero Data Retention を有効にしている組織は cloud sessions を利用できません。** また **IP allowlisting を有効にしている組織では、Anthropic ホストのセッションがすべて認証エラーになります**。cloud sessions は Anthropic 側のインフラから API を呼ぶためです。**セキュリティ設定を固めた組織ほど、使えない側に倒れます。** 使わせる方針なら、情シスと先に握っておく必要があります。

**クレジットは個人の Pro / Max のみが対象です。** Team / Enterprise は cloud sessions 自体は使えますが、告知はクレジットの対象として Pro と Max しか挙げていません。**「会社のアカウントで請求できるはず」と案内すると外します。**

**評価の観点では、GA になったこと自体が意味を持ちます。** research preview のままでは本番運用の稟議が通りにくい組織があります。**製品ライフサイクル上の位置づけが変わったので、可用性・サポート・データ保持の条件を改めて確認したうえで、評価を再開する価値があります。** ただし self-hosted environments 側は public beta のままなので、**自社インフラで動かす前提なら成熟度は別に評価してください。**

## 副業・個人活用視点

**Pro / Max に加入していて GitHub を使っているなら、10月7日までに請求しておく価値があります。** 請求自体は `/claim-credit` を打つだけで、費用はかかりません。**使わなければ11月4日に失効するだけです。** 「いつ使うか決まっていないから後で」と先送りすると、請求期限のほうが先に来ます。

**個人の使いどころとして現実的なのは、長時間かかって手を離しておける作業です。** 大きめのリファクタリング、依存ライブラリの一括更新、テストを通すまでの繰り返し、ドキュメントの全面書き換え。**ノートPCを閉じて出かけられるというのが、cloud sessions の実質的な価値です。** 副業で本業の合間に作業する人にとって、**「作業の続きを機械に預けて移動する」ができるのは時間の使い方が変わります。**

**制約も正確に押さえておきます。** **GitHub 連携が前提**なので、GitHub に置いていないプロジェクトはそのままでは対象外です（`CCR_FORCE_BUNDLE=1` でローカルリポジトリを送る手はありますが、その場合セッションから元のリモートへ push は返せません）。また **cloud VM は無課金でも、モデル利用は通常のプラン枠を消費します。** 並列で3本走らせれば3本分減ります。**クレジットを使い切った後は、いつもの枠が減るだけ**という点は、請求前に理解しておいたほうがよいところです。

**クレジットの条件は公式ドキュメントに載っていません。** 金額と期限は公式アカウントの告知と報道が出所です。**請求時に CLI が表示する条件を一次情報として確認してください。**
