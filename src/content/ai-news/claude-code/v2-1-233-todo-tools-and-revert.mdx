## 要約

Claude Code **v2.1.233** が 2026-08-14 に公開されました。目立つ変更が2つあります。

1つ目は **Todo / タスク追跡ツールが新しいモデルで使えなくなった**ことです。TaskCreate / TaskGet / TaskUpdate / TaskList と TodoWrite が、**Opus 4.8、Sonnet 5、Fable 5、Mythos 5 およびそれ以降のモデルでは提供されなくなりました**。`CLAUDE_CODE_ENABLE_TODO_TOOLS=1` を設定すれば戻せます。設定を触っていなくても挙動が変わる種類の変更です。

2つ目は**前版の権限変更が一部 revert された**ことです。v2.1.232 で入った Bash の権限変更のうち、Windows の Cygwin 形式シンボリックリンクに関するものと、入力リダイレクト（`< file`）に関するものが巻き戻されました。公式は「より狭い範囲の版を後のリリースで戻す」としています。あわせて、Windows で auto mode が通常の `cd <dir> && <command> > file` のような Bash コマンドで繰り返し手動承認を求める v2.1.232 の退行も修正されました。**修正が広すぎて正常な操作まで止めていた**という形です。

一方で**新しいセキュリティ修正が1件**入っています。Windows のパスを NT デバイスプレフィックス（`\??\`）で綴ると UNC パス検証を回避できた問題が修正され、**NTLM 認証情報の漏洩ベクトル**が塞がれました。

機能追加もあります。`--worktree` フラグと `claude agents` ビューが **GitLab のマージリクエスト URL** に対応しました（MR は `!N` として表示されます）。Anthropic 上流のアプリゲートウェイには `forward_user_identity` 設定（オプトイン）が加わり、サインイン中のユーザー identity をヘッダーとして送ることで、**ゲートウェイの背後のプロキシがユーザー単位に支出を割り当てられる**ようになりました。Linux では Bash ツールのコマンドに対するメモリ cgroup 対応（`CLAUDE_CODE_TOOL_MEMORY_LIMIT`、オプトイン）が入り、暴走したビルドがセッションを止めなくなりました。`CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS` で WebFetch のセッション URL キャッシュ TTL も設定できます（既定の15分は変更なし）。

修正では、権限プロンプト待ちの間に環境が停止したときクラウドセッションが失われた扱いになる問題、固定タイムアウトで長時間ストリームを切るサーバーに対して MCP v2 接続が subscriptions/listen ストリームを開き続ける問題、Claude Desktop / VS Code 配下で権限プロンプト時に Notification フックが発火しない問題、サンドボックス有効時に Linux のアイドルセッションが CPU コアを1つ占有し続ける問題などが直りました。

## 何が変わったか

- **Todo / タスク追跡ツールが Opus 4.8、Sonnet 5、Fable 5、Mythos 5 以降で無効化**（`CLAUDE_CODE_ENABLE_TODO_TOOLS=1` で復帰）
- v2.1.232 の Bash 権限変更のうち、Cygwin symlink と入力リダイレクト（`< file`）に関するものを revert
- Windows で auto mode が `cd <dir> && <command> > file` に承認を求める v2.1.232 の退行を修正
- Windows の NT デバイスプレフィックス（`\??\`）による UNC パス検証回避を修正（NTLM 認証情報の漏洩ベクトル）
- `--worktree` と `claude agents` ビューが GitLab のマージリクエスト URL に対応
- `forward_user_identity`（オプトイン）でユーザー identity をヘッダー送出し、プロキシ側でユーザー単位の支出割り当てが可能に
- `CLAUDE_CODE_TOOL_MEMORY_LIMIT`（Linux、オプトイン）で Bash コマンドをメモリ cgroup 制限
- `CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS` で WebFetch のキャッシュ TTL を設定（既定15分は変更なし）
- `claude self-hosted-runner` のセッション開始が高速化
- print モードで未知のモデル ID に `[claude-code:unrecognized_model]` を stderr 出力

## 業務インパクト（一般企業向け）

**まず Todo ツールの件です。** これは設定を変えていなくても挙動が変わります。

新しいモデル（Opus 4.8、Sonnet 5、Fable 5、Mythos 5 以降）を使っている場合、Claude Code はタスクリストを作らなくなります。**タスク管理をエージェントに任せる前提で手順書を書いていた組織は、更新後に「動きが変わった」と見えます。**公式は理由を説明していませんが、新しいモデルが外部のタスク管理ツールなしでも作業の筋道を保てるようになった、という判断が背景にあると読むのが自然でしょう。

対応は2択です。`CLAUDE_CODE_ENABLE_TODO_TOOLS=1` で戻すか、戻さずに様子を見るか。**まず戻さずに使ってみることを勧めます。**戻すのはいつでもできますし、ツールを外した状態が新しい既定である以上、そちらが想定された動きです。ただしタスクリストの出力を前提にした自動処理（ログ収集やダッシュボード連携）を組んでいる場合は、壊れる前に確認してください。

**次に権限修正の巻き戻しです。** 前日の v2.1.232 で「Cygwin symlink 経由の権限バイパスを修正した」と告知されましたが、その修正が1日で revert されました。理由は明示されていませんが、Windows で通常の `cd && command > file` にまで承認を求めるようになった退行が同時に修正されていることから、**修正の範囲が広すぎて正常な操作を止めていた**と読めます。

実務的な意味は2つあります。1つは、**Cygwin symlink 経由の経路は現時点で塞がっていない**ということ。Windows 環境で Git Bash を使っている場合、この経路は依然として残ります。もう1つは、**セキュリティ修正が必ずしも定着するとは限らない**ということです。「修正が入ったから安心」ではなく、次のバージョンで戻っていないかを確認する必要があります。とくに更新の判断材料としてリリースノートを使っている組織は、**前版の内容が後版で否定されることがある**前提で読むべきでしょう。

一方、NT デバイスプレフィックスの修正は新規に入ったもので、こちらは NTLM 認証情報の漏洩に関わります。**Windows 環境の優先度は引き続き高い**です。

`forward_user_identity` は、ゲートウェイを立てている組織にとって実用的な追加です。これまでゲートウェイ経由の利用は支出が一括で見えるだけでしたが、**プロキシ側でユーザー単位に割り当てられる**ようになります。部門別の按分をしたい場合の足場になります。オプトインなので、必要な組織だけが有効にすれば済みます。

Linux のメモリ cgroup 対応も地味に効きます。**暴走したビルドがセッションごと巻き込む**という事故は、CI 的な使い方をしていると珍しくありません。`CLAUDE_CODE_TOOL_MEMORY_LIMIT` で上限を切っておけば、ビルドが死んでもセッションは生き残ります。

## 副業・個人活用視点

個人利用で最初に気づくのは、やはり **Todo ツールが消えたこと**でしょう。作業の進行がタスクリストで見えていたのが、見えなくなります。

これは好みが分かれる変更です。リストが出ることで進捗が把握しやすかった人には後退に見えますし、リストの生成自体がノイズだった人には改善に見えます。**`CLAUDE_CODE_ENABLE_TODO_TOOLS=1` で戻せるので、両方試して決めればいい**話です。判断材料が手元にあるうちに決めておくと、後で悩まずに済みます。

`CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS` は、調査系の作業をする人には使いどころがあります。既定は15分で、同じ URL を何度も取りに行かない仕組みですが、**更新の速いページを追っているときは短くしたい**場面があります。逆に長い調査で同じ資料を何度も参照するなら伸ばす手もあります。

GitLab のマージリクエスト対応は、クライアントが GitLab を使っている案件で効きます。**`--worktree` に MR の URL を渡せる**ようになったので、GitHub と同じ流れでレビュー作業に入れます。前版でプラグインマーケットプレイスの GitLab 対応が入り、今回で作業フロー側も揃った形です。受託で GitLab に当たることが多いなら、この2版はまとめて価値があります。

案件として拾うなら、**更新に伴う挙動変更の吸収**が切り口になります。Todo ツールの無効化は、それを前提にした手順書やドキュメントを持つ組織では書き換えが必要です。加えて前版の権限修正が巻き戻された件は、**「リリースノートをどう読むか」を整理する提案**につながります。前版の内容が後版で否定されることがある以上、更新のたびに差分を追う体制が要ります。

発信のネタとしては、Todo ツールの有無で作業の進み方がどう変わるかの比較が読まれるでしょう。**公式が理由を説明していないぶん、実際に使った所感には価値があります。**タスクリストが消えて困る作業と、むしろ速くなる作業を分けて書けると、読者が自分の設定を決められます。
