## 要約

Claude Code 2.1.243 が 2026-08-24 に公開されました。直前の 2.1.240 と 2.1.241 が公式記載 `Bug fixes and reliability improvements` の1行だけだったのに対し、**本版は組織運用に直接効く設定が4つ同時に入った、まとまりの大きいリリース**です。

もっとも影響が大きいのは **`modelPricing`** です。これは managed setting として、**組織の契約単価（per-model rates）と割引率（discount multiplier）を、`/cost`・ステータスライン・テレメトリのコスト表示に反映させる**設定です。裏を返すと、これまでこれらの数字はすべて**定価（list price）で計算されていた**ということです。契約単価で使っている組織にとっては、画面に出ていた金額と実際の請求額がずれていたことになります。

**`modelPicker`** は `/model` の選択リストを、順序とラベル付きで組織側が定義できる設定です。Vertex / Bedrock 形式を含むどの ID 表記も受け付け、既定のラインナップに**追加する**形でも、**置き換える**形でも使えます。使ってよいモデルを絞る、社内の呼び名でラベルを付ける、といった運用が設定ファイルでできるようになりました。

**`promptCacheTtl` と `subagentPromptCacheTtl`** は、プロンプトキャッシュの保持時間をメイン会話とサブエージェントで分ける設定です。API キー利用者およびクラウドプロバイダー利用者向けで、公式が挙げる使い方は「**メイン会話は1時間のキャッシュを維持しつつ、サブエージェントは5分に据え置く**」というものです。長時間の対話は文脈を持ち続けさせ、使い捨てのサブエージェントには持たせない、という配分になります。

認証面では、**`/login` に「Sign in with your Console account（Anthropic Console アカウントでサインイン）」という鍵レスの選択肢が追加**されました。公式表記では推奨（recommended）で、API キーの作成と並ぶ選択肢として提示されます。目的は明快で、**API キーの発行を許可していない組織でもサインインできるようにする**ためです。

可視性の追加も複数あります。`/usage` には **Loops の内訳**が入り、ループ単位で実行回数・総トークン・1回あたりトークン・最終実行が見えるようになりました。公式は「暴走したり冗長になっている `/loop` タスクを見つけやすくするため」と説明しています。`/status` には、上位の managed source が有効なため適用されなかった managed settings ソースを列挙する **`Skipped sources`** 行が追加されました。`/mcp` と `/plugins` では、組織が認証を管理している claude.ai コネクタに **`managed` マーカー**が付きます。`/tasks` とエージェント詳細ダイアログには、各サブエージェントが動いたモデルと effort level が表示されます。

修正側では、**非対話（`-p`）／SDK セッションでリモート MCP サーバーが切断後に一度も復帰しなかった不具合**が直りました。自動再接続するか、失敗として報告されるようになります。無人実行で MCP を使う構成では、これまで沈黙したまま壊れていた可能性がある箇所です。

## 何が変わったか

- **`modelPricing`**（managed setting）: 組織の契約単価と割引率を `/cost`・ステータスライン・テレメトリのコスト表示に適用。従来は定価計算
- **`modelPicker`**: `/model` の選択リストを順序・ラベル付きで定義。Vertex / Bedrock を含む任意の ID 表記に対応。既定リストへの追加と置き換えの両方が可能
- **`promptCacheTtl` / `subagentPromptCacheTtl`**: プロンプトキャッシュの TTL をメイン会話とサブエージェントで分離（例: メイン1時間 / サブエージェント5分）。API キー利用者・クラウドプロバイダー利用者向け
- **`/login` → Anthropic Console の鍵レスサインイン**: API キーを発行せずサインインできる選択肢を追加（公式表記で推奨）
- `/usage` に **Loops 内訳**（ループ単位の実行回数・総トークン・1回あたりトークン・最終実行）
- `/status` に **`Skipped sources`**（上位の managed source があるため適用されなかった設定ソースの一覧）と、Claude Code on the web 向け GitHub 接続状態（Pro / Max）
- `/mcp`・`/plugins` に、組織が認証を管理する claude.ai コネクタの **`managed` マーカー**
- `/tasks` とエージェント詳細に、サブエージェントが動いたモデルと effort level を表示
- 修正: 非対話（`-p`）/ SDK セッションでリモート MCP サーバーが切断後に復帰しない問題
- 修正: デスクトップアプリ起点の MCP サインインが client ID metadata document 対応サーバー（例: Linear）で `Invalid redirect URI` になる問題
- 修正: サーバー側の一時的な無効化がキャッシュされ、起動時に auto mode が使えなくなる問題
- 修正: API 過負荷時に auto mode のツール呼び出しが約1分待たされた末に `temporarily unavailable` で拒否される問題
- 修正: `/resume` が直近50セッションしか一覧しない制限（スクロールで追加読み込み）

## 業務インパクト（一般企業向け）

**まず確認すべきは `modelPricing` です。** 契約単価で Claude を使っている組織なら、**これまで `/cost` やステータスラインに出ていた金額は自社の実勢ではありません**。定価ベースの数字を見て「思ったより高い」と判断していたなら、その判断の前提が変わります。逆に、テレメトリのコスト値を社内のダッシュボードへ流している場合、**この設定を入れた瞬間に過去との連続性が切れます**。切り替えの日付を記録しておかないと、後から見た人が「使用量が急に減った」と誤読します。

**`modelPicker` は、モデル統制を「お願い」から「設定」に移せる機能です。** どのモデルを使うかは、これまで各開発者の選択に委ねられていました。コスト面でも品質面でも、組織として揃えたい場面はあります。`modelPicker` で既定リストを置き換えれば、選べる範囲そのものを定義できます。**ただしこれは managed settings の運用が前提です。** 配布の仕組みが無い組織では、設定ファイルが手元にあるかどうかで挙動が分かれます。同時に入った `/status` の `Skipped sources` は、まさにその「配ったつもりの設定が効いていない」状態を見つけるための行です。**モデル統制を入れるなら、`Skipped sources` の確認手順もセットで配ってください。**

**鍵レスのコンソールサインインは、導入可否そのものを動かす変更です。** API キーの発行を禁止している組織は珍しくありません。長期の資格情報がローカルに置かれることを避けたい、という理由は妥当です。その方針を維持したまま Claude Code を導入できる経路ができました。**セキュリティ部門との議論が「API キーを許可するか」から「コンソールアカウントの管理をどうするか」へ移ります。** 論点が変わるだけで、なくなるわけではない点には注意してください。

**プロンプトキャッシュの TTL 分離は、コストと文脈保持のトレードオフを設計する余地が増えたということです。** メイン会話を1時間保つ設定は、長時間の作業でキャッシュが切れて再送が発生するのを防ぎます。一方サブエージェントは短命で、長い TTL は無駄になりやすい。**この配分は、自社の使い方を測ってから決める話です。** 既定のまま使うのも判断のひとつで、設定できるようになったこと自体は「設定すべき」を意味しません。

**運用監視の観点では `/usage` の Loops 内訳が効きます。** `/loop` のような繰り返し実行は、止め忘れや条件の緩さがそのままトークン消費に出ます。ループ単位で回数とトークンが見えるようになったことで、**「誰かのループが回りっぱなし」を後追いで特定できる**ようになりました。月次のコストレビューに、この画面の確認を入れる価値があります。

## 副業・個人活用視点

**個人で API キー運用をしている場合、`promptCacheTtl` は実際に効く設定です。** 長い作業セッションでキャッシュが切れて文脈を再送すると、そのぶん課金が乗ります。メイン会話の TTL を伸ばして、サブエージェントは短いままにする。**この一行の設定が、月末の請求額に見える差として出る**種類の変更です。まず自分の使い方で、どのくらいの間隔で作業を中断しているかを見てから決めてください。

**支援先へ Claude Code を導入する立場なら、鍵レスサインインは提案の通し方を変えます。** 「API キーを配る前提」で止まっていた案件は、これで再提案できます。情シスに対して、長期資格情報を配らずに済む構成を示せることは、それだけで話の入口が変わります。**導入が止まっていた理由が技術ではなく運用方針だったケースほど、この変更が効きます。**

**`modelPricing` と `modelPicker` は、伴走支援のメニューとして具体的に説明できる材料です。** 「AI のコストが見えない」「どのモデルを使えばいいかバラバラ」という相談は頻出しますが、抽象的な助言で終わりがちでした。managed settings に契約単価とモデルリストを書く、という**手を動かせる作業として提示できる**ようになりました。設定を入れて終わりではなく、`Skipped sources` で効いているか確認するところまでを一連の手順にすると、成果物として渡せます。

**`/usage` の Loops 内訳は、自分の使い方を見直す道具としても使えます。** 自動化を組んでいるほど、どのループがトークンを食っているかは把握しづらくなります。**回数ではなく「1回あたりトークン」を見る**と、設計が雑なループが浮き上がります。個人の副業でコストが直接利益を削る立場なら、ここを定期的に見る習慣は割に合います。
