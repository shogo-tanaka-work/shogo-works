## 要約

Claude Code v2.1.221 は、バグ修正のみだった v2.1.220 に続いて公開された大型リリースです。目立つのは 2 つのセキュリティ修正で、いずれも「権限チェックをすり抜けてコマンドが実行される」という、承認フローを前提に運用している組織にとって前提が崩れる種類の問題でした。

1 つ目は Bash tool の権限チェックのバイパスです。zsh の `[[ ]]` 正規表現条件文の中にコマンドを隠すと、権限チェックを迂回して実行できてしまう挙動が修正されました。該当するコマンドは今後 permission プロンプトが表示されます。2 つ目は Windows の PowerShell 権限チェックで、クォート文字を含むパスの扱いを誤っていた問題です。こちらも対象パスは承認を求めるようになりました。

sandbox 周りでは、認証情報ファイル向けの `mode: "mask"` が追加されました。Linux / WSL では、sandbox 内のコマンドが読むのはセンチネル値の複製（ファイル全体、または `extract` 正規表現で捕捉したスパンだけ）で、実際の値は egress のタイミングで sandbox proxy が差し替えます。つまり「sandbox 内のプロセスに本物の API キーを渡さないまま、外部への通信は成立させる」構成が取れるようになりました。macOS ではファイルマスキングは `deny` にフォールバックします。

運用面の変更もまとまっています。`/plugin` からインストールしたプラグインは安全な場合に即時有効化され、これまで必要だった `/reload-plugins` が不要になりました。バックグラウンドセッションの既定挙動は「作業保全のため commit と push を行い、必要なときだけ draft PR を開き、CLAUDE.md の git 指示に従い、最後に成果物の所在を報告する」に変更されています。`/fork` で分岐したセッションは元のチェックアウトを共有せず、自前の worktree を作るようになりました。

VSCode 拡張には Focus view が入りました。ツール実行のログを畳んで、ターンごとの要約と実行中インジケータだけを表示する切り替えで、`Ctrl+Alt+F` または「Claude Code: Toggle Focus view」コマンドで使えます。

## 何が変わったか

- zsh の `[[ ]]` 正規表現条件文に隠したコマンドが Bash tool の権限チェックを迂回できた問題を修正（該当コマンドは permission プロンプトを表示）
- Windows の PowerShell 権限チェックで、クォート文字を含むパスが承認をスキップしていた問題を修正
- sandbox の認証情報ファイルに `mode: "mask"` を追加（Linux / WSL。macOS は `deny` にフォールバック）
- VSCode 拡張に Focus view を追加（`Ctrl+Alt+F` で切り替え）
- `claude plugin validate` が、Claude Desktop の managed marketplace sync で拒否される名前を事前警告
- `claude-api` skill に `prompt-audit` サブコマンドを追加（旧モデル向けに書かれたプロンプト・ツール説明の監査）
- `/plugin` インストール後、安全な場合はプラグインが即時有効化（`/reload-plugins` 不要）
- バックグラウンドセッションが既定で commit / push を行い、必要時のみ draft PR を作成、最後に成果物の所在を報告
- `/fork` したセッションが自前の worktree を作成
- `/status` がセッション種別（`interactive` / `attached` / `unattended`）を表示
- Stats パネルが cache トークンを集計に含め、input / output / cache read / cache write の内訳を表示
- Google Vertex AI で Claude 4.5 世代以降の tool search を再有効化
- auto mode の権限チェックが会話プレフィックスのキャッシュを再利用し、prompt cache コストを削減
- Team / Enterprise の spend limit メッセージが、組織の月次上限ではなく個人の上限を正しく示すよう修正
- MCP まわりの修正多数（`--mcp-config` のサーバーが print モードで初回ターン前に接続されない問題、スリープ復帰時のトークン同時更新競合など）

## 業務インパクト（一般企業向け）

権限チェックのバイパス修正は、Claude Code を「危険なコマンドは人間が承認する」前提で導入している組織にとって最優先の更新です。zsh の条件文を使った迂回は、承認ログを見ても実行されたコマンドが見えないため、監査記録の信頼性そのものに関わります。Windows の PowerShell パス問題も同様で、承認フローを社内ルールに組み込んでいる場合は、バージョン更新を待たずに配布計画へ入れる価値があります。

sandbox の `mode: "mask"` は、情シス・セキュリティ部門が扱いやすい選択肢を増やす追加です。これまでは「認証情報ファイルを sandbox 内から読ませる（実値が露出する）」か「`deny` で読ませない（動かない機能が出る）」の二択でしたが、実値を渡さずに外部通信だけ成立させる第三の選択肢ができました。macOS では `deny` にフォールバックするため、OS ごとに挙動が変わる点は運用ドキュメントに明記しておく必要があります。

バックグラウンドセッションの既定挙動変更は、社内の Git 運用ルールに直接触れます。既定で commit と push を行うようになったため、「AI が勝手に push しない」ことを前提にしていた組織は、CLAUDE.md の git 指示を明示的に書き直しておくべきです。Claude Code は CLAUDE.md の指示に従うと明記されているので、ルールを文書化していれば挙動を制御できます。逆に言えば、文書化していない組織は既定挙動をそのまま受け入れることになります。

プラグインの即時有効化は利便性の改善ですが、社内配布プラグインを段階的に検証している組織では「インストール = すぐ有効」に変わる点を配布手順に反映しておくと混乱を避けられます。

## 副業・個人活用視点

個人開発でセキュリティ設定まで細かく詰めていないケースは多いですが、`mode: "mask"` は副業案件で他社の API キーを扱うときに効きます。クライアントから預かった認証情報を sandbox 内のプロセスに実値のまま渡さずに済む構成は、「預かった鍵の扱い」を説明する材料になります。契約時のセキュリティ質問への回答としても使えます。

Focus view は、画面共有しながら作業する場面で価値があります。ツール実行のログが延々と流れる画面はクライアントに見せづらく、要約だけ表示できると進行状況を説明しやすくなります。ペアプロ形式のコンサルティングや、講座の実演で使いやすい追加です。

バックグラウンドセッションの commit / push 既定化は、複数案件を並行で回している個人には効率面でプラスですが、リポジトリを取り違えたときの影響も大きくなります。案件ごとに CLAUDE.md へ git 運用ルールを書いておくのが実質的な安全装置になります。`/status` でセッション種別が見えるようになったのも、複数セッションを同時に走らせる運用では地味に効く改善です。

`claude-api` skill の `prompt-audit` は、過去に受託して納品したプロンプトやツール定義を新しいモデル向けに見直す作業に使えます。旧モデル向けの書き方が残っている箇所を洗い出せるため、保守案件の提案材料にしやすい機能です。
