## 要約

GPT-5.4 と GPT-5.4 mini が、2026-08-31 に Codex から退役します。対象は ChatGPT 認証で Codex を使っているユーザーです。OpenAI API 経由および API キーによるセッションでは、これらのモデルは引き続き利用できます。認証の経路によって扱いが変わる点が、まず押さえるべきところです。

推奨される移行先は次のとおりです。

- `gpt-5.4` → `gpt-5.6-terra`（GPT-5.6 Terra）
- `gpt-5.4-mini` → `gpt-5.6-luna`（GPT-5.6 Luna）

公式が更新対象として挙げているのは、ワークスペースの既定モデル、保存済み設定、管理された構成（managed configurations）、カスタムエージェント、スケジュール済みタスクです。この列挙自体が、実務上の面倒さを物語っています。モデル名は1箇所で指定するものではなく、使っているうちにあちこちへ散らばります。特にスケジュール済みタスクは、普段目に入らないところで動き続けるため、退役当日まで気づかないという事故が起こりやすい対象です。

タイミングとして見逃せないのは、移行先の Terra と Luna が前日の 2026-07-30 に値下げされたモデルであることです。Luna は約80%減、Terra は約20%減でした。旧世代を畳んで新世代へ寄せる動きと、その新世代の価格を下げる動きが、同じ週に並んでいます。

## 何が変わったか

- GPT-5.4 と GPT-5.4 mini が 2026-08-31 に Codex から退役する
- 対象は ChatGPT 認証のユーザー。OpenAI API 経由および API キーセッションでは引き続き利用可能
- 移行先: `gpt-5.4` → `gpt-5.6-terra`、`gpt-5.4-mini` → `gpt-5.6-luna`
- 期限までに更新が必要な対象: ワークスペースの既定モデル、保存済み設定、managed configurations、カスタムエージェント、スケジュール済みタスク

## 業務インパクト（一般企業向け）

やることは明確で、期限も決まっています。難しいのは「どこにモデル名が書かれているか」を漏れなく洗い出すことです。

優先して確認すべきは、人が普段見ない場所です。スケジュール済みタスクは典型で、設定した本人以外は存在を知らないことすらあります。managed configurations も同様で、情シスや管理者が過去に配布した設定に古いモデル名が残っていると、利用者側では気づけません。カスタムエージェントは作成者ごとに散らばるため、組織として一覧を持っていないと網羅できません。

したがって、対応の第一歩は棚卸しの担当を決めることです。「各自で確認してください」という周知だけでは、スケジュール済みタスクと managed configurations が残ります。管理者側で把握できる範囲を先に洗い、残りを利用者へ依頼する二段構えが現実的です。

ChatGPT 認証と API キーで扱いが違う点も、社内周知では明示すべきです。API を使っている開発チームは今回の退役の対象外なので、「Codex の話であってうちの API 連携は関係ない」という切り分けが必要になります。逆に、この区別を伝えないと、不要な対応工数が発生します。

構造的な教訓としては、モデル名の指定箇所を集約しておく設計の重要性です。モデルの退役は今後も繰り返し起こります。今回の対応をその場しのぎで済ませると、次の退役でも同じ棚卸しをやることになります。可能なら、モデル指定を設定の1箇所に寄せ、そこを変えれば全体に反映される構成へ寄せておく方が、長期的には安上がりです。

コスト面では、移行が値下げと重なっているのは幸運です。Terra と Luna は 2026-07-30 に値下げされており、Luna は約80%減です。退役対応の棚卸しをするタイミングで、どの処理をどのモデルに割り当てるかも見直すと、対応工数を無駄にせずに済みます。単に置き換えるのではなく、Luna で足りる処理を Luna に寄せる判断まで含めて進めるのが得です。

## 副業・個人活用視点

個人で Codex を使っている場合も、確認すべき箇所は同じです。ワークスペースの既定モデル、保存済み設定、自作のカスタムエージェント、そしてスケジュール済みタスク。特にスケジュール済みタスクは、一度設定したまま忘れているものがある可能性が高い対象です。8月31日を過ぎて動かなくなってから気づくより、今のうちに一覧を見ておく方が確実です。

複数のクライアント環境で Codex を使っているなら、環境ごとに確認が必要です。自分のワークスペースだけ直しても、案件側の設定が古いままなら止まります。委託先の環境で自分がカスタムエージェントを作っている場合、その棚卸しは自分の責任範囲になる可能性があります。契約の切れた案件でも、自分が作った設定が残っていることはあります。

移行先の Luna が約80%値下げされた点は、個人利用でははっきり効きます。`gpt-5.4-mini` を使っていた処理をそのまま `gpt-5.6-luna` に移すだけで、コストが下がる可能性があります。退役対応が結果的にコスト削減になるという珍しいパターンなので、面倒がらずに進める理由になります。

API キーセッションでは引き続き GPT-5.4 が使えるという点は、覚えておくと役に立ちます。どうしても旧モデルの挙動が必要なケース（既存の出力と互換を取りたい、検証済みのプロンプトを動かし続けたい）があるなら、API 経由という逃げ道があります。ただし API 側の退役スケジュールは別途あり得るので、恒久的な解決策として当てにするのは避けた方が無難です。
