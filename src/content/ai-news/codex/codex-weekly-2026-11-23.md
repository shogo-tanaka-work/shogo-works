## 今週の要点

**セキュリティ側の修正が2件あります。0.169.x を使っているなら 0.170.0 以降へ上げてください。**

- **権限更新時と子スレッドで、既存のサンドボックス制限が失われていました** (0.170.0)。制限が外れた状態で動く余地があったため、優先度が高い修正です。
- **MCP OAuth の資格情報が、取り消し・ログイン・ログアウト中に競合していました** (0.170.0)。古い資格情報の書き込みが上書きされる経路がふさがれ、再接続も取り消し安全になりました。

**既定の変更が2つあります (0.171.0)。**

- **GPT-6.2 Sol と Astra がモデルカタログに入り、Sol が既定の選択になりました。** 別のモデルを前提にした運用はカタログ設定を確認してください。
- **TUI ワークスペースが既定で有効になりました。** 検索可能なドキュメントプレビュー、画像プレビュー、サブエージェントのトランスクリプトが本会話の横に並びます。

0.169.1 は Chores のみで、公式のハイライトはありません。

## 変更一覧

**サンドボックスと権限** — Linux ネットワークサンドボックスで **`request_key` をブロック**、**x32 syscall に seccomp 制限を強制**、Windows でサンドボックス設定を繰り返したときのファイル権限の保持 (0.170.0, 0.171.0)。**作業ディレクトリを変えても権限プロファイルが保たれる**ように、**遅延した完了イベントが新しいターンの承認を取り消さない**ように修正 (0.171.0)。サンドボックスのドキュメントが権限プロファイルとファイルシステムのルールを説明するよう更新 (0.170.0)。

**資格情報と企業連携** — **ID トークンを refresh token なしで発行する IdP での enterprise MCP サインイン**を修正、ワークロード ID 認証向けの **SPIFFE JWT-SVID** 対応、Deno と Google Cloud SDK 向けのマネージド CA 既定値、放置された信頼済み Git リポジトリの回収 (0.171.0)。

**リモート実行** — `codex exec --remote` で既存の app server 上の非対話セッションを開始・再開、TUI から `/rc` と `/remote` でローカルのリモートコントロールとペアリングコードを管理 (0.171.0)。

**TUI と MCP** — カスタム MCP ステータスラインの選択と作成（`tui_extensions_statusline` 有効時）、プロンプトコンポーザの undo / redo ショートカット、セッション切り替え時の下書き・キュー・入力の保持 (0.171.0)。OTLP HTTP エクスポータの**認証ヘッダーの自動更新**、環境をまたぐ同名 MCP サーバーの利用（実験的）、TUI のリアルタイム音声通話の WebRTC ネゴシエーション (0.170.0)。
