## 要約

OpenAI Codex の stable 版 0.148.0 が 2026-08-18 にリリースされました。パッチではなく、機能追加が複数入った回です。

**会話のエクスポート**が入りました。`/export` で TUI の会話全体を Markdown として出力でき、出力先はクリップボードかファイルを選べます。作業ログを手作業で議事録や引き継ぎ資料へ写す必要がなくなります。

**セッション操作**が広がりました。`codex exec fork` でセッションを分岐できます。加えて TUI の resume picker からセッションのアーカイブと復元が可能になりました。1 本の長い会話を途中から分岐させて別案を試す、終わった作業を一覧から片付ける、という運用ができます。

**起動時の待ち時間**も改善されています。TUI の初期化中にプロンプトを下書きでき、resume と fork の進捗が起動中に表示されます。

**コストの可視化**として、対象ワークスペースでは推定スレッドクレジットまたはコストが `/status`、ステータスライン、ターミナルタイトルに表示されるようになりました。

**プロバイダー**に Amazon Bedrock Runtime が組み込みで追加されました。AWS プロファイル、リージョン、GPT-5.6 のルーティングに対応します。

**Hooks** は非同期でコマンドを実行できるようになり、MCP ツールを呼び出せるようになりました。既存機能の派生改善という位置づけですが、影響は小さくありません。

バグ修正も広範囲です。モデル切替と設定の永続化、セッション再開時のディレクトリ・ポリシーの復元、一時的な障害を跨いだプロバイダーの再接続、ターミナル入力と認証フロー、CRLF や折り返し行の描画、プラットフォーム横断のサンドボックスアクセス制限などが直っています。ドキュメント面では bundled skill-creator ガイドが整理され、未完了の TODO プレースホルダを検証で弾くようになりました。

なおこの stable の後、2026-08-19T00:57:19Z に alpha `rust-v0.149.0-alpha.1` が出ています。

## 何が変わったか

- `/export` で TUI 会話全体を Markdown 出力（クリップボードまたはファイル）
- `codex exec fork` でセッションを分岐。TUI の resume picker からアーカイブ・復元
- TUI 初期化中にプロンプトを下書き可能。resume / fork の進捗を起動中に表示
- `/status`・ステータスライン・ターミナルタイトルに推定クレジット / コストを表示（対象ワークスペース）
- Amazon Bedrock Runtime を組み込みプロバイダーとして追加（AWS プロファイル / リージョン / GPT-5.6 ルーティング）
- Hooks がコマンドを非同期実行でき、MCP ツールを呼び出せるように
- セッション再開時のディレクトリ・ポリシー復元、プロバイダーの障害跨ぎ再接続などを修正

## 業務インパクト（一般企業向け）

この回で最も効くのは **Amazon Bedrock Runtime の組み込みプロバイダー化**です。AWS 上でデータとワークロードを完結させたい組織にとって、Codex の導入経路が 1 つ増えました。AWS プロファイルとリージョンをそのまま使えるため、既存の AWS 権限管理の枠組みに乗せられます。これまで「OpenAI へ直接接続する経路しかないから見送り」となっていた案件が、検討のテーブルに戻ってくる可能性があります。導入判断をする側は、既存の Bedrock 利用状況と権限設計を確認するところから始められます。

次に **Hooks から MCP ツールを呼べるようになった**点です。これは自動化の設計そのものを変えます。これまで Hooks は「特定のタイミングでコマンドを実行する」仕組みでしたが、MCP ツールを叩けるようになったことで、Hooks を起点に社内システムやチケット管理・監視基盤へ連携できます。非同期実行が入ったことで、重い処理を Hooks に置いても Codex 本体の応答を止めません。Codex を業務フローに組み込んでいる組織は、既存の Hooks 設定を見直す価値があります。

**コストの可視化**は地味ですが、組織導入では効きます。推定クレジット / コストが `/status` とステータスラインとターミナルタイトルに出るため、利用者が自分の消費を意識しながら作業できます。「使わせてみたら想定を超えていた」という事後発覚を減らす方向の変更です。ただし「eligible workspaces」限定と書かれているため、自社が対象かは確認が必要です。

**`/export` による会話の Markdown 出力**は、引き継ぎと監査の両方に効きます。エージェントに何を指示し、何をさせたかの記録を、そのまま資料として残せます。AI エージェントの作業ログをどう保全するかは、監査対応の論点として今後増える領域です。

## 副業・個人活用視点

個人で使う場合に一番効くのは `codex exec fork` と `/export` です。

fork は「ここまでの文脈は共有したまま、別のアプローチを試す」という使い方ができます。長い会話を進めた後で方針を変えたくなったとき、これまでは最初からやり直すか、文脈が汚れたまま進めるかの二択でした。分岐できるようになったことで、A 案と B 案を同じ前提から並べて比べられます。TUI からのアーカイブ・復元と組み合わせると、セッション一覧が実用的な作業台になります。

`/export` は、案件の作業記録をそのまま納品物や技術記事の下書きに使える形で取り出せます。クライアントワークで「何をやったか」を説明する必要がある場面、あるいは自分のブログや Zenn の記事ネタとして残す場面で、書き起こしの手間が丸ごと消えます。

コスト表示がターミナルタイトルにまで出るようになったのは、従量課金で使っている個人にとって実利があります。作業に集中しているときほど消費を見失いやすいので、常に目に入る位置に出るのは有効です。

Hooks の非同期実行と MCP 呼び出しは、個人でも「コミット前に自動でチェックを走らせる」「特定の操作をしたら通知を飛ばす」といった小さな自動化に使えます。非同期になったことで、重い処理を挟んでも手が止まりません。
