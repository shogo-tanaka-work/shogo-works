## 要約

OpenAI Codex の stable リリース **`rust-v0.148.0`** が 2026-08-18 に公開されました。`## New Features` に6項目が並ぶ、まとまった量の更新です。変更は大きく3方向に分かれます。

1つ目は**セッションの持ち出しと再利用**です。TUI の会話を `/export` でクリップボードまたはファイルへ **Markdown として書き出せる**ようになりました。加えて `codex exec fork` でセッションを分岐でき、resume picker からセッションのアーカイブと復元ができます。TUI の初期化が終わる前からプロンプトを書き始められるようになり、resume や fork の進捗が起動中に表示されます。

2つ目は **Amazon Bedrock Runtime の組み込みプロバイダ化**です。AWS profile と region の指定に対応し、GPT-5.6 のルーティングもサポートします。これまで AWS 経由でモデルを使う場合は自前で設定を組む必要がありましたが、標準のプロバイダとして選べるようになりました。

3つ目は **Hooks の拡張**です。hook が**非同期でコマンドを実行**できるようになり、さらに **MCP tool を呼び出せる**ようになりました。従来の同期的なコマンド実行だけでは表現しづらかった、外部システムを絡めた前処理・後処理を組めます。

このほか、`/status`・status line・ターミナルタイトルに**推定スレッドクレジットまたはコストが表示**されるようになりました（対象ワークスペースのみ）。

Bug Fixes では sandbox の扱いが重要です。Linux と Windows で、**拒否されたパスや読み取れないパスに対して fail closed** になりました。判定できないものを通してしまう挙動が塞がれた形です。ほかに、モデル切り替えや設定更新が古い指示を残したりターン途中で変わったりしなくなった点、再開したセッションが保存済みの作業ディレクトリと承認ポリシーを復元するようになった点、一時的なプロバイダ障害をまたいでターンが再接続する点、MCP サーバーが OAuth 再認証後に Codex の再起動なしで復帰する点などが含まれます。

## 何が変わったか

- **Amazon Bedrock Runtime が組み込みプロバイダに追加**（AWS profile / region の指定、GPT-5.6 のルーティング対応）
- **`/export` で TUI の会話を Markdown 出力**（クリップボードまたは新規ファイル）
- **`codex exec fork` によるセッション分岐**と、resume picker からのアーカイブ / 復元
- **Hooks が非同期実行と MCP tool 呼び出しに対応**
- `/status` / status line / ターミナルタイトルに推定スレッドクレジットまたはコストを表示（対象ワークスペース）
- TUI の初期化中にプロンプトを下書きでき、resume / fork の進捗が起動中に見える
- sandbox が Linux / Windows で拒否パス・読み取り不能パスに対し fail closed に
- 再開したセッションが作業ディレクトリと承認ポリシーを復元。プロバイダの一時障害をまたいでターンが再接続

## 業務インパクト（一般企業向け）

**Bedrock 対応は調達と統制の面で効きます**。AWS 上でモデル利用を集約し、請求・監査・ネットワーク境界を AWS 側に寄せている組織では、Codex だけが別経路になる状態が解消されます。AWS profile と region を指定するだけで済むため、開発チームごとに環境変数の組み方が分かれる問題も減ります。すでに Bedrock を標準としている組織にとっては、Codex 導入のハードルが1段下がったと見てよいでしょう。

**Hooks からの MCP tool 呼び出しは、既存の社内システムとの接続点になります**。たとえばコード変更の前にチケット管理システムの状態を確認する、実行後に社内の監査ログへ記録する、といった処理を hook として挟めます。非同期実行に対応したことで、待ち時間の長い処理を挟んでも操作全体が止まりにくくなりました。エージェントの動作を組織のワークフローに合わせて縛る手段が増えた、という位置づけです。

**`/export` は記録と共有の実務に直結します**。エージェントとのやり取りをそのまま Markdown で出せるため、レビュー用の記録、引き継ぎ資料、インシデントの経緯説明に転用できます。あわせてセッションの fork とアーカイブが入ったことで、「同じ前提から別の方針を試す」「終わった作業を畳んで一覧を整理する」という運用が標準機能でできるようになりました。

sandbox の fail closed 化は、**判定できないパスを許可してしまう余地をなくす**変更です。エージェントにファイル操作を任せる範囲を決めている組織は、更新後に従来通らなかった経路が塞がれる可能性があるため、既存の設定で意図した通りに動くか一度確認しておくと安全です。

## 副業・個人活用視点

個人の使い方で効くのは **`/export` とセッションの fork** です。副業案件では「何をどう実装したか」を後から説明する必要が出ることが多く、TUI の会話をそのまま Markdown で残せると、作業ログを別途書き起こす手間が省けます。納品物に添える技術メモの下敷きにもできます。

セッションの fork は、**同じ前提から複数の実装方針を比べたいとき**に向きます。ゼロから説明し直さずに分岐できるため、方針の比較にかかる時間が短くなります。使い終わったセッションを resume picker からアーカイブできるので、案件が並行するときも一覧が散らかりません。

コスト表示は対象ワークスペース限定ですが、表示される環境なら**作業ごとの費用感を掴む材料**になります。副業では見積もりに対する実コストの把握が効いてくるため、`/status` で都度確認する習慣をつけておくと、単価設定の判断材料が貯まります。

Hooks の MCP 対応は個人だとやや大がかりですが、たとえば作業終了時に自分の記録用ツールへ自動で追記する、といった小さな自動化から試せます。
