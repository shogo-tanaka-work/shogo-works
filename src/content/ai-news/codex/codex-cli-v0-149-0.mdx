## 要約

OpenAI Codex の stable リリース `rust-v0.149.0` が 2026-08-20T21:04Z（JST 2026-08-21 06:04）に公開されました。前の stable は 2026-08-18 の `0.148.0` です。npm では `@openai/codex@0.149.0` として配布されています。

今回のリリースを一言でまとめると、**Codex を「1セッションの CLI」から「複数エージェントの実行環境」として扱う方向の整備**です。

中心は **`codex agents` ダッシュボード**です。対話的な画面で、タスクの検索・開始・オープン・リネーム・停止ができます。これまで複数タスクを並行させる場合、どのセッションで何が動いているかを自分で覚えているか、セッションを渡り歩いて確認する必要がありました。一覧から操作できるということは、**並行実行を前提にした使い方が公式に想定された**ということです。

**`codex queue`** が追加され、既存のローカル / リモートセッションへメッセージを送れるようになりました。あわせて、キューに入れたメッセージが**アイドル状態のセッションを確実に起こす**よう修正されています。従来は「投げたはずのメッセージが処理されない」ケースがありえたということでもあります。セッション名の重複解決も改善されました。

**TUI セッション内の作業ディレクトリ操作**として `/cd`、`/pwd`、`/cwd` が追加されました。セッションを閉じて開き直さなくてもディレクトリを移動できます。モノレポや複数リポジトリをまたぐ作業では、これだけで往復が減ります。

**`codex doctor` の診断範囲が拡大**し、エンドポイント保護、ネットワーク / プロキシの失敗、デスクトップアプリの状態、アップデート接続性を見るようになりました。企業ネットワークで動かないときの切り分けが、自前の調査から `doctor` の出力へ移ります。

**SDK 側の変更も実務に効きます。** CLI の設定オーバーライドを厳密に渡せるようになり、reasoning effort に **`max` / `ultra`** を選択できるようになりました。Vim 編集は文字置換と `cw` / `c$` / `cc` などの change motion に対応範囲が広がっています。

修正のうち影響が大きいのは、**スレッドの resume / fork 時に権限プロファイルが正しく復元されるようになった**点です。権限が意図せず変わった状態で再開していた可能性があったということになります。このほか、サブエージェント活動の重複表示と通知ルーティングの改善、WebRTC Realtime のサイドバンド接続がトランスポート喪失後に再接続するようになった点、TUI のスレッド再生バッファに上限を設けてメモリ肥大を防いだ点が入っています。

ドキュメントでは、外部コントリビューションは PR ではなく issue と設計議論を通すべきことが明文化され、secure devcontainer における **DNS エクスフィルトレーションのリスクと信頼境界の限界**が文書化されました。

なお窓内の alpha は `rust-v0.149.0-alpha.3` / `.4` / `.7`、`rust-v0.150.0-alpha.1` の4件を確認しています。

## 何が変わったか

- **`codex agents` ダッシュボード**を追加。タスクの検索・開始・オープン・リネーム・停止を対話的に操作
- **`codex queue`** を追加。既存のローカル / リモートセッションへメッセージを送信
- キュー投入したメッセージが**アイドル状態のセッションを確実に起こす**よう修正。セッション名の重複解決を改善
- TUI セッション内に **`/cd`、`/pwd`、`/cwd`** を追加
- **`codex doctor`** がエンドポイント保護、ネットワーク / プロキシの失敗、デスクトップアプリの状態、アップデート接続性を診断
- **SDK が CLI 設定の厳密なオーバーライドに対応**。reasoning effort に **`max` / `ultra`** を選択可能
- Vim 編集が文字置換と `cw` / `c$` / `cc` などの change motion に対応
- **スレッドの resume / fork 時に権限プロファイルを正しく復元**（修正）
- サブエージェント活動の重複表示と通知ルーティングを改善、WebRTC Realtime のサイドバンド接続がトランスポート喪失後に再接続、TUI スレッド再生バッファに上限
- ドキュメントに **secure devcontainer の DNS エクスフィルトレーションのリスクと信頼境界の限界**を明記

## 業務インパクト（一般企業向け）

**権限プロファイルの復元修正は、真っ先に確認すべき項目です。** スレッドの resume / fork 時に権限プロファイルが正しく戻っていなかったということは、**再開したセッションが意図と違う権限で動いていた可能性がある**ということです。Codex に権限プロファイルを設定して統制している組織では、これは統制の穴にあたります。バージョンを上げるまでの間、resume / fork を使った作業がどれだけあったかは把握しにくいので、少なくとも**今後は 0.149.0 以降を前提にする**という方針を出しておくのが妥当です。

**`codex agents` ダッシュボードは、運用の型が変わる可能性のある追加です。** 「1人1セッション」で使っている限り恩恵は小さいですが、**タスクを並行させて回す使い方**では、状態の把握コストが下がります。ここで組織として決めるべきは、並行実行を推奨するかどうかです。並行させれば速くなりますが、レビューの負荷は同時に上がります。**エージェントの並行数と、それをレビューできる人数の比率**を意識しないと、レビューされない変更が積み上がります。

**`codex doctor` の診断拡大は、情シスの問い合わせ対応を軽くします。** 企業ネットワークではプロキシや TLS インスペクション、エンドポイント保護ソフトが原因で動かないことがよくあります。これまでは「動きません」という報告から切り分けを始める必要がありました。**`codex doctor` の出力を添えて問い合わせる**という運用を最初に決めておくと、往復が減ります。社内のヘルプデスク手順に1行足すだけの話です。

**secure devcontainer の DNS エクスフィルトレーションに関する文書化**は、セキュリティレビューの材料です。devcontainer でサンドボックス化していれば安全、という理解が広まりやすいところに、公式が**信頼境界の限界**を明記しました。ネットワークを塞いだつもりでも DNS 経由で情報が出る経路が残る、という話です。サンドボックス前提でレビューを通している組織は、この文書を読み直す価値があります。

SDK の reasoning effort に `max` / `ultra` が入った点は、コスト管理に直結します。**選べるということは、選ばせると使われるということ**です。SDK 経由で Codex を組み込んでいる場合、effort をどこで決めるか（呼び出し元か、設定で固定か）を先に決めておかないと、請求額が読めなくなります。

## 副業・個人活用視点

**`codex queue` と `codex agents` の組み合わせは、隙間時間で作業する人に効きます。** 長い処理を投げて別のことをし、思いついた追加指示をキューに入れておく、という進め方ができます。キューに入れたメッセージがアイドルセッションを起こすようになったので、「投げたのに動いていない」という無駄な待ちが減ります。ダッシュボードでどのタスクが止まっているかを一覧で見られるのも、断続的に作業する状況とは相性がよいはずです。

**`/cd`、`/pwd`、`/cwd` は地味ですが効きます。** 複数の案件を並行して受けていると、リポジトリを行き来する回数が多くなります。セッションを閉じずに移動できるということは、それまでの文脈を保ったまま別ディレクトリを触れるということです。

**`codex doctor` は、自分の環境を疑うときの最初の一手として覚えておく価値があります。** 自宅の VPN、会社支給端末のセキュリティソフト、テザリング。個人で作業していると環境要因は多様です。原因の切り分けに30分使うより、まず `doctor` を叩くほうが早いです。

SDK の `max` / `ultra` は、**単価と品質のトレードオフを自分で握れる**ようになったということです。受託で Codex を組み込んだ納品物を作る場合、どの effort を既定にするかは仕様として明記しておくべき項目になります。「速いが浅い」構成と「遅いが深い」構成を切り替えられる設計にしておくと、クライアント側の予算に合わせやすくなります。

Codex は stable と alpha が並行で出ており、今回の窓でも alpha が4件出ています。**alpha を追う必要はありません。** stable の `rust-vX.Y.Z` だけを見て、権限・サンドボックス・SDK 設定のように自分の構成と噛み合う変更を拾う、という読み方で十分です。
