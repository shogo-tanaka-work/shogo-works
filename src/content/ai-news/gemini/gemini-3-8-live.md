## 要約

Google は 2026-09-15、**音声対話向けの2モデル、Gemini 3.8 Live と Gemini 3.8 Live Extended Thinking** を発表しました。公式は「これまでで最も高度な live dialogue モデル」と位置づけています。

**2モデルの役割は明確に分かれています。**

**3.8 Live は規模とコスト効率を重視**した汎用型で、会話の知性・流暢な対話・視覚的グラウンディング（カメラ映像などの視覚情報にもとづく応答）を組み合わせています。**3.8 Live Extended Thinking は高難度タスク向け**で、知性と多段推論を強化しています。

**今回の中核は「話しながら処理する」という一点に集約されます。**

公式および開発者向けポストは、モデルが**会話の流れを保ったままツール呼び出しや API 呼び出しをバックグラウンドで実行**できると説明しています。

**これが何を解決するかは、既存の音声 AI を使ったことがあれば実感しやすいはずです。** 従来の音声アシスタントは、外部データを調べる必要が出た時点で**黙り込みます。** 利用者からは、処理中なのか止まったのか区別がつきません。**この沈黙が、音声 AI が実用に乗らない最大の理由の一つでした。**

**Google の設計上の答えは「処理と発話を分離する」ことです。** 調べながら話し続けられるなら、沈黙は発生しません。**モデルの賢さではなく、対話体験の連続性を改善した更新**と読むのが正確です。

**性能面では、3.8 Live Extended Thinking が Artificial Analysis の Speech-to-Speech リーダーボードで1位**とされています。

**提供経路は4系統に分かれています。** 開発者向けは **Gemini API と Google AI Studio**（Live API 経由）。企業向けは **Gemini で private preview**、Gemini Enterprise for Customer Experience と **Google Workspace 法人顧客向けは「coming soon」**。一般利用者向けは **Gemini Live**、および Workspace の **Docs（Google AI Pro / Ultra 契約者）と Gmail / Keep（全 Google AI 契約者）**です。

**価格は音声入力 $0.005/分、音声出力 $0.018/分**です。トークン単位ではなく**分単位の課金**である点は、コスト試算の方法が通常の LLM と異なることを意味します。

開発者向けポストでは、先月公開済みの **Gemini 3.5 Transcribe**（85言語以上に対応、Word Error Rate はストリーミング 4.0% / 非ストリーミング 2.6%）と併せて、音声プロダクト構築の組み合わせとして提示されています。

## 何が変わったか

- **会話を中断せずにツール / API 呼び出しを実行**できる音声モデルが2種類登場
- **Gemini 3.8 Live**: スケールとコスト効率重視。**視覚的グラウンディング**に対応
- **Gemini 3.8 Live Extended Thinking**: 多段推論を強化。**Speech-to-Speech リーダーボード1位**
- **Live API 価格: 音声入力 $0.005/分、音声出力 $0.018/分**（分単位課金）
- 開発者向け: **Gemini API / Google AI Studio**（Live API 経由）
- 企業向け: **Gemini で private preview**
- **Gemini Enterprise for Customer Experience と Workspace 法人顧客は coming soon**（時期の明示なし）
- 一般向け: **Gemini Live**、Workspace の **Docs**（Google AI Pro / Ultra）、**Gmail / Keep**（全 Google AI 契約者）
- 併用候補として **Gemini 3.5 Transcribe**（85言語以上、WER 4.0% / 2.6%）

## 業務インパクト（一般企業向け）

**この更新が効くのは、電話・受付・問い合わせ対応の自動化を検討している組織です。**

**これまで音声 AI の導入が止まっていた理由は、精度よりも体験でした。** 顧客情報を調べる、在庫を確認する、予約枠を見る——どれも外部システムへの問い合わせが必要で、その間 AI は黙ります。**数秒の沈黙は、電話越しでは「切れた」と受け取られます。** 実証実験は通っても本番投入できない、という結果になりがちでした。

**話しながら調べられるなら、この壁は下がります。** 「お調べしますね」と言いながら実際に調べる、という人間のオペレーターと同じ振る舞いが可能になります。

**ただし、日本企業がすぐ動ける状況ではありません。ここは正確に把握すべきです。**

**Workspace 法人顧客向けは「coming soon」で、時期は示されていません。** 企業向け Gemini は private preview です。**つまり、Workspace を契約している日本企業が明日から社内で使える、という話ではありません。** 現時点で確実に使えるのは **Gemini API / AI Studio 経由の自前実装**です。

**したがって、今の実務的な選択肢は2つです。** API で自社実装して試すか、**Workspace 提供を待つか。** 前者は開発リソースが要り、後者は時期が読めません。**「発表された = 使える」ではない**という区別を、社内説明の時点で明確にしておく必要があります。

**コスト構造には注意点があります。分課金です。**

通常の LLM はトークン課金なので、**出力を短くすればコストが下がります。** 分課金では効きません。**通話時間がそのままコストです。** 音声入力 $0.005/分・音声出力 $0.018/分で、仮に平均5分の通話が1日100件なら、入出力合計で1日あたりおよそ $11.5、月20営業日で $230 前後という桁感になります（実際の入出力比率で変動します）。

**この構造は、試算の仕方を変えます。** 「1件あたりいくら」を出すには、**平均通話時間の実測値**が必要です。**既存のコールログから平均通話時間を出しておくことが、導入検討の最初の作業**になります。そして**「AI が丁寧に長く話すほどコストが上がる」**という、通常の LLM とは逆の圧力が働く点も設計に織り込む必要があります。

**視覚的グラウンディング対応は、用途を広げます。** カメラ映像を見ながら会話できるということは、**現場作業の支援、設備点検、商品の問い合わせ**といった、言葉での説明が難しい場面に使えます。ただしこれも Live API 経由の実装が前提です。

**セキュリティ・統制の観点では、音声データの取り扱いが新しい検討項目になります。** テキストのやり取りと違い、**音声は話者の識別が可能**です。顧客との通話を AI に通す場合、**録音・処理に関する同意の取り方**は既存の規程で足りるか確認が要ります。

## 副業・個人活用視点

**個人にとって、この発表は「今すぐ使えるもの」と「作れるようになったもの」に分かれます。**

**今すぐ使える側は Gemini Live と Gmail / Keep です。** Google AI の契約者であれば、音声での対話がスムーズになります。**Docs での利用は Google AI Pro / Ultra 契約者**が対象です。移動中や作業中に音声で指示を出す使い方をしている人には、沈黙が減るぶん体感が変わります。

**作れるようになった側が、収益に直結します。**

**音声エージェントの受託開発は、これまで提案しづらい領域でした。** デモでは動くが、実運用では沈黙が問題になり、「もう少し様子を見ましょう」で終わる。**その最大の反論材料が消えた**ことになります。

**具体的な案件の形としては、小規模事業者の電話対応が現実的です。** 個人経営の飲食店、整体院、美容室のような**「営業中は電話に出られない」業種**は明確な課題を持っています。予約の受付と簡単な問い合わせ対応だけでも価値があります。

**ただし、価格設計は慎重にすべきです。分課金であることが直接効きます。**

**受託で作る場合、ランニングコストがクライアント負担か自分負担かを最初に決める必要があります。** 通話時間が読めない状態で「月額固定」で請けると、**通話が増えるほど赤字になります。** 基本料金 + 通話時間従量、という構造にするのが安全です。

**そして、提案時に実測値を持っておくことが差になります。** 「月にどれくらいかかりますか」は必ず聞かれます。**クライアントの現在の入電数と平均通話時間をヒアリングして試算を出せるかどうか**で、提案の説得力が変わります。これは AI の知識ではなく、見積もりの基本作業です。

**Gemini 3.5 Transcribe との組み合わせも案件になります。** 85言語以上に対応し、WER がストリーミングで 4.0% という精度です。**通話の文字起こしと要約を納品物に含める**なら、対応工数の可視化という別の価値を足せます。

**注意点として、企業向け提供が private preview / coming soon である点は、提案時に伏せてはいけません。** 「Google が発表した機能です」と言って、実際は API 経由の自前実装だった、という説明不足は後で問題になります。**何を使って作るのかを明示する**のが、この段階では誠実な進め方です。
