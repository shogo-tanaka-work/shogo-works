## 要約

2026-09-03、Google が **Gemini の音声モデル（Gemini Audio models、Gemini 3.5 Live 統合）を使った3つの音声機能**を発表しました。**Gmail Live、Docs Live、Keep Live** の3つです。

**共通しているのは、タイピングを前提としない操作系である**という点です。音声で読み上げてもらう機能ではなく、**話しかけて作業を進める**方向です。

**Gmail Live は、受信トレイに対する会話型の検索です。**

公式が挙げている例は **「What's my flight's gate number?」（自分のフライトのゲート番号は？）** です。**キーワードで検索して、ヒットしたメールを開いて、該当箇所を探す**——この3段階が、**質問1つに置き換わります。**

**Docs Live は、ハンズフリーの執筆支援です。**

リアルタイムの会話を通じて **「構造化された、文脈を踏まえた文書をその場で組み立てる」**。ここまでなら既存の AI 執筆支援と大きく変わりません。

**この機能で本当に重要なのは、参照範囲です。**

**Docs Live は、Gmail、Drive、Chat、および Web から詳細を引いてきます。**

つまり、**文書作成の入力元が、開いている文書の中に閉じていません。** 「先週のあのメールの数字を入れて」「Drive にある前回の資料の構成に合わせて」といった指示が、**アプリを切り替えずに通る**という設計です。

**Keep Live は、話した内容を整理されたメモへ変換します。** 公式表現では **「アイデアを捉え、構造化し、整理された実行可能なメモへ洗練する」**。音声メモの文字起こしではなく、**構造化まで含む**点が要点です。

**提供対象はプランで分かれます。ここは正確に押さえてください。**

- **Gmail Live と Keep Live**: **Google AI Plus / Pro / Ultra** の加入者
- **Docs Live**: **Pro / Ultra のみ**（AI Plus は対象外）
- **Google Workspace のビジネス顧客向けは「coming soon」**

**ロールアウトは、公開時点（2026-09-03）の「今週」から開始**です。**言語や地域の制約については、当該ポストに明示がありません。** 日本語での利用可否は、この発表だけからは判断できません。

## 何が変わったか

- **Gemini の音声モデル（Gemini 3.5 Live 統合）を使った音声機能を3つ追加**
- **Gmail Live**: 受信トレイに対する**会話型検索**。公式例は「What's my flight's gate number?」
- **Docs Live**: ハンズフリーの執筆支援。会話しながら**構造化された文脈依存の文書**を組み立てる
- **Docs Live の参照範囲は Gmail / Drive / Chat / Web を横断**。開いている文書の中に閉じない
- **Keep Live**: 話した内容を**構造化された実行可能なメモ**へ変換
- 提供: **Gmail Live・Keep Live は Google AI Plus / Pro / Ultra**、**Docs Live は Pro / Ultra のみ**
- **Workspace ビジネス顧客向けは「coming soon」**
- ロールアウトは **2026-09-03 の週から開始**
- **言語・地域の制約は当該ポストに記載なし**

## 業務インパクト（一般企業向け）

**この発表は「音声で操作できるようになった」で終わらせると、要点を落とします。効く論点は3つです。**

**1つ目は、Docs Live の横断参照が、情報の流れを1つ増やすという点です。**

**Gmail、Drive、Chat、Web を横断して文書へ引いてくる**——利便性としては明確な前進です。**同時に、統制の観点では新しい経路が1本増えたことを意味します。**

**具体的に想定すべき状況は単純です。** ある社員が文書を作るとき、**自分がアクセスできる Gmail・Drive・Chat の内容を、音声の指示ひとつで文書へ引き込める。** 引き込まれた先の文書が、**より広い範囲に共有される**とどうなるか。

**これは新しい種類のリスクではありません。** 従来もコピー&ペーストで同じことは起きました。**変わったのは摩擦です。** アプリを開いて、探して、選んで、貼り付ける——**この手数が、意図の確認を挟む余地になっていました。** 音声で通ると、その余地が消えます。

**現時点で慌てて対応する必要はありません。ビジネス顧客向けは「coming soon」だからです。** ただし、**Workspace 版が来た時点で、参照範囲の統制が管理者の論点になる**ことは予測できます。**Workspace Updates 側での続報を注視する対象です。**

**2つ目は、Gmail Live が「検索の言い換え」を不要にする、という点です。**

**メール検索が難しいのは、探しているものを検索語に翻訳する必要があるからです。** 「あの案件の見積もり」を `from:○○ 見積` に変換する作業。**これは慣れないと成功率が低く、慣れても取りこぼします。**

**質問の形のまま投げられるということは、この翻訳が不要になるということです。** 効果が出やすいのは、**メール検索が苦手なまま「必要な情報が見つからない」と言い続けている層**です。ここは、**ツールを教えるより機能が入れ替わる方が早い**類の課題でした。

**3つ目は、プラン差を正確に伝える必要がある、という点です。**

**Docs Live だけが Pro / Ultra 限定で、AI Plus では使えません。**

**社内で「Google の新しい音声機能が使える」と一括アナウンスすると、Gmail と Keep では動くのに Docs では動かない、という問い合わせが確実に発生します。** しかも **AI Plus 加入者にとっては、3つのうち2つだけ動く**という、原因の分かりにくい状態になります。

**アナウンスするなら、機能名とプランを対にして書いてください。** そして **Workspace ビジネス版は「まだ来ていない」**ことを明示する。**個人の Google AI 契約と、会社の Workspace 契約は別物**であり、ここを混同したまま「うちでも使える」と期待させると、後で説明が面倒になります。

**なお、言語対応が明記されていない点も、そのまま伝えるべきです。** **音声機能は言語対応の差が出やすい領域**です。「英語では動くらしい」という状態で日本語の検証結果を待つのが正確で、**発表を根拠に「日本語でも使える」と言わない**方が安全です。

## 副業・個人活用視点

**個人の実務では、Docs Live が最も価値が出やすい機能です。ただし理由は「音声で書けるから」ではありません。**

**1つ目。Docs Live の本当の価値は、移動中や作業中に「書き始められる」ことです。**

**文書作成でいちばん重い工程は、白紙から最初の構成を出すところです。** 机に向かってから考え始めると、**構成を決めるまでに時間が溶けます。**

**移動中や単純作業中に、話しながら構成だけ作っておく。** 机に戻ったときには**骨格がある状態から始められる。** **音声で全部書き上げようとするのではなく、構成と論点出しだけを音声でやる**——この切り分けが実用的です。

**そして Gmail・Drive・Chat を参照できるということは、「先週のあのやり取りの内容を踏まえて」が通るということです。** 資料を開いて確認する工程を挟まずに、**文脈込みで話を進められます。**

**2つ目。Keep Live は、アイデアの取りこぼしに効きます。**

**思いついた瞬間に記録できないアイデアは、ほぼ失われます。** そして音声メモの問題は、**録りっぱなしで後から整理されないこと**でした。

**Keep Live は構造化まで含みます。** 「捉える → 構造化する → 実行可能なメモへ洗練する」という3段階が公式の説明です。**後で整理する前提の記録は溜まる一方になる**ので、**記録の時点で整理まで終わる**のは実務的な差になります。

**3つ目。ただし、支払っているプランを確認してください。**

**Docs Live は Pro / Ultra のみで、AI Plus では使えません。** **3つのうち Docs Live が最も価値が高い**と判断するなら、**プランの見直しが検討対象になります。**

**逆に言えば、Gmail Live と Keep Live だけで十分なら AI Plus のままで足ります。** **「新機能が出たから上位プランへ」ではなく、「どの機能が自分の実務に効くか」から逆算する**——ここを間違えると、使わない機能に払い続けることになります。

**最後に、この種の発表を人に紹介するときの注意です。**

**言語対応が書かれていません。** 音声機能は、**英語で動くことと日本語で動くことの間に大きな差がある**領域です。**「新機能が出た」と紹介した相手が試して動かなかった場合、損なわれるのは紹介した側の信頼です。**

**一次情報に書かれていないことは、書かれていないと言う。** 自分で試して確認できたら、**そのときに「日本語で動いた」と付け加える。** 情報の速さより、**言えることと言えないことの線引き**の方が、長い目では価値を生みます。
