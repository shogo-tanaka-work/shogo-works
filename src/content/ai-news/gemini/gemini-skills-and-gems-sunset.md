## 要約

Google は 2026-09-30、**Gemini アプリと Workspace アプリへ skills を導入する**と発表しました。同時に、**Gems の廃止日程が確定しました。**

**この発表は、当サイトの日次チェックで 2026-09-27 から「保留」として持ち越していた案件の決着にあたります。** 当時はアプリ内通知で「Gems が skills へ移行する」という表示だけが出ており、**公式の告知ページもヘルプ記事も見つからない状態**でした。移行日として 2026-11-17 という日付だけが通知に現れており、裏付けが取れないまま3日間、記事化を見送っていました。**本日の Workspace Updates Blog の個別ポストが、その一次情報です。**

**skills とは何か。** 公式の定義は「skills は再利用可能なカスタム指示であり、Gemini へプロンプトを出すときにいつでも使える」です。

**Gems との決定的な違いは2つあります。**

**1つ目は、インラインで動くこと。** Gems は「その Gem との会話へ入る」という形式でした。使うには Gem を選んで、専用のスレッドを開く必要がありました。**skills は、通常のプロンプトの中で呼び出します。** 会話の場所を移動しません。

**2つ目は、重ねられること（stack）。** 公式は「1つのプロンプトの中で複数の指示セットを stack できる」と明記しています。**Gems では、複数の Gem を同時に使うことができませんでした。** 「社内文書のトーンで書く」Gem と「英語へ訳す」Gem を両方使いたい場合、どちらかを諦めるか、1つの Gem に両方の指示を詰め込むしかありませんでした。**skills はこれを解消します。**

**対象エディション。** Workspace の skills は Business Starter / Standard / Plus、Enterprise Starter / Standard / Plus、教育向けアドオン（Google AI Pro for Education）、AI Expanded Access。Gemini アプリの skills は**全 Workspace 顧客と個人の Google アカウント**で使えます。**ただし年齢制限が非対称です。Workspace 側は18歳以上のユーザー限定で、Gemini アプリ側は全年齢**が対象です。教育機関では、この差が運用に影響します。

**ロールアウト日程。** Workspace の skills は Rapid Release が **2026-10-05〜10-12**、Scheduled Release が **2026-10-19〜11月中旬**。Gemini アプリの skills は両ドメインとも **2026-10-13〜11月中旬**。

**そして本題の、Gems の終わり方です。**

- **2026-11-17** — Gems が**設定パネルへ移動**します。この時点では作成も利用も引き続き可能です
- **2027-03-01（business / enterprise）** — **Gems の作成・編集・利用が不可**になります。あわせて **skills の「下書き」への自動移行が開始**されます
- **2027-06-01（education）** — 教育向けにも同じ制限が適用されます

**注意すべきは、自動移行が「下書き（draft skills）」までである点です。** 移行された skills がそのまま意図どおり動く保証は、公式には書かれていません。**下書きという語を素直に読むなら、確認と調整は利用者側の作業です。**

**管理者設定。** 管理コンソールの「Allow people to use skills in Studio and Gemini in Workspace」で制御します。公式は管理者に対して、**skills への移行を促し、利用者へ移行日程を周知するよう**求めています。

## 何が変わったか

- **skills（再利用可能なカスタム指示）**が Gemini アプリと Workspace アプリへ導入される
- skills は**インラインで動作**し、**1プロンプト内で複数を stack できる**（Gems はどちらもできなかった）
- **対象エディション**:
  - Workspace: Business Starter / Standard / Plus、Enterprise Starter / Standard / Plus、Google AI Pro for Education、AI Expanded Access
  - Gemini アプリ: 全 Workspace 顧客 + 個人 Google アカウント
- **年齢制限が非対称**: Workspace の skills は18歳以上限定、Gemini アプリの skills は全年齢
- **ロールアウト**:
  - Workspace: Rapid Release 2026-10-05〜10-12、Scheduled Release 2026-10-19〜11月中旬
  - Gemini アプリ: 両ドメイン 2026-10-13〜11月中旬
- **Gems の廃止日程**:
  - **2026-11-17**: 設定パネルへ移動（作成・利用は継続可能）
  - **2027-03-01**（business / enterprise）: 作成・編集・利用が不可、**skills の下書きへ自動移行開始**
  - **2027-06-01**（education）: 同じ制限を適用
- 管理コンソールに「Allow people to use skills in Studio and Gemini in Workspace」設定が追加
- 自動移行の到達点は**「下書き」**であり、動作確認は利用者側の作業

## 業務インパクト（一般企業向け）

**Gems を業務で使っている組織には、期限付きの作業が発生します。**

**まず、何本あるかを数えてください。** Gems は個人が勝手に作れるため、**組織として何本動いているかを把握していない会社が多いはずです。** 部署ごとに「議事録の整形用」「顧客向けメールの下書き用」といった Gem が点在している状態は、よくあります。**2026-11-17 に Gems が設定パネルへ移動すると、入口が目立たなくなります。** 利用者が「使えなくなった」と言い出す前に、一覧を作っておく方が楽です。

**次に、優先順位をつけてください。** 全部を移すのは無駄になる可能性が高いです。

**Gems の多くは、作られたが使われていません。** 一度試して満足し、その後は普通にプロンプトを打っている、という例が大半です。**移行対象は「複数人が継続的に使っているもの」に絞るのが現実的です。** 利用実績が確認できないものは、**移行せずに捨てる**という選択を最初から選択肢に入れてください。

**自動移行を待つかどうかの判断。** 2027-03-01 に下書きへ自動移行されますが、**これを待つ理由は薄いです。**

理由は2つあります。**(1) 自動移行は「下書き」までで、検証は人が行う必要があります。** 作業量は手で作り直す場合と大きく変わりません。**(2) 2027-03-01 は、作成・編集・利用が同時に止まる日です。** その日に初めて下書きを見て、動かないことに気づくと、**業務が止まった状態で復旧作業をすることになります。**

**推奨する時期は 2026-10-05 以降（Rapid Release の開始）です。** skills が使える状態になってから、**Gems と skills を並行で動かせる期間が 2027-03-01 まで約5か月あります。** この並行期間が移行の猶予です。期限ぎりぎりまで引っ張ると、この猶予を使い切ります。

**管理者が先に決めるべきこと。** 管理コンソールの skills 設定を**有効にするか**です。既定値が公式に明記されていないため、**ロールアウト前に設定画面を確認してください。** 無効のままロールアウトを迎えると、利用者には「Gems が設定パネルへ移動し、skills も使えない」という状態が見えます。これは問い合わせを生みます。

**教育機関には別の論点があります。** **Workspace の skills は18歳以上限定で、Gemini アプリの skills は全年齢**です。この非対称は、高校以下で運用する場合に説明が必要になります。「Gemini アプリでは使えるのに、Docs では使えない」という状態を、利用者が理解できる形で周知する必要があります。**期限も education は 2027-06-01 で、business / enterprise より3か月遅い**点に注意してください。

**最後に、skills の設計方針についてです。** stack できるという性質は、**プロンプト資産の作り方を変えます。**

Gems は「1つで完結させる」設計を強いていました。複数使えないため、**1つの Gem に必要な指示を全部詰め込む**しかありませんでした。結果として、似た内容の Gem が少しずつ違う形で量産される状態になりがちでした。

**skills では、小さく分けて組み合わせる方が有利です。** 「社内文書のトーン」「箇条書きで出す」「英語へ訳す」を別々の skill にして、必要な組み合わせで呼ぶ。**移行のときに、この設計へ作り直す価値があります。** Gems をそのまま1対1で skills へ移すと、stack できる利点を捨てることになります。

## 副業・個人活用視点

**個人の Google アカウントでも skills は使えます。** Gemini アプリ側は全 Workspace 顧客と個人アカウントが対象で、ロールアウトは 2026-10-13 からです。

**まず、自分の Gems を確認してください。** 個人利用でも、**作って忘れている Gems は意外に多いです。** 個人アカウントについては公式が business / enterprise / education の期限を明示している一方で、**個人アカウントの Gems がいつ使えなくなるかは、この発表文からは読み取れません。** 少なくとも 2026-11-17 に設定パネルへ移動することは共通と読めるため、**その前に棚卸ししておくのが安全です。**

**受託・支援の仕事をしている場合、ここに案件があります。**

**「Gems の棚卸しと skills への移行」は、期限が決まっていて、作業範囲が明確で、成果が見えやすい案件です。** この3条件が揃う仕事は、提案が通りやすいです。**2027-03-01 という日付を示せることが、提案の強さになります。** 「いつかやった方がいい」ではなく「この日に止まります」と言えます。

**提案の組み立て方を具体的に書きます。**

**第1段階は棚卸しです。** 組織内の Gems を一覧化し、利用実績と作成者を確認する。**この段階だけで独立した小さな案件になります。** 多くの組織は一覧を持っていません。

**第2段階は選別です。** 移行する / 捨てる / 統合する、の3分類に振り分ける。**ここが支援者の価値が出る場所です。** 社内の人は「自分が作った Gem を捨てる」判断をしにくいため、外部の方が決めやすいという構造があります。

**第3段階が移行です。** 選別して残ったものを skills へ作り直す。**ここで stack を前提にした分割設計を入れます。** 1対1で移すのではなく、小さい skill の組み合わせへ再設計する。**この再設計が、単なる移し替えとの差別化になります。**

**期限の使い方に注意点が1つあります。** 「2027-03-01 に止まります」は事実ですが、**今は 2026年10月で、1年5か月先です。** 危機感を煽る形で売ると、顧客は「まだ先だ」と判断します。

**代わりに、2026-11-17 を使ってください。** Gems が設定パネルへ移動する日です。**この日に利用者から「Gems が見つからない」という問い合わせが発生します。** 問い合わせ対応のコストは、1年5か月先の廃止より具体的です。**「11月に問い合わせが出ます。その前に周知文を用意しませんか」という提案は、今月動く理由になります。**

**個人の学習としては、stack という概念そのものを押さえる価値があります。**

**「大きな指示を1つ作る」から「小さな指示を組み合わせる」への移行**は、Gemini に限った話ではありません。Claude の Skills、OpenAI の plugin、各種エージェントフレームワークで、同じ方向の設計が続いています。**指示を部品として設計できるかどうかが、AI ツールを使う側のスキルとして分離されてきています。**

**この観点で、自分の手持ちのプロンプトを見直してください。** 長いプロンプトを1本持っている人より、**役割ごとに分かれた短いプロンプトを組み合わせられる人の方が、新しいツールへの移行が速くなります。** 今回の移行は、その練習の機会として使えます。
