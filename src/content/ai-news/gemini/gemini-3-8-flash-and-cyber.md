## 要約

2026-09-02、Google が **Gemini 3.8 Flash** と **Gemini 3.8 Flash Cyber** を公開しました。

**まず頻度に注目してください。** 3.7 Flash から**3週間**、**6週間で3回目の Flash リリース**です。公式自身がこの数字を冒頭に置いています。

**そして価格。** 3.8 Flash は **3.7 Flash と同じ導入価格**、**$0.75 / 100万入力トークン、$3.75 / 100万出力トークン**です。**導入価格の期限は 2026-12-31**、以後は **$1.50 / $7.50** の標準価格に戻ります。

**性能は上がっています。** DeepSWE v1.1（長期ホライズンのソフトウェアエンジニアリング）で**多くのより大きなフロンティアモデルを上回り**、HLE-Verified で **54.9%**。Vals Finance Agent V2 と Harvey's Legal Agent Benchmark でも 3.7 Flash と他のフロンティアモデルを上回るとしています。

**ここまでなら「同じ値段で速くて賢くなった」という話です。** しかし公式は、性能向上の理由を率直に書いています。

**「3.8 Flash はより多く働く（works harder）」。**

**複雑なタスクでは、推論ステップを追加し、ツールを反復的に呼びます。** そして——**「特に高い effort 水準では、性能を最大化するためにトークンを多く使うことがある」**と明記されています。

**この一文が、この発表でいちばん実務に効きます。** **単価は据え置きでも、1タスクあたりのトークンが増えれば、請求額は上がります。**

**公式はその対処も書いています。** 計算効率が第一の制約になる用途では、**effort 水準を下げてトークンの上乗せを抑える**か、**引き続き完全にサポートされる 3.7 Flash を使い続ける**よう案内しています。

**提供先**は、Google Antigravity、Google AI Studio、Android Studio、Gemini Enterprise、Gemini アプリ（Pro / Ultra 加入者）、Google 検索の AI Mode です。

**もう一方の Gemini 3.8 Flash Cyber は、一般には提供されません。**

脆弱性の自律的な発見と自動パッチに特化したモデルで、20言語にまたがる社内ベンチマークで**成功率70%超**、パッチ生成は CWE-Bench で **pass@1 47.2%**（先行フロンティアモデルは 47.8%）を大幅に低いコストで達成したとしています。Chrome Security チームは「はるかに大きい商用モデルより **2.6倍多くの正しいパッチ**」を得たと報告しています。

**提供は、同日に発表された Fairwind Program 経由に限られます。** 対象は**政府機関と国家サイバー当局、重要インフラ事業者（医療・通信・エネルギー・金融）、中核テクノロジープラットフォーム**で、全世界で650を超えるパートナーが参加しているとされています。参加には**社内アクセス範囲の限定と多要素認証**が条件として課されます。

**そして、両者の関係が興味深い。** 公式は、**汎用側のコーディングと推論の向上が「サイバーセキュリティという要求の厳しい領域での訓練」によって駆動された**と書いています。**攻防の訓練が、一般的なコード能力を押し上げた**という主張です。

## 何が変わったか

- **Gemini 3.8 Flash** 公開。**3.7 Flash から3週間、6週間で3回目**の Flash リリース
- 価格は**据え置き**: **$0.75 / 100万入力トークン、$3.75 / 100万出力トークン**（導入価格、**2026-12-31 まで**）。以後 **$1.50 / $7.50**
- ベンチマーク: **DeepSWE v1.1** で多くのより大きなフロンティアモデルを上回る。**HLE-Verified 54.9%**。Vals Finance Agent V2 / Harvey's Legal Agent Benchmark でも改善
- **「より多く働く」設計**: 複雑なタスクで推論ステップを追加しツールを反復呼び出し。**高 effort ではトークン消費が増えうる**と公式が明記
- 効率優先の用途には **effort を下げる**か **3.7 Flash の継続利用**を案内（3.7 は引き続き完全サポート）
- 提供先: **Google Antigravity / AI Studio / Android Studio / Gemini Enterprise / Gemini アプリ（Pro・Ultra）/ 検索の AI Mode**
- **Gemini 3.8 Flash Cyber** は**一般提供なし**。**Fairwind Program**（政府・重要インフラ・中核プラットフォーム向け、650超のパートナー）経由のみ
- Cyber 版の実績: 20言語ベンチで**成功率70%超**、CWE-Bench **pass@1 47.2%**、Chrome Security で**2.6倍の正しいパッチ**
- 公式は、**サイバー領域での訓練が汎用のコーディング・推論の向上を駆動した**と説明

## 業務インパクト（一般企業向け）

**API でモデルを本番に組み込んでいる場合、この発表への対応は「切り替える／切り替えない」の二択ではありません。**

**単価が同じだからといって、コストが同じとは限らない**——ここを最初に押さえてください。

**「より多く働く」は、性能の説明であると同時にコストの説明です。** 推論ステップが増え、ツール呼び出しが反復されれば、**同じタスクでも消費トークンは増えます。** 公式が自ら「特に高い effort 水準では」と条件を付けている以上、**増分は effort 設定に依存します。**

**やるべきことは、切り替え前の実測です。**

**自社の代表的なタスクを10〜20件用意し、3.7 Flash と 3.8 Flash で、同じ effort 水準で流す。** 見るのは精度だけではありません。**入力・出力トークン数、ツール呼び出し回数、所要時間**を並べます。

**そのうえで「単価×トークン」で実効コストを比べる。** 精度が上がってもコストが1.5倍になるなら、**その1.5倍に見合う精度差があるか**という判断になります。タスクによって答えは変わります。**バッチ処理で精度が効く用途なら払う価値がある。単純な分類や抽出なら、3.7 Flash のままが合理的**という結論も普通にありえます。

**この「効率優先なら 3.7 Flash を使い続けてよい」という案内は、額面どおり受け取ってよい部分です。** 3.7 Flash は**引き続き完全にサポート**されると明記されています。**新しいものへ機械的に乗り換える必要はない**——これは公式の立場でもあります。

**もう一つ、期限の管理を忘れないでください。**

**導入価格は 2026-12-31 まで。** 2027-01-01 から、**入力も出力も2倍**になります。**$0.75 → $1.50、$3.75 → $7.50。**

**これは値上げではなく、導入価格の終了です。** しかし請求額の上では同じことです。**年末までの実測値をそのまま来年の予算に使うと、モデル費用だけで2倍ずれます。** 予算計画には、**12月末を境に単価が変わる**前提を今のうちに織り込んでおくべきです。

**リリース頻度についても、運用方針を決めておく価値があります。**

**6週間で3回。** この頻度が続くなら、**「新しいモデルが出るたびに検証して乗り換える」という運用は現実的ではありません。** 検証コストが、得られる改善を上回ります。

**現実的なのは、乗り換えの基準を先に決めることです。** 「四半期に一度だけ見直す」「特定のベンチで自社タスクが N% 改善したら乗り換える」「価格改定のタイミングで再評価する」——**基準がないと、毎回その場で判断することになり、それ自体がコストになります。**

**Workspace / Gemini アプリ側の利用者には、直接の作業はありません。** Pro / Ultra 加入者には順次届きます。**ただし、体感として「返答までの時間が伸びた」と感じる場面はありうる**——推論ステップを増やす設計である以上、これは自然な帰結です。**遅くなった＝不具合、ではない**ことは、社内の問い合わせ対応として押さえておくとよいでしょう。

**Cyber 版については、一般企業に打てる手はありません。** Fairwind Program の対象は政府・重要インフラ・中核プラットフォームです。

**しかし、無関係ではありません。** **防御側の能力がここまで来ているということは、同じ基盤知能が攻撃側にも近い水準で存在しうるということです。** 公式は「攻撃能力より修正能力を優先して投資した」と明言していますが、**それは Google の選択であって、技術的な限界ではありません。**

**押さえるべき実務的な帰結は一つです。** **脆弱性が発見されてから悪用されるまでの時間が、これから短くなる。** パッチ適用のリードタイムを、**「月次でまとめて」から「重要度に応じて即時」へ**寄せる圧力が上がります。自社のパッチ運用が月次サイクルなら、その前提が持つかどうかを見直す時期です。

## 副業・個人活用視点

**個人開発で API を使っている人にとって、この発表は「安くなった」ではなく「読みにくくなった」です。**

**単価表だけを見て月額を見積もると、外します。**

**個人利用の規模では、トークン消費の増加はダイレクトに効きます。** 月に数千円の範囲で使っている人が、同じ使い方で1.5倍になれば、体感としてはっきり分かります。**そして原因が単価ではなくトークン数にあるため、料金ページを見ても理由が分かりません。**

**対処は難しくありません。** **effort を明示的に下げる。** 公式が案内している方法そのものです。個人開発のタスクは、**そもそも最高性能を必要としないものが大半**です。要約、分類、整形、下書き——**これらに高い effort を割り当てる理由はありません。**

**「既定値のまま使う」のが、いちばん高くつく選択**になりました。設定を一度見直す価値があります。

**そして、乗り換えないという判断も持っておいてください。**

**3.7 Flash は完全にサポートされ続けます。** 動いているものを動かし続けるのは、個人開発では特に合理的です。**新しいモデルが出るたびに検証する時間があるなら、その時間で機能を1つ作った方が、たいていは価値が大きい。**

**受託や相談を受ける側には、この発表は説明の材料として使えます。**

**「新しいモデルが出たので切り替えましょう」と言うのは簡単です。** しかし**「切り替えると請求が上がる可能性があります。理由は単価ではなくトークン数です」と説明できる人**は、そう多くありません。**公式が自ら書いている情報を読んでいるかどうかの差**です。

**そのうえで「まず10件で実測しましょう」と提案できれば、それは具体的な作業になります。** 見積もれる仕事です。**「最新モデルへの移行支援」より「移行すべきかの判断支援」の方が、実は価値が伝わりやすい**——この構図は覚えておく価値があります。

**リリース頻度の話も、そのまま持って行けます。**

**6週間で3回のペースは、クライアント側から見ると不安の材料です。** 「うちのシステム、また古くなるんじゃないか」という質問は必ず来ます。

**そこで「乗り換え基準を先に決めておきましょう」と提案できるかどうか。** 四半期ごとの見直し、自社タスクでの改善率の閾値、価格改定のタイミング——**基準を文書にしておけば、次のモデルが出たときに慌てなくて済みます。** これは技術の話ではなく運用設計の話で、**技術者が提供できる価値としては、意外と評価されにくく、しかし実際には効く部分**です。

**最後に、2026-12-31 の期限だけは、カレンダーに入れておいてください。** **入力・出力とも2倍**です。個人開発の規模でも、**気づかないうちに月額が倍になるのは避けたい**種類の変化です。
