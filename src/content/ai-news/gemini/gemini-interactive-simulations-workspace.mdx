## 要約

Google Workspace Updates が 2026-08-24、**Gemini アプリのチャット内でインタラクティブな可視化を生成する機能を、Workspace 顧客へ提供開始した**と告知しました。従来の回答は「テキスト＋静的な図」が中心でしたが、質問に応じて**操作できるシミュレーション、3Dモデル、表、グリッド**が返るようになります。公式が挙げる例は「DNA の仕組みを3Dで見せて」で、生成された3D構造を回転・ズームできます。ほかに、振り子がエネルギーを行き来する様子の観察、キャッシュバーンレートのインタラクティブな表なども例示されています。

**注意が要るのは、これが新機能の発表ではなくロールアウトだという点です。** 機能自体の初出は **2026-04-09 の blog.google 記事**で、そのときは一般の Gemini アプリ利用者向けにグローバル展開されました。ただしその記事の末尾には、**「Education と Workspace アカウントではまだ利用できない」**と明記されていました。今回の告知は、**その除外が解かれた**ことを意味します。8月19日の学生向け発表でも「インタラクティブな可視化を全 Gemini アプリ利用者へ展開」と触れられており、その流れの Workspace 面での着地にあたります。

実務上もっとも重要なのは提供条件です。**管理者向けには「Gemini が有効な全組織で既定ON」**と明記されており、この機能は Workspace 管理コンソールの **Generative AI 設定という既存の制御下**に入ります。裏を返せば、**機能単独のオン・オフは用意されていません**。エンドユーザー側の設定もありません。使い方は「見せて」「可視化して」と依頼するだけです。

ロールアウトは **Rapid Release / Scheduled Release の両ドメインで「Available now」**、対象は全 Google Workspace 顧客、Workspace Individual 契約者、および最低年齢要件を満たす利用者です。**利用上限（usage limits）が適用される**とされていますが、上限の具体的な数値は告知に含まれていません。

つまり、**組織側が何も操作しなくても、Gemini が返してくるものの種類が変わります。** これは機能追加としては地味ですが、統制の観点では見過ごせない形です。

## 何が変わったか

- Gemini アプリのチャット内で、質問に応じた**操作可能な3Dモデル・シミュレーション・表・グリッド**が生成される
- 対象が **Workspace 顧客・Workspace Individual へ拡大**（2026-04-09 の初出時点では Education / Workspace は明示的に対象外）
- **管理者: Gemini が有効な全組織で既定ON**。Workspace 管理コンソールの Generative AI 設定という既存制御に従う
- **機能単独のトグルは無い**。エンドユーザー側の個別設定も無い
- ロールアウト: **Rapid Release / Scheduled Release の両ドメインで提供済み**（Available now）
- 対象: 全 Google Workspace 顧客、Workspace Individual 契約者、最低年齢要件を満たす利用者
- **利用上限が適用される**（具体的な数値は告知に記載なし）

## 業務インパクト（一般企業向け）

**「既定ON・機能単独のトグルなし」の組み合わせは、統制の観点でいちばん扱いにくい形です。** 管理者にできるのは、Generative AI 設定で Gemini そのものを止めるか、このまま使うかの二択です。**機能単位で判断する余地がありません。** 生成物の性質が変わることに懸念があっても、対応策が「Gemini を止める」しかない、という状況になります。

**まず確認すべきは、生成された可視化がどこへ出ていくかです。** インタラクティブな3Dモデルや表は、チャット内で完結するとは限りません。**説明資料として社外へ持ち出される可能性がある**なら、その内容の正確性を誰が担保するのかという論点が立ちます。文章なら読み手が「AI が書いた文章」として読みますが、**3Dモデルやシミュレーションは「計算された結果」に見えます。** 見た目の説得力と、裏付けの強さが一致しない。この差は、教育や社内研修で使われるときに特に効いてきます。

**Rapid Release と Scheduled Release の両方で同時に出ている点にも注意してください。** 通常、Scheduled Release ドメインは検証の猶予を持てますが、今回はその猶予がありません。**Scheduled Release を選んでいる理由が「変更を段階的に受け入れるため」だった組織にとっては、その前提が今回は効いていない**ということです。すでに全ドメインで利用可能な状態になっています。

**利用上限の数値が公開されていない点は、業務組み込みの判断を難しくします。** 「利用上限が適用される」とだけ書かれていて、何回まで、どの単位で、超えたらどうなるかが分かりません。**この機能を業務手順に組み込むのは、上限の実態が見えてからにしたほうが安全です。** 手順書に書いた操作が、繁忙期に上限で止まると、そこで手順そのものが機能しなくなります。

**社内アナウンスは出しておく価値があります。** 「何も設定していないのに Gemini の返し方が変わった」という状態は、ヘルプデスクへの問い合わせを生みます。**変更の事実と、これが Google 側のロールアウトであることを先に伝えておくだけで、問い合わせの多くは防げます。** 併せて、生成された可視化を社外資料に転用する場合の扱いを一行添えておくと、後から個別に指導する手間が減ります。

## 副業・個人活用視点

**説明の仕事をしている人にとって、これは道具が1つ増えた話です。** 研修や講座で概念を説明するとき、静的な図では伝わりにくい対象があります。物理現象、構造、時間変化を伴うもの。**その場で「見せて」と頼めば操作できるモデルが出てくる**なら、資料作成の前段階、つまり「どう見せるか」を試す工程が速くなります。完成品として使えるかは別として、**検討の速度が上がる**のは確かです。

**ただし、そのまま納品物に使うのは慎重に。** 生成された可視化は、見た目の完成度に対して裏付けの強さが不明です。**「AI が作った図です」と明示せずに資料へ入れると、後で説明責任が自分に返ってきます。** 教材や研修資料として提供する立場なら、事実確認を経たものだけを使い、それ以外は自分で作り直す線引きを最初に決めておいてください。

**Workspace を使う支援先への提案材料としては、統制側の話のほうが刺さります。** 「既定ONで入ってきて、機能単独では止められない」という状況は、情シスにとって説明が要る事象です。**変更が入ったこと自体を先に伝えられる立場にいることが、そのまま価値になります。** Workspace Updates を巡回して顧客に要点を渡す、という支援は地味ですが継続的に必要とされます。

**個人利用の観点では、学習用途との相性が良い機能です。** 概念を「読む」のではなく「動かす」ことができると、理解の定着が変わります。**とくに独学で新しい分野に入るとき、最初の全体像をつかむ段階で効きます。** ただし利用上限の実態が不明なので、学習計画をこの機能に依存させるのは避けたほうが無難です。
