## 要約

Cloudflare は 2026-11-18、プレビューで公開していた抽出モデル **Clairic** を再設計して更新し、軽量版の **Clairic-flash** を新たに発表しました。どちらも Workers AI で利用でき、**重みが Hugging Face で公開**されています。発表は、新設の「Workers AI superintelligence team」の名義で出されました。

Clairic は、文章を生成するのではなく、**指定した項目の値を型付きで返す**モデルです（10月のプレビュー時の紹介記事を参照）。今回は、プレビューで寄せられた「領収書の画像から読み取りたい」「サポートチケットから値を取り出したい」といった用途を受けて、**抽出を主目的に作り直した**と公式は説明しています。

## 何が変わったか

- **再設計**: 通常のテキスト・数値の項目は、1回の順伝播で出すのをやめ、**項目ごとに自分が書いたトークンを参照して次を選ぶ方式**（並列スロット自己回帰）に変更。全項目をバッチ内で同時に進めるため、1リクエストの遅延は小さいまま、精度が上がったとしている。計算・推定・予測・期間・日付計算向けには専用のヘッドを学習させている
- **API は据え置き**: 確信度、文字位置（スパン）、確率が各回答に付く型付きインターフェースは変わらず、スキーマも既存のまま
- **画像・PDF の読み取り**: 画像に加えて PDF も対象。最大4つの画像またはPDFページまで同時に渡せる。供給元、明細、合計が別ページにあっても1リクエストで取り出せ、明細は説明・数量・単価をまとめた行として返せる
- **モデルとエンドポイントの入れ替え**: プレビュー時は 9B を `@cf/cloudflare/clairic` で提供していた。今後は **9B を `@cf/cloudflare/clairic-flash` へ移し、27B を `@cf/cloudflare/clairic` で提供**する
- **価格（入力100万トークンあたり）**: Clairic（27B）が $0.24、Clairic-flash（9B）が $0.10。出力トークンは課金しない方針を維持。報道では、2026-12-01 まで両モデルを $0.10 とする期間があるとされるが、これは二次情報で、公式の価格表で確認が必要
- **遅延（公式の計測、p50 / p95）**: テキスト項目で Clairic が 358 / 736 ms、Clairic-flash が 155 / 328 ms。画像項目ではそれぞれ 453 / 976 ms、305 / 605 ms
- **公式の評価結果**: 4つの内部評価で、プレビュー版より正解数が増加（例: 領収書の合成データで 369/576 → 576/576）。Liquid AI の D1.2（OCR と組み合わせ）や ScaleDown の Extract との比較も載せているが、**公開された抽出ベンチマークは存在せず、すべて自社評価**で、公式自身も「参考値」と述べている
- **オープンウェイト**: Clairic と Clairic-flash の重みを Hugging Face で公開

## 業務インパクト（一般企業向け）

請求書、納品書、問い合わせメールなどからの項目抽出は、多くの企業が汎用の LLM で行っている業務です。専用の小型モデルは**コストと遅延を下げる**選択肢になります。

最初に確認したいのは、**プレビュー版 Clairic を使っている場合の影響**です。`@cf/cloudflare/clairic` が 9B から 27B に変わるため、同じ ID を呼んでいる既存の連携は、精度・遅延・価格が変わります。コストを据え置きたい処理は、`clairic-flash` へ明示的に切り替えるのが公式の案内に沿います。

導入判断では、公式の評価が**自社の内部評価**である点に注意してください。実際の帳票（手書き、傾き、多言語）を使った評価セットで、抽出精度と「確信度で人に回す閾値」を決めてから本番に入れるのが安全です。確信度が返るため、自動処理と人の確認の振り分けを設計しやすい一方、計算は引き続きコード側で行う設計が堅実です。

重みが公開されたことで、データを外に出せない業務では、自社環境で動かす選択肢も出てきます。ただし、ライセンス条件は公式ページで確認してください。

## 副業・個人活用視点

領収書や請求書の入力代行、問い合わせの自動仕分けなど、**定型の読み取り**を請ける場合に使いやすいモデルです。小さく速い `clairic-flash` を既定にして、精度が足りない案件だけ `clairic` を使う、という段階的な使い分けでコストを抑えられます。

PDF に対応したため、「画像にしてから送る」手間が減ります。ただし、同時に渡せるのは最大4つまでなので、長い文書は分割する前提で設計してください。顧客の帳票を扱う場合は、**守秘義務とデータの送信先**を契約で確認し、まず自分の書類で試すのが安全です。
