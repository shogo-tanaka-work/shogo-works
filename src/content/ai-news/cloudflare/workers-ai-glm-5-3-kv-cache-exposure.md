## 要約

Cloudflare は2026-10-26、**Workers AI の GLM-5.3 で、他の顧客のリクエストの内容が応答に混ざる問題があった**と公開報告しました。対象モデルは `@cf/zai-org/glm-5.3` です。

- **期間**: 2026-08-27（モデル公開時）から 2026-09-09
- **影響**: 681,280 トークンを超える長いプロンプトへの応答のうち**155件**。少数の顧客が、直前に同じモデルへ送られた他の顧客のデータを含む応答を受け取った
- **悪用**: 影響のあったリクエストは、Cloudflare 自身のテストと研究者のものを除くと、通常の長文脈利用と時期・量が一致しており、**意図的な悪用の証拠はない**と公式は述べている
- **他モデル**: Workers AI の他のモデルは影響を受けていない

発端は2026-09-08に HackerOne 経由で届いた研究者の報告です。Cloudflare は翌朝に再現を確認し、**インシデント宣言から40分以内にモデルを停止**しました。設定の修正とエンジンのパッチを当て、**同日の19:40（UTC）に復旧**しています。今回の記事は、その経緯を SGLang 側の投稿と合わせて公開した協調開示です。

### 原因は2つ重なっていた

**1つ目は設定の不一致です。** GLM-5.3 はコンテキスト長 1,048,576 トークンで公開されましたが、prefill 側 GPU の KV cache プールには 681,280 トークン分しかありませんでした。Cloudflare はこの差を公開前から把握していましたが、エンジンが超過分をエラーとして返すと想定していました。事前テストでは長文脈でも成功のステータスが返ったため、問題ないと判断しています。**公式は、確認していたのが HTTP ステータスと性能だけで、出力の内容と一貫性を検証していなかった点を、テストの欠落と認めています。**

**2つ目は SGLang のバグです。** prefill と decode を別のGPU群に分ける構成では、プールに収まらないプロンプトが「拒否済み」と記録されたのに、受付の判定を通ってしまいました。decode 側は、予約したメモリページのうち1ページしか書き込まれていない状態で応答を生成し、**残りのページに残っていた他の人のプロンプトや生成途中の文章を読んでしまいます。** クライアントにはエラーではなく HTTP 200 が返り、応答も自然な文章でした。

## 何が変わったか

- **設定の修正**: GLM-5.3 の KV cache プールを約204万トークンに拡大し、コンテキスト長の約2倍にした。有効なリクエストが拒否経路に入らなくなる
- **エンジンの修正**: 拒否されたリクエストは、メモリ確保や転送の前に元のエラーで終了させるパッチを適用した。SGLang 本体にも反映され、**v0.5.20 で修正、v0.5.21 と v0.5.22 で追加対応**が入っている
- **横展開**: SGLang で提供する全モデルに同じ修正と強化を適用し、新規デプロイの要件にした
- **検査の変更**: KV プールのサイズとコンテキスト長の一致を、稼働中のエンジンから直接確認してからデプロイする
- 自前で SGLang を使う運用者には、**v0.5.22 以降への更新が推奨**されている

## 業務インパクト（一般企業向け）

**まず確認したいのは、GLM-5.3 を使っていたかどうかです。** 使っていない場合、公式は他モデルへの影響はないとしており、対応は不要です。使っていた場合も、影響があったのは**約68万トークンを超える極端に長いプロンプト**で、通常の業務利用で届く長さではありません。

それでも、**入力に顧客情報や社内機密を含めて長文脈で処理した心当たりがあるなら、期間（2026-08-27〜09-09）の利用記録を見直す価値があります。** 逆に、他の顧客のデータが自社の応答に混ざった可能性もあります。応答を業務に取り込む処理がある場合は、その期間の長大な入力に対する出力を確認してください。公式の記事には、顧客へ個別通知を行ったかどうかの記載が見当たらないため、**自社が当該のリクエストに含まれるかは、現時点で記事からは判断できません。**

**より大きな教訓は、マルチテナントの AI 基盤の信頼性は、提供側の運用品質に依存するということです。** 今回の問題は、モデルの精度ではなく、**メモリの使い回しと拒否処理の取りこぼし**という推論基盤の実装で起きました。外部の推論 API を調達する際は、機密度の高い入力を長文脈で渡してよいかを、**データ区分ごとに決めておく**のが現実的です。契約や監査の観点では、今回のように**事故の経緯を時系列と原因つきで公開する事業者**かどうかも、選定の材料になります。

## 副業・個人活用視点

**個人の利用では、影響を受けた可能性は低いと考えてよいでしょう。** 68万トークンは、一般的な文書数百冊分に相当する長さです。ただし、コードベース全体や大量のログを一度に渡す使い方をしていた場合は、**期間内にそうした入力をしていないか**を思い出してください。

**受託や開発で学べるのは、検証の観点です。** Cloudflare が自ら認めた欠落は「**HTTP ステータスが正常なら大丈夫だと判断した**」ことでした。自分で AI を組み込むときも、長い入力や上限ぎりぎりの入力を流して、**エラーが返ることだけでなく、出力が入力に沿っているか**を確かめるテストを1本入れておくと、同種の取りこぼしに気づけます。

**セルフホストで SGLang を使う人は、バージョンの確認が先です。** 公式は v0.5.22 以降への更新を強く推奨しています。あわせて、起動ログに出るプールのサイズと、設定したコンテキスト長を見比べる習慣を持つと、今回の設定不一致は自分の環境でも見つけられます。
