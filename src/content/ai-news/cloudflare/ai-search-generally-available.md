## 要約

Cloudflare は 2026-10-01、**AI Search** を preview から **一般提供（GA）**へ移しました。あわせて **課金開始日が 2026-11-01** と明示されました。

**AI Search が何なのかを先に確認します。** **Workers AI / Vectorize / R2 / Browser Run を束ねた「フルマネージドな索引・検索パイプライン」**です。RAG（社内データを検索して LLM に渡す仕組み）を作るとき、従来は**クローラーを書き、チャンク分割の方式を決め、埋め込みを作り、ベクトルDB に入れ、検索クエリを書く**という一連の設計判断が必要でした。AI Search はこれをまとめて引き受けます。

**2026-08-06 に単一コマンド化と価格の preview 提示が行われており、今回はその続報にあたります。** 当時「課金は未開始で、開始前に告知する」とされていた部分が、**2026-11-01 開始として確定しました。**

**GA での機能追加は2点です。**

**1点目は、マルチモーダル埋め込みです。** **Qwen3-VL-Embedding** により、**画像をピクセルのまま埋め込んで検索**できるようになりました。構成は二重で、**視覚情報とテキストキャプションの両方を保持**します。ストレージ効率は **Matryoshka Representation Learning** で確保しています。テキスト専用モデルを使う場合も、**ToMarkdown でキャプション化すれば画像を検索対象にできます。**

**この二重構成が実務的に重要です。** 画像検索を「キャプション化してテキスト検索する」方式だけで組むと、**キャプションに書かれなかった情報は検索できません。** 図表の中の数値、写真の構図、スクリーンショットのレイアウト。これらはキャプション生成の時点で落ちます。ピクセルを直接埋め込む経路が併存するなら、**キャプションの質に依存しない検索**ができます。

**2点目は、ファイル処理の拡張です。** **最大ファイルサイズが 4 MiB から 10 MiB へ**拡大しました。対応形式は Markdown / HTML / CSV / JSON / PDF。**スキャン PDF の OCR** に対応し、これは**画像処理の取り込みトークンとして課金**されます。

**価格（2026-11-01 から）を整理します。**

| 項目 | 単価 | 無料枠 |
| --- | --- | --- |
| 取り込み（基本） | $0.75 / 100万トークン | 月500万トークン |
| 画像処理（加算） | +$0.50 / 100万トークン | 月500万トークン |
| ストレージ | $2.00 / GB・月 | 10 GB |
| セマンティック検索 | $0.75 / 1,000件 | 月1,000件 |
| 全文検索 | $0.10 / 1,000件 | 月1,000件 |

**埋め込みとリランキングは対象 Workers AI モデルであれば込み**で、サードパーティモデルは別課金です。

**今後の予定**として、動画・音声処理、キーワード検索のスケール改善、**エージェント向けのサイト組み込みの簡素化**が挙げられています。

## 何が変わったか

- **AI Search が GA**（2026-10-01）。**課金開始は 2026-11-01**、開始前に通知
- **マルチモーダル埋め込み**: **Qwen3-VL-Embedding** で画像をピクセルのまま埋め込み
  - 視覚情報とテキストキャプションの**両方を保持する二重構成**
  - **Matryoshka Representation Learning** でストレージ効率を確保
  - テキスト専用モデルでも ToMarkdown のキャプション化で画像を検索可能
- **ファイルサイズ上限が 4 MiB → 10 MiB**
- 対応形式: Markdown / HTML / CSV / JSON / PDF
- **スキャン PDF の OCR** に対応（画像処理の取り込みトークンとして課金）
- 価格は上表（取り込み・画像処理・ストレージ・セマンティック検索・全文検索）
- 埋め込みとリランキングは対象 Workers AI モデルなら込み。サードパーティは別課金
- 今後: 動画・音声処理、キーワード検索のスケール改善、エージェント向けのサイト組み込み簡素化

## 業務インパクト（一般企業向け）

**最初に押さえるべきは「2026-11-01 から課金される」という事実です。**

**preview 期間に動かしている構成がある組織は、10月中に見積もりを出す必要があります。** 「無料で試していたものが11月から請求される」という形で発覚するのが最悪です。見積もりに必要な数字は3つです。**(1) 索引対象のデータ量**（取り込みトークンとストレージ）、**(2) 月あたりの検索回数**、**(3) 画像・スキャンPDF の割合**（画像処理の加算）。

**無料枠の読み方に注意が要ります。検索が月1,000件というのは、社内検索としては小さいです。**

**セマンティック検索 1,000件/月は、1日あたり約33件です。** 100人の組織で社内検索として常用すれば、**初週で超えます。** 単価は 1,000件あたり $0.75 と安いので金額は問題になりにくいですが、**「無料枠で収まる」という前提で稟議を通すと、実績値と合わなくなります。** 全文検索は $0.10/1,000件とさらに安いため、**セマンティックと全文を使い分ける設計**がコストに効きます。

**取り込み側は、更新頻度が効きます。** $0.75/100万トークンという単価自体は安いのですが、**取り込みは「更新のたびに発生する」**点を見落としやすいです。社内ドキュメントが頻繁に更新される環境では、**初回索引のコストより再索引のコストが大きくなります。** 更新検知を行って差分だけ入れる設計にできるかを確認しておくべきです。

**次に、マルチモーダル対応が業務でどこに効くかです。**

**日本企業の社内ドキュメントは、画像と PDF の比率が高い**傾向があります。業務マニュアルのスクリーンショット、Excel で作った図表を貼った資料、スキャンした紙の規程。**これらは従来の RAG で最も検索しにくい部分でした。**

**OCR 対応とファイルサイズ 10 MiB への拡大は、ここに直接効きます。** とくに**スキャンした紙の規程類**は、「存在は知っているが探せない」状態になりがちです。OCR が標準で使えるなら、索引の対象に入ります。

**ただし期待値の調整が必要です。** OCR の精度は原稿の状態に依存します。**手書きの書き込みがある紙、傾いたスキャン、低解像度のFAX**は、OCR をかけても検索に耐える品質にはなりません。**「スキャンPDF が索引できる」は「スキャンPDF が検索できる」とは別です。** 導入時は、自社の資料を代表的に10件ほど入れて精度を確認してから範囲を決めるべきです。

**3つ目に、GA になったことの意味です。**

**preview と GA の違いは、本番で使ってよいという公式の表明です。** 社内の情報システム部門が「preview のサービスは本番に入れない」という方針を持っている場合、**今回の GA でその障壁が外れます。** 稟議の文面として「一般提供されたサービス」と書けるかどうかは、実務では小さくない差です。

**一方で、マネージドであることの制約は変わりません。** 内部構成（チャンク分割の方式、リランキングの挙動）が隠れているため、**精度が出ないときに調整できる範囲は自前構成より狭いです。** これは 2026-08-06 の時点から変わっていない論点です。**「設定で済む」ことと「思い通りに調整できる」ことは両立しません。**

**判断の順序としては、こうです。** **まず無料枠の範囲で自社資料を入れて精度を見る。** 精度が業務に足りるなら、**次に11月以降のコストを試算する。** 精度が足りないなら、**自前構成で調整するか、そもそも RAG 以外の手段を考える。** この順序を逆にして、コスト試算から始めると、精度が足りなかったときに試算が無駄になります。

## 副業・個人活用視点

**個人開発者にとって、この更新の価値は「無料枠の範囲で RAG を本番運用できる」ことです。**

**無料枠を個人の規模で読み直します。** 取り込み月500万トークン、ストレージ 10GB、セマンティック検索 月1,000件。**個人開発のサービスや、自分用の検索ツールなら、これで足ります。** 1日33クエリは、自分1人で使うには十分です。

**つまり、11月の課金開始後も、個人用途は実質無料で続けられる可能性が高いです。** これは「ベータが終わったら有料になる」パターンとは違います。**無料枠が明示されている設計**なので、どこまで無料で使えるかが事前に分かります。

**個人で作る価値があるものを2つ挙げます。**

**1つ目は、自分の資料の検索です。** 過去に書いた記事、受講したセミナーの資料、スクリーンショットで残した手順。**これらは量が増えると自分でも探せなくなります。** AI Search の無料枠に入れておけば、セマンティック検索で引けます。**ストレージ 10GB は、テキストと PDF なら相当な量が入ります。**

**とくに画像対応が効きます。** 自分用のナレッジは**スクリーンショットの比率が高い**ことが多く、ファイル名も「スクリーンショット 2026-05-12 14.33.21.png」のような状態で放置されがちです。**ピクセルのまま埋め込めるなら、ファイル名に頼らず探せます。**

**2つ目は、受託の提案材料です。**

**「社内のドキュメントを検索できるようにしたい」は、AI 関連で最も多い相談の1つです。** そして**最も見積もりが難しい案件**でもあります。精度が出るかどうかが事前に分からず、出なかったときの責任の所在が曖昧になるためです。

**AI Search を使うと、この案件の進め方を変えられます。** **無料枠の範囲で顧客の実資料を入れて、精度を先に見せる。** これなら、**作ってから「使えない」と言われるリスクを前に倒せます。**

**提案時の見積もりの出し方を具体的に書きます。** 11月からの単価が公開されているため、**「資料 X GB、月 Y クエリならコストは月 Z ドル」という形で数字が出せます。** これは顧客にとって判断しやすい情報です。多くの AI 案件は「使ってみないとコストが分からない」と説明されるため、**事前に数字が出せること自体が差別化になります。**

**注意点を2つ書きます。**

**1つ目。精度の検証を無料枠で行うとき、顧客のデータを扱う点を先に合意してください。** 「試しに入れてみました」で顧客の社内文書を外部サービスへ送ると、それ自体が問題になります。**検証用に扱える資料の範囲を書面で確認してから**動くべきです。

**2つ目。コストの試算は「取り込み」を忘れないこと。** 検索回数は見積もりやすいのですが、**更新のたびに再索引が発生する**点を試算に入れ忘れると、実績が見積もりを超えます。顧客のドキュメント更新頻度を聞いておく必要があります。

**学習の観点では、マルチモーダル埋め込みの二重構成に注目する価値があります。**

**「画像をキャプション化してテキストとして扱う」方式と「ピクセルを直接埋め込む」方式は、どちらも成立しますが、落ちる情報が違います。** 前者はキャプションに書かれなかった情報を落とし、後者はテキストとしての厳密な一致を取りにくくします。**両方を保持するという判断は、「どちらが優れているか」ではなく「失うものが違うから両方持つ」という設計です。**

**この考え方は、検索に限らず応用が利きます。** 要約を作るときに原文も残す、構造化データに変換するときに元テキストも持つ。**変換は常に情報を落とすので、落ちたものが必要になる可能性があるなら、変換前も残す。** 当たり前のようですが、ストレージを節約しようとして変換後だけを残し、後で困るというのは頻出の失敗です。
