## 要約

Cloudflare は 2026-11-20 の changelog で、**Agents SDK v0.34.0** が `PiHarness` を **Pi 1.6** に更新したと告知しました。中心は「待つツール」です。ツールが人の返答や期限、別のセッションの完了を待つあいだ、**Durable Object を起こしたままにせず、休止させられる**ようになります。

これまで、人の承認待ちのような長い待機をエージェントに持たせると、待っている間も実行環境が生きたままになる設計になりがちでした。今回の変更は、待機をツールの戻り値として表し、条件が満たされたときに再開する形にしています。

## 何が変わったか

- **保留（park）**: ツールが結果の代わりに「保留」を返すと、信号が届くか期限が来たときに Pi がそのツールをもう一度実行する。待機中は呼び出しが残らないため、Durable Object は休止できる
- **再開の合図**: 新しい `harness.signal()` で信号を届ける。公式の例は、ユーザーに質問を出して保留し、回答が来たら信号で再開する `ask_user` ツール
- **subagent の待機**: `submit()` と `continue()` に `notify` が加わり、別セッションの入力が落ち着いた時点で、保留していたツールを起こせる
- **承認ゲート**: `beforeTool` フックで、実行前のツール呼び出しを保留にし、人が承認するまで待たせられる
- **既存履歴からの開始**: `harness.root()`、`sessions.create()`、`sessions.fork()` が Pi の `init` を受け取り、セッション作成と同じコミットで履歴を書き込める。ルートセッションは初回利用時に作られる
- **中断時の入力保持**: `submit(input, { onAbort: "keep" })` で、回答を止めても、次に送られた入力が捨てられない
- **安定性**: 切れたプロバイダー接続の再試行が増えた。Anthropic 側がメッセージの続きを処理できなくなった場合、`agents/models/pi-ai` が会話全体を再送して失敗を避ける。`PiHarness.dispose()` でセッションごとの状態を解放できる

## 業務インパクト（一般企業向け）

人が途中で確認する流れ（承認、追加情報の入力）を持つ業務エージェントを、**待機のたびにリソースを占有しない設計で作れる**ようになります。申請の承認、問い合わせへの返答待ち、期限つきの再確認などが典型です。

導入を検討する場合は次を確認してください。

- **料金への影響**: 休止できるという説明にとどまり、待機中の課金や上限の扱いは今回の告知から読み取れません。Durable Objects の料金ページと自社の利用量で確認する
- **承認の記録**: `beforeTool` で保留にしても、誰がいつ承認したかを残す仕組みは自分で用意する必要がある
- **対象は SDK 利用者**: 既製の Cloudflare 製品の設定画面で使える機能ではなく、Agents SDK でコードを書く開発者向けの更新

## 副業・個人活用視点

承認ゲートと待機ツールは、**依頼者の確認を挟むエージェント**を小さく作るのに向いています。たとえば、見積もりの下書きを作り、依頼者が承認してから送信する流れを、常駐させずに組めます。

ただし SDK のバージョンを上げる前に、既存のエージェントが依存する挙動（ルートセッションの作成タイミングなど）が変わっている点を、公式ドキュメントで確認してください。納品物に使う場合は、期限切れ時の動作と中断時の入力の扱いを、テストで固定しておくと安全です。
