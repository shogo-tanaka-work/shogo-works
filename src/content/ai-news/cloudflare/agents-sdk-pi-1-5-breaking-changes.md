## 要約

Cloudflare は2026-11-03、Agents SDK v0.33.0 で `PiHarness` を **Pi 1.5** に更新したと告知しました。主な狙いはストリーミング時の保存コストの削減です。

- Pi は回答やツール出力を更新のたびに保存するのをやめ、**1秒以内にまとめて保存**する
- SQLite 上でストレージのトランザクションが、長い回答で**約27倍**、並列ツールを使うターンで**約5.7倍**減り、CPU も約4分の1減る
- 2,048 セッションのベンチマークで、1つの Pi harness の処理は**毎秒 88 回から 459 回**に上がった
- 500 KB のツール呼び出しをストリームしたとき、従来は約20秒の CPU と 100 MB のヒープを使っていたが、新版は追記方式で負荷を下げた

## 何が変わったか

**新しい API と設定**

- `session.watch()` が `session.events()` を置き換える。最新の会話記録と、ストリーム中の回答・実行中のツール・直前の実行が答えなしで終わった理由といったライブ状態を返す
- `session.continue()` は、メッセージを足さずに既存の会話記録から新しい実行を始める。モデルエラー後や、ターン上限に達した後の再開に使う
- `defaults.maxTurns` で、新規セッションの 1 回の実行が回せるツールのラウンド数に上限を付けられる
- Pi の code mode のスクリプトから `browserTool` を呼び、スクリーンショットを `image()` に渡せる

**削除・破壊的変更**

- `retry()` と `parked` ステータスは削除された。再起動の上限で切れたタスクは、待機状態で止まらず終了する
- Pi 1.5 で動いた会話は Pi 1.4 で読めない。公式は、デプロイに問題が出たら**ロールバックせず前に進めて直す**よう案内している

**既定設定でのトレードオフ**

- 更新は画面にはすぐ流れるが、保存は一括になる。クラッシュすると、最大で約1秒分のストリーム途中経過が失われ得る。この間隔は Recovery の設定で変えられる

## 業務インパクト（一般企業向け）

**Agents SDK で Pi を使っているチームだけが対象です。** 使っていなければ何も起きません。

**コスト面では追い風です。** 書き込み回数の削減は、Durable Object のストレージ課金や CPU 時間に効く可能性があります。ただし数字は公式の SQLite ベンチマークの結果で、自社の負荷で同じ比率になるかは測らないと分かりません。

**アップグレードの手順は、通常のライブラリ更新より慎重にします。**

- 呼び出し側で `session.events()` を使っている箇所を `session.watch()` に、`retry()` と `parked` を使う箇所を取り除く
- 巻き戻せないため、まず検証環境で本番に近い会話データを使って動かす
- 1秒間隔の一括保存で許容できる損失かを、業務の性質（途中経過が失われて困るか）で判断する

**注意点**: 本記事は changelog の記述に基づく。移行の全項目は Pi Durable 1.5.0 の公式 changelog にあり、本記事では確認していない。

## 副業・個人活用視点

**個人開発や受託の小さなエージェントでは、性能向上より破壊的変更の把握が先です。** 依存を最新に追従させる運用なら、`session.events()` を使ったサンプルコードやテンプレートが古くなっていないかを確認します。

**新 API の `session.continue()` と `maxTurns` は、実用上の安全弁になります。** モデルがエラーで止まった会話を、ユーザーに再入力させず続きから動かせます。ツール呼び出しが止まらない暴走も、ターン上限で抑えられます。

**受託案件では、巻き戻し不可を事前に伝えます。** 納品後に Pi 1.5 へ上げると元に戻せないため、更新作業を見積もるときの前提として共有しておくと安全です。
