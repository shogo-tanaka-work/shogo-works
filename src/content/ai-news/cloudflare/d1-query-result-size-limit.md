## 要約

Cloudflare は2026-10-30、**D1 のクエリ結果に 50MB の上限を設け、2026-11-04（水）から適用する**と告知しました。

- 50MB を超える結果を返すクエリは**失敗**し、次のエラーになる: `D1 query result exceeded the maximum response size limit of 50 MB`
- 上限は、リクエスト全体の **99.999 パーセンタイル**を含む水準に置かれており、**大半の利用者は影響を受けない**
- **REST API 経由のインポートとエクスポートは対象外**。従来どおり動く

## 何が変わったか

- 適用日は**2026-11-04**。告知から適用まで5日しかない
- 超過時は、結果が切り詰められるのではなく**クエリそのものが失敗する**
- 対策（公式の案内）
  - `SELECT *` をやめ、必要な列だけを取得する
  - `LIMIT` と `OFFSET` で、結果を分割して取得する
- 詳細は公式ドキュメントの D1 の制限と、エラー一覧に載っている

## 業務インパクト（一般企業向け）

**ほとんどの業務アプリは、何もしなくて構いません。** 画面表示や通常の検索で 50MB を返すことは稀です。

**確認が要るのは、全件を一度に取り出す処理です。** 夜間の集計、外部システムへの書き出し、バックアップ代わりの全件取得、レポート作成などは、データが増えるほど結果が大きくなります。**今は通っていても、適用日以降に失敗する可能性**があります。

確認の手順は次の通りです。

- 大きな結果を返し得るクエリ（全件取得、大きな JSON や BLOB 列を含む取得）を洗い出す
- 実際の結果サイズを、検証環境で測る
- 超え得る場合は、分割取得か列の絞り込みに変える
- エラーメッセージを監視の検索条件に加え、適用日以降に失敗が出ていないかを見る

**注意点**: 本記事は changelog の記述に基づく。結果サイズの数え方（圧縮の有無、列ごとの扱い）は公式ページから確認できていない。

## 副業・個人活用視点

**個人開発や小規模な受託では、影響を受ける場面は限られます。** ただし、ログや履歴を溜め続けるテーブルを、管理画面から一括で書き出す機能を作っている場合は要注意です。

**対応は小さな変更で済みます。** 取得を `LIMIT` で区切って繰り返す処理にしておくと、データが増えても失敗しません。納品先に D1 を使ったシステムがある場合は、**書き出し系の処理がないかを11月4日までに確認し、顧客に一言伝えておく**と、後の問い合わせを避けられます。

**情報源の制約**: 本記事は Cloudflare の changelog（2026-10-30）に基づく。サイズの計測方法と、制限に近い場合の挙動は未検証。
