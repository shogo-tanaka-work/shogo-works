## 要約

Cloudflare は2026年11月13日、Workers と Durable Objects に利用額の上限とアラートを設定できるようにしました。暴走したループや想定外のアクセスで利用量が増えても、請求額を抑えられます。公式ブログ（Introducing Spend Management）によると、今後は他の製品にも広げる予定です。

上限は、アカウント全体の現在の請求期間に対して、製品ごとに設定します。上限に達すると、Cloudflare はその製品の対応する操作をブロックします。止めずに知りたいだけの場合は、ブロックをオフにしてメールアラートだけを受け取れます。

## 何が変わったか

- **対象製品**: 現時点は Workers と Durable Objects。製品ごとに別の設定を持つ
- **設定場所**: ダッシュボードの Billing > Spend limits。上限額、通知先メール、アラートのしきい値を選ぶ
- **例**: Workers に $10 の上限を設定し、$5 と $9 でメールアラート。アラートを受けながら動かし続けるには、Block usage をオフにする
- **到達時の挙動**: 対応する操作をブロックする。再開するには、上限を現在の利用額より上げる、オフにする、削除する。次の請求期間が始まっても再開する
- **CLI**: `cf billing spend-policies create` に `--product-id workers`（または `durable_objects`）、`--threshold-cents`（米セント単位。5000 で $50）、`--action usage_block` を渡す
- **注意**: 利用量の報告とブロックには時間がかかるため、記録される利用額は上限を超えることがある
- **既存機能との関係**: アカウント全体の利用額を通知する予算アラートは併用できる。AI Gateway はユーザー別・モデル別の予算で AI 推論のコストを管理でき、今回の機能と組み合わせて計算資源と推論コストの両方を管理する

## 業務インパクト（一般企業向け）

従量課金の基盤では、設定ミスや攻撃による使用量の急増が、そのまま請求に響きます。これまでは通知で気づく運用が中心でしたが、今回は上限で止められます。一方で、上限に達すると本番の処理がブロックされる点が新しい論点です。止めてよい環境（開発・検証）には上限を、止めたくない本番にはアラートのみを、という使い分けが現実的です。

上限が超過しうる仕様も、社内の説明に入れておくべき点です。「上限＝請求の絶対上限」ではありません。また、cf CLI で設定できるため、設定を手順書やコードに落として、アカウントごとに統一できます。

## 副業・個人活用視点

個人や小規模案件で Workers を使う場合、顧客のアカウントに上限を入れておくと、想定外の請求の説明責任を減らせます。公式は、設定をコーディングエージェントに任せるためのプロンプトも用意しています。ただし本番を止める設定になるため、納品時には、どの環境で上限を有効にしているかを顧客に伝えてください。
