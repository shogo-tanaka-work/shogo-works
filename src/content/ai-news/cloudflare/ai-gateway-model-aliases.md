## 要約

Cloudflare は2026-11-04、**AI Gateway にモデルエイリアス（model aliases）を追加**したと告知しました。

- エイリアスは「**複数のモデルをまとめたプール**」で、`custom/support-fast` のような1つの名前で呼び出す
- AI Gateway は**設定した順にモデルを試し**、リクエストが失敗したら次のモデルへ**フォールバック**する
- 順番ではなく、**スマートルーティング**でリクエストごとにモデルを選ばせることもできる
- アプリは名前だけを参照するので、**モデルの入れ替えやルーティング方式の変更を再デプロイなしで**行える

作成と管理は、ゲートウェイの Routing ページで、既存の dynamic routes と並べて行います。

## 何が変わったか

- 複数モデルのプールに**1つの名前**を付け、アプリ側はその名前だけを使う
- 失敗時の**自動フォールバック**を、コードではなくゲートウェイの設定として持てる
- REST API では `/accounts/{account_id}/ai/run` の `model` にエイリアス名を指定する
- 呼び出すゲートウェイは `cf-aig-gateway-id` ヘッダーで選ぶ
- **エイリアスは個々のゲートウェイに属する**。別のゲートウェイで同じ名前を使うには、そこにも作る

## 業務インパクト（一般企業向け）

**モデルの切り替えが運用作業になります。** これまで、モデルの世代交代や障害時の切り替えはコード修正と再デプロイが必要でした。エイリアスを使えば、業務アプリのコードに触れず、ゲートウェイの設定で入れ替えられます。

**障害対策として使えます。** 主モデルが失敗したときに次のモデルへ自動で回す設計を、アプリ側に実装せずに持てます。

導入時に決めておくこと:

- どの用途にどの名前を付けるか（例: 問い合わせ対応用、要約用）。**名前は用途で付け、モデル名を含めない**と、差し替えても名前が嘘にならない
- フォールバック先のモデルの**料金・品質・データの扱い**が、主モデルと同じ基準を満たすか。品質の違うモデルへ黙って切り替わる状況は、業務上の事故になり得る
- 設定を変更できる人と、その変更履歴の残し方。コードのレビューを通らず本番の挙動が変わる点は、統制上の論点になる

**注意点**: 本記事は changelog の記述に基づく。スマートルーティングの選択基準や、フォールバックの条件（どのエラーで切り替わるか）の詳細は、公式ドキュメント（Model aliases）で確認が必要。

## 副業・個人活用視点

**小さな案件でも、モデルの入れ替えを楽にできます。** 新しいモデルが出るたびにコードを直して再デプロイする代わりに、エイリアスの中身だけを変えれば済みます。複数の顧客向けに別々のゲートウェイを用意すれば、顧客ごとに使うモデルを設定で変えられます。

**費用の安いモデルを先頭に置いて、失敗時だけ高いモデルへ回す構成が組めます。** ただし、どちらが応答したかによって品質と費用が変わるため、納品時に「失敗時は別モデルに切り替わる」ことを説明しておくと、後の認識違いを避けられます。
