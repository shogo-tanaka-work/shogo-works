## 要約

Cloudflare は 2026-09-27、年次の **Founders' Letter** を公開しました。製品リリースではありません。changelog 側に該当エントリは無く、blog 単独の発表です。同社が見ているインターネットの構造変化と、それに対して打つ施策の方向を示す文書です。

**読むべき理由は、数字の訂正が入っているからです。**

Cloudflare は従来、**自動トラフィックが人間のトラフィックを追い越す時期を2027年半ばと予測**していました。本レターはこれを訂正し、**実際には2026年5月に既に追い越していた**としています。**1年以上早かった**ことになります。さらに、**5年以内に自動トラフィックが人間の1,000倍に達しうる**という見通しを示しています。

自社サイトのアクセスログを見る側にとって、これは抽象論ではありません。**「アクセス数が増えた」がそのまま「見込み客が増えた」を意味しない状態が、例外ではなく既定になっている**ということです。

**レターの中心にある問題提起は「コモンズの悲劇」です。** エージェントは利用者にとって効率的です。しかし **1つのレストランを推薦するために999軒をクロールし、負荷を負担した999軒には何も還元されない**。利用者1人あたりの便益は上がるのに、情報を提供している側のコストだけが積み上がる構造です。Cloudflare はこれをサイト運営者側の持続性の問題として扱っています。

**もう一つ、観測として面白いのは Web の総量についての記述です。** 同社によれば、**Web は2025年半ばから急増しており、その主因は「slop」（低品質な自動生成コンテンツ）ではなく、AI の支援を受けた新しい作り手**です。レターは "AI has unleashed a new cohort of creators. Individuals with ideas but without coding skills...are able to bring new creations to life" と述べています。**アイデアはあるがコードは書けなかった層が、作れる側に回った**という整理です。**開発者プラットフォームの利用者は700万人を超え**、vibe coding 系ツールの既定デプロイ先になっているとしています。

**懸念として挙げられているのは寡占化です。** エージェントはデータの多い既存事業者を選びやすい。**選ばれるかどうかがエージェントの判断に依存するなら、新規参入の障壁はむしろ上がる**、という筋です。

打ち出された施策は3方向です。**クローラーの効率化によるサーバー負荷の低減、エージェントがコンテンツやアプリを使った際の対価還元の仕組み、同じ方向性の組織との提携。** ただし **具体的な製品名・提供時期・価格は、本レターには一切示されていません。** 方向の表明にとどまります。

## 何が変わったか

- **製品機能の追加は無い**。年次の方針表明であり、changelog には該当エントリが無い
- **自動トラフィックが人間を追い越した時期を 2026-05 と確定**（従来予測は2027年半ば。1年以上の前倒し訂正）
- **5年以内に自動トラフィックが人間の1,000倍**に達しうるとの見通しを提示
- **Web の総量増加の主因を「slop」ではなく AI 支援を受けた新しい作り手**と位置づけ
- **開発者プラットフォームの利用者が700万人超**であることを開示。vibe coding 系ツールの既定デプロイ先になっているとする
- エージェントによる既存事業者への集中と、新規参入障壁の上昇を懸念として明記
- 施策は3方向（クローラー効率化 / 対価還元 / 提携）。**製品名・提供時期・価格は未提示**

## 業務インパクト（一般企業向け）

**まず効くのはアクセス解析の読み方です。** 自動トラフィックが人間を上回っているなら、**セッション数や PV をそのまま需要の指標として扱う運用は前提が崩れています。** 人間由来とエージェント由来を分けて見る集計になっているか、月次レポートの定義を一度確認する価値があります。分けていない組織では、**去年と今年の数字を並べた時点で比較が成立していません。**

**次にインフラ費用です。** 転送量や実行回数で課金される構成なら、**費用の一部はエージェントのクロールに対して払っています。** それが5年で1,000倍に向かうという見通しである以上、**「アクセスが増えたので増強する」という判断の前に、増えているのが誰なのかを分解する**手順を入れる必要があります。Cloudflare が「クローラーの効率化」を施策に挙げているのは、裏を返せば**現状のクロールが非効率で、その非効率のコストはサイト側が負担している**という認識だからです。

**経営レベルで効くのは寡占化の指摘のほうです。** エージェントがデータの多い既存事業者を選びやすいなら、**「検索で見つけてもらう」を前提にした集客設計は、そのままでは通用しなくなります。** 中堅・中小にとっては、認知経路がエージェントの判断に握られるという話です。**自社の情報が構造化されて機械可読になっているか**、**一次情報として参照される固有の内容を持っているか**が、以前より直接的に効いてきます。

**ただし施策は何も出ていません。** 対価還元の仕組みは方向が示されただけで、製品も時期も価格もありません。**このレターを根拠に今すぐ発注する話は無い**というのが正確な状態です。予算化するのは早すぎます。**いま動かすべきは計測の定義で、投資判断は具体が出てからで間に合います。**

## 副業・個人活用視点

**個人の作り手にとっては、むしろ追い風の記述が入っています。** Web の増加の主因が AI 支援を受けた新しい作り手だという観測、そして開発者プラットフォームの利用者700万人という数字です。**「コードは書けないがアイデアはある」層が実際に作る側へ回っている**という Cloudflare 側からの裏づけになります。案件提案で「AI で作れるようになった」と言うときの、観測に基づく根拠として使えます。

**一方で、自分のサイトやブログを収益源にしている場合は逆風の話です。** エージェントが内容を読んで要約し、利用者が元サイトに来ないなら、**表示回数に依存した収益は構造的に痩せます。** レターが対価還元を論点に挙げていること自体が、**現時点でその還元が存在していない**ことの確認でもあります。

**実務的な打ち手は2つです。** 1つは、**閲覧数に依存しない収益（受託、講座、コミュニティ）へ比重を移すこと**。もう1つは、**エージェントに引用されやすい書き方に寄せること**です。後者は一見矛盾しますが、**引用されて名前が残ることが認知経路として機能するなら、流入が減っても指名が増える**余地はあります。どちらに賭けるかは扱う領域によりますが、**「今のままの PV 前提で5年」は、この数字を見る限り成立しません。**

Cloudflare のレターは方針表明です。**製品が出るまでは、対価還元をあてにした事業計画は立てられません。** それでも、**自動トラフィックが既に人間を上回っているという一点は、今日から数字の読み方を変える理由になります。**
