## 要約

Cloudflare は 2026-10-19、**Cloudflare API MCP サーバー**が MCP 仕様の **step-up authorization（段階的な権限引き上げ）** に対応したと告知しました。

従来、エージェントに Cloudflare API を触らせるには、**接続時に必要そうな権限をまとめて許可する**しかありませんでした。今回は **最小権限で始め、足りなくなった時点で追加する**流れが取れます。

流れは次のとおりです。`https://mcp.cloudflare.com/mcp` に接続し、同意画面で **Minimal** を選びます。エージェントの作業中に未許可のスコープが必要な呼び出しが起きると、サーバーは**不足スコープを名指しした `insufficient_scope` チャレンジ**を返します。MCP クライアントがそれを受けて利用者に承認を求め、承認されると処理が続きます。**すでに許可したスコープは維持されます。**

対象は step-up authorization に対応する MCP クライアントです。公式ポストは**具体的なクライアント名やプラン・料金には触れていません**。

## 何が変わったか

- Cloudflare API MCP サーバー（`https://mcp.cloudflare.com/mcp`）が **step-up authorization** に対応
- 同意画面で **Minimal** を選ぶと、最小権限で接続を始められる
- 未許可スコープが必要になると、**`insufficient_scope` チャレンジ**で不足スコープが示される
- MCP クライアントが利用者へ追加承認を求め、**許可済みスコープは維持**される
- 利用には、クライアント側が MCP 仕様の step-up authorization に対応している必要がある（対応クライアントの一覧は公式ポストに記載なし）

## 業務インパクト（一般企業向け）

**エージェントに渡す権限を、作業を見ながら決められるようになります。**

これまでの接続は「念のため広めに許可する」になりがちでした。DNS やデプロイを触る API に、**使うかどうか分からない権限まで最初から付ける**ことになります。情シスやセキュリティの観点では、ここが一番説明しにくい部分でした。

step-up では、**最初は読み取り中心の最小権限**で接続し、書き込みや設定変更が必要になった時点で**その場で承認**します。承認の記録が「何の作業で追加したか」と結びつくため、**権限の棚卸しや監査のときに理由を追いやすく**なります。

注意点が2つあります。**1つ目は、クライアント側の対応が前提**であることです。対応していないクライアントでは、追加承認の流れが動きません。導入前に、社内で使っている MCP クライアントが対応しているかを確認してください。**2つ目は、承認する人が作業を見ている必要があること**です。無人で回すエージェントでは、承認待ちで止まる可能性があります（公式ポストは無人実行の扱いに触れていません）。

## 副業・個人活用視点

**受託案件で顧客の Cloudflare アカウントに入る場合、説明がしやすくなります。**

「まず読み取りだけで構成を確認し、変更が必要になったらその都度ご承認いただく」という進め方を、**ツールの仕様として示せます**。顧客側は広い権限を預けずに済み、こちらも「勝手に変更した」という疑いを避けられます。

個人利用でも、自分のアカウントに常時広い権限のエージェントを置かずに済みます。**最初は Minimal で始め、足りなくなったら足す**だけで、事故の影響範囲が小さくなります。
