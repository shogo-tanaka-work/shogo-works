## 要約

Anthropic は 2026-09-16、**Claude Cowork と chat を1つの Claude へ統合する**と発表しました。

これまでの Claude には、**入力前に選ぶモード**がありました。短い質問なら chat、レポート作成やリサーチのような重い作業なら Cowork です。今回の変更で、**この選択そのものが無くなります。** 何をしたいかを書けば、Claude 側がタスクに必要な手段を判断します。

**公式は統合の理由を利用者の不満として説明しています。** 「Cowork を大きな作業のための別の場所として、Design を視覚的作業のための場所として作った。利用者は両方を使っており、**どちらにタスクが属するかを決めるのが煩わしいと言われた**。片方で始めたものがもう片方に引き継がれない問題もあった」。

**この説明は、機能追加ではなく機能の配置ミスを認めたものです。** Cowork は独立した製品として作られましたが、**利用者にとっては「モードを選ぶ」という作業が毎回発生する障害物**になっていました。今回消えるのは機能ではなく、その障害物です。

**展開は Pro / Max プランから始まり、web / デスクトップ / モバイルで数週間かけて段階的に行われます。** 有効化の操作は不要で、順番が来れば切り替わります。Team / Free は「soon」とされ、**Enterprise については組織に変更が入る少なくとも30日前に通知**されます。

**実務上、最も注意が要るのは2点です。**

**1つ目は、同じプランでもアカウントごとに切替時期が違うことです。** ヘルプセンターは「同じプランのアカウントでも変更が見えるタイミングは異なる」と明記しています。入力欄に「Chat」「Cowork」の選択肢が残っていれば未移行です。**つまり、社内に「新画面の人」と「旧画面の人」が数週間にわたって混在します。**

**2つ目は、移行が非可逆であることです。** 「一度新体験になると、分離された『Chat』『Cowork』の選択肢へは戻せません」と公式に書かれています。**評価期間を置いて戻す、という選択肢はありません。**

引き継ぎ自体は行われます。既存の chat、タスク、プロジェクト、設定、コネクタ、スキル、artifacts はそのまま移ります。Cowork のタスクは Recents へ chat と統合されます。

**ただし、設定の置き場所がいくつか変わります。** Cowork の Global instructions は **Settings > General の「Instructions for Claude」へ統合**されます。公式は「あなたの instructions が意図どおりか確認してください」と、わざわざ確認を促しています。Web 検索のトグルは廃止され、Claude が必要と判断したときに検索します。Research は `/deep-research` または入力欄下の「+」ボタンから呼び出します。

権限モードは2種類に整理されています。**Manual（既定）は実行前に都度確認**、**Auto は逐一確認せず、実行前に自動の安全チェックが走る**方式です。

## 何が変わったか

- **chat と Cowork のモード選択が廃止**され、同一会話から重いタスクを依頼できる
- 重いタスクは**クラウドで継続**し、ノートPCを閉じても止まらない（ローカルのファイル・アプリを使うタスクは Claude Desktop の起動が必要）
- 成果物（ドキュメント、**数式が動くスプレッドシート**、プレゼン）を会話から直接受け取れる
- 接続済みアプリ（Google Drive / Gmail / Microsoft 365 / Slack）をタスク実行中に参照できる
- スケジュール実行タスクをクラウドで回せる（PC の電源が落ちていても継続）
- モバイルから進捗確認・質問への回答・軌道修正ができる
- **展開: Pro / Max が先行、web / デスクトップ / モバイル、数週間かけて段階的**
- **Team / Free は後続。Enterprise は変更の30日以上前に通知**
- **移行は非可逆。旧「Chat」「Cowork」選択には戻せない**
- Cowork の Global instructions → **Settings > General の「Instructions for Claude」へ統合**
- Web 検索トグルは廃止。Research は `/deep-research` または「+」ボタン
- 権限モードは **Manual（既定・都度確認）と Auto（自動安全チェック）** の2種類

## 業務インパクト（一般企業向け）

**この変更で最初に壊れるのは、社内マニュアルの記述です。**

Claude を業務に入れている組織は、手順書に「Cowork を開いて」「chat ではなく Cowork でやる」といった**モード名を含む記述**を持っているはずです。**モードが消えるので、これらの記述は無効になります。** しかも段階展開なので、**「書き換えた新マニュアルがまだ届いていない人には合わない」という期間**が発生します。

**現実的な対処は、マニュアルからモード名を消すことです。** 「Cowork で議事録を整形する」ではなく「Claude に議事録の整形を依頼する」と書けば、移行前の人にも移行後の人にも通じます。**モード名への依存を外すのは、今回だけでなく今後の UI 変更に対する耐性にもなります。**

**次に問い合わせです。** 「同僚の画面にはあるモード選択が自分にはない」「Cowork はどこへ行った」という形で来ます。**原因は障害ではなく段階展開なので、調査は空振りします。** 情シスやAI推進担当が事前に「数週間かけて順次切り替わる。操作は不要。旧画面へは戻せない」と告知しておけば、問い合わせの多くは発生しません。

**設定の移動は、告知しないと事故になります。** Cowork の Global instructions が Settings > General へ統合される件は、**公式自身が「意図どおりか確認してください」と書いている**箇所です。組織として共通の instructions を配っていた場合、**統合後の内容が想定と違う可能性**があります。移行を確認したら、まずここを見るよう案内すべきです。

**Enterprise の30日前通知は、準備期間として使えます。** 通知が来てから慌てるのではなく、**通知が来る前に「モード名を含む文書の棚卸し」を済ませておく**のが実務的です。Pro / Max を個人で使っている社員は先に移行するため、**社内の誰かが先に新画面を見ている**状態になります。その人に確認してもらえば、実物を見ながら準備できます。

**ガバナンス面では、権限モードの整理が論点です。** 既定は Manual（都度確認）なので、何もしなければ従来どおりです。**Auto は「逐一確認しない」モード**であり、公式は実行前に自動の安全チェックが走ると説明していますが、**組織として Auto を許容するかは別途判断が要ります。** 特に、コネクタ経由で社内 SaaS に書き込める状態で Auto を有効にすると、確認なしの操作範囲が広がります。

**一方で、過度に身構える必要はない側面もあります。** 今回の変更は**新しい権限が開くものではありません。** Cowork でできたことが会話から呼べるようになるだけで、接続済みコネクタもスキルも既存のものです。**「何ができるか」は変わらず、「どこから呼べるか」が変わります。** 前日の Gemini の MCP コネクタのように「管理者が何もしなければ新しい接続先が開く」類の変更とは性質が違います。

## 副業・個人活用視点

**個人で Pro / Max を使っている人には、この変更は素直に有利です。** 先行して切り替わるのも Pro / Max です。

**最大の実務的な変化は「閉じても止まらない」点です。** 重いタスクはクラウドで継続するため、**依頼して離席し、戻ってきて受け取る**という使い方ができます。公式が挙げている例も「出社前に依頼し、移動中にスマホで進捗を見て、着席したら出来上がっている」というものです。

**副業で時間が細切れになる人ほど、この差は効きます。** これまでは「作業を始めたら終わるまで画面の前にいる」のが前提でした。**依頼と受け取りを分離できると、平日の夜30分しか取れない日でも、依頼だけして寝る、という進め方ができます。** スケジュール実行と組み合わせれば、毎週決まった作業を回せます。

**モード選択が消えること自体も、実は個人利用の方が恩恵が大きい**かもしれません。組織では「この作業は Cowork」と運用ルールで決められますが、**個人は毎回自分で判断していた**からです。その判断コストがゼロになります。

**注意点は、移行が非可逆であることです。** 個人利用でも「前の UI の方が慣れていた」という理由で戻すことはできません。**ただし、これは機能が減る変更ではありません。** 公式は「主に chat を使っているなら、特に何も変える必要はない」としています。**今までどおり短い質問を投げる使い方は、そのまま続けられます。**

**受注業務で Claude を使っている場合は、納品物の作り方が変わる可能性があります。** 重いタスクをクラウドで回せるということは、**リサーチや資料作成を依頼して別の案件を進める**という並行作業ができるということです。単価を時間で決めている場合、**同じ時間で処理できる件数が増える**方向に効きます。

**逆に、クライアントの環境が Enterprise の場合は、まだ先の話です。** Enterprise は30日前通知を経てからなので、**「自分の Pro では新画面、クライアント先では旧画面」という状態**がしばらく続きます。手順を共有するときは、どちらの画面を前提にしているか明示しないと混乱します。
