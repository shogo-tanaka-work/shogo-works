## 要約

Anthropic が2026年10月7日、小型モデルの新版 **Claude Haiku 5.5**（`claude-haiku-5-5`）を公開しました。公式は「これまでに出した中で最も安く、最も速く、最も高性能な小型モデル」と位置づけています。9月22日の Opus 5.5、9月28日の Sonnet 5.5 に続き、**Claude 5.5 ファミリーの小型枠がこれで埋まりました。** Sonnet 5.5 公開時に「数週間のうちに追加予定」とされていたものが、約1週間半で出てきた形です。

**いちばん大きな変化は価格体系そのものです。** Haiku 5.5 は **Claude で初めて「プロンプト長に応じた段階価格」を採用したモデル**です。

- **10万トークン以下のプロンプト**: 入力 **$0.10** / 出力 **$0.50**（per MTok）
- **10万トークン超のプロンプト**: 入力 **$0.50** / 出力 **$2.50**（per MTok）

Haiku 4.5 は一律 $1 / $5 でした。つまり**10万トークン以下の領域では、単価が10分の1になりました。** 10万トークンを超える領域でも $0.50 / $2.50 で、Haiku 4.5 の半額です。Batch API はさらに半額（$0.05 / $0.25、$0.25 / $1.25）、キャッシュ読み取りは $0.01 / $0.05 です。

**ここは注意が必要な設計です。** Claude 4.6 以降のモデルは「1M トークンの全域を標準価格で提供する（90万トークンのリクエストも9千トークンのリクエストも同じ単価）」が原則でした。公式ドキュメントは **Haiku 5.5 をその原則の明示的な例外**として記載しています。10万トークンという境界をまたぐと、入力・出力ともに単価が5倍になります。

**仕様面も素直な強化です。** コンテキストウィンドウは Haiku 4.5 の 200k から **1M トークン**へ、最大出力は 64k から **128k トークン**へ拡大しました（Batch API では `output-300k-2026-03-24` beta ヘッダで 300k）。そして **adaptive thinking と `effort` パラメータに対応した初の Haiku** です。既定 effort は `medium`。モデルが自分で「どれだけ考えるか」を決め、`effort` で品質と速度・コストのトレードオフを調整できます。知識カットオフは2026年6月、退役は2027年10月7日より前には行わないとされています。

**公式が挙げた顧客ベンチマーク**は次のとおりです。Ask in Document が Haiku 4.5 の 0.76 に対して **0.84**。Box AI は **Haiku 4.5 比で11ポイント高く、レイテンシは約半分**。HubSpot の CRM スイートが3回平均で **92.8%**。Devin Fusion では Haiku 5.5 をサイドキックに据えた構成が FrontierCode で **66.2** という上位スコアを出しています。公式の想定用途は、分類・要約・テキスト生成といった高ボリューム処理、チャットや音声エージェントのようなリアルタイム用途、大きなモデルから仕事を渡されるサブエージェント、ブラウザ・デスクトップ自動化（フォーム入力やデータ入力）です。

**提供範囲は広いです。** Claude API（`claude-haiku-5-5`）、Claude in Amazon Bedrock（`anthropic.claude-haiku-5-5`）、Claude Platform on AWS、Google Cloud、Microsoft Foundry、そして **Claude Code**。claude.ai 側では **Free / Pro / Max / Team / Enterprise の全プラン**が web / iOS / Android でモデルとして選択できます。Claude Code は同日の v2.1.293 で、Anthropic API 上の既定 Haiku モデルとして Haiku 5.5 を取り込みました。

**そして、ここからが移行作業です。** 公式は「Haiku 4.5 向けに書いたコードは Haiku 5.5 で壊れる可能性がある」と明記しており、破壊的変更が5点あります。**モデル ID を差し替えるだけでは済みません。**

## 何が変わったか

- **`claude-haiku-5-5` を公開**。Claude API / Amazon Bedrock / Claude Platform on AWS / Google Cloud / Microsoft Foundry / Claude Code で提供
- **価格が Claude 初のプロンプト長段階制**。10万トークン以下は入力 $0.10 / 出力 $0.50、10万トークン超は入力 $0.50 / 出力 $2.50（per MTok）
- Batch API は半額（$0.05 / $0.25、および $0.25 / $1.25）、キャッシュ読み取りは $0.01 / $0.05
- **Haiku 4.5（一律 $1 / $5）比で、10万トークン以下は10分の1、10万トークン超は半額**
- **コンテキストが 200k → 1M トークン**、最大出力が 64k → 128k トークン（Batch は beta ヘッダで 300k）
- **adaptive thinking と `effort` に対応した初の Haiku**。既定 effort は `medium`
- **browser use tool に対応**（Claude API と Google Cloud）
- 安全性分類器がリクエストを拒否し得る。`stop_reason: "refusal"` のハンドリングが必要（サーバー側フォールバックは提供されない）
- **破壊的変更1**: 手動 extended thinking（`budget_tokens`）が **400 エラー**。adaptive thinking へ置き換える
- **破壊的変更2**: `temperature` / `top_p` / `top_k` の非既定値が **400 エラー**。指定を外す
- **破壊的変更3**: assistant message prefill が **400 エラー**。`messages` はユーザーターンで終える
- **破壊的変更4**: computer use は `computer_toolset_20260801` が必須。旧 `computer_20250124` は不可（Claude API と Google Cloud）
- **破壊的変更5**: 以前のターンを書き換えると thinking ブロックが無効になる。thinking ブロックを送り返すなら会話は append-only に保つ
- **挙動変更**: adaptive thinking が既定オンのため、**応答が `thinking` ブロックから始まり得る。** 先頭ブロックを答えとして読むコードは、`type` フィールドで選ぶよう直す
- **挙動変更**: thinking のテキストは既定で省略される。要約を受け取るには `thinking.display` を `"summarized"` に設定する
- **挙動変更**: トークナイザが Claude 4.7 以降と同じものになり、**同じ文章が約30%多いトークン**になる
- **挙動変更**: thinking ブロックは生成したアカウント（または連携アカウント）でしか機能しない
- 退役は **2027年10月7日**より前には行わないとされる（Anthropic 運用プラットフォーム）

## 業務インパクト（一般企業向け）

**まず「10分の1」をそのまま予算に落とさないことです。** 単価は10分の1になりましたが、**同じ文章のトークン数が約30%増えます。** トークナイザが Claude 4.7 系と同じものに変わったためで、公式も「トークンで測っている・予算を組んでいるものはすべて変わる」と明記しています。実質コストは `0.1 × 1.3 ≒ 0.13`、つまり**おおよそ8分の1程度**が出発点の見積りです。加えて adaptive thinking が既定オンなので、**thinking トークンが出力側に乗ります。** 削減幅は小さくなる方向です。それでも大きな削減ですが、「10分の1」で稟議を書くと後で説明が必要になります。

**10万トークンの境界を、設計の判断点として扱ってください。** ここをまたぐと単価が5倍です。長いマニュアルや規程をまるごとプロンプトに前置する構成だと、境界を超えた瞬間に Haiku 4.5 の半額どまりになります。**逆に言えば、RAG で必要な部分だけを渡す設計に投資する価値が、価格表の上で明示された**ということです。「全部入れてしまえば楽」という設計が、ここで初めて明確に高くつきます。自社のプロンプトが平均・最大で何トークンなのかを、まず測ってください。

**移行は「モデル ID の差し替え」ではなくコード変更です。** 情シスや開発委託先に投げるときは、少なくとも次の棚卸しを依頼してください。`budget_tokens` を使っている箇所、`temperature` などサンプリングパラメータを明示している箇所、assistant prefill で出力形式を縛っている箇所、computer use のツール版数、そして**応答の先頭ブロックを答えとして読んでいる箇所**です。最後のものは特に見つけにくく、テストが通っているのに本番で「空の答えが返る」形で出ます。`stop_reason: "refusal"` のハンドリングも、サーバー側フォールバックがないため自前で書く必要があります。

**claude.ai 側は Free プランでも選べます。** ここは統制の話です。全プランでモデル選択に Haiku 5.5 が並ぶため、**利用者が「速いから」と無意識に小型モデルへ切り替える**ことが起き得ます。回答品質の前提が揃っていない状態で業務判断に使われるリスクがあるので、「どの業務でどのモデルを使うか」を決めている組織は、周知のタイミングを合わせておくとよいです。

**Claude Code を使っている組織は、既定が静かに変わったことを認識しておいてください。** v2.1.293 で Anthropic API 上の既定 Haiku モデルが Haiku 5.5 になりました。トークナイザが違うため、**バージョン更新日をまたいだ利用量の比較が成立しません。** 消費量をモニタリングしている場合、基準日をリリース単位で持つ必要があります。

## 副業・個人活用視点

**単価 $0.10 / $0.50 は、個人の実験予算の意味を変えます。** 10万トークン以下に収まる処理なら、100万トークンの入力が約15円です。大量の記事タイトルを分類する、問い合わせメールを種類別に振り分ける、スクレイピングした情報を構造化する——こうした「量で殴る」処理が、**個人の財布で成立する価格帯に入りました。** Batch API を使えばさらに半額です。

**受託案件では「段階価格を踏まえた設計」が提案の差になります。** クライアントが「社内文書を全部読ませたい」と言ったとき、**10万トークンの境界を示して「ここで単価が5倍になるので、検索で絞ってから渡す設計にします」と説明できる**かどうかは、見積りの説得力に直結します。価格表に境界が書かれているので、根拠として提示しやすい材料です。

**サブエージェント構成の提案も現実的になりました。** 公式の想定用途に「大きなモデルから仕事を渡されるサブエージェント」が明記されています。判断は Opus 5.5、手数の多い実行は Haiku 5.5、という振り分けを価格差（$4 / $20 対 $0.10 / $0.50）で説明できます。Devin Fusion のベンチマークも、Haiku 5.5 をサイドキックに据えた構成のスコアです。

**ただし、個人開発の既存コードほど破壊的変更に引っかかりやすい点は覚えておいてください。** `temperature` を明示していたり、assistant prefill で JSON を強制していたりするコードは、個人が素早く書いたものほど多いはずです。移行時は「動かなくなったら 400 エラーの本文を読む」で解決しますが、**先に `effort` と adaptive thinking の挙動を試してから本番に入れる**ほうが手戻りが少なくて済みます。
