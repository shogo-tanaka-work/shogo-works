## 要約

Anthropic は 2026-09-17、**Life Sciences Verification Program（LSVP）**を発表しました。**審査を通過したライフサイエンス専門職に、生物学関連の作業について通常より緩和されたセーフガードを適用した Mythos / Opus / Sonnet モデルへのアクセス**を与えるプログラムです。

**既に早期アクセスプログラムで数十組織をオンボード済み**で、今回から広くライフサイエンスのコミュニティへ応募を開放します。**ベータ提供で、初期対象はチームと研究機関**。個人の Pro / Max プランへの拡大は「時間をかけて」とされています。

**プログラムの目的は明確です。一般提供されている Fable 系モデルでは現在ブロックされる作業を可能にすること。** 具体的には**創薬、研究生物学、臨床開発、製造**が挙げられています。対象はアカデミアのラボ、スタートアップ、製薬企業など、規模を問いません。

**審査で見られるのは3点です。** 研究者としての**資格（research credentials）**、**セキュリティ基準**、**倫理的な研究監督体制（ethical research oversight）**。この3つのレビューを通過した組織が、grant を申請できます。

**grant は2種類あります。**

**Standard Use** は、ライフサイエンス業務の大半をカバーします。**チーム全体へ拡張でき、多様な日常的ワークロードに使えて、更新は年1回**。対象モデルは **Mythos 5.1 / Opus 5 / Sonnet 5** で、**今後のモデルにも適用**されます。公式は、基礎科学、R&D、サプライチェーンと製造、臨床開発、品質保証、規制対応、投資とデューデリジェンスまでを列挙しており、**ライフサイエンス企業の業務全般**を想定していることが分かります。

**High-risk Use** は、Standard Use でもブロックされる領域向けのアドオンです。**ライフサイエンス関連の要求をブロックする全セーフガードを解除します。** ただし条件が厳しく、**適用は単一の研究プロジェクト単位**（チーム全体ではない）で、**更新は6か月ごと**。公式は「dual-use の作業をしている研究者は、通常 Standard を1つ持つ」形になると説明しています。

**grant は Claude Science、Claude.ai、Claude Code、API の全プロダクト面で利用できます。**

## 何が変わったか

- **Life Sciences Verification Program（LSVP）**が開始され、広く応募受付が始まった（既に数十組織が早期アクセスでオンボード済み）
- **ベータ提供。初期対象はチームと研究機関**。個人 Pro / Max への拡大は将来
- 一般提供の Fable 系モデルでは**ブロックされる作業**（創薬、研究生物学、臨床開発、製造）が対象
- 審査項目は**研究者としての資格 / セキュリティ基準 / 倫理的な研究監督体制**の3点
- **Standard Use**: チーム全体へ拡張可、**更新は年1回**、Mythos 5.1 / Opus 5 / Sonnet 5 と今後のモデルに適用、科学分類器が一般提供モデルより寛容
- **High-risk Use**: **ライフサイエンス要求をブロックする全セーフガードを解除**するアドオン、**単一の研究プロジェクト単位**、**更新は6か月ごと**
- grant は **Claude Science / Claude.ai / Claude Code / API の全プロダクト面**で有効

## 業務インパクト（一般企業向け）

**ライフサイエンス業界でない組織にとっても、このプログラムには読む価値があります。構造が新しいからです。**

**これまで、AI のセーフガードは全員一律でした。** 何がブロックされるかはモデルの仕様であり、ユーザーが変えられるものではありませんでした。**LSVP は、その前提を変えます。審査を通した顧客には、異なるセーフガードが適用されます。**

**つまり「このモデルは何ができるか」という問いに、「誰が使うかによる」という答えが加わりました。**

**この変化が一般の組織に及ぼす影響は2つあります。**

**1つは、ベンダー選定と利用規約の読み方です。** 「Claude で何ができるか」を調べるとき、**自社に適用されるセーフガードの設定を確認する**という項目が加わります。今回はライフサイエンス限定ですが、**同じ構造が他の規制業種——金融、医療、法務——へ広がる可能性は十分にあります。**

**もう1つは、審査項目そのものが参考になる点です。** 資格、セキュリティ基準、倫理的な監督体制の3点は、**AI ベンダーが「この顧客なら緩和してよい」と判断する基準です。** 自社が AI ベンダーと踏み込んだ交渉をする場合、**この3点を整備しておくことが前提条件になる**と読めます。特に**倫理的な監督体制**は、技術的な対策ではなく組織的な仕組みの話であり、**準備に時間がかかります。**

**更新頻度の差も設計として読む価値があります。** Standard は年1回、**High-risk は6か月ごと**。さらに High-risk は**チーム単位ではなくプロジェクト単位**です。**リスクが高い権限ほど、範囲を狭く、期間を短く**——これは社内の権限設計にそのまま応用できる原則です。

**自社で AI の利用ルールを作るときも、同じ形が使えます。** 「全社員に一律の禁止事項」ではなく、**「通常の権限」と「申請ベースの追加権限（範囲限定・期限つき）」の2階建て**にする。**LSVP はこの設計の実例です。**

**ライフサイエンス業界の組織にとっては、直接的な影響があります。** 「Claude は生物学の質問に答えてくれない」という制約が、**回避するものではなく申請して解くもの**になりました。**社内で非公式な迂回方法が共有されているとしたら、それをやめて正規の申請へ切り替える**のが正しい対応です。

## 副業・個人活用視点

**個人にとって、このプログラムは当面「対象外」です。** 初期対象はチームと研究機関で、個人の Pro / Max への拡大は「時間をかけて」とされています。**ライフサイエンス領域で個人研究をしている場合でも、現時点では所属組織を通じた申請が前提になります。**

**それでも押さえておく価値があるのは、この構造が今後の標準になりうるからです。**

**AI を業務で使うコンサルや講師にとって、「モデルの制約は交渉可能になった」という事実は説明の材料になります。** 「AI が答えてくれないのは仕様です」で終わっていた話が、**「用途と体制を示せば、緩和される経路がある」**に変わりました。**規制業種のクライアントに対して、諦める以外の選択肢を示せる**のは実務的な価値があります。

**提案としては、審査項目の整備を支援する形が考えられます。** セキュリティ基準と倫理的な監督体制の文書化は、**AI 導入とは独立に価値がある作業**です。LSVP への申請が直接の目的でなくても、**「AI ベンダーと踏み込んだ交渉をする前提を整える」**という文脈で提案できます。

**教材としては、「セーフガードは全員一律ではなくなった」という1点を伝えるのが最も効きます。** AI の安全機構を「動かせない仕様」として理解している受講者は多く、**審査と契約で変わるものだという認識に更新する**必要があります。**同時に、緩和には審査と更新義務が伴うという対価も伝えるべきです。** 「申請すれば制限が外れる」と単純化すると誤解を招きます。

**権限設計の教材としても使えます。** Standard は年1回更新・チーム単位、High-risk は6か月更新・プロジェクト単位。**リスクが高いほど範囲を狭く期間を短く**という原則が、実在するプログラムの形で示されています。社内ルールを設計する演習の題材として具体的です。
