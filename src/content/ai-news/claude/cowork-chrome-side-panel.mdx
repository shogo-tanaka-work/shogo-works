## 要約

Anthropic が 2026-08-12、**Claude in Chrome のサイドパネルを Claude Cowork セッションとして統合**しました。

これまでサイドパネルでの会話は、デスクトップ / Web / モバイルの Claude アプリとは切り離されていました。統合により、**会話が全プラットフォーム間で同期**します。公式の説明は「ブラウザで始めた作業を、後で別の場所から続けられる」というものです。

サイドパネルからは Claude がブラウザ操作を行えます。リンクのクリック、テキスト入力、ページ間の移動、フォーム入力に対応します。狙いとして公式が挙げているのは、**Claude と直接の連携を持たないアプリケーション**への到達です。具体例として「レガシーシステムや社内ダッシュボード」が名指しされています。加えて **Skills と connectors もブラウザ環境の中で機能**します。

安全面では、結果に影響のある操作の前に自動承認の仕組みが働きます。**当初の依頼内容と実行しようとしている操作を照合し、一致しないものをブロックする**設計です。

提供範囲はプランで分かれます。**Max / Team は即日**、**Pro は数週間かけて順次展開**。**Enterprise は既定でオフ**で、管理者が有効化したうえで、承認済みドメインにアクセスを限定できます。

なお、旧 Claude in Chrome 拡張が廃止されるかどうかは公式発表では明示されていません。

## 何が変わったか

- Chrome サイドパネルの会話が Claude Cowork セッションとして扱われるようになった
- サイドパネルの会話がデスクトップ / Web / モバイルと同期する
- リンククリック、テキスト入力、ページ遷移、フォーム入力といったブラウザ操作に対応
- Skills と connectors がブラウザ環境の中で機能する
- 結果に影響のある操作の前に、当初の依頼と照合して一致しないものをブロックする
- Max / Team は即日、Pro は数週間かけて順次展開
- Enterprise は既定でオフ。管理者が有効化し、承認済みドメインへアクセスを限定できる

## 業務インパクト（一般企業向け）

現場で意味が大きいのは、**API 連携のないシステムに手が届く**という点です。

社内の自動化が止まる理由は、たいてい技術の高度さではありません。「基幹システムに API がない」「ベンダーが連携を提供していない」「管理画面から手作業で取るしかない」という、もっと素朴な壁です。公式が「レガシーシステムや社内ダッシュボード」を名指ししているのは、この層を狙っていることの表明でしょう。ブラウザで開ける画面であれば、連携の有無に関係なく操作の対象になります。

会話の同期も、地味ですが運用に効きます。これまでは**ブラウザで調べた内容をデスクトップアプリへ持ち込むために、手で貼り直す**必要がありました。同期されるということは、調査はブラウザ、まとめはデスクトップ、確認はモバイル、という自然な流れがそのまま繋がるということです。Skills と connectors がブラウザ側でも動くので、環境ごとに使える機能が違うという分かりにくさも解消されます。

**Enterprise の管理者にとっては作業が発生します。**既定オフなので、有効化しない限り誰も使えません。そして有効化するなら、承認済みドメインの設計を先に決める必要があります。ブラウザ操作を許すということは、その Chrome が開けるあらゆる画面が対象になり得るということです。**どのドメインを許すかを決めずに有効化するのは避けるべき**でしょう。逆に言えば、ドメイン制限の仕組みが用意されているのは導入判断をしやすくする設計です。

安全機構については、期待の置き方を間違えないことが大事です。**当初の依頼と操作を照合する仕組みは、依頼の範囲外の操作を止めるもの**であって、依頼そのものが不適切だった場合には働きません。「経費精算を提出して」と頼んで金額を間違えるリスクは、この仕組みでは防げません。結果に影響のある操作は、依頼の内容自体を確認する運用が別途必要です。

## 副業・個人活用視点

個人で使う場合、**Max / Team なら即日、Pro は数週間待ち**という順序です。Pro を使っていて手元に来ていないなら、それは展開待ちで設定の問題ではありません。

実務で効くのは、やはり**API のないサービスの操作**でしょう。クライアントが使っているツールに API がない、管理画面を毎回開いて手で処理している、という状況は副業案件でよく出会います。ブラウザで開ける範囲なら操作を任せられるので、単価の低い転記作業から手を引く余地が生まれます。

会話の同期は、複数の環境を行き来する働き方をしている人ほど恩恵があります。**移動中にモバイルで確認して、戻ってからデスクトップで続ける**という流れが素直に繋がります。これまで貼り直しに使っていた手間がなくなるだけでも、細切れの時間が使えるようになります。

案件として持ち込むなら、**「連携できないから諦めていた自動化」の再検討**が切り口になります。過去に「API がないので難しい」と回答した案件を持っているなら、そこは掘り直せる可能性があります。ただしブラウザ操作は画面の変更に弱いので、**UI が変わったら止まる前提で提案する**か、影響の小さい作業に絞ってください。壊れない前提で見積もると保守で苦しみます。

企業向けの支援としては、Enterprise の管理者設定が案件になります。既定オフで、有効化とドメイン設計が必要という構図は、**そのまま導入支援の作業内容**になります。どの業務で使うか、そのためにどのドメインを許すか、許した範囲で何ができてしまうか。この整理を代行する形なら、単発の設定作業ではなく運用設計の相談として成立します。

発信のネタとしては、**社内ダッシュボードのような「連携がない画面」を実際に操作させてみる**検証が読まれるでしょう。公式が名指ししている用途なので期待値は高く、実際にどこまで動くかは誰もが知りたい部分です。うまくいかなかった箇所も含めて書くと、判断材料としての価値が上がります。
