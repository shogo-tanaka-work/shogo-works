## 要約

Anthropic が 2026-08-14、**今後の Claude モデルが透かし入りのテキストを生成する**ことを説明した記事を公開しました。目的は、そのテキストの生成に Claude が関与した可能性を判定できるようにすることです。理由は **EU AI Act への準拠**で、他の主要 AI プロバイダーも同じ Code of Practice に署名しており、それぞれ独自の透かしを実装します。**Claude 固有の動きではありません。**

仕組みは、生成時の「どちらでもよい選択」を利用します。言語モデルは1語ずつ次の語を選びますが、「今日の天気は寒くて…」の次に来るのが `overcast` か `grey` かは、意味をほとんど変えません。通常この選択は乱数で決まります。透かしは**この乱数の出どころを変えます**。任意の乱数生成器の代わりに、**鍵と直前の数語から次の語を決める**わけです。語の選ばれ方はランダムなままですが、鍵を持つ者は語の並びが鍵と整合するかを検査でき、そこから Claude が生成した確率を割り出せます。

公式が明示している性質は次の通りです。**出力の品質や内容に実用上の影響はない。** 透かし入りと透かしなしのテキストを読者が区別することはできない。**テキストに何も追加されず、隠し文字も入らない。** 追加のトークンを要さず、費用も増えない。そして**識別情報は含まれず、特定の個人・組織・チャットへ辿ることはできない**。

適用範囲は段階的です。**2026-08-02 以降に EU で提供開始されたモデルは提供開始時点から**機械可読なマーキングに対応します。それ以前に提供が始まったモデルについては、今後数か月かけて展開されます。Anthropic は**透かし検出 API を近く提供する**としています。

なお、Claude が翻訳したテキストも透かしを持ちます。すべての語を Claude が選んでいるためです。

## 何が変わったか

- 今後の Claude モデルが透かし入りのテキストを生成する
- 方式は「どちらでもよい語の選択」に鍵由来のパターンを埋め込むもの
- テキストへの追加・隠し文字はなく、追加トークンも費用増もない
- 読者には透かしの有無を区別できない
- 識別情報は含まれず、個人・組織・チャットへは辿れない
- 2026-08-02 以降に EU で提供開始されたモデルは提供時点から対応。以前のモデルは数か月かけて展開
- 透かし検出 API を近く提供予定
- Claude による翻訳テキストにも透かしが入る
- EU AI Act 対応であり、他の主要プロバイダーも同じ Code of Practice に署名して独自実装する

## 業務インパクト（一般企業向け）

**設定作業は発生しません。**透過的に適用され、費用も品質も変わりません。その意味では「何もしなくていい更新」です。

ただし、**考えておくべきことは生まれます。**これまで「AI が書いたかどうか」は、文章の癖から推測するしかありませんでした。今後は鍵を持つ者が確率的に判定でき、検出 API も提供されます。つまり**第三者が判定できる状態になります。**

これが効いてくるのは、AI 利用の開示方針を決めていない組織です。社外へ出す文書に AI をどこまで使ってよいか、使った場合に開示するか。これまでは実質的に検証不能だったので、方針がなくても問題が表面化しませんでした。**検出できるようになると、方針の不在が露呈します。**取引先や顧客から「これは AI が書いたものか」と問われたときに、答えを持っているかどうかが分かれ目になります。

とはいえ**過剰反応も避けるべき**です。透かしは「Claude が関与した確率」を示すだけで、誰がいつどう使ったかは分かりません。識別情報が含まれない設計なので、**個人を特定して咎めるような使い方はできません。**「AI 利用が全部バレる」という理解は誤りです。

実務として整理するなら、次の順序でしょう。まず**社内向けと社外向けを分ける**。社内資料の下書きに AI を使うことは、そもそも開示の対象になりません。次に社外向けについて、業種や取引先の要求水準に照らして方針を決める。最後に、その方針を文書化して周知する。**検出できるようになったから方針を作るのではなく、方針がないことのリスクが上がったから作る**という理解が正確です。

EU 市場向けにサービスを提供している場合は、話が別です。**EU AI Act は AI 生成コンテンツのマーキングを求めており**、提供側にも義務が及びます。自社サービスが AI 生成物を出力しているなら、Anthropic 側の対応とは別に、自社としての対応が要ります。ここは法務と確認すべき領域です。

## 副業・個人活用視点

個人で使う分には、**日々の作業は何も変わりません。**出力の品質は変わらず、費用も増えません。透かしの有無を読者が見分けることもできません。

意識しておくべきは、**納品物に AI を使うときの扱い**です。受託でライティングや資料作成をしている場合、成果物が Claude 由来かどうかを検証できる状態になります。これまでは事実上分からなかったものが、分かるようになる。

対応は単純で、**契約や打ち合わせの段階で AI 利用について合意しておく**ことです。多くの案件では AI の利用自体が問題になることはありません。問題になるのは、「使っていない」と説明したのに使っていた場合です。**後から判定できる状態になった以上、曖昧にしておくメリットはありません。**

逆に言えば、**AI を使うことを前提に合意できていれば何も気にする必要がない**ということでもあります。生産性を上げる手段として使い、その分だけ速く安く納品する。この形が取れているなら、透かしが入っても困る場面はありません。

案件として拾える切り口は、**AI 利用方針の整備**です。「社外向け文書で AI をどこまで使ってよいか」を決めていない組織は多く、検出可能になったことは方針を作る動機になります。ただし**「バレるから作る」という煽り方をすると筋が悪い**です。識別情報は含まれず個人は特定できない、という事実を正確に伝えたうえで、開示方針の必要性を説明する方が信頼されます。

発信のネタとしては、**仕組みそのものの解説**が向いています。「どちらでもよい語の選択に鍵由来のパターンを入れる」という方式は、説明すれば理解できる程度の複雑さで、かつ直感に反する面白さがあります。隠し文字が入るわけでも、特定の語に偏るわけでもない。**誤解されやすい部分を正確に説明する記事**は、この手の話題では価値が出ます。
