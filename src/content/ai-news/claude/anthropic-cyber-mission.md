## 要約

Anthropic が **Anthropic Cyber Mission** を発足させました。防御側に道具・研究・資源を届ける長期の取り組みとして位置づけられ、**重要インフラ**と**オープンソース**の2領域から始めます。

**最初に性質を押さえてください。これは一般提供の製品発表ではありません。** パートナープログラム、エンジニアリング支援、資金、研究を組み合わせた**組織的な取り組み**です。**ただし OSS Scanner だけは、今すぐ申し込める無料サービスです。**

**重要インフラ側の実体は Critical Infrastructure Defense Program（CIDP）** です。電力・水道・交通の OT と政府システムを対象に、**OT 事業者へサービスを提供する信頼されたセキュリティプロバイダーへ**、フロンティアの Claude モデル・**常駐エンジニア**・脅威リサーチを提供します。

**初期パートナーの顔ぶれが、プログラムの形を示しています。** Accenture / Booz Allen / CrowdStrike / Deloitte / Dragos / Hitachi / Insane Cyber / Nozomi Networks / Palo Alto Networks / PwC / Rockwell Automation。**コンサルティングファーム、セキュリティベンダー、そして OT 機器メーカー**が混ざっています。少数のコホートで開始し、今後数か月でパートナーと対象セクターを広げるとしています。関心の登録は受け付けています。

**つまり Anthropic は OT 事業者へ直接モデルを届けるのではなく、その手前のプロバイダーへ届けています。** これは実務の形として理解できます。**OT の現場は、モデルを渡されても使えません。** 必要なのは現場を知っている人の手で、そこは既存のプロバイダーが持っています。

**オープンソース側の実体は OSS Scanner です。** opt-in したプロジェクトに対し、**Anthropic の最上位モデルによる定期スキャンを無料**で提供します。

**そして本件でもっとも評価すべきなのは、公式が明記している制約です。**

**レポートはモデル生成であり、人手レビューを経ずに送られます。** 公式は**誤りが混じり得ることを自分で書いています。** Anthropic は true-positive 率を **90% 超**と見込み、改善を続けるとしています。報告に対応しきれないプロジェクトには、引き続き**人手で検証した開示**を行うとされています。

**「人手レビューなしで送る」を明記したのは誠実です。** そして**受け取る側には実務的な意味があります。** 10件に1件程度は誤検知だという前提で読む必要があります。

関連する展開として、**規模を問わずセキュリティチームが拡張版 Cyber Verification Program へ応募できる**こと、**メンテナが Claude for Open Source（無料の Claude Max）へ応募できる**ことが挙げられています。前史として 6月の州・地方・部族政府向けプログラム、同週の Project Glasswing の Cyber Verification Program への統合、8月の **Defender Advantage Fund（0xDAF）** があります。

**Anthropic の現状認識も記録しておく価値があります。** 「高性能モデルは攻撃側にも広く行き渡っており、防御側の道具が十分な数の防御者に届いていない」。そして**「2年以内に AI は防御側に有利に働くと見込むが、短期はより厳しくなる」**。理由として、**脆弱性の悪用が安価になった一方で、修正の速度は上がっていない**という非対称を挙げています。

## 何が変わったか

- **Anthropic Cyber Mission が発足**（2026-10-08）。**重要インフラ**と**オープンソース**の2領域から開始
- **Critical Infrastructure Defense Program（CIDP）**: OT 事業者へサービスを提供する**セキュリティプロバイダー向け**に、フロンティアの Claude モデル・**常駐エンジニア**・脅威リサーチを提供
- 初期パートナー: Accenture / Booz Allen / CrowdStrike / Deloitte / **Dragos** / **Hitachi** / Insane Cyber / **Nozomi Networks** / Palo Alto Networks / PwC / **Rockwell Automation**
- CIDP は**少数のコホートで開始**。今後数か月でパートナーとセクターを拡大。関心の登録は受付中
- **OSS Scanner**: opt-in した OSS プロジェクトへ、**最上位モデルによる定期スキャンを無料提供**
- **OSS Scanner のレポートはモデル生成で、人手レビューを経ずに送られる**（公式明記）。**true-positive 率は 90% 超の見込み**
- 対応しきれないプロジェクトには**人手で検証した開示**を継続
- 関連: **規模を問わずセキュリティチームが拡張版 Cyber Verification Program へ応募可能**、**メンテナは Claude for Open Source（無料の Claude Max）へ応募可能**
- Anthropic の見立て: **2年以内に AI は防御側有利になるが、短期はより厳しくなる**（悪用は安価化、修正の速度は変わらず）

## 業務インパクト（一般企業向け）

**一般企業に直接提供される製品はありません。確認すべきことは1つだけです。**

**重要インフラに関わる事業なら、自社のセキュリティプロバイダーが CIDP パートナーかを確認する価値があります。** リストに **Dragos / Nozomi Networks / Rockwell Automation / Hitachi** が入っているのは示唆的です。**OT セキュリティと制御機器の側から入っている**ということは、**現場の機器に近いところで使われる想定**だと読めます。

**契約しているプロバイダーがリストにある場合、問い合わせる価値があります。** 聞くべきは「このプログラムで何が変わるか」です。**常駐エンジニアと脅威リサーチが入るなら、提供されるサービスの中身が変わる可能性があります。** 自社が追加費用なしで恩恵を受けるのか、別メニューになるのかは、プロバイダー側しか答えられません。

**OSS を公開している組織には、直接の選択肢があります。**

**自社製品の一部を OSS にしている、あるいは社内で OSS を保守している場合、OSS Scanner は無料で使えます。** ただし**申し込む前に、工数を見積もってください。**

**論点は誤検知です。** true-positive 率 90% 超という数字は、**裏返せば 10件に1件程度は誤検知**です。**そして人手レビューを経ずに送られます。** つまり**届いたレポートの仕分けは、受け取った側の仕事です。**

**これが問題になるかは、プロジェクトの規模と体制で決まります。** 専任の保守担当がいるなら、誤検知の仕分けは通常業務の範囲です。**担当が片手間なら、レポートが溜まって放置される**という形になります。放置されたレポートは、**「脆弱性の指摘を受けていたのに対応しなかった」という記録として残ります。** 対応できない体制で受け取るのは、リスクを増やす選択になりえます。

**公式が「対応しきれないプロジェクトには人手で検証した開示を続ける」と書いているのは、この問題を認識しているということです。** 申し込む前に、**週に何件来るのか、仕分けの基準をどう決めるか**をプロバイダー側に確認するのが順序です。

**Anthropic の「短期はより厳しくなる」という見立ては、計画の前提として使えます。**

**悪用が安価になり、修正の速度は変わらない。** この非対称は、**自社のパッチ適用の速度が相対的に不足していく**ことを意味します。**2年待てば防御側が有利になる**という見立てを信じるとしても、**その2年をどう凌ぐかは自社の問題です。** セキュリティ予算の説明材料として、**ベンダー自身が「短期は厳しい」と言っている**事実は使えます。

## 副業・個人活用視点

**個人にとって、使える選択肢が2つあります。**

**1つは Claude for Open Source です。** **OSS のメンテナなら、無料の Claude Max に応募できます。** 個人で OSS を保守している人にとって、これは実質的な金銭的価値です。**応募条件の詳細は公式で確認が必要ですが、該当する可能性があるなら見る価値があります。**

**もう1つは拡張版 Cyber Verification Program です。** 公式は**「規模を問わずセキュリティチームが応募できる」**としています。**個人が対象に入るかは、応募要項を確認する必要があります。** 前週の Cyber Verification Program の拡張では、**Red Team Access が組織のみで個人は対象外、Defense Access は脆弱性報告の実績があれば個人も対象**という条件でした。**今回の記述が同じ枠組みを指すなら、実績がある個人には道があります。**

**OSS Scanner は、自分のプロジェクトを持っている人には試す価値があります。** ただし**誤検知の仕分けが自分の仕事になる**点は同じです。**個人プロジェクトなら、むしろ練習台として良いかもしれません。** 誤検知を含むレポートを読んで、**本物かどうかを自分で判断する**作業は、脆弱性の読み方の訓練になります。**仕事で誤検知だらけのスキャン結果を渡される場面は必ず来る**ので、先に慣れておく価値があります。

**学習の題材としては、「AI が出した指摘の仕分け」という工程そのものが本題です。**

**本件は、ベンダー自身が「人手レビューなしで送る、90% 超が真」と明記した珍しい例です。** 通常こういう数字は出てきません。**90% という数字が与えられたとき、受け取る側の体制はどうあるべきか。** これは AI を業務へ入れるときの一般的な設問です。

**考えるべきは「10% の誤りをどこで吸収するか」です。** 受け取った人が全件読むのか、機械的に優先度でフィルタするのか、専門家に回すのか。**吸収する工程を設計しないまま精度の数字だけ見て導入すると、現場が詰まります。** 本件は、その設計を考える題材としてちょうどよい具体性があります。
