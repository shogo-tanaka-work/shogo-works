## 要約

Anthropic は Claude Managed Agents を、自社のクラウドやオンプレミスで運用できる形で提供し始めました。以前は実行環境だけを自社側に置く self-hosted sandboxes までで、制御面や履歴は Anthropic 側にありました。今回は、サーバー、データベース、サンドボックスを含むサービス全体を自社で動かします。

公式ドキュメントによると、サーバーが Anthropic に接続するのは、推論の提供元が Claude API の場合だけです。Anthropic はサーバーやそのログへリモートアクセスできません。利用するには Anthropic のアカウントチームへの申請が必要です。なおブログ本文は今回取得できず、公式ドキュメントと二次報道を根拠にしています。

## 何が変わったか

- **自社で運用するもの**: サーバー、そのデータベース、エージェントの shell やファイルツールを実行するワーカーのサンドボックス。エージェント、セッション、履歴も自社のインフラに置く
- **モデル呼び出しの送り先**: Anthropic 直接のほか、Amazon Bedrock、Google、Microsoft Foundry、自社ゲートウェイが報じられている
- **既定のデータの流れ**: 各モデルリクエストは、会話履歴とツール結果を Anthropic へ送る。外に出る範囲はモデルリクエストが中心になる
- **分離の単位**: 1つのデプロイは1テナント・1信頼レベル向け。テナントや信頼レベルが違うなら、別デプロイにする
- **利用開始**: アカウントチームへ問い合わせて申請する

## 業務インパクト（一般企業向け）

金融、医療、公共など、セッション履歴や認証情報を社外に置けない組織が、Managed Agents の枠組みを検討できます。一方で運用責任は重くなります。サーバーの可用性、DB のバックアップ、シングルサインオンとロール設計、サンドボックスの分離、環境キーの管理は、自社の仕事です。公式は、エージェントが実行するコードがサンドボックス内の資格情報でサーバーを呼べるため、セッションごとにサンドボックスを分けるよう求めています。

自社環境へ移しても、会話履歴とツール結果は既定でモデル提供元へ送られます。「データが社外に出ない」とは言えない点を、社内の説明資料で正確に書く必要があります。

## 副業・個人活用視点

個人や小規模事業者の多くには運用負荷が過大で、通常のクラウド版で足ります。この機能は、顧客が厳しいセキュリティ要件を出す案件で、構成の選択肢として説明できるようにしておく程度が現実的です。提案時には、self-hosted sandboxes と今回のサービス全体の自社運用を、混同せずに説明してください。
