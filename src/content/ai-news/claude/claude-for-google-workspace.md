## 要約

Anthropic が **Claude for Google Workspace** を公開しました。Google **Docs / Sheets / Slides に Claude のサイドバー**が入り、**開いているファイルを読んで直接編集します。**

**これまでとの違いは、コピー＆ペーストの往復が消えることです。** Claude に文書を直させるには、本文をコピーして Claude に貼り、返ってきた結果をまた貼り戻す必要がありました。**この往復は、作業の手間というより、長い文書で破綻する工程でした。** 書式が落ち、途中で切れ、どこを直したのか分からなくなる。**サイドバーが同じファイルを編集するなら、この問題が構造的に消えます。**

提供状況は **beta** で、対象プランは **Pro / Max / Team / Enterprise** です。導入は **Google Workspace Marketplace** からで、**利用者自身のインストールと、管理者による組織一括配布の両方**に対応します。組織が Marketplace アプリをブロックしている場合は、**管理者が Claude を許可リストへ入れるか、管理者インストールを行う**必要があります。ブロックされた利用者には Google 側のメッセージ「This application is not allowed by your administrator」が出ます。**これは Claude 側ではなく Google 側の制御なので、Anthropic に問い合わせても解決しません。**

**もっとも評価すべき設計は、データアクセス範囲の限定です。**

**Claude が読むのは、現在開いているファイルと、有効化したコネクタだけです。** Drive、Gmail、Calendar、その他のファイルには到達しません。そして**この単一ファイルのスコープは、Claude 側の実装ではなく Google 側の権限で強制されます。**

**この違いは、情シスの審査では決定的です。** 「アプリ側が読まないようにしています」は実装の約束で、不具合や仕様変更で破れます。**「プラットフォーム側の権限で読めません」は構造です。** Workspace アドオンの審査で「このアプリはどこまで見えるのか」を確認するとき、**答えが権限モデルで返るのは強い材料になります。**

参照用のファイルは **1メッセージあたり20件まで**添付できます。つまり「開いているファイルしか読めない」を回避する手段は、**利用者が明示的に添付する**という形で用意されています。

アプリ別の用途として公式が挙げているのは、**Docs** が書き直し・構造の組み替え・契約書レビュー・見出しの統一・メモからの表作成、**Sheets** が数式のデバッグ・データの正規化・モデル構築・VLOOKUP のトラブルシュート・感度分析、**Slides** が下書きスライドの作成・内容の分割・タイトルの統一・スタイル付きのグラフ挿入です。

**制約は公式に列挙されています。** **Firefox 非対応**（Chrome / Edge / Safari のみ）。**1回の処理は6分まで。** リンク付きグラフの作成と自動更新は不可。**Docs のコメント解決は不可。** **Connected Sheets（BigQuery）非対応。** 定期実行の自動化やカスタムメニューの作成は不可。モデルはサイドバーのピッカーから、自分のプランで使えるものを選びます。

## 何が変わったか

- **Google Docs / Sheets / Slides に Claude のサイドバーが入り、開いているファイルを直接編集する**（2026-10-06、beta）
- 対象プランは **Pro / Max / Team / Enterprise**
- 導入は **Google Workspace Marketplace**。**利用者の個別インストールと管理者による組織一括配布の両方**に対応
- **Marketplace をブロックしている組織では、管理者の許可リスト登録または管理者インストールが必要**（ブロック時のメッセージは Google 側のもの）
- **Claude が読むのは「開いているファイル」と「有効化したコネクタ」だけ。** Drive / Gmail / Calendar / 他のファイルには到達しない
- **この単一ファイルのスコープは Google 側の権限で強制される**
- 参照ファイルの添付は **1メッセージあたり20件まで**
- モデルは**サイドバーのピッカーから、自分のプランで使えるものを選ぶ**
- 制約: **Firefox 非対応**（Chrome / Edge / Safari のみ）、**1回の処理は6分まで**、リンク付きグラフの作成・自動更新は不可、**Docs のコメント解決は不可**、**Connected Sheets（BigQuery）非対応**、定期実行の自動化・カスタムメニュー作成は不可

## 業務インパクト（一般企業向け）

**情シスが最初に決めるのは、Marketplace の配布方針です。**

選択肢は3つあります。(1) 管理者インストールで全社に配る、(2) 許可リストへ入れて利用者の判断に任せる、(3) ブロックしたまま様子を見る。**Marketplace をブロックしている組織では、何もしなければ (3) になります。** そして**利用者からは「Claude が使えない」という問い合わせが来ます。** 原因は Google 側のポリシーなので、**先に方針を決めて周知した方が、問い合わせ対応より安いです。**

**審査の論点は、通常の Workspace アドオンより少なくなります。** 「どのファイルが読まれるのか」が**開いているファイルに限定され、それが Google の権限で強制される**なら、**「Drive 全体を読まれるのではないか」という最大の懸念が構造的に消えます。** 審査資料にはこの点を明記してください。ただし**コネクタを有効化すれば範囲は広がります**。コネクタの許可方針は別に決める必要があります。

**業務手順書の書き換えが必要になる箇所があります。** 「Claude に貼り付けて整形し、結果を Docs に戻す」という手順を文書化している組織は、**その手順が不要になります。** 一方で**手順書に残しておくべきは、どの文書を Claude に読ませてよいかの基準**です。開いているファイルだけとはいえ、**開くファイルを選ぶのは利用者**です。「人事評価の個票を開いた状態でサイドバーを使う」のは、技術的には可能です。**判断は利用者に残るので、基準を文書で示すしかありません。**

**制約のうち、業務設計に効くのは3つです。** **1回6分の制限**は、長大な文書の一括処理が途中で切れることを意味します。**章ごとに分ける運用**が前提になります。**Connected Sheets（BigQuery）非対応**は、データ分析の現場で効きます。BigQuery 連携のシートを扱っている部門には、**最初から「対象外」と伝えてください。** **Firefox 非対応**は、ブラウザを統制している組織では確認が必要です。

**beta であることを、展開計画に反映してください。** 仕様と制約は変わります。**全社展開の前に、対象業務を絞った検証**——たとえば提案書の整形と議事録の構造化だけ——を2〜4週間回し、**6分制限に当たる頻度**と**書式の崩れ方**を実測してから広げるのが現実的です。

**ライセンスの確認も忘れないでください。** 対象は Pro / Max / Team / Enterprise です。**無償プランの利用者は使えません。** 部門内で一部の人だけが使える状態は、業務手順の統一を壊します。**誰に配るかはライセンスの話として先に整理してください。**

## 副業・個人活用視点

**単価が上がるのは「導入設計」の仕事です。**

このアップデートの価値は機能そのものより、**「どのファイルを開いた状態で使ってよいかの基準づくり」**にあります。技術的な制御がない領域なので、**ルールと周知で埋めるしかありません。** ここは**ドキュメントを書ける人の仕事**であり、エンジニアでなくても取れます。

**Marketplace の配布方針を決める支援は、小規模企業で確実に需要があります。** Workspace の管理コンソールを触れる人が社内にいない企業は珍しくありません。**「許可リストに入れる」「管理者インストールで配る」という操作と、その違いの説明**ができるだけで、相談先として選ばれます。

**提案の切り口としては、「置き換え」より「往復の削除」が通りやすいです。** 「AI で文書を作りましょう」は警戒されます。**「今、Claude に貼って戻す作業をしている人がいるなら、その往復が消えます」**は、現場の実感に直結します。**既にやっている作業の手間を消す提案は、決裁が速いです。**

**制約を先に言えるかが、信頼の分かれ目です。** 「1回6分まで」「BigQuery 連携のシートは対象外」「Firefox では動かない」を**提案の時点で伝える**と、導入後の「できると言ったのに」が起きません。**公式が制約を列挙してくれている案件は、むしろ提案しやすいです。** 列挙をそのまま確認項目に変えるだけで、精度の高い説明になります。

**個人の作業では、Sheets の数式デバッグがいちばん効きます。** VLOOKUP が返らない、参照がずれている、という状態は**文章で説明するのが難しく、コピペでも伝わりにくい**種類の問題です。**シートを開いた状態で聞ける**なら、質問のコストが劇的に下がります。受託で他人のスプレッドシートを引き継ぐ仕事をしているなら、ここは実測で効果が出ます。

**ただし、クライアントのファイルを開いて使う場合は確認を取ってください。** 技術的にはそのファイルしか読まれませんが、**契約上「第三者の AI サービスにデータを渡したか」は別の論点です。** 「開いているファイルしか読まれない」は説明材料になりますが、**無断で使ってよい理由にはなりません。** 先に許可を取るのが、長く仕事をもらう条件です。
