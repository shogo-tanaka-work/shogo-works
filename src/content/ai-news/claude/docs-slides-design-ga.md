## 要約

Anthropic が **Docs / Slides / Design の beta 終了**を告知しました。**Free を含む全プランで使えます。** 公式は累計で **4,500 万件超**の docs / decks / designs が作られたとしています。

**ただしこの告知の本題は GA ではありません。期限が2つあることと、移行で消えるものがあることです。**

**1つめの期限は 2026-10-15 です。** Enterprise では Docs / Slides / Design が**この日に既定で有効化されます。** 管理者は前倒しでの有効化もできます。つまり**何もしなければ 10-15 に全社で使えるようになります。**

**2つめの期限は 2026-12-14 です。** **standalone の `claude.ai/design` が閉鎖されます。** Design は 2026-09-16 から Claude の会話内で動いており、今回その移行が完了する形です。

**そして、移行で失われるものが公式に明記されています。**

**standalone 側の Claude とのチャットと、プロジェクトのコメントは移行されません。** 閉鎖後は参照できません。**standalone プロジェクトの公開リンクも同時に停止します。** デザインシステムは Artifacts ページから移行でき、プロジェクト自体は閉鎖まで動きます。

**ここが実務上もっとも重い部分です。** 「移行できます」という告知を読んで安心すると、**移行されるのはデザインシステムだけ**という区別を見落とします。**チャットとコメントは、移行機能では救えません。** 必要なら**閉鎖前に手元へ退避する**しかありません。

Enterprise 向けの強化は次のとおりです。Artifacts の **CMEK 対応**、管理者が選ぶテンプレート、チームでの共同編集、（管理者が許可した場合の）**組織外共有**、**書式を保つ PowerPoint / PDF 書き出し**、**編集可能な Google Slides への直接書き出し**、モバイル編集。

**書式を保つ書き出しと編集可能な Google Slides への直接書き出しは、実務では GA 自体より効きます。** AI で作った資料が使われない最大の理由は、**書き出すと書式が崩れて手直しの方が高くつく**ことです。ここが改善されるなら、成果物が実際に下流へ流れます。

## 何が変わったか

- **Docs / Slides / Design が beta を抜け、Free を含む全プランで利用可能**（2026-10-08）
- 累計 **4,500 万件超**の docs / decks / designs が作成済み（公式）
- Enterprise 向けに **Artifacts の CMEK 対応**、管理者が選ぶテンプレート、チーム共同編集、**管理者が許可した場合の組織外共有**、モバイル編集
- **書式を保つ PowerPoint / PDF 書き出し**と、**編集可能な Google Slides への直接書き出し**
- **2026-10-15: Enterprise で Docs / Slides / Design が既定で有効化**（管理者は前倒し有効化も可能）
- **2026-12-14: standalone の `claude.ai/design` が閉鎖**
- **移行されないもの: standalone 側の Claude とのチャット、プロジェクトのコメント。** 閉鎖後は参照不可
- **standalone プロジェクトの公開リンクは閉鎖時に停止**
- 移行できるもの: **デザインシステム**（Artifacts ページから）。プロジェクト自体は閉鎖まで稼働

## 業務インパクト（一般企業向け）

**Enterprise 管理者には、10-15 までに決めるべきことがあります。**

**既定で有効化されるという形は、放置が選択肢にならないことを意味します。** これまで「検討中」で止めていた組織でも、**10-15 以降は利用者が使い始めます。** 止めたいなら、**その日より前に無効化の設定を入れる**必要があります。**判断を先送りした結果が「有効」になる**という向きを、まず押さえてください。

決めるべき中身は3つです。(1) **有効化するか無効のままにするか。** (2) **組織外共有を許可するか。** 公式は「管理者が許可した場合」としているので、既定では閉じているはずですが、**資料を社外へ出せるようになる設定は、情報区分のルールと突き合わせる必要があります。** (3) **管理者テンプレートを用意するか。** 用意しないと、全社の資料の見た目が利用者ごとに散ります。

**CMEK 対応は、鍵管理を要件にしている組織では審査の通過条件になります。** これまで Artifacts が審査で止まっていた組織は、**ここが変わったことで再検討の材料ができました。** 審査を一度落としている場合、落ちた理由が鍵管理だったかを確認する価値があります。

**standalone Design を使っていた組織は、12-14 までの作業が別途あります。**

**順番を間違えないでください。** 最初にやるのは移行ではなく、**「何が移行されないか」の確認**です。移行されないのは **Claude とのチャットとプロジェクトのコメント**です。**コメントには、なぜその案を選んだかという判断の記録が残っていることがあります。** デザインの意思決定の経緯が必要な組織では、**これが消えるのは実害です。** 必要な分は**閉鎖前にエクスポートするか、スクリーンショットなり書き起こしで手元に残す**しかありません。

**公開リンクの停止は、社外への影響があります。** standalone プロジェクトの公開リンクで**クライアントや協力会社に共有していた場合、12-14 にそのリンクが死にます。** 配布先の棚卸しと、**新しい共有先の案内を先に出す**必要があります。リンク切れに気づくのが相手側だと、信用の問題になります。

**デザインシステムの移行は Artifacts ページから行えます。** ここは公式に手段が用意されているので、**作業自体は重くありません。** 重いのは移行されない側の退避です。

**スケジュールとしては、10-15 の有効化判断を先に片付け、11月中に standalone の棚卸しと退避、12月上旬に移行完了**が無理のない順序です。12-14 の直前に着手すると、退避が必要な量を見誤ったときに間に合いません。

## 副業・個人活用視点

**Free プランで Docs / Slides / Design が使えるようになったのは、提案の作り方に直接効きます。**

**これまで「Claude の有料プランがないと使えない」と説明していた機能が、無料でも使えます。** 中小企業や個人事業主への提案で、**相手に課金を求めずに成果物を見せられる**のは強いです。「まず無料で作ってみましょう」から入れると、導入の最初の壁がなくなります。

**書式を保つ PowerPoint 書き出しと、編集可能な Google Slides への直接書き出しは、納品物の実用性を変えます。**

受託で資料を作る仕事をしていると、**AI で作った資料をそのまま納品できない理由はほぼ「書き出すと崩れるから」**です。崩れた資料を手で直す時間が入ると、AI を使った意味が薄れます。**編集可能な形で渡せるなら、クライアント側で続きを直せます。** これは**納品後の修正依頼が減る**という形で利益に直結します。見積の前提として織り込める変化です。

**standalone Design を個人で使っていた場合も、12-14 の期限は同じです。**

**個人の方が危ないかもしれません。** 組織なら誰かが棚卸しをしますが、個人は**公開リンクでクライアントに共有したまま忘れている**ことがあります。**12-14 にそのリンクが死ぬと、相手から「見られません」と連絡が来ます。** 今のうちに、**過去に共有した公開リンクを一覧にしておく**のが安いです。

**学習の題材としては、「移行されるもの / されないもの」の読み分けが本題です。** サービスの統合や閉鎖の告知を読むとき、**「移行できます」の対象が何かを確認する習慣**があるかどうかで、事故の有無が決まります。本件は公式が明記してくれている分、親切な事例です。**明記されていないサービスの方が多い**ので、この読み方を身につける練習台として使ってください。
