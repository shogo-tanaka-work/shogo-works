## 要約

Anthropic が Artifacts の新種として **Claude Dashboards** と **Claude Motion** を beta 公開しました。いずれも会話から成果物を作り、**作った後も使い続ける**前提の機能です。

**この2つは一見すると別物ですが、設計の方向は同じです。** どちらも「出てきたものの出自を説明できる」側に寄せてあります。

**Dashboards** は社内データに接続してダッシュボードを生成します。接続先として公式が挙げるのは **BigQuery / Databricks / Snowflake / Redshift / ClickHouse** といったデータ基盤と **Salesforce** です。自然言語で質問すると、**各数値から元クエリへ辿れます。** グラフごとに**データの最終更新時刻**が表示されます。作ったダッシュボードは Amplitude / Grafana / Hex / Mixpanel / Perplexity / PostHog / Sigma へ送れます（Looker / monday.com / Tableau は coming soon）。

**公式が自分の位置づけを限定しているのが珍しい点です。** Dashboards は「素早い探索的な質問向けで、踏み込んだ分析は BI ツールが必要」と明記されています。**これは期待値調整として正確です。** 社内の BI を置き換える話ではなく、**BI に持ち込む前の「とりあえず見たい」を埋める**機能として読むべきです。

**Motion** はプロンプトからアニメーション解説動画を作ります。全社向けの短尺、取締役会資料用のアニメーショングラフ、製品ウォークスルーが用途として挙がっています。エディタでの編集と Claude への修正指示の両方に対応し、**MP4 で書き出せます。**

**そして Motion の最も重要な仕様は、公式が明言している「動画生成モデルを使っていない」という一文です。**

テキスト・グラフ・図形・画像を**コードでアニメーションさせる**方式のため、**生成映像や AI 生成人物は出てきません。** 書き出し先として Adobe / Descript / HeyGen / Higgsfield / invideo / Luma AI / Runway が挙がっています（Canva / Captions は coming soon）。

**この違いは、社内の審査では決定的です。** 「AI が作った動画」を広報物や研修素材に使うとき、論点になるのは**生成された人物の肖像、学習データの出自、生成映像であることの開示義務**です。**Motion はこれらが構造的に発生しません。** 動かしているのは自分が与えたテキストと数値と図形なので、**「この映像のどの部分が生成物か」という問いが成立しません。**

## 何が変わったか

- **Claude Dashboards が beta 公開**（2026-10-08）。社内データ基盤に接続してダッシュボードを生成し、鮮度を保つ
- 接続先は **BigQuery / Databricks / Snowflake / Redshift / ClickHouse** などのデータ基盤と **Salesforce**
- **各数値から元クエリへ辿れる。** グラフごとに**データの最終更新時刻**が表示される
- 外部送信先は Amplitude / Grafana / Hex / Mixpanel / Perplexity / PostHog / Sigma（**Looker / monday.com / Tableau は coming soon**）
- 公式の位置づけは「**素早い探索的な質問向け**。踏み込んだ分析は BI ツールが必要」
- **Claude Motion が beta 公開。** プロンプトからアニメーション解説動画を作り、**MP4 で書き出せる**
- **Motion は動画生成モデルを使っていない**（公式明記）。テキスト・グラフ・図形・画像を**コードでアニメーションさせる**ため、**生成映像・AI 生成人物は出てこない**
- Motion の書き出し先は Adobe / Descript / HeyGen / Higgsfield / invideo / Luma AI / Runway（**Canva / Captions は coming soon**）
- 対象は **Dashboards が有料プラン全般、Motion が Team / Enterprise**。いずれも beta
- **Enterprise では両方が既定で無効。** `Organization settings > Artifacts` で管理者が有効化する

## 業務インパクト（一般企業向け）

**Dashboards で最初に決めるのは、データ基盤への接続を許すかどうかです。**

接続先に並んでいるのは **BigQuery / Snowflake / Databricks / Redshift / Salesforce** です。**これらは多くの組織で「最も機密性の高いデータが集まっている場所」です。** Claude のサイドバーが開いているファイルだけを読む話とは、桁が違います。**接続を許すかどうかは、Artifacts の有効化とは別に判断すべき論点です。**

判断材料として使えるのが、**各数値から元クエリへ辿れる**という仕様です。**これは監査の観点では強い材料になります。** ダッシュボードの数字が信用できない理由は、たいてい「どう集計したか分からない」ことです。**クエリが見えるなら、数字の正しさを人が検証できます。** 逆に言えば、**クエリを読める人がいない部門に配るダッシュボードは、検証されないまま意思決定に使われます。** 配布範囲は、クエリを読める人がいるかどうかで切るのが現実的です。

**グラフごとの最終更新時刻は、地味ですが効きます。** ダッシュボードの事故で多いのは「止まっていたパイプラインの古い数字を見て判断した」という形です。**各グラフに時刻が出ていれば、見ている人が気づけます。**

**「探索向け」という公式の位置づけは、そのまま社内への説明に使ってください。** ここを曖昧にすると、**既存の BI の置き換えを期待した部門が出てきます。** 置き換えようとすると、権限設計・定義の統一・履歴の保持といった BI 側の機能が足りないことに後から気づきます。**最初から「BI に持ち込む前の探索」と言い切った方が、落胆が小さくなります。**

**Motion は、広報・人事・研修の素材内製で検討する価値があります。**

**判断が早く済むのは、AI 生成映像の論点が発生しないからです。** 社内で「AI 動画を使ってよいか」を審査すると、生成人物の肖像、学習データ、開示義務の3点が必ず出ます。**Motion はコードアニメーションなので、この3点に答える必要がありません。** 審査資料には**「動画生成モデルを使用していない（公式明記）」**の1行を入れてください。これで論点が1つ消えます。

ただし**Motion は Team / Enterprise 限定**です。Pro では使えません。**そして Enterprise では既定で無効**なので、**管理者が有効化するまで利用者からは存在しません。** 「使えるようになったと聞いたが出てこない」という問い合わせは、ここが原因です。**先に有効化の方針を決めて周知した方が安いです。**

**両方 beta である点は、素材の作り方に影響します。** 仕様が変わる前提で、**作ったダッシュボードや動画を業務手順書に組み込むのは早いです。** 当面は「毎月の定例報告を Motion で作る」ではなく、**単発の素材で試して、6分や書き出しの制約に当たるかを実測する**段階です。

## 副業・個人活用視点

**Dashboards は有料プラン全般で使えるので、個人でも試せます。**

ただし**接続先がデータ基盤中心**なので、個人の手元に BigQuery や Snowflake があるケースは多くありません。**現実的に効くのは Salesforce 接続と、受託先のデータ基盤に触る案件です。** 後者では**クライアントのデータ基盤に接続する許可を取るのが先**で、これは技術の話ではなく契約の話です。**勝手に繋がない**という当たり前の線を、最初に確認してください。

**受託で効くのは「クエリが見える」ことの説明価値です。** クライアントに数字を出すとき、「どう集計したか」を聞かれるのは常です。**元クエリを一緒に見せられる形で納品できるなら、説明の往復が減ります。** これは成果物の品質というより、**レビューにかかる時間の削減**として提案に書けます。

**Motion は Team / Enterprise 限定なので、個人のプランでは使えません。** ここは正確に把握しておく必要があります。**ただし「AI 生成映像を使わずにアニメーション解説を作る」という方向自体は、個人の案件でも効きます。** 中小企業向けに研修素材や製品説明の動画を作る仕事では、**「AI 生成の人物は出しません」と言い切れることが、そのまま受注理由になる**場面があります。生成映像を避けたい業種（医療、金融、公的機関まわり）では、この区別が効きます。

**学習の題材としては、Dashboards の方が応用が広いです。** 「自然言語の質問をクエリに落とし、数値から元クエリへ辿れるようにする」という構造は、**自分でツールを作るときの設計の型**になります。生成した SQL を隠すか見せるかで、ツールの信頼性がまるで変わる。**この判断を体験できる題材として使ってください。**
