## 要約

Anthropic は 2026-09-16、Cowork と chat の統合発表と同じタイミングで、**Claude Docs と Claude Slides を新規に提供開始**し、**既存の Claude Design も会話の中から使えるようにした**と発表しました。

公式の説明はこうです。「ドキュメントを頼めば、あなたと Claude で一緒に書く。プレゼンを頼めば、Claude がスライドを下書きする。**直接編集でき、Claude からそのまま発表もでき、PowerPoint または PDF として書き出せる**」。

**この発表の重心は「AI の出力がファイルになった」点にあります。**

これまで Claude の成果物は、チャット内のテキストか、artifacts と呼ばれるブラウザ内の生成物でした。**そこから先、つまり「同僚に配る」「会議で映す」「クライアントに送る」段階では、結局コピーして自分で整形する作業が残っていました。** Docs と Slides は、その最後の工程を引き受けます。

**PowerPoint / PDF への書き出し対応は、この文脈で読むと意味が変わります。** 単なるエクスポート機能ではなく、**Claude の出力を既存の業務フロー（PowerPoint で作り、メールで送り、会議で映す）に接続する経路**です。

**3機能の役割は公式に分けて説明されています。Claude Design はブランドに沿ったビジュアルとモックアップ、Claude Slides はプレゼン、Claude Docs は「Claude とチームで一緒に書く living document」**です。会話内に生成されるチャートや図（artifacts）とは区別され、**「他人の前に出す成果物」向けの経路**として位置づけられています。

**提供条件は3つとも同じで、有料プランでのベータです。** そして **Enterprise については管理者が有効化のタイミングを決めます。** Claude Design を単体で使っている場合は従来どおり動作します。

**公式が推す使い方は「1つの会話から複数の成果物」です。** 週次レポートを頼むと同時に「ハイライトを5枚のスライドにして」と付け加えると、**レポートとスライドが同じ会話から出てくるため、内容が最初から揃っている**という説明がなされています。別々に作って整合を取る手間が消える、という主張です。

成果物には**共有可能な単一リンク**が割り当てられ、モバイルからも開けます。要素を選んで動かす直接操作と、Claude への指示による修正の両方が使えます。スライド上に Claude 向けのコメントを残す運用も示されています。

## 何が変わったか

- **Claude Docs**（新規・ベータ）— Claude とチームで共同編集する living document
- **Claude Slides**（新規・ベータ）— プレゼンの下書きと、Claude からの直接発表
- **Claude Design**（既存）— 会話内から利用可能に。単体利用は従来どおり
- **PowerPoint / PDF への書き出し**に対応
- スプレッドシートは**数式が動く状態**で受け取れる
- 成果物は**1つの共有リンク**で扱え、モバイルからも開ける
- 直接編集と、Claude への指示による修正の両方が可能
- スライドに**Claude 向けのコメント**を残せる
- **3機能とも有料プランでのベータ提供**
- **Enterprise は管理者が有効化のタイミングを決定**

## 業務インパクト（一般企業向け）

**この機能で増えるのは「社外へ出る経路」です。ここが管理上の論点になります。**

チャット内のテキストは、社外へ出るまでに必ず人の手を経ます。コピーし、社内のテンプレートに貼り、体裁を整える。**その工程が、意図せず人間のレビューとして機能していました。** PowerPoint で直接書き出せるということは、**この工程を飛ばして配れる**ということです。

**しかも3機能ともベータです。** ベータ品質の出力が、体裁の整ったファイルとして出てきます。**見た目が整っていると中身も検証済みに見える**ため、レビューが甘くなる方向に働きます。**「AI が作ったスライドを、見た目が良いのでそのまま役員会に出した」は現実に起きる事故の形です。**

**したがって、導入時に決めるべきは機能の可否ではなく、レビュー基準です。** 具体的には「社外配布物は必ず人が内容確認する」「数値が入る資料は出典を確認する」という2点を先に決めておけば、機能自体は素直に便利です。

**Enterprise 管理者にとっては、有効化タイミングの判断が発生します。** 同日発表の Cowork / chat 統合は30日前通知を経て自動的に来ますが、**Docs / Slides / Design は管理者が決める**という違いがあります。**これは実質的に、レビュー基準を整える猶予が与えられているということです。** 統合と同時に有効化せず、基準を決めてから開ける、という順番が取れます。

**既存の資料作成フローとの関係も整理が要ります。** 多くの組織には既定のテンプレートやブランドガイドラインがあります。**Claude Design は「ブランドに沿ったビジュアル」を作るとされていますが、組織のガイドラインをどう読み込ませるかは別途設計が必要**です。何も与えなければ、Claude の既定のスタイルで出てきます。

**一方、明確な利点もあります。** 「1つの会話からレポートとスライドが出る」という構造は、**実務で頻繁に起きる不整合を潰します。** レポートを書いた後にスライドを作り、その間に数字が更新されて食い違う、という事故は珍しくありません。同じ会話から生成されていれば、少なくとも出発点は揃います。

**共有リンクの扱いは確認事項です。** 成果物に単一リンクが付くということは、**リンクを知っている人がアクセスできる仕組み**が存在するということです。組織として、**このリンクの共有範囲がどう制御されるかは、有効化前に確認すべき項目**です。公式発表と現時点のヘルプ記載では、リンク共有の権限モデルの詳細までは示されていません。

## 副業・個人活用視点

**個人事業主やフリーランスにとって、ここは直接売上に効く部分です。**

**提案書と提案スライドを別々に作る作業は、受注前の無償作業の代表格です。** 案件を取れるかわからない段階で、資料作成に数時間かける。**それが1つの会話から出るなら、提案にかけるコストが下がります。** 提案の本数を増やすか、1本あたりの検討時間を厚くするか、どちらにも回せます。

**PowerPoint 書き出しが効くのは、納品形式を指定される場面です。** 「編集できる形で納品してほしい」と言われたときに、PDF しか出せないと詰みます。**PowerPoint で出せるなら、クライアント側で修正できる状態で渡せます。** 研修資料や社内説明資料の制作を請けている場合、これは受注条件に直結します。

**Claude Docs の「living document」という位置づけは、伴走型の案件と相性が良い**と考えられます。納品して終わりではなく、更新し続ける文書（運用マニュアル、議事録の蓄積、ナレッジベース）をクライアントと共同編集する形です。共有リンク1つで開けるため、**クライアント側に新しいツールの導入を求めずに済みます。**

**ただし、ベータであることは価格設定に反映すべきです。** 「Claude で作りました」と言わずに納品するなら、出力の検証は自分の責任になります。**見た目が整っているぶん、検証を省きたくなる誘惑が強い**という点は自覚しておく必要があります。**数値・固有名詞・日付は、書き出す前に必ず自分で確認する**という手順を固定するのが現実的です。

**単価の考え方も変わり得ます。** 資料作成を「時間×単価」で請けている場合、**制作時間が減れば売上も減ります。** 成果物ベース、あるいは「何を作るか決める部分」に価値を置いた価格設定へ移す方が、この変化とは整合します。**Claude が下書きできるのは形式であって、何を載せるべきかの判断ではありません。** そこが残る価値です。

**なお、Claude Design を単体で使っている人は従来どおり動きます。** 今回の変更で既存のワークフローが壊れることはありません。
