- **教材の軸は「限定公開の発表を見た時点で、評価の準備を始めるかどうか」に置く。** 9月30日の Argon 発表は「信頼済みサイバー防御者へ限定提供、一般提供の時期は未定」だった。**その2週間後に有料 API とアプリへ降りてきた。** 限定公開のニュースを「自分には関係ない」と読み飛ばす習慣があると、一般提供に気づくのが遅れる。**「限定公開 → 一般提供の期間」を実測値として持っておくこと**が、情報の読み方を変える。
- **「価格に有効期限が付いたモデル」の扱い方を、手順として教える。** 導入価格は入力 $2 / 出力 $10、**2026-11-30 を過ぎると $4 / $20 で2倍になる。** PoC のコスト試算をそのまま本番見積もりへ使うと、**稟議の途中で前提が変わる。** 教材では「導入価格で出した数字」と「標準価格で出した数字」を**必ず併記する**という作業手順まで落とす。これは Argon 固有の話ではなく、**導入価格が設定されるモデルすべてに効く型**である。
- **キャッシュ入力95%引きが効く構成を具体で示す。** 同じ長いコンテキストを繰り返し使う形（社内文書を前提にした QA、長い仕様書への連続質問）では、**単価の差がそのまま運用コストの差になる。** 「安い」で終わらせず、**どの構成で効いてどの構成で効かないか**を分けて説明する。単発の短い問い合わせが多い用途では、キャッシュ割引はほぼ効かない。
- **モデル ID とコンテキストウィンドウを「書かなかった」判断を、そのまま教材にする。** 執筆環境から `ai.google.dev` が DNS 解決できず、models / pricing / changelog ページへ到達できなかった。**検索では二次情報が互換性のない値を並べていた。** 記事ではモデル ID を書かず、「実装前に公式ドキュメントで確認せよ」と明記した。**「到達できなかったものを推測で埋めない」判断の実例**として使える。読者が実装でつまずいたときに戻ってこられる記事は、この境界が明示されている。
- **「1M unified input-output token limit」という表現の読みにくさを題材にする。** 10月13日の発表は「Gemini API 経由で業界最高の1M統合入出力トークン上限」と書き、9月30日の発表は「出力上限が64K → 1M」と書いている。**入力と出力を合わせた枠なのか、入力枠が別にあるのかは、この2文からは確定できない。** 長い入力を前提に設計する場合、**ここを確認せずに進めると後で作り直しになる。** 公式の文面が曖昧な箇所を見つける練習として良い例である。
- **ベンチマークの出所を区別する習慣を教える。** RareBench 57% と LabBench 52.2% は **Gamow Labs の私的評価（private evals）**で、第三者が同条件で再現できない。Vals Index の1位も対象領域が finance / coding / legal / tax に限定されている。**稟議資料へ「業界1位」とだけ書くと、根拠を聞かれて答えられない。** 数字と一緒に出典の性質を書く、という作業を型にする。
- **Gemini アプリ側の変更を「情シスから見えない経路」として扱う。** Argon のアプリ提供は **Google AI Pro / Ultra 加入者**が対象で、個人契約で業務利用している社員は**Workspace 管理コンソールから見えない。** 40以上のアプリ連携と離席中もタスクを続けるトグルが入ったことは、**業務データが通る経路が増えた**ことを意味する。「どのプランの Gemini を業務で使ってよいか」を決めていない組織の論点として提示する。
- **macOS アプリにエージェント型コーディング UI が入った点は、開発環境の管理の話へ接続する。** Antigravity の UI が Gemini macOS アプリへ入った。**エージェントがコードを書いて実行する経路が1つ増えた**という形で、既存の開発ツール管理の延長として扱える。新しい論点ではなく、**既存の管理対象が1つ増えた**という整理が正確である。
- **既存 Knowledge への反映は不要と判断した。** Gemini 関連の既存教材に「Argon が限定提供である」と書いた箇所はない（9月30日の発表は記事化しておらず、日次サマリーと9月の recap メモに言及があるだけ）。将来モデル一覧や料金表を Knowledge へ持つ場合は、**導入価格の期限（2026-11-30）を表に入れると古くなるのが早い**ため、価格は記事側に置き、Knowledge には「価格は期間限定で変わる前提で確認する」という判断軸だけを残す。
- **日次チェック運用側の反省点として記録する。** 2026-10-01 の日次サマリーは、blog.google の日付が取得できなかった状況で Argon を「既存記事として記事化済みの話題」と書いていたが、**実際には記事化していなかった。** 日付が取れないときに「既出だろう」と推定すると、取りこぼしが起きる。**記事化済みかどうかは `src/content/ai-news/` の実ファイルで確認する**という手順を、曖昧な状況ほど厳密に適用する必要がある。
