- **最も汎用性の高い教材点は課金単位の違い**である。通常の LLM はトークン課金なので「出力を短くすれば安い」が成立するが、**Live API は分課金なので通話時間がそのままコスト**になる。**AI が丁寧に長く話すほど高くつく**という逆方向の圧力が働く。受講者はトークン課金を暗黙の前提にしているため、ここで一度崩す価値が大きい。
- **演習: 分課金前提でランニングコストを試算させる。** 入力 $0.005/分・出力 $0.018/分、平均通話5分、1日100件、月20営業日。**桁が出せるかどうかを確認する。** 単価表を読んで月額に落とす作業は、AI 知識ではなく見積もりの基礎技能であり、提案の説得力を直接左右する。
- **「発表された」と「自社で使える」の距離を測る訓練**として優秀な事例。同じ1本の発表の中に、一般提供（Gemini Live / Gmail / Keep）、Pro-Ultra 限定（Docs）、private preview（企業向け Gemini）、**時期未定の coming soon（Workspace 法人）**が同居している。**提供段階を4層に分けて読む型**を教える。
- **音声 AI の実用障壁が精度ではなく「処理中の沈黙」だった**という指摘は、技術課題の捉え方の題材になる。**モデルを賢くする方向ではなく、対話体験の連続性を改善する方向で解決している。** 「性能改善＝賢さ」と考えがちな受講者の視野を広げる。
- **受託案件のリスク設計として、従量課金を固定月額で請ける危険**を扱う。通話時間が読めない状態で月額固定にすると、利用が増えるほど赤字。**基本料金＋通話時間従量**という構造の合理性を、具体的な数字で示させる。
- **提案の前提として「クライアントの現在の入電数と平均通話時間」をヒアリングする**という段取りを教える。試算に必要な変数を先に特定してから商談に入る、という基本動作。**AI 案件でも見積もりの作法は従来と変わらない**という結論に着地させる。
- **視覚的グラウンディングは用途拡張の例**として短く扱う。言葉での説明が難しい場面（現場作業、設備点検）に音声＋映像で対応できる。ただし **Live API 経由の自前実装が前提**である点を必ず添える。
- **音声データ特有の統制論点**を入れる。テキストと違い**音声は話者識別が可能**。顧客通話を AI に通す場合、録音・処理の同意取得が既存規程で足りるかの確認が要る。**データ種別が変わると統制要件も変わる**という一般則。
- **提案時に実装手段を伏せない**という職業倫理の話を入れる。「Google が発表した機能」と言って実態は API 自前実装、という説明は後で必ず問題になる。**提供段階を正確に伝えることが信頼の前提**という整理。
- 恒久教材へ反映する場合、**モデル名・価格・提供段階は書かない**（変わる）。残すのは **(1) 課金単位を最初に確認する、(2) 提供段階を4層で読む、(3) 従量原価の役務は従量で請ける** の3点。
