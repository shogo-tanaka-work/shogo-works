- **モデル追加と退役をセットで読む型**を教える題材にする。2つの changelog に分かれているが実体は入れ替えで、片方だけ見ると「安いモデルが増えた」で終わる。GitHub Copilot のモデル更新はこの形が繰り返されるため、読み方そのものを教材化する価値がある。
- Business / Enterprise が**既定オフ**である点は、Copilot 教材で繰り返し出る構造。`github-copilot/copilot-kimi-k3` でも同じ扱いだったので、個別モデルの話としてではなく「新モデルは組織では既定オフ」という一般則として整理し、各記事はその実例として参照させる。
- コスト教材の実材料になる。表示価格 73% 減、年額契約はプレミアムリクエスト乗数 0.25 倍という具体的な数字が出ているため、**モデル使い分けの損得を数字で示す**演習が組める。同日追加された usage report のモデル別トークン内訳（詳細メモ `2026-08-11T000003-usage-report-per-model-tokens.md`）と組み合わせると、施策 → 実測の往復が作れる。
- 使い分けの指針は「軽量な作業は小型モデル」だけでは行動が変わらない。**定型リファクタリング / テスト雛形 / コメント整備**のように具体的な作業名まで落とす。抽象度を上げたままだと、結局既定モデルが使われ続ける。
- 小型モデルの評価を高性能モデルと同じ土俵でやらせない。**得意な作業と苦手な作業を分けて検証させる**課題設計にしないと、「安いが使えない」という不当な結論に着地する。
- vision 対応は演習に組み込みやすい（エラー画面のスクリーンショットを渡す）が、**機微情報の写り込み**という運用リスクとセットで扱う。画像入力を DLP 方針とどう揃えるかは企業導入編の論点。
- 期限のある管理者作業（2026-09-10）は、そのまま「AI ツールの管理者運用には期限付きタスクが定期的に発生する」という話に接続できる。退役カレンダーを持つ運用の必要性を説明する具体例として使う。
