- 「モデルが増える」こと自体より、**Business / Enterprise で既定オフ・管理者が明示的に有効化する**という配布モデルが教材価値の中心。オープンウェイトモデルを組織に入れるかどうかの判断が管理者に降りてくる構造を、Copilot 教材の管理者向け節で扱う。
- モデルごとに稟議を回す運用は破綻する、という前提から入る。**有効化の条件をあらかじめ定義しておく**（提供元の種別 / データの取り扱い / コスト上限）というアプローチを、演習として書かせる形にできる。個別モデルの是非を議論させても教材の寿命がない。
- 価格（入力 $3 / 出力 $15 / キャッシュ $0.30 per 1M）は変動しやすいため、教材本文に数値を書かず「従量課金でモデルごとに単価が異なる」という原則だけ記す。エージェント的な使い方はトークンが伸びやすくモデル選択の影響が体感より大きい、という点は残す価値がある。
- ロールアウトが incident で一時停止された点は、「changelog に載っていても自分の環境に来ているとは限らない」という一般則の実例として使える。管理者が有効化した事実と実際に配信された事実は別、という切り分けは問い合わせ対応の教材にもなる。
- 受講者が個人プランと法人環境の両方に触れる場合、**自分の環境で出せる成果と納品先で再現できる成果がずれる**問題を扱う。モデル依存の手順を納品物に含めるときの注意として、受託系の受講者に響く。
- 既存の Copilot モデル関連記事（`kimi-k2-7-copilot-ga`、`copilot-enterprise-teams-model-policy` 等）と重複しやすい。この記事は「オープンウェイト×既定オフ」の切り口に絞り、モデルポリシー機能そのものの解説は既存記事へ寄せる。
