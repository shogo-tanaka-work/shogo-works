- **「ベンダーの AI 機能は数か月単位で消える」ことの実例**として使える。Spark → VS Code / Copilot CLI への統合という公式説明は、AI ツール選定教材で「ツール単体ではなく、既存ワークフローに統合されるものを選ぶ」という判断軸の裏づけになる。抽象論ではなく、廃止理由を提供元自身が「統合されたから」と書いている点が引用価値。
- `llm()` 関数が GitHub Models 廃止で動かなくなる点は、**プラットフォーム提供のモデルアクセスに依存するリスク**の具体例。GitHub Models 廃止（2026-07-30）→ Spark 廃止（2026-08-04 告知）という 1 か月強の連鎖になっている点まで含めると、「依存の連鎖」の教材として強い。設計指針としては「モデルは自前の API キーで抽象化しておく」に落ちる。
- **シャドー IT の棚卸し**という切り口が使える。Spark のようなノーコード寄りツールは情シスの管理外で使われやすく、廃止告知が来て初めて「誰が何を作っていたか」を調べることになる。ガバナンス教材で「利用実態の把握が先、統制は後」を説明する事例。
- エクスポート期限（2026-08-31）は期限つきタスクなので、**教材ではなく運用チェックリスト側**に置く種類の情報。教材本文に日付を書くと数か月で陳腐化する。
- 移行時に発生する「モデルアクセスの費用を誰の予算で持つか」という論点は、**内製ツールの TCO**の教材で使える。開発コストだけでなくランニングの帰属先を決めないと移行が止まる、という実務的な詰まりどころ。
- Copilot Billing Preview アプリの廃止は同日告知だが単体では教材価値が薄い。Copilot の課金 UI 系は変更が多いので、**課金管理の教材を書くなら日付とバージョンを明記して書く**という注意の材料に留める。
