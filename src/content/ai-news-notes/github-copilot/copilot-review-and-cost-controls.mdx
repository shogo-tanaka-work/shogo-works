- **Code Quality の自動レビュアー撤回は「静かに止まる変更」の教材素材**として価値が高い。壊れてエラーが出るのではなく、期待していた動作が起きなくなるだけなので、数週間気づかれない。この種の変更にどう気づくか（changelog の定期確認、既定値に依存しない設定）という運用の話に接続できる。
- GA からわずか3週間で既定を撤回している点は、「既定値は動きうる」ことの実例。教材では、重要な挙動は明示的に設定しておく（暗黙の既定に依存しない）という原則の根拠として使う。
- effort level の Low / Medium → Lite / Balanced 改名は、ドキュメント保守の題材。設定値は自動引き継ぎで動作は変わらないが、手順書と画面表示が食い違う状態は新任者を混乱させる。「動くから直さなくていい」と「読めるから直さなくていい」は別、という区別。
- ROI ダッシュボードは、AI 導入の投資対効果をどう説明するかというテーマの中核素材。指標が Cost/dev/month・人件費比率・月間 PR 数の3つに絞られている点、公式自身が directional estimate と断っている点の両方を書く。精密な効果測定として提示させない。
- PR 数を効果指標に使うことの限界も触れておく価値がある。PR が増えることは必ずしも価値が増えることではない（細切れの PR が増えただけかもしれない）。公式指標をそのまま鵜呑みにしない読み方を教える機会になる。
- usage metrics API のエージェント別内訳は、「導入したまま誰も使っていないツールに払い続ける」問題の検出手段。SaaS のライセンス最適化と同じ構造で、AI ツール特有の話ではない。
- トークン消費表示（web の Copilot Chat）と `/side`（App）・`/btw`（VS Code）は、セットで「会話を分けることがコスト面でも有利」という設計として説明できる。Claude Code の会話分割やコンテキスト管理と同じ理屈が成り立つため、ツール横断の原則として教えられる。
- CLI の `/worktree` `/rewind` は Claude Code の同種機能との比較素材。ツール比較教材（`compare-with-cursor.mdx` 等）で、同じ課題に各ツールがどう答えているかを並べる形に使える。
- 演習化は部分的に可能。effort level の切り替えと ruleset の設定は個人リポジトリで試せる。ROI ダッシュボードと usage metrics API は組織の管理者権限が要るため、画面例の提示に留める。
