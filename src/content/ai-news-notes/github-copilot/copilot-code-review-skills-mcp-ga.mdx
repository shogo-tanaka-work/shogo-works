- `SKILL.md` をリポジトリに置いてレビュー基準を注入する構造は、Claude Code / Codex のスキル運用と同型。「AI への指示をリポジトリ管理の資産にする」という考え方を横断的に説明する教材の核にできる。
- 「規約は Wiki にあるが守られない → レビューで指摘されるルールは守られる」という対比は、ドキュメント運用の教材で使える強い論点。
- MCP 呼び出しを読み取り専用に限定した設計は、AI にどこまで権限を渡すかの判断例。セキュリティレビューの議論を「権限の範囲」から「読ませる情報の範囲」へ絞れる、という整理で教材化する。
- 帰属表示は「AI の指摘の根拠を辿れるようにする」実装例。AI レビューが現場で無視される原因（根拠が見えない）への対処として説明できる。
- GitHub / Playwright の MCP サーバーが既定で有効という点は、導入審査の教材で「既定値を確認する」チェック項目の実例にできる。
- Pro / Pro+ が対象に入るため、個人向け教材でも扱える。`SKILL.md` が引き継ぎ資料として機能するという副業視点の使い方も教材化余地あり。
- 現時点で対応するKnowledge記事が存在しないため、relatedKnowledgeは空配列。
