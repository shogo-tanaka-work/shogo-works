- **バージョン番号が同じまま仕様が変わる**という事象の実例。2026-06-17 の記事（720p / image-to-video 中心）と本件（1080p / 3系統対応）を並べると、「モデル名とバージョンだけで仕様を判断してはいけない」という教訓が具体的に示せる。既存記事 `xai-grok/grok-imagine-video-1-5` との関係を教材でも明示する。
- text / image / reference の3入力の使い分け（ゼロから = text、手元素材あり = image、一貫性が必要 = reference）は、動画生成の教材でそのまま使える整理。
- 「単発クリップから一貫性のある連作へ」という関心の移動は、同日の Seedance 2.5（参照入力：画像30枚 / 動画10本 / 音声10本）と並べると複数ベンダーの共通トレンドとして示せる。
- 企業が動画を作るとき単発で終わることは稀（製品紹介・研修・SNS はいずれも複数本）という前提は、reference-to-video の価値を説明する導入として使える。
- 「ネイティブ1080p」と「アップスケール」の違いは、納品要件を満たせるかの確認項目として実務的。仕様表の読み方の教材にできる。
- API 提供 vs UI ツールの向き不向き（大量生成・パイプライン化 = API、試行錯誤 = UI）は、ツール選定の軸として一般化できる。
- 参照素材を外部へ送ることになるため、ベンダー審査の対象がコードではなく画像・映像素材になる、という論点。Grok 4.5 の Copilot 追加（2026-07-28）と同じ審査の枠で扱える。
- xAI の release notes が月単位表記のみで提供開始日を追えない点は、記録・監査の観点で「自社で確認した日と確認時点の仕様を残す」という実務対応として教材化できる。
