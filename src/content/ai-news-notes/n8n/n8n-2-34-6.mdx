- **Google Ads の v21 sunset 対応は、外部 API 依存の自動化が抱える構造的リスクの実例。**ワークフロー側は何も変えていないのに、依存先の API 提供終了で止まる。n8n 教材で「作って終わりにできない」ことを説明する具体例として使える。しかも利用者はリリースノートを読まない限り、なぜ止まったか分からない。
- ここから**依存ノードの更新情報をどう追うか**という運用の話へつなげる。使っているノードの一覧を持ち、リリースノートで該当ノード名を検索する、という具体的な手順まで落とす。ワークフローが増えるほど依存の把握者がいなくなるので、一覧そのものを管理対象にする。
- Microsoft Teams の OAuth スコープ復元は、**権限スコープが変わると何が壊れるか**の題材。スコープは目に見えないため、失敗して初めて気づく。認証まわりを扱う教材で、更新後に主要操作の疎通を確認する手順とセットで教える。
- 「同一 Instance AI セッション内なら更新承認をスキップ」は、**AI が作ったものへの承認をどこまで求めるか**という設計判断の実例。毎回聞けば安全だが使われなくなる、というトレードオフを、セッション単位で緩める折衷案として整理できる。HITL 設計の教材（`n8n/n8n-2-35-0` の HITL 節）と接続する。
- **stable（2.34.6）と pre-release（2.35.3）を混ぜて説明しない**こと自体が教材になる。同日に出た2つの版で、片方はバグ修正のみ、もう片方は機能追加込み。どちらを本番へ入れるかの判断は、版のチャネル表記を読めるかどうかで決まる。
- 3日連続のパッチ（2026-08-12 / 08-13 / 08-14）という事実は、**機能リリース直後の版を本番へ即時適用しない**運用判断の裏づけとして引き続き使える。
