- 「決定論的ワークフロー」と「AI の判断」を混在させる設計思想は、ツール固有の話ではなく汎用の設計原則。教材では「毎回 LLM に判断させると結果がぶれる → 固定できる部分は固定する」という一般則の具体例として扱い、n8n や Dify のワークフロー教材と横並びで比較できるようにする。
- Gatekeepers の「権限ゼロ起点 + 都度申請」は、Claude Code の権限設計、MCP のスコープ、Cloudflare Wallets の 2 層ウォレットと同じ構造。エージェント権限設計の節を作り、4 例を並べて「同じパターンが各社で再発明されている」ことを示すと定着しやすい。
- ブループリント配布（他人が独立コピーを作れる）は、社内ツールが無秩序に増える問題と表裏一体。企業導入編で「配布しやすさは棚卸しコストと引き換え」という論点として置く。Excel マクロの歴史と接続すると非エンジニア受講者に伝わりやすい。
- OSS である＝運用・保守は自社責任、という点は受講者が見落としやすい。「無料」と「コストが低い」を分けて説明する実例に使う。
- 詳細な手順の教材化は時期尚早。公開直後で構成が変わる可能性があるため、当面は設計思想の教材に留め、手順は記事へリンクする。
