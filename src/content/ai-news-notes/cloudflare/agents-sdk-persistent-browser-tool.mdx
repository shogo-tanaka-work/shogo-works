- **教材の軸は「使い捨てだったことが、実は安全弁として働いていた」に置く。** 従来はターンごとにブラウザが捨てられ、**「1ターンで終わる」制約が実質的な安全弁**だった。ログイン状態が10分残るようになって、**その安全弁が外れた。** 機能追加を「できることが増えた」とだけ説明すると、この側面が落ちる。**制約が持っていた副作用を言語化する**練習として良い題材である。
- **解決された問題を「何が組めなかったか」から説明する。** 1ターン目でログインし、2ターン目で続きをやろうとすると**セッションが切れてログインからやり直し**になっていた。結果として**ログインが必要なサイトでの多段作業は現実的に組めなかった。** 業務システムはほぼすべてログインが必要なので、**この制約がエージェントの射程を「公開情報の取得」に限っていた。** 機能名から入るより、できなかったことから入ると理解が速い。
- **Durable Object の hibernate を越える点は、2段の説明が必要だと教える。** 「使われていない間は止まる」→「止まっても外部のブラウザは生きている」。**Cloudflare を触っていない人には hibernate 自体が伝わらない。** 機能の列挙は誰でも書けるが、**なぜそれが難しかったのかを書ける人は少ない。** 技術記事の読まれ方を分けるのはこの部分である。
- **認証情報の設計を3つの問いに落とす。** (1) **どのアカウントでログインさせるか**（個人の認証情報か、エージェント専用アカウントか）、(2) **そのアカウントの権限範囲**（読み取りのみか、更新も許すか）、(3) **10分という寿命を長いと見るか短いと見るか。** 公式は「既定」と書くので変更の余地があると読めるが、**changelog には変更方法が書かれていない。** 問いの形で提示すると、受講者が自分の環境へ当てられる。
- **`restarted: true` の後処理が実装側の責任である点を強調する。** セッションが落ちると新しいブラウザが作られ**ログイン状態は失われる。** ツールはフラグを返すので検知はできるが、**そのあと何をするかは書く必要がある。** ここを書かないと、**ログイン画面に対して作業を続けようとする**挙動になり得る——エラーで止まるのではなく、間違った画面で動き続ける。**「検知できる」と「対処が書かれている」は別**という一般論へ展開できる。
- **10分という数字を、人を挟む設計／挟まない設計の分岐として教える。** 人の承認を挟むと、**エージェントが作業 → 人へ確認 → 人が会議から戻って返信**で10分を超える。超えるとログイン状態が失われる。**人を挟まず連続して動く構成では10分は十分。** 同じ数字が、構成によって「短い」と「十分」に分かれる。**制約を数字で持っておくと設計の分岐が自分で引ける**という例になる。
- **モデルが CDP のコードを書いて操作する点は、制御の所在の話へ接続する。** 固定コマンドの組み合わせより柔軟だが、**何が実行されるか事前に列挙できない。** サンドボックスの外には出ないものの、**どのサイトへアクセスできるかはネットワーク側で制御する話**になる。許可ドメインを絞る設計が実装の前に必要、という順序を示す。
- **提案の形が変わることを、営業の観点で明示する。** RPA が入っている領域（ログイン → 一覧を開く → 条件で絞る → エクスポート）と重なる。ただし提案は「全部自動化します」ではなく **「10分で終わる単位に切って、その中で完結させます」** になる。**制約を理解した提案は、理解していない提案より通る。** これは営業資料の書き方の教材として使える。
- **バージョンごとの対応表を自分で作る価値を示す。** `web_search` が v0.27.0 以降、`web_fetch` と `browserTool` が **v0.28.0 以降**。**Agents SDK は版ごとに使えるツールが変わっている段階**で、公式は個別の changelog に散らしている。**まとまった対応表は需要があり、検索で拾われる。** 日次チェックを続けていれば自然に作れる成果物である。
- **試して確かめられる条件が良いことを伝える。** 必要なのは Cloudflare アカウントと Browser Run だけで、**大掛かりな環境構築が不要。** ログイン状態が本当に残るか、10分で本当に切れるか、`restarted: true` が返るかは自分で確認できる。**公式が書いていない箇所**（アイドルタイムアウトの変更方法、中断されたツール呼び出しの挙動）を実験で埋めた記録は、**公式ドキュメントの代わりとして読まれる。**
- **既存 Knowledge への反映は不要と判断した。** Cloudflare の Agents SDK を扱う Knowledge 記事は持っていない。将来持つ場合は、**バージョン番号とタイムアウト値は記事側に置き、Knowledge には「エージェントのブラウザセッションには寿命があり、失効後の分岐を実装する」という設計原則だけを残す。** 数値は変わるが、原則は残る。
