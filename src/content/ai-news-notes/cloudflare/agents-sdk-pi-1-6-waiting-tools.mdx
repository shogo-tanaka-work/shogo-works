- **待機をツールの戻り値として表す考え方を教える。** 「結果を返す」「保留して後で呼び直す」の2択にすると、待っている間に何も動かさずに済む。長時間タスクを会話の外で管理する発想の入口になる。
- **承認ゲートは実行の直前に置く。** ツールを呼ぶ前に止めて人の確認を待つ位置を、図にして示す。どの操作に承認を付けるかを、影響の大きさで仕分ける演習にする。
- **「休止できる」と「料金が下がる」を混同させない。** 公式の説明は前者までで、請求への影響は書かれていない。書かれていないことを確認事項として残す練習にする。
- **承認の記録は別設計。** 保留と再開の仕組みがあっても、誰がいつ承認したかの証跡は自分で残す。監査の観点で補う箇所を考えさせる。
- **中断時に入力を捨てない設計。** 回答を止めたとき、次の指示が消えない挙動は、利用者の体験を左右する。失敗時の振る舞いを先に決める習慣として扱う。
- 恒久教材へ反映する場合、**バージョン番号と API 名は書かない**（変わる）。残すのは「待機は保留として表し、占有しない」「承認は実行直前に置く」「承認の証跡は別に残す」の3点。
