- **「サーバーを用意せずに実行できる」の裏側を説明する。** 関数は隔離された Worker で動き、利用者の Worker は不要。実行場所が変わっても、**どこで動くかを把握する責任は残る**ことを図で示す。
- **後始末を演習にする。** セッションが自動で閉じない仕様は、リソースの閉じ忘れを学ぶ題材として使える。実行後に `close` を呼ぶところまでをコードの型として覚えさせる。
- **API・Worker・ダッシュボードの3経路を比較させる。** 同じ機能に API トークンが要る経路と要らない経路がある。権限の持たせ方が経路で異なる点を表にする。
- **既存セッションへの追加実行を使った設計。** ログイン済みのセッションで後続のスクリプトを回す形は便利だが、資格情報が残る時間も延びる。保持時間とのトレードオフを考えさせる。
- **個人活用の切り口は定点観測。** 対象サイトの規約確認を、技術の前に必ず行う手順として教える。
- 恒久教材へ反映する場合、**エンドポイント名・料金・上限は書かない**（変わる）。残すのは「実行場所が変わっても後始末は自分の責任」「経路ごとに権限の持ち方が違う」「自動アクセスは対象サイトの規約を先に確認する」の3点。
