- **「最適化する前に、測れる状態を作る」という順序の教材として最適な事例。** プロンプトキャッシュを効かせても、集計側が対応していなければ成果が見えない。しかも見えない方向が「実際より高く見える」側なので、最適化を進めるほど数字が改善しないという逆転が起きる。**測定の穴は、努力を無駄に見せる**という一般則の具体例。
- **前日（2026-09-08）の OpenAI Prompt Cache Diagnostics GA、Anthropic のコスト削減ガイドと合わせて、3日分で1つの流れとして扱える。** 業界が同時にキャッシュ最適化へ向かい、その翌日に測る側が追いついた、という時系列。**ベンダー横断で同じ論点が動くときは、周辺ツールの対応まで見る**という調査姿勢の教材にもなる。既存の2記事から相互参照させる。
- **フォールバック仕様（片方省略で `per_token_in` を使う）は、設定ミスが静かに通る設計の実例。** エラーにならず、ただ数字が高く出るだけなので気づきにくい。「どちらか書けば有効」という親切設計が、書き忘れの検出を潰している。**設定系の落とし穴として、デフォルト値の方向を確認する**という点検項目に一般化する。
- **ゲートウェイ導入は技術選択ではなく組織的選択、という読み替え**が教材の芯になる。AI 利用が部門へ広がるとコストが分散し誰も全体を見なくなる。ゲートウェイを入れることは「誰が全体を見るか」を決めることでもある。**AI ガバナンスのコスト面**として、権限・統制の章とは別に1節を立てられる。
- 副業・受託向けには、**原価が見えないと値付けできない**という切り口が効く。さらに「キャッシュ設計を入れて月額をこれだけ下げた」という報告が次の仕事につながる、という実績化の道筋まで示す。**最適化の手間をかける前に測定を用意する**という順序の指導とセットにする。
- 恒久教材へ反映する場合、ヘッダー名とフィールド名は変わりうるので詳細は書かない。残すのは**「キャッシュを含めた実単価で測る」**という原則と、カスタムコスト設定時の確認手順（両方のキャッシュ単価を明示する）だけにする。
