- **「中継するがマージンを取らない」は、収益源が別にあることの表明**である。価格表を読むときに「どこで儲けるつもりか」を探す習慣は、ベンダー選定の精度を上げる。無料・原価提供の箇所は、その会社が囲いたい場所の裏返しである。
- 上の一般形: **無料の機能は親切ではなく設計**。何が無料で何が有料かの境界線を見ると、その製品の戦略が読める。提案時に「なぜこれが無料なのか」を説明できると、信頼の質が変わる。
- **「マージン無し」と「安い」を混同しない**という読み分け。中継手数料がゼロでも、原価（パートナーのリスト価格）が高ければ総額は高い。**見積もりでは原価と手数料を分けて示す**と、顧客側で比較ができる。
- **自社が供給側に回るときに、自分が主張してきた基準を調達条件にする**という筋の通し方。Cloudflare は AI クローラー制御を推してきた立場で、検索パートナーに robots.txt 尊重を義務づけた。**言行一致はコストがかかるが、それ自体が差別化になる**実例として使える。
- **ソース帰属表示が「仕様として保証されている」ことの価値。** 出典付き回答は企業案件でほぼ必須だが、検索APIによっては帰属情報が取れず後付けで苦労する。**要件定義の段階で「出典を出せるか」をAPI選定基準に入れる**という手順の具体例。
- **ZDR の識別表示は、法務確認の工数を調達フェーズへ前倒しする仕組み**である。従来は各社ポリシーを個別に読んでいた。**「確認作業を誰のどの工程に置くか」の設計**として、他の領域にも転用できる。
- **BYOK の対象範囲は公式記述から読み取れない**という例。「既存組織向け」という書き方は、3社のキーに限るのか他社も通せるのかを決めていない。**曖昧な記述は実機確認の対象としてマークする**習慣が要る。
- **統合コスト（Workers Bindings で1行）は、個人開発では機能差より効く**。学習コストと保守コストが総所有コストの大半を占める規模では、「何ができるか」より「どれだけ早く動くか」が選定理由になる。
- **検索プロバイダーが3社に限定されている点は、現時点の制約として正直に伝える。** マルチベンダー前提の提案では、ロックインの度合いを先に説明しておくと、後の信頼を守れる。
