- **「サイトを AI に読ませる」設計の第3段階として位置づける。** HTML をそのまま読ませる、Markdown に変換して読ませる（Markdown for Agents）、検索 API を用意して必要な箇所だけ取らせる、という進み方を図にする。
- **発見の仕組みを分けて教える。** エージェントが機能の存在を知る方法（`meta` と front matter の自己申告）と、実際に使う方法（`/.well-known/search`）は別の話。「用意しただけでは使われない」点を押さえる。
- **返り値が生成回答ではない点を使う。** 検索結果を返す側と、回答を作る側（エージェント側のモデル）を分ける設計は、責任の所在を考える題材になる。
- **公開面の棚卸しを演習にする。** 検索対象にしたくないページを洗い出し、Bot 管理・AI Crawl Control・WAF のどれで絞るかを選ばせる。
- **個人活用の切り口は、サイト改善の小さな提案。** トグルの有効化より、公開範囲の整理と動作確認に価値がある、と伝える。
- 恒久教材へ反映する場合、**ベータの仕様・パス名・料金は書かない**（変わる）。残すのは「クロールより検索で渡す設計」「発見用の自己申告と実際の利用は別」「公開面は先に棚卸しする」の3点。
