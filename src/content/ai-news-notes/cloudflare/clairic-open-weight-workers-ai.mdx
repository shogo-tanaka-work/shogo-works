- **「何でも LLM に任せる」から「用途に合わせた小型モデルで置き換える」へ。** 公式の狙いは、高価な LLM の利用を、小さく速く安い専用モデルで補うこと。抽出のように**出力の型が決まっている処理**は置き換え候補になる、という判断基準を教える。
- **同じモデル ID の中身が変わる事例。** プレビュー時の `clairic`（9B）が、今後は 27B を指す。**ID を固定しているだけでは、挙動や価格が変わる**。モデルを指す名前が何を保証しているのかを確認する習慣の題材になる。
- **自社評価の読み方を演習にする。** 「1,263/1,263」のような満点に近い数字が並ぶが、公式が「公開された抽出ベンチマークはない」「参考値」と書いている。**評価セットの作成者と、比較相手の条件**を確認させる。そのうえで、自分のデータでの評価セットを作る手順につなげる。
- **確信度を使った人への振り分け。** 回答ごとに確信度が付くことで、「高い確信度は自動処理、低いものは人が確認」という運用を設計できる。閾値は実データで決める、という点を強調する。
- **「計算はコードで行う」という線引き。** プレビュー時の記事にある限界（長い算術は不安定）と合わせて扱う。モデルに任せる部分とコードに任せる部分の分担を、図にさせる。
- **オープンウェイト公開の意味。** 自社環境で動かせる選択肢が生まれるが、ライセンス・運用コスト・更新追随は別問題。**「公開されている」と「業務で使える」は別**という整理にする。
- **価格設計の比較。** 入力のみ課金、出力は無料という体系は、通常の LLM と比較しにくい。1件あたりの総コストで比べる方法を示す。
- 恒久教材へ反映する場合、**モデル名・価格・エンドポイント名は書かない**（変わる）。残すのは「出力の型が決まった処理は専用モデルが向く」「自社評価の数字は参考値として読む」「確信度で人に回す」「同じ ID でも中身が変わりうる」の4点。
