- **導入は「今は動いているから大丈夫」という思い込みから。** データは増える。**今日の結果サイズではなく、増えた後のサイズ**で考える習慣を付ける。
- **「切り詰め」と「失敗」の違いを説明する。** 超過時にエラーになる仕様は、気づきやすい反面、本番で突然止まる。**どちらの挙動かを先に確認する**ことを教える。
- **棚卸しの型として使う。** 「大きく返し得るクエリを洗い出す → 実測する → 分割や列の絞り込みに直す → 監視に加える」の4段階は、他の制限変更にも使い回せる。
- **全件取得の設計を見直す題材にする。** 画面は一覧と詳細に分け、書き出しは分割取得にする。**一度に全部取る設計は、制限に当たりやすい**。
- **告知から適用まで短い点も扱う。** 5日では顧客調整が間に合わない場合がある。**更新情報を購読し、期限の近いものから対処する**運用を促す。
- **受講者への問い**: 自分のシステムで、データが10倍になったら失敗する処理はどれか。失敗したとき、誰がどこで気づくか。
- 恒久教材へ反映する場合は、**数値（50MB）や日付を書かない**（変わる）。残すのは「制限変更は棚卸しで受ける」「全件取得は分割する」の2点。
