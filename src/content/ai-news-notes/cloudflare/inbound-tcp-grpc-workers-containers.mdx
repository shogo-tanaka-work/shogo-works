- **「Workers は HTTP のみ」という既存の説明が古くなる。** 教材やハンズオンで Workers を HTTP 専用として紹介している箇所は、Spectrum 経由で TCP も受けられる、と注記が必要になる。ただしベータ・プラン制限つきなので、本文を書き換えるより補足にとどめる。
- **3段構成（Worker → Durable Object → Container）を図で見せる。** 各層の役割（入口で受ける／状態と接続を持つ／アプリを動かす）を分けて説明すると、「なぜ Worker だけで完結しないのか」が伝わる。**Worker と DO は暗号化されたまま中継し、TLS は Container が終端する**点は誤解されやすい。
- **ベータと制限は必ず表にする。** 提供プラン、1ゾーン1ポート制限、Spectrum Enterprise の有無で何が変わるかを、受講者が自分の契約に当てはめられる形で整理させる。
- **公開ポートを開ける前のチェック演習。** 接続元の制限、認証、ログの置き場所を、HTTP の WAF が効かない前提で考えさせる。
- **個人活用の切り口は「音声・ストリーミングのデモ」。** 既存の gRPC サンプルを載せて動かす演習にできる。顧客向け本番には、ベータの仕様変更リスクと切り戻し手段をセットで教える。
- 恒久教材へ反映する場合、**ベータ状態・提供プラン・ポート数の制限は書かない**（変わる）。残すのは「Workers の入口は HTTP だけとは限らない」「多段構成では各層の責務とログを先に決める」「公開ポートは認証・接続元制限を自前で設計する」の3点。
