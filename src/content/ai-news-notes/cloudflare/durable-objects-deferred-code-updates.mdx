- **導入は「更新すると接続が切れた」経験から。** 状態を持つサービスでは、デプロイが利用者の体験を壊し得る。**中断を減らす既定の変更は歓迎できるが、新しい前提を生む**ことをセットで教える。
- **旧新コードの併存を、設計の演習にする。** 保存形式を変える更新を例に、旧コードが新形式を読めない場合に何が起きるかを考えさせる。**段階的に出す（読めるようにしてから書き換える）**考え方が中心。
- **「既定が変わった」ことへの感度を育てる。** 設定を触っていなくても、挙動が変わる。**更新情報を定期的に確認する理由**になる。
- **例外手段を知っておく。** 即時適用に戻す手段があること、いつ使うか（障害対応など）を示す。**使う条件を事前に決めておく**ほうがよい。
- **ベストエフォートの意味を説明する。** 「最大5分」は保証ではない。**保証がない前提で設計する**練習にする。
- **受講者への問い**: 自分のサービスで、旧コードと新コードが同時に動いたら壊れる箇所はどこか。それを事前に見つける手段はあるか。
- 恒久教材へ反映する場合は、**設定キー名や秒数を書かない**（変わる）。残すのは「デプロイ中は旧新コードが併存し得る」「互換期間を設けて段階的に出す」の2点。
