- **網羅性を上げた結果として検索機能が必要になった**、という因果を教材にできる。280コマンドなら `--help` で辿れる。3,000では辿れない。**機能を増やすと、探す手段を別に用意しなければ使われなくなる**。これは CLI に限らず、社内システムでも管理画面でも同じ構図。「作ったが誰も知らない機能」の一般化。
- **JSON が既定で、人間向け整形がその上に乗る**という順序の逆転が象徴的。**一次的な利用者を機械と想定した設計**。従来の CLI は人間向けに作り、機械向けに `--json` を足していた。**誰を一次利用者とするかで、デフォルト値が変わる**という設計論の実例。
- **手書きでは到達できない網羅性を、生成で得た**話。Forge が OpenAPI から生成している。**「全 API を CLI で覆う」は人力では割に合わないが、定義から生成すれば成立する**。自社 API を持つ組織への示唆として使える。定義（OpenAPI）を正本にしておくと、後から取れる選択肢が増える。
- **「置き換えではなく別ツール」という判断**を扱いたい。互換性を守りながら改善するか、互換を捨てて作り直すか。Cloudflare は後者を選び、**代わりに18か月の保守期限を約束した**。**破壊的な刷新を、移行期間の提示とセットで出す**のは、利用者への誠実さの標準形。
- **「18か月」に始点が書かれていない**点は、期限の読み方の教材になる。ベータ終了後から数える。**つまり今はまだカウントが始まっていない**。期限付き告知を読むとき、数字だけ見て逆算すると外す。始点の定義を確認する習慣。
- **統制の難しさが量から来ている**ことを示したい。280なら「許可するコマンドの一覧」を作れる。**3,000ではホワイトリストが維持できない**。だから統制の軸が「コマンドの許可」から「認証情報のスコープ」へ移らざるを得ない。**対象が増えると、統制の方法そのものを変えなければならない**という一般則。
- **便利さと危険が同じ性質から出ている**構図が明快。自然言語で探せる・JSON で読める・全 API を覆う——エージェントに任せやすい理由と、意図しない操作に到達しやすい理由が完全に同一。**「便利だが危険」ではなく「便利だから危険」**。トレードオフの説明として精度が高い。
- **個人開発の全権トークン問題**は耳が痛い話として使える。面倒だから全権で1つ作る。そこにエージェントを繋ぐ。**新しいツールを入れるタイミングは、放置していた権限設計を直す口実になる**という実践的な勧め方ができる。
