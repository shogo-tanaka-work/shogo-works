- 「Workers AI = Cloudflare のモデル、AI Gateway = 外部モデルのプロキシ」という従来の二分法で書かれた説明は、統合後は境界のない1つの入口として書き直せる。教材では旧構造を説明してから統合を示すより、最初から統合後の姿を提示する方が読者の負担が少ない。
- 移行コストが `env.AI.run()` の第3引数追加だけ、という点は教材の実演として最適。before / after のコード差分が2行で収まり、しかも追加すると可観測性が付くという分かりやすい利得がある。
- LLM を使うアプリのコスト管理を扱う教材の中核素材。「プロバイダごとに請求が分かれると全体像が見えなくなる」という問題は、規模を問わず発生する。クレジットのウォレットという仕組みは、上限を先に決めてから使い始める運用と相性が良い。
- 価格表が公開されていない点は必ず明記する。公式が言っているのは「レート上限が上がる」「クレジットを横断で使える」の2点だけで、「安くなる」とは書いていない。教材で節約効果を断定すると読者が請求で裏切られる。
- model-first routing / smart routing は未提供。教材では将来形として書き分け、これを前提にした設計を勧めない。パイロット段階の機能を前提に設計させるのは教材として無責任。
- モデル選定の柔軟性という切り口が、この統合の本質的な価値。「一度選んだモデルを惰性で使い続ける」状態が、契約・請求・可観測性の再設定コストによって生まれていた、という構造の説明は他の技術選定にも転用できる考え方。
- Agents Week（2026-08-03〜08-07）の一連の発表（MCP v2 / Kitesurf / AI Search / WebMCP / Agent Readiness / Precursor）の中に位置づけると、Cloudflare がエージェント向けプラットフォームをどう組み立てているかの全体像が示せる。個別記事の索引としても機能する。
- 演習化しやすい。Workers の無料枠で `env.AI.run()` を書き、第3引数の有無で可観測性ダッシュボードの表示がどう変わるかを確認させる形が組める。
