- **セキュリティ教材の「賢さで防ぐな、構造で塞げ」という原則の実例として使う。** プロンプトで指示する / ツール呼び出しを制限する / URL を検証する、はいずれも**エージェントの判断と実装の正しさに依存する。** guardrails は依存の位置を実行環境へ移す。**プロンプトインジェクションが成立する理由の説明とセットで教える**と一気に通る。
- **「通信先はエージェントの判断だけで決まらない」という点を最初に示す。** 訪問先のページが外部リソースを呼ぶので、エージェントが意図しない通信が出る。**受講者はここを見落とす。** ブラウザが「何でも読み込める実行環境」であるという性質から説明する。
- **PDF / 帳票生成の例が最も刺さる。** HTML テンプレートに CDN フォントや外部画像が入っているのは珍しくない。**生成処理のつもりが外部通信を伴う処理になっている**という気づきは、受講者が自分の環境で即確認できる。**演習: 自分のテンプレートの外部参照を数えさせる。**
- **ワイルドカードの危険性を必ず扱う。** `*.example.com` はサブドメインテイクオーバーで穴になる。**便利な設定ほど範囲が広い**という一般則の実例。自社管理下に限定できるなら完全一致を並べるほうが安全、という判断軸を教える。
- **「ワークフローごとに許可リストを分ける」という設計判断を演習にする。** 全ワークフローで共通リストにすると最も広い要件に合わせた設定になり、絞る意味が消える。**最小権限は粒度の話である**という原則へ接続。今回の更新自体が「セッション単位 → ホスト単位」への粒度の細分化なので、題材と原則が一致している。
- **Live View の読み取り専用モードは、権限設計の教材として独立して使える。** 「見せるために共有した URL が操作権限も渡していた」という状態は、**閲覧と操作を分けていない設計の典型**。社外・別部門への共有、監査対応の文脈で説明する。
- **副業・受託向けには「聞かれる質問への回答」として教える。** 「暴走しないのか」「漏れないのか」に対し、**実行環境で許可リストに限定すると答えられるかどうか**で提案の説得力が変わる。デモ・検収での読み取り専用 Live View の使い方も具体的に示す。
- **changelog に書かれていないことを「制限なし」と読まない**という情報の読み方も教える。プラン条件・上限の記載がないだけで、無いとは書かれていない。**一次情報の読み方の演習**として小さく置ける。
- 恒久教材へ反映する場合、**Puppeteer の具体的なコードと Cloudflare 固有の製品名は書かない。** 残すのは「エージェントの通信制御は実行環境側に置く」「許可リストの粒度はワークフロー単位まで下げる」「閲覧と操作は分けて共有する」の3点。**他ベンダーのサンドボックスにも同じ構造が来る**ため、汎用の章として書ける。
