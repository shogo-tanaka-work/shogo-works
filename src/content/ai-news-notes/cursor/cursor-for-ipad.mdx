- 「エージェント前提の開発ではボトルネックが実装からレビューへ移る」という論点の実例。手元の実行環境の性能より、投げた結果を確認する導線の方が全体のスループットを決めるという説明に使える。
- レビュアーが少数に集中しているチームでの効果（待ち時間の削減がそのまま全体速度になる）は、開発プロセスの教材で具体的に扱える。
- 「モバイルで承認していいのはどの規模の変更までか」というチームルールの必要性は、AI ツール導入で必ず出てくる「便利さと品質のトレードオフ」の実例。
- Bitbucket / Azure DevOps 対応は、ツール選定の前提条件として「ホスティング先の対応可否」を先に確認するという教材の実例。日本のエンタープライズで Azure DevOps 利用が一定数ある点に触れる。
- Inbox は「並列でタスクを投げると管理コストが発生する」というエージェント運用の構造的課題への回答。複数エージェント運用の教材で参照できる。
- Cursor は `src/content.config.ts` の tool enum に含まれるため記事化可能。ただし Knowledge 側に Cursor 教材が未整備なので relatedKnowledge は空配列。
