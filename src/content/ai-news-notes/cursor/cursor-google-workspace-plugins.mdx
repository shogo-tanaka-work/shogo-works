- 「コーディングエージェントの権限範囲が業務データへ広がる」という論点は、Cursor 固有ではなく Claude Code の MCP コネクタや Codex のプラグインにも共通する。ツール横断で使える教材テーマとして扱えるので、Cursor 単体の機能紹介では終わらせない。
- 教材化するなら、機能一覧より「導入判断のチェックリスト」の形が有効。権限スコープ（send まで含むか）、監査ログの取得可否、アカウント分離、Workspace 管理コンソール側の制御、の4点を軸にする。
- 公式 changelog に管理者向け制御の記載がない点は、そのまま教材の材料になる。「ベンダーが制御を提供していない場合、組織側で何を設計する必要があるか」を考えさせる演習にしやすい。
- 副業・フリーランス向けには、複数クライアントのアカウント分離が実務上いちばん効く注意点。契約上の守秘義務と技術構成が直結する例として使える。
- 検証してログ化する余地あり。read 系のみ有効化した状態での挙動と、send / create 系を含めた場合の差分を実測すると、`ai-verification-log` 形式の記録として残せる。
