- **「エージェントの待ち時間はどこで生まれるか」を分解する教材の材料になる。**モデルの推論時間だけを見ていると、実際の体感を説明できない。環境構築・依存解決・初回トークンまでの時間を分けて示すと、改善の打ち手が変わることを教えられる。
- **温かいコピーを維持する設計**は、コンテナやサーバーレスの warm start と同じ発想である。エージェント固有の話にせず、一般的な起動コスト削減パターンの一例として整理すると応用が効く。
- **失敗した build を有効化しない**という設計は、デプロイのグリーン／ブルーやヘルスチェック付きロールアウトと同型。ハーネスエンジニアリング教材で、**エージェントの実行環境もデプロイ対象として扱う**という論点に接続できる。
- 「最後に成功した build で走り続ける」挙動は、利点と落とし穴を両方教える。壊れたコミットで止まらないのは利点だが、**古い環境で走り続けていることに気づかない**リスクがある。Builds タブでどの build が使われたか確認できる点をセットで説明する。
- **エージェント出力の不安定さを切り分ける**という文脈で使える。原因がモデルなのか環境なのか分からないという相談は多い。build の記録が残ることで環境側は追えるようになる、という具体例。
- 既存環境の有効化に設定変更の確認が要る点は、**移行手順を扱う教材の実例**になる。「新規は自動、既存は手動」というパターンは他ツールでも頻出する。
- 10倍・3倍という数字は公式の自己申告であり、測定条件は開示されていない。教材で引用するなら条件不明である旨を添え、**依存関係の重さで恩恵が変わる**という補足を入れる。
