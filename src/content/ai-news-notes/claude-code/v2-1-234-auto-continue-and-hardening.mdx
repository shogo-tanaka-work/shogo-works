- **「制約が安全弁として働いていた」という論点**が、この版の教材価値の中心。利用上限で止まる挙動は不便だったが、同時に夜間タスクの暴走やコスト超過を実質的に止めていた。自動継続が既定 on になると、その副次的な安全弁が外れる。**不便さを取り除いたら、それが担っていた別の役割も消える**という一般則の実例として使える。
- 既定 on で `/config` から off にできる形なので、「戻せるスイッチ付きで既定を変える」パターンの再例でもある。v2.1.233 の `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` と並べると、**破壊的変更の出し方**として一貫した設計思想が見える。
- **セキュリティ修正は複数バージョンにまたがる**、が最重要の教材ポイント。v2.1.233 で NTLM 認証情報の漏洩ベクトルを「塞いだ」と告知されたが、リモートファイル読み取り・セッション復元・CLAUDE.md の include・workflow スクリプト・ファイルアップロードの経路は開いたままで、v2.1.234 で閉じた。**「修正済み」は脆弱性クラスが全経路で閉じたことを意味しない**。リリースノートの読み方を教える教材の中核に据えられる。
- **MCP 診断のシークレット表示は、ログ運用の教材になる**。診断出力は共有されやすい（サポートへ送る、チャットに貼る）。そこに解決済みの値が出ていれば漏れる。**秘密値は解決前の `${VAR}` 形式で表示する**という設計原則を、実際のバグと修正で示せる。
- **マスキングは強すぎても機能を壊す**、という対の論点も同じ版にある。権限プレビューのマスキングが承認者からコマンド・パス・宛先を隠していた。隠したら承認が形骸化する。**セキュリティ機構は強度ではなく適切さで評価する**という話につながる。
- **`claude-api` skill の約200k+→約25kトークン削減**は、コンテキスト管理を教える具体的な数字として使える。「参照ドキュメントを必要時に読む」という遅延読み込みの設計で8分の1になった。**skill やツール定義がコンテキストを占める量を意識する**という運用観点の実例。
- GitLab 対応は v2.1.232（プラグインマーケットプレイス）→ v2.1.233（`--worktree` と agents ビューの MR URL）→ v2.1.234（フッター/ステータスラインの MR バッジ）で3版にまたがる。**バージョン単位ではなく機能単位で追う読み方**の実例として、v2.1.233 のメモから継続して使える。
