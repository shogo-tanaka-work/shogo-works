- **今週最大の教材は 2.1.259 → 2.1.260 の revert である。** `Read()` の deny ルールを Bash 引数へ広げた結果、`Read(./**/build/**)` を設定していた環境で **`npm run build` が全モードで拒否された**。セキュリティ強化が日常業務を止め、**1日で撤回された**。「厳しくすれば安全」という直感に対する反例として、これ以上ないほど具体的である。**誤検知のコストを見積もらない安全強化は、運用側から拒否される**——この一件で説明できる。
- **併せて教えるべきは「変更を可逆に保つ設計」**。1日で戻せたのは、変更が独立していて切り離せたからである。**セキュリティ強化をまとめて入れると、1つ壊れたときに全部戻すことになる。** 変更の粒度と可逆性はセットで設計する。
- **「権限ルールを書いたこと」と「効いていること」は別**（2.1.260）。括弧を含むパスというごく普通の記法でルールが無効として捨てられ、**読み取り専用のはずのフォルダが書き込み可能だった。** さらに閉じていない `[` が1つあるだけで全ファイル編集が失敗していた。**設定が silently 無効化される**のがいちばん危ない失敗の形である。教材としては、**権限ルールは書きっぱなしにせず、実際に拒否されるかを試す**という運用習慣まで落とす。
- **zsh の変数代入にコマンド置換を隠すと自動承認されていた**（2.1.260、`REPORTTIME` / `REPORTMEMORY` / `DIRSTACKSIZE`）。**シェルの構文解釈の差がそのままセキュリティ境界の穴になる**という具体例。bash と zsh でパースが違うという前提を持っていないと防げない。前週の TOCTOU（シンボリックリンク）と並べると、**「入力を正規化しきる前に権限判定してしまう」**という同じ原則違反の別バリエーションとして整理できる。
- **`allowedMcpServers` の意味変更**（2.1.259）は、**設定名から挙動が推測できなくなる**典型例。許可リストの対象が「ユーザーが自分で追加したサーバーだけ」に変わった。**許可リストの対象範囲を明示しない設定名は誤解を生む**という設計上の教訓であり、同時に**既存設定の意味が更新で変わりうる**という運用上の教訓でもある。managed settings を配っている組織向けの棚卸し手順の題材になる。
- **Containment Escape**（2.1.257、クラウドメタデータ資格情報を自動承認から除外）は、**エージェントが動く「場所」自体が権限境界になる**という話。ローカルで安全な設定が、クラウドに載せた瞬間に危険になる。**実行環境を移すときは権限設計をやり直す**という原則の実例。
- **管理設定がパース不能なら起動を拒否する**（2.1.259）というフェイルセーフの選択。壊れた設定で無防備に動くより止まる。設定配布の仕組み全般に転用できる。**「壊れたときにどちらへ倒すか」を決めておく**のが設計であり、決めていないと必ず緩い側へ倒れる。
- **フィーチャーフラグが旧バージョンにも適用されていた**（2.1.261 で修正）。バージョンを固定して安定を得ているつもりの環境に、**サーバー側のフラグ経由で挙動変更が入っていた**ことになる。**「バージョンを固定すれば挙動が固定される」は成り立たない**——SaaS 型ツールの再現性を議論するときの重要な反例。
- **既定モデルが Fable 5.1 に変わった**（2.1.257）。モデル公開とクライアント既定値の切り替えが同日である。**明示的に固定していない限り、既定値の変更は自動で降ってくる。** 同週の Codex 0.153.4（既定が Astra へ）と並べると、**「モデルを設定ファイルで固定する」という運用指針**を2つの実例で裏づけられる。
- **`CLAUDE_CODE_SUBAGENT_MODEL_FORCE`**（2.1.258）はコスト統制の話。サブエージェントが高価なモデルで走ると、親の指定だけ見ていては費用が読めない。**どのプロセスがどのモデルを使うかを明示的に固定できることが、予算統制の前提**である。
- **プロンプトキャッシュのミス理由の可視化**（2.1.260）は、コスト最適化を精神論から計測可能な作業へ移す。**ツール定義やシステムプロンプトの変更がキャッシュミスの原因になる**という点は、エージェント設計の実務知識としても効く。動的にツール定義を組み立てる設計は、それだけでキャッシュを壊しうる。
- **`/skill-doctor`**（2.1.261）は「Skill を作りっぱなしにしない」運用の入口。棚卸しコマンドとして紹介できる。**`bashOutputMaxChars` / `taskOutputMaxChars`** は、長い出力でコンテキストを食い潰す事故への対処。**同じ週の Codex 0.152.0 が MCP ツール単位の出力上限を入れており**、両ツールが同時期に同じ問題へ対処している。**コンテキストは共有資源であり、上限管理が必要になる段階に来た**という読み方ができる。
- **macOS 12 の起動不能が 2.1.255〜2.1.257 の3版にわたって残った**（2.1.258 で修正）。日次リリース型ツールの現実的なリスク——**最新へ自動更新する運用は、回帰を最短で踏む運用でもある。** 一方で修正も速い。どちらを取るかは業務の停止許容度で決める、という判断枠組みの題材。
- **2.1.263 は CHANGELOG が1行のみ**（「バグ修正と信頼性の改善」）。**版が進んだ事実は追えるが、中身は追えない。** これを「更新なし」と混同しないことが記録運用上重要である。同週の n8n 2.38.2 / 2.37.7 / 2.37.10 も同じ状態で、**リリース型ツールの追跡では珍しくない。**
