- **非推奨エイリアスの扱いを教える良い教材**。`--remote` は動く。動くから放置される。**「動いているが非推奨」が最も忘れられやすい状態**で、外れた瞬間に CI が落ちる。棚卸しのトリガーを「壊れたとき」ではなく「非推奨と告知されたとき」に置く、という習慣づけに使える。
- **`--cloud` と `--remote-control` の紛らわしさ**は、そのまま命名の教材になる。片方はクラウドで動かす、片方はローカルを遠隔操作する。**逆の意味に近いのに名前が似ている**。公式が注記を入れざるを得なかった事実そのものが、命名レビューの必要性の証拠。
- **「クラウドで動かすと別料金」という誤解が実際に起きた**点を見せたい。Anthropic が4時間半後に補足を出している。**発表側が意図した内容と、受け手が読んだ内容がずれた実例**として具体的。リリースノートを書く側の教材にもなる。
- **セキュリティ設定を固めた組織ほど使えない**、という逆説を扱う。Zero Data Retention 有効なら利用不可、IP allowlisting 有効なら全セッション認証エラー。**「安全側に倒した設定」と「新機能の利用可否」が衝突する**のは実務で頻出する構図で、情シスと事業側の調整が要る典型例。先に握る、という段取りの話に繋げられる。
- **クレジットの出所が公式ドキュメントではなく公式 X 投稿である**点を明示したのは意図的。**同じ「公式」でも、ドキュメントと SNS では参照の安定性が違う**。後から確認できるか、改訂履歴が残るか。一次情報の質を段階で見る練習。
- **期限管理そのものを教材にする**。請求 10-07、失効 11-04。**「請求は無料なので先にやる、使い道は後で考える」が正解になる場面**がある。意思決定を先送りせず、選択肢だけ確保しておく判断。逆に「使い道が決まってから」は期限のある話では負ける。
- **クレジット対象が個人 Pro / Max のみ**という点は、案内ミスが起きやすい箇所。**「会社アカウントでも請求できるはず」と伝えると外す**。対象範囲を確認せずに社内展開する失敗として具体的。
- **research preview から GA への昇格が稟議に効く**、という組織の現実。機能は前から使えたのに、ラベルが変わるまで通らない。**技術的成熟度とラベルは別物だが、ラベルが意思決定を動かす**。この非対称性を理解しておくと、導入提案のタイミングを選べる。self-hosted 側が public beta のままである点とセットで示す。
