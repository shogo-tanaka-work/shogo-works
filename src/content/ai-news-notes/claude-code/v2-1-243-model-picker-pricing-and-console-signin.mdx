- **「画面に出ていた金額は定価だった」**という事実は、AI コスト管理の教材の入口として強い。`modelPricing` が追加されたということは、それ以前は契約単価が反映されていなかったということである。ツールが出す数字を無条件に信じない、という一般則を、具体例つきで教えられる。
- **設定を入れた日付を記録しないと時系列が壊れる**、という論点は、コスト可視化の教材で必ず扱う価値がある。定価から契約実勢に切り替われば、使用量が変わっていなくても金額は下がる。「数字が動いたら、まず計測方法が変わっていないかを疑う」は、AI に限らない分析の基本動作として提示できる。
- **`modelPicker` は「モデル統制をお願いから設定へ移す」実例**である。ハーネスエンジニアリングの「ガードレール層」を説明するとき、ルール文書で縛るのと設定で縛るのは別物だという話をするが、その具体例がまた1つ増えた。CLAUDE.md に「このモデルを使うこと」と書くのと、`/model` の選択肢自体を定義するのとの差を並べると伝わりやすい。
- **`Skipped sources` の追加は「配ったつもりの設定が効いていない」問題への公式の回答**として読める。managed settings を配る運用は、配布より検証のほうが難しい。設定を入れる手順と、効いているか確認する手順をセットで教えないと現場では機能しない、という教訓の裏付けに使える。
- **プロンプトキャッシュ TTL の分離は、「設定できる＝設定すべき」ではない**ことを教える題材になる。メイン1時間・サブエージェント5分という公式の例は妥当だが、自分の中断パターンを測らずに真似しても効果は出ない。計測してから調整する、という順序を守らせる訓練に使える。
- **鍵レスサインインは、導入障壁が技術ではなく運用方針であるケースの実例**。API キー禁止という方針は妥当な判断であり、それを崩さずに導入できる経路ができた。研修で「AI 導入が進まない理由」を扱うとき、技術的制約と組織方針を切り分ける題材として提示できる。あわせて「論点が消えるのではなく、コンソールアカウント管理へ移るだけ」という点も一緒に教えると、安易な万能薬扱いを防げる。
- **`/usage` の Loops 内訳は「回数ではなく1回あたりを見る」という分析視点の教材**になる。総トークンだけ見ていると、回数が多いループと1回が重いループを区別できない。設計が雑なのはたいてい後者である。この見方は AI 以外のコスト分析にもそのまま転用できる。
- **非対話 / SDK セッションで MCP が切断後に復帰しなかった不具合**は、無人実行の落とし穴の実例として使える。人が見ているセッションなら気づくが、無人実行では沈黙したまま壊れる。ハーネス設計で「失敗を失敗として報告させる」ことの重要性を、実際の不具合として提示できる。
