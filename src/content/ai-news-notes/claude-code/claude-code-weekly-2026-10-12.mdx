- **今週いちばん強い教材は、「権限の確認そのものが迂回されていた」事例が3版にまたがって出たこと**（2.1.292 / 2.1.294 / 2.1.295）。**前週（2.1.284 / 2.1.289）は「ルールの判定がコマンドの書き方ですり抜けた」型だったが、今週はもう一段内側である。** 2.1.292 は**承認を求めるプロンプト自体が出なかった**、2.1.294 は**指示文で書いた hook が判定を誤った**、2.1.295 は**権限 hook をすり抜けたツール呼び出しがあった**。**ガードレールを足すほど安全になるのではなく、ガードレール自体が検証対象になる**という主張を、2週で合計7件の公式修正で裏づけられる。
- **「自然言語で書いた制御は、解釈の精度に依存する」が2.1.294 で公式の修正として確定した。** 同じ hook の記述が、バージョンによってブロックする / しないに分かれた。**決定的に止めたい操作は、指示文ではなくコマンドやパターンで書く**という設計判断の根拠にできる。あわせて**「hook を入れたら、ブロックされるはずの操作を実際に試す」テスト工程**を導入手順に入れる動機になる。
- **hook の fail-closed 設定（2.1.295）は、「落ちたときどちらに倒すか」を教える最良の粒度である。** hook が起動に失敗・タイムアウト・想定外の終了コードを返したとき、操作を通す（可用性優先）か止める（安全性優先）か。**この分岐が設定として選べるようになったこと自体**が教材になる。**同じ週に GitHub Copilot の local sandboxing が GA になり、enterprise 側で強制でき開発者が弱められない形で出ている。** 「エージェントの実行を落とす側の仕組み」がベンダー横断で同時に整備されている構図が示せる。
- **Shift-JIS 編集の拒否（2.1.296）は、日本語環境向け教材で必ず触れる価値がある。** 従来は**非 ASCII 文字を置き換えてファイルを壊していた**。「エージェントにファイルを編集させる前に文字エンコーディングを確認する」という運用上の注意が、公式の修正として裏づけられた。**国内の既存システム（Shift-JIS の CSV、レガシーな設定ファイル）を触らせる案件では、事前の変換か対象外指定が必要**という結論まで一息でつながる。
- **`BASH_ARGV0` 経由の自動承認（2.1.296）は、許可リスト方式の限界を示す実例として前週の4件に続く。** 変数経由の間接参照で権限チェックが開く。**前週の「複合コマンドの入れ子」「環境変数の前置」「裸の変数代入」と並べると4種類**になり、**「シェルの表現力が権限チェックの敵になる」**という一般化ができる。
- **既定値の変更が4週連続で出ている**（今週は 2.1.293 の既定 Haiku → Haiku 5.5、前週は auto mode の全プラン既定化と既定 Sonnet の 5.5 化）。**既定値の変更は変更履歴の中で扱いを別にする**という原則を、連続した実例で裏づけられる。今回はさらに**トークナイザが違うため消費量の見え方が変わる**という計測側の影響がある。**AI ツールの利用量を経営に報告している組織は、モデル切替日を基準日として記録する**という運用に落ちる。
- **同じ週に GitHub Copilot 側で「IDE 更新をしないと利用メトリクスから agent 活動が落ち、遡及補填されない」という告知が出た。** Claude Code の既定モデル切替と並べると、**AI ツールの利用量の数字は、ツール側の変更で簡単に断絶する**という話になる。**計測系の変更履歴そのものを記録する**という結論は、片方だけでは弱いが2件並べると説得力が出る。
- **サブエージェント単位の `autoCompactWindow`（2.1.296）と Agent tool の `effort`（2.1.292）は、委譲の設計を扱う章にまとめて置ける。** サブエージェントは短命で文脈も小さいため、メイン会話と同じ閾値・同じ推論量にする必要がない。**「調査は軽く、実装は重く」という配分をツールの設定として書ける**ようになった。
