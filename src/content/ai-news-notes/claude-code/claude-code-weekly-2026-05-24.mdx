- **コマンド改名は、教材を持つ側にとって最も面倒な変更**である。`/simplify` → `/code-review` は、スクリーンショット・手順書・動画すべてに波及する。**教材の保守コストは機能追加より改名で発生する**という運用実感を伝えられる。
- **改名と同時に中身が入れ替わった**点が重要。名前が同じでも挙動が違う、名前が変わって挙動も変わる、の2パターンを区別して確認する習慣を教えられる。旧挙動（整理・修正）が削除されたことに気づかないと、期待した動作が返ってこない。
- **Bash 裸変数代入での権限プロンプトバイパス**は、「許可ルールは文字列マッチであり、意味の理解ではない」ことの実例。権限設計の限界を具体的に示せる。
- **`/usage` の内訳化**は、コスト管理を「総額を見る」から「どこが食っているかを見る」へ進める話。スキル・サブエージェント・MCP のどれが重いかを測れると、削減が推測ではなく作業になる。
- **2.1.147 のリグレッション（exit code 127）と 2.1.148 での修正**は、最新版に飛びつくリスクの実例。1つ待つ、という判断の根拠に使える。
