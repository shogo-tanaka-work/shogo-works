- 「承認ダイアログの表示と実行内容が食い違いうる」は、権限承認を人の確認に頼る運用の限界を示す最良の教材例。Claude Code の権限設定を教える節で、「承認は万能ではない」「更新の追従自体が統制の一部」という前提として扱う。
- `bypassPermissions` が組織ポリシーを迂回できていた件は、「ポリシーを設定した」と「ポリシーが効いている」の差の実例。企業導入編で、設定後の検証手順を必ず入れる根拠として使える。
- マーケットプレイスの `owner/*` ワイルドカードは、「ポリシーは単純なほど守られる」という運用原則の具体例。個別列挙が破綻する理由まで含めて教材化すると、他ツールの許可リスト設計にも転用できる。
- `/review` → `/code-review` 統合は、手順書のコマンド表記を更新する必要がある変更。教材やレッスン内のコマンド表記に `/review` が残っていないか、版更新時にチェックする対象として記録しておく。
- 同日に Codex 側でも cyber 対応モデルの自動レビュー既定値が安全側へ変更されている（rust-v0.146.1）。「モデルの能力が上がると既定の安全設定を締める」というベンダー横断の傾向として、並べて示すと理解が立体的になる。
