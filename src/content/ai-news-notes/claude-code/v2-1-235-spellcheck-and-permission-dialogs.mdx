- **権限ダイアログの2件は、権限まわりの教材を書くときの実例として強い**。「表示と実際の付与範囲がずれる」「全容を表示できないのに恒久許可を出せる」は、UI 設計の不備がそのままセキュリティ問題になる典型。抽象的な最小権限の説明より、この2件を出す方が伝わる。
- **Shift+Tab の不具合は、操作ミスと権限付与が地続きになる例**。エージェント運用の教材で「承認 UI は誤操作を前提に設計する必要がある」を説明する材料になる。
- `spellcheck` は**ローカル辞書で完結する設計**が要点。入力内容を外部へ出さない前提の組織でも使える、という説明ができる。機能そのものより「なぜローカル辞書なのか」の方が教材価値が高い。
- v2.1.233 → 234 → 235 と3日連続でリリースが続いている。**教材では版ごとに追わず、権限まわり・パフォーマンス・UI という軸でまとめる方が陳腐化しにくい**。
- 業務インパクトは中程度。既存教材の前提を変える変更ではないため、Knowledge への反映はしていない。
