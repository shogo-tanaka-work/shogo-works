- **今週の4件は「権限チェックの入口が複数ある」ことの帰結である。** 環境変数の前置き、`sed`、worktree 作成、`/rewind` の symlink。**共通点は、どれも素直な「ツール呼び出し」の形を取っていない経路**にある。環境変数の前置きはコマンド文字列の構文の問題、`sed` は編集系ツールとして扱われていなかった問題、worktree と `/rewind` はファイルシステム操作の副作用。**権限チェックを「ツール名で引く」設計にすると、ツール名を経由しない操作が漏れる。** ガードレール設計を教えるときの中心教材になる。
- **「細工した環境変数の前置きでコマンドの一部を隠す」は、パーサーの前段で起きる攻撃の典型である。** 変数代入を先頭に並べた形にすると、**権限チェックが見る文字列と shell が実際に実行する文字列がずれる。** 検査対象と実行対象が同じ文字列でなければ、検査は意味を持たない。SQL インジェクションや shell インジェクションと同じ構造で、**「検査してから渡す」ではなく「検査した物をそのまま渡す」**という原則の実例として説明できる。
- **`sed` の抜け穴は、ツールの分類が実際の作用と合っていなかった例である。** `sed` は読み取りにも書き込みにも使える。`sed -n '1,10p'` は読み取りだが、インプレース編集のオプションを付ければ破壊的編集になる。**同じコマンド名が、オプションによって権限クラスを変える。** 前週からの `timeout DURATION` でラップした読み取り専用コマンドへの不要なプロンプト（2.1.319 で修正）と合わせると、**コマンド名による分類は両方向に誤る**（止めるべきを通し、通すべきを止める）ことが見える。
- **4週連続で「境界の漏れ」系列が続いている。** 10月第3週の起動ファイル、第4週の symlink と設定ファイル、前週の `--restricted` × Read 許可ルール、そして今週の4件。**「1件直したから安全」と言えない**という前週メモの指摘が、さらに強化された。**ガードレールの不具合は、同じ機構の別条件で繰り返し出る。** フックや権限レイヤーのテストに「正常系で止まる」ではなく「あらゆる入力形で止まる」を要求する根拠として使える。
- **`permissions.denyInsteadOfPrompting` は、無人実行での設計選択を明示した設定である。** 権限プロンプトで待つはずの呼び出しを**拒否してターンを続ける。** 無人実行では「待つ」は事実上のハングなので、**待つ代わりに拒否して進む**という選択肢を設定として与えた。CI やバッチでエージェントを回すときの設計パターンとして、`allow` / `ask` / `deny` の3値に「ask を deny に倒す」第4の運用が加わったと整理できる。
- **`claude -p` の終了コード変更は、CI を持つ組織に直接効く。** auto mode で拒否されたのに exit 0 を返していた。**「何もできなかった」が「成功」として CI を通っていた**ことになる。fail-open の一種で、**終了コードは最も安いガードレール**である。自動化を組むときに「失敗が失敗として伝わるか」を確認させる題材として素直。前週の PowerShell フックの exit code 2 の件と同じ系列である。
- **`--trust-workspace false` がフックと skills も止めるようになった点は、信頼境界の定義の話である。** リポジトリをクローンしただけで、そのリポジトリの設定ファイルにあるフックが走る。**「コードを読む」と「コードを実行する」の境界が、設定ファイル経由で曖昧になる。** self-hosted runner で外部リポジトリを扱う場合に直結する。CI の `pull_request` と `pull_request_target` の違いと同じ問題圏で、並べて説明できる。
- **資格情報の失効通知（`loginExpiresAt`、10日前からの警告）は、運用の失敗モードを先に潰す設計である。** 無人実行は、**失効した瞬間に理由不明で止まる**のがいちばん困る。10日前から警告を出せば、止まる前に気づける。**「壊れてから知る」から「壊れる前に知る」への移行**で、証明書やトークンの期限監視を教えるときの実例になる。失効後に別のサインインへ流れて**課金先の組織が変わる**警告も入った点は、フォールバックが静かに別の結果を生む例として、同じ週の xAI の `grok-imagine-image-quality` 退役（`low` 設定へ振り替え）と並べられる。
- **今週は3つの退役・変更の型が同時に出ている。** ①Claude Code の Opus 4.8 fast mode（11-30）は**止まる**。②GitHub Copilot の3モデル廃止（11-16）は**代替が自動で有効になる**。③xAI の `grok-imagine-image-quality`（11-02 発効）は**自動で流れるが品質設定が下位へ変わる**。**退役告知は「止まるか / 自動で流れるか / 流れた先が同等か」の3段で読む。** 3段目で落ちる③がいちばん気づきにくい。モデル退役の棚卸しを教える回の中心に置ける対比である。
- **cost report API と IdP グループ別の集計は、AI 支出の配賦が実務課題になったことの表れである。** `assume_role` による別 AWS アカウントのロールと開発者単位のコスト配賦、プール予算の引き当て順（`admin.pooled_conflict_rule`）まで来ている。**「誰がいくら使ったか」から「どの部門の予算から引くか」へ**論点が移った。同じ週の GitHub Copilot の BYOK 分離（自前キー・ローカルモデルを Copilot ホスト分と切り分け）と合わせると、**AI コストの可視化は各ベンダーで同時に細分化が進んでいる。**
- **最小限の Knowledge 反映案**: 既定スキップのままでよい。ただし Claude Code を CI / 無人実行で使う手順を扱う教材があれば、**`claude -p` が auto mode の拒否で exit 1 を返すようになった**ことと、**LLM ゲートウェイ配下では `CLAUDE_CODE_AUTO_MODE_SERVER` の設定が要る**ことの2点を注記する価値がある。モデル退役を扱う箇所には、**Opus 4.8 fast mode が 2026-11-30 に削除され、通常の Opus 4.8 へフォールバックしない**ことを引き続き記す。
