- **同じ形の欠陥が1リリースで3か所直った**という事実が、この週の最大の教材価値。ファイルツール、Grep/Glob の deny ルール、プラグインコマンドのパス。**「権限チェックした対象」と「実際に操作する対象」が同一であることを保証していない**という一つの原則違反が、実装箇所ごとに再発している。TOCTOU を抽象論ではなく、同一製品の同一リリースの修正リストで説明できる。
- **シンボリックリンクは「作業ディレクトリ内」という境界を無効化する**。パスの文字列で境界を判定する設計は、リンクを辿った先まで見ないと破れる。ファイアウォールの宛先判定や、アップロード先のパス検証でも同じ構造の欠陥が出る。分野をまたいで転用できる。
- **修正されても送信済みの事実は消えない**（2.1.248 の資格情報アップロード）。インシデント対応の思考として、「直った」と「影響が無くなった」は別だと教える題材。パッチ適用で完了とせず、**露出期間に何が出たかを数える**ところまでが対応である。
- **`--restricted` が「設定ファイルをすべて無視する」点が設計として面白い**。制限モードを設定で表現すると、設定を書き換えられる者が制限を外せる。**制限の強度は、それを解除できる人の範囲で決まる**という原則の実装例。CI 用の実行プロファイルを設計するときの参考になる。
- **危険な管理設定にだけ承認を要求する**（TLS 終端・プロキシ・資格情報注入・サンドボックス弱体化）という中間解。全部承認にすると形骸化し、全部素通しにすると危ない。**承認の対象をどう線引きするか**を、実在の分類で議論できる。
- **`/cost` のプロンプトキャッシュ行（ヒット率・ミス・再キャッシュ・warm/cold）**は、コスト最適化の授業でそのまま使える。効果を測る手段が製品側に用意されたことで、「キャッシュを効かせる」が精神論から計測可能な作業になった。
- **seat 型 Enterprise の既定モデルが Opus 5 になった**点は、コスト前提の変更として管理者に効く。既定値の変更は、誰も操作しなくても請求が変わる類の更新である。
- **auto-compact 窓の 934K → 967K**（Sonnet 5 の 1M 窓）は、安全余裕をどこに取るかの話。使い切る側へ倒すと文脈は保たれるが、圧縮失敗の余地は狭まる。設定値の背後にあるトレードオフを読む練習題材。
