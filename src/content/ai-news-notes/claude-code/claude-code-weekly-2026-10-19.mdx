- **今週の中心は「ルールの書き方ではなく、ルールの照合が外れていた」事例である**（2.1.299 の MCP deny / ask）。**正規化後のサーバー名に二重アンダースコアが含まれると、ルールが適用されなかった。** 前週の7件（2.1.292 / 294 / 295）は「迂回」「解釈のずれ」「すり抜け」だったが、**今週は文字列の正規化という実装の内側の話である。** 3週分を並べると、**ガードレールが効かない理由は「書き方」「解釈」「照合」の3層に分かれる**という整理ができる。受講者に「自分の deny ルールはどの層で壊れうるか」を考えさせられる。
- **「読み取り専用のつもりの mode が書いていた」は、mode 設計の教材に向く**（2.1.299 の plan mode）。**フックが許可した書き込みを plan mode が実行していた。** つまり**2つの制御が重なったとき、どちらが勝つかが決まっていなかった。** 権限設計の演習では「許可の論理和か、禁止の論理積か」を先に決める、という結論まで一息でつながる。
- **拒否されたログインがトークンを残す（2.1.300 の `forceLoginOrgUUID`）は、「失敗パスの後片付け」の実例である。** 成功時の処理は書かれるが、**拒否時に書いたものを消す処理は抜けやすい。** 自作のツールでも同じ構造が出るため、「エラーハンドリングは戻り値を返すだけでは終わらない」という一般論へ展開できる。
- **Shift-JIS の黙示変換拒否（2.1.299）は、前週（2.1.296 の Edit / NotebookEdit）に続いて Write にも入った。** **2週で Edit → Write の両系統が揃った**ことになる。日本語環境向け教材では、**「過去に Claude Code で編集した Shift-JIS ファイルは壊れている可能性がある」**という形で、既存案件の棚卸しまで含めて扱う価値がある。レガシーな CSV・設定ファイルを触らせる案件では事前の変換か対象外指定が必要、という結論は前週と同じである。
- **hook の同時実行上限12（2.1.302）は、エージェント設計の定番の落とし穴を1つの数字で説明できる。** フックは1イベント1回に見えて、**並列セッションでは簡単に数十本走る。** 上限を決めずに外部コマンドを呼ぶ設計は、ある日マシンを止める。**上限が「公式の既定」として入ったこと自体**が、自作の自動化にも上限を置く根拠になる。
- **アイドル圧縮の54分は、課金構造が機能設計に出た最良の例である**（2.1.299）。**1時間のプロンプトキャッシュから逆算された数字**で、技術的な最適値ではない。**「キャッシュの寿命が UX を決める」**という主張を、具体的な数字1つで裏づけられる。あわせて 2.1.300 の**キャッシュ書き込みの 5分 / 1時間内訳**を並べると、「どちらの TTL に書いたか」が測れるようになった流れとして一体で扱える。
- **「モデルを選ばせない」機能と「何が動いたかを測る」機能が、同じ週に同じ方向で動いた。** Claude Code は **auto mode の classifier decision を OpenTelemetry へ出す**ようになり（2.1.301）、**同じ週に GitHub Copilot の HydraFusion が複数モデルの編成をステップ別 effort で行う**更新を出した（10-14）。**選択をツール側へ委ねるほど、可観測性が要件になる。** この2つを並べると、「自動選択は便利だが、説明責任が残る」という主張が1社の話でなくなる。
- **可観測性の方向が3製品で揃っている。** Claude Code の **GenAI semantic conventions 属性**（2.1.300）、同日の Claude Platform の OpenTelemetry エクスポート（ベータ）、**同じ週の n8n 2.44.0 の「すべての span に execution identity を付与」**。**エージェントの実行を1本のトレースで追う**という方向がベンダー横断で進んでいる。可観測性の章では、特定製品の機能ではなく業界の収束として扱える。
- **既定の挙動の変更が今週も出ている**（2.1.302）。**ターミナル外で subagent がバックグラウンド実行**、**fork subagent が既定有効**、**サードパーティセッションが `default` モードで開始**の3点。**「同じツールでも実行環境で既定が変わる」**という注意喚起は、デスクトップアプリ / VS Code / ターミナルを併用する受講者に実害として伝わる。既定値の変更は変更履歴の中で扱いを別にする、という原則の継続事例でもある。
- **最小限の Knowledge 反映案**: 既定スキップのままでよい。ただし MCP の deny / ask ルールを扱っている教材があれば、**「サーバー名にアンダースコアを含む場合、2.1.298 以前ではルールが適用されなかった」**の1行を注記として入れる価値がある。権限ルールの正しさを前提にした手順は、この版より前では成立しない。
