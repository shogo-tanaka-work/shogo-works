- **今週最大の教材は「資格情報はログとエラー画面から漏れる」である**（2.1.268、露出2件）。攻撃者が突破するより先に、**利用者自身が画面共有・CI ログ・バグ報告で外へ出す。** セキュリティ教材はどうしても侵入経路の話に寄るが、実務でいちばん多いのはこの自損型である。**「秘密情報を扱うコードは、エラーメッセージの組み立て方まで設計対象」**という原則を、製品側の実例で裏づけられる。
- **併せて教えるのは事後対応の手順である。** 修正版へ更新しても、**すでに外へ出た資格情報は戻らない。** 露出系の修正は「更新して終わり」ではなく、(1) 更新、(2) 露出しうる経路の棚卸し、(3) 該当する資格情報のローテーション、の3段構えになる。教材では、この3段目まで書かないと片手落ちになる。
- **シンボリックリンク経由の権限すり抜けが2週連続で出た**（前週 2.1.252、今週 2.1.268）。**同じ原因系の不具合が繰り返されるのは、その抽象化が本質的に難しいということ。** パス正規化と権限判定の順序という、TOCTOU 系の古典的な問題である。**「リンク先まで解決してから判定する」を実装の前提に置く**という設計原則の題材として、実例が2つ揃った。
- **テレメトリへの `user.email` / `user.groups` 追加**（2.1.265）は、**利便性と統制がトレードオフではなく、両方が同時に増える**珍しい例。管理者は使用実態を把握でき、同時に個人識別情報が観測基盤へ流れる。**「観測できること」と「記録してよいこと」は別**という、AI ガバナンス教材の中心論点をそのまま突く。導入企業の情シス・法務レビューで実際に問われる項目である。
- **許可リストが読めないときに全許可へ倒れていた**（2.1.267）。fail-open と fail-closed の教材として、前週の「管理設定がパース不能なら起動を拒否」と同系列である。**2週続けて同じ方向の修正が入っている**ことから、**この製品は fail-open だった箇所を順に潰している段階**だと読める。自社で AI ツールの設定配布を組むときは、**「設定が読めなかった場合」の分岐を最初から書く**という手順に落とす。
- **バックスラッシュによる封じ込め回避**（2.1.267）は、前週の「zsh の変数代入にコマンド置換を隠す」と同じ構造。**パス・シェル構文の解釈差が、そのままセキュリティ境界の穴になる。** Windows 由来の区切り文字が macOS / Linux の検証を素通りするという形で、**プラットフォーム差が攻撃面になる**ことまで示せる。
- **`maxEffortLevel`**（2.1.267）は、AI コスト統制の設計パターンとして完成度が高い。**上限だけを管理者が固定し、その下は利用者が自由に選ぶ。** 禁止でも放任でもない中間形であり、Bedrock / Vertex / Foundry を含む全プロバイダーに効く点で、マルチクラウド環境でも破綻しない。**AI 利用ガイドライン策定の演習で、この形を雛形として提示できる。**
- **`claude plugin eval`**（2.1.269）は、**ハーネスエンジニアリングの「品質層」の具体物**である。プラグインやプロンプトの品質を「動かして確かめる」から「スイートで測る」へ移す。同じ週に GitHub Copilot の code review が Lite をアンサンブル化して **+47% / +31% / +11% という数値**を公開しており、**AI の振る舞いを定量評価する方向が業界横断で進んでいる**という文脈で並べられる。
- **2.1.269 の翌日に 2.1.270 が回帰修正で出た**。しかも 2.1.269 は `claude plugin eval` を含む大型リリースである。**大型リリース直後に更新すると回帰を踏む確率が上がる**という運用則の、今週ぶんの実例。前週の macOS 12 起動不能（3版にわたって残存）と並べると、**日次リリース型ツールの更新タイミングをどう決めるか**という議論の材料が2つになる。
- **権限確認が急に増えたとき、まず設定を疑わない**（2.1.270）。実際には前版の回帰だった。**「挙動が変わった → 自分の設定が悪い → 設定を緩める」**という誤対応が、統制を自ら壊す経路になる。**CHANGELOG を先に見る**という手順を運用教材に明示する根拠。
- **プロンプトキャッシュ修正が 2.1.267 に集中している**（MCP サーバーの再送、ツールの増減、`/model` 切替など）。**キャッシュは前置きが一定であることに依存する**という原則の裏返しで、**動的にツール定義を組み立てる設計はそれだけでキャッシュを壊す。** コンテキストエンジニアリング教材のコスト節で、「なぜ動的なツール定義が高くつくか」を説明する具体例になる。
- **今週の Codex はロールアップを作っていない**（窓内の stable が `0.154.0` の1件のみ）。**片方が毎日出て片方が止まる週がある**というのは、2ツールを並行運用している読者に効く情報である。**更新頻度そのものがツールの性格差**であり、追随コストの見積もりに直結する。
