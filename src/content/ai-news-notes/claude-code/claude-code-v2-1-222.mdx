- `plan-mode-worktrees.mdx` で worktree を隔離手段として説明している箇所は、前提の確認が必要。「worktree は隔離になるが、実装のバグで抜けることがある」という一段上の説明を足すか、少なくとも「バージョンを上げ続けることが隔離の前提」と書く。本リポジトリの `.claude/rules/branch-management.md` は worktree を例外手段としているので、方針差は明示する。
- PreToolUse auto-allow のバイパス修正は `hooks.mdx` の内容そのものではなく、「hooks による制限は監査記録の信頼性に直結する」という運用側の話。教材本文の修正は不要だが、v2.1.221 の権限バイパス修正と並べて「2日連続で権限まわりの修正が出た」事実を運用章の事例に使える。
- `SendMessage` の permission classifier 評価は `agent-teams.mdx` / `subagents.mdx` に関係する。エージェント間連携が増えると「メッセージ経由の抜け道」が論点になる、という設計上の注意として追記候補。
- Remote Control の repo-local 有効化禁止は、設定スコープ（user / project / local）の教材で使いやすい実例。「オンは上位スコープのみ、オフは下位でも可」という非対称な設計は、権限設計の考え方として一般化できる。
- ultraplan の削除は、教材や講座資料に登場していないか要確認。機能名を出している箇所があれば削除する。廃止告知なしにリリースで消えた点は「AIツールの機能は予告なく消える」事例として使える。
- `/usage` の MCP 按分修正は、コスト管理の教材で数値を扱うときの注意（バージョンによって集計基準が変わる）として1行。
