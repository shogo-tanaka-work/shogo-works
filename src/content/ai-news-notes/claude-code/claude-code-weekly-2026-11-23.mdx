- **今週の中心は「allow ルールが信頼できる単位ではなくなった」ことである。** 2.1.327 は `Bash(pnpm dlx *)` のような**任意のパッケージを実行できる allow ルールを auto mode が無視する**ようにした。パスやバージョン付きの形（`/usr/bin/npm run:*`）も同じ扱いになった。ルールは「このコマンドを許す」と書いているつもりでも、実体は「任意のコードを実行する入口を許す」である。**ルール文字列の見た目と、それが開ける権限の広さは一致しない。** 許可リストを教えるときの題材として素直で、「ワイルドカードを置く位置で危険度が変わる」ではなく「**そのコマンドが他のプログラムを起動できるかどうかで危険度が決まる**」と言い切れる。
- **前週からの連続性で見ると、権限チェックの話が6週続いている。** 10月第3週の起動ファイル、第4週の symlink と設定ファイル、11月第1週の `--restricted` × Read 許可、第2週の4件、前週の 2.1.321・2.1.323・2.1.325、そして今週の 2.1.327。ただし**今週は性質が変わった**。前週までは「漏れの修正」が主だったが、今週は「**判定の基準そのものを動かした**」（作業ディレクトリの内外の判定、`blockReadsOutsideWorkingDirectories` の対象拡大、任意パッケージ実行型ルールの無視）。修正を積む段階から、設計を締め直す段階へ移ったと読める。**修正が続く箇所は、いずれ既定が変わる**という予測として教材に使える。
- **auto mode の課金分類器フォールバック削除の予告は、安全チェックのコスト構造を露わにする。** これまでは分類器が使えないとき課金リクエストへフォールバックして判定を続けていた。削除後は「確認を求めるか拒否する」になる。つまり**安全チェックには金がかかっており、払えないときどちらへ倒すかという設計判断がある**。前週の fail-open の議論（`--permission-mode auto` が緩い側へ倒れていた）の続きで、今回は fail-closed 側へ寄せる明示的な宣言である。**ガードレールの可用性は、ガードレール自体の設計項目**だと示す実例になる。
- **2.1.328 の hooks の変更2件は、監査ログを hooks で作る設計の限界を示す。** managed `PostToolUse` hooks が**実行前に拒否された呼び出しでは発火しない**。拒否は安全側の挙動だが、**「拒否された」という事実こそ監査で見たい情報**である。それがログに残らない。Code Mode 側では `UserPromptSubmit` hooks がスクリプト出力に走らなくなり、出力のマスキングを `PostToolUse` の `updatedToolOutput` へ移す必要が出た。**どちらも「hook が呼ばれる前提」が変わると、監査とマスキングが静かに止まる**類の変更である。自作のガードレールを教えるときは、**hook の発火条件を仕様として固定し、発火しなかったことを検知する仕組みを別に持つ**という指針に落ちる。
- **自己ホストランナーの「不要な差分を省く」変更も同系列である。** トランスクリプトに差分が無い場合が出てくるため、全件必要なら managed settings で `bashEditDiffEnabled: true` を明示する。性能のための省略が、監査証跡の欠落として表に出る。**「既定は軽い、証跡が要るなら明示的に重くする」**という設計は Claude Code 全体で一貫しており、無人運用の `sandbox.autoAllowBashIfSandboxed`（前週）と同じ形をしている。
- **403 のログ行の文言変更は、見落としやすい運用破壊である。** 「サーバー側の理由を先頭に出す」改善だが、**旧文言に一致させているログアラートは黙って鳴らなくなる**。ログの文言はインターフェースであり、改善が互換性を壊す。監視を教える回で、**文字列マッチのアラートは上流の文言変更で死ぬ**という具体例として使える。
- **`deniedMcpServers` が2版で二度変わった点は、拒否ルールの粒度の難しさを示す。** 2.1.328 で名前指定をクラウド・自己ホストにも及ぶようにし、2.1.330 で**名前指定は URL を共有する他コネクタに及ばない**ようにした。名前で拒否するか URL で拒否するかは、「同じ実体を複数の名前で参照できる」環境では別の意味を持つ。**拒否ルールは、識別子が1対1でない世界では必ず曖昧になる。** 現在の正解は「URL ごと止めたいなら正確な URL を拒否する」である。
- **資格情報の修正2件は、どちらも「失敗したときに何が残るか」の話である。** `claude auth logout` が資格情報を残していた（2.1.326）のは、**ログアウトが成功したように見えて成功していなかった**例。macOS で Keychain を読めるが書けないときの繰り返しサインアウト（2.1.329）は、**部分的に動く権限が最も厄介**な例で、修正後は該当セッションが失効時に停止して理由を表示し、他セッションはサインインを維持する。「読めるが書けない」を正常系と異常系のどちらにも入れない設計が、両方を壊していた。
- **スケジュールタスクの上限が7日から30日へ伸びた件は、既存タスクに適用されない。** 本リリース以前に作ったタスクは7日で終わる。**設定の変更が既存オブジェクトへ遡及しない**典型で、「上げたのに挙動が変わらない」という問い合わせの原因になる。無人運用を教える回で、**版を上げた後に既存のスケジュールを作り直す**という手順として残す価値がある。
- **third-party provider で auto mode が既定になった件（2.1.328）は、既定の緩和である。** 権限モード未指定の対話セッションが auto mode で開始する。今週の他の変更が締める方向なのに対し、ここだけ広げる方向で、**「安全性チェックが使える環境では緩め、使えない環境では締める」**という一貫した基準で動いていると読める。`disableAutoMode` でオフにできる。
- **最小限の Knowledge 反映案**: 既定スキップのままでよい。ただし Claude Code を CI / 無人実行で使う手順を扱う教材があれば、**任意パッケージ実行型の allow ルールは auto mode で効かない**、**監査ログを hooks で作る場合は「拒否された呼び出し」が落ちる**、**自己ホストランナーで全差分が必要なら `bashEditDiffEnabled: true`**、**版を上げたらスケジュールタスクを作り直す**の4点を注記する価値がある。Opus 4.8 の fast mode 削除（2026-11-30、残り7日）も引き続き残す。
