- **今週いちばん強い教材は、権限ルールの抜け穴4件を「同じ型」として並べられること**（2.1.289）。複合シェルコマンドの入れ子部分、環境変数を前置した破壊的コマンド、裸の変数代入がコマンド前に来る形、シンボリックリンク経由の IDE 参照。**すべて「ルールは設定済みなのに、コマンドの書き方で判定をすり抜けた」**である。**権限設定を入れた時点で安全だと考える運用は危ない**という主張を、1リリースの4件で示せる。**ルールを書いたあとに「すり抜ける書き方」を試す検証工程が要る**という結論まで一息でつながる。
- **「ログに資格情報が残る経路」の棚卸しリストとして、2.1.286 の5件がそのまま使える。** MCP のエラーメッセージ、ログ中の Bearer トークン、不可視文字を含む秘匿値、URL のパスワード部分（特殊文字と IPv6）、フィードバック用トランスクリプトの JSON。**自社でログ設計をするときのチェックリストに変換できる。** 前週の 2.1.275（資格情報露出）と合わせると、**同じベンダーの同じ領域で2〜3週おきに修正が出ている**という頻度の話もできる。
- **更新だけでは終わらない修正の型を2つ示せる。** 資格情報のログ露出（2.1.286）と、managed settings 下でのプラグイン自己承認（2.1.284）はどちらも、**更新すれば今後は塞がるが、それまでの期間に起きたことは戻らない。** **(1) 更新、(2) 設定とログの読み直し、(3) その期間に通った操作の確認**という3段構えが要る。**3週連続で同じ手順を要求されている**ことを示すと、手順を定型化する動機になる。
- **`prompt_text` は「マスキング漏れがアップデートで静かに起きる」最良の実例**（2.1.287）。`prompt` を伏せていても、複製キーの `prompt_text` を伏せ忘れればプロンプト本文が外部へ出る。**キー名の列挙（denylist）で実装していると、ベンダーがキーを増やした瞬間に穴が開く。** 対策は allowlist 方式へ寄せること。**観測性の設計の章で、denylist と allowlist の選択がセキュリティ要件になる例**として置ける。
- **「何もしなくても変わる」の実例が、今週も2件出た**（2.1.284 の auto mode 全プラン既定化と既定 Sonnet の 5.5 化）。**前週の 2.1.280（Pro / Team Standard の既定モデル変更）、前々週の 2.1.278（分類器のサーバー側既定）と並べると3週連続である。** **既定値の変更は変更履歴の中で扱いを別にする**という原則を、連続した実例で裏づけられる。
- **`CLAUDE_CODE_DISABLE_WEB_FETCH` は、統制の教材として扱いやすい粒度**（2.1.285）。**エージェントの外向き通信を環境変数1本で落とせる。** 「エージェントが外部へ出る経路を、機能単位で落とせるか」という点検項目として具体化でき、**同じ週に GitHub Copilot が computer use（画面と入力デバイスの操作）を public preview で出したこと**と対にすると、**口が増える側と塞ぐ側が同時に動いている**という構図が示せる。
- **「ユーザー拡張が組織管理設定を上書きできてしまう」問題が2週連続で出た。** 2.1.284 は managed settings 下でのプラグインの自己承認、2.1.289 は**ユーザー plugin が組織管理下の MCP サーバーのサインインツールの説明文を書き換えられる**問題。**「管理者が決めたものをユーザー側の拡張が変えられるか」という権限モデルの検証項目**として、社内の AI 統制チェックリストに入る観点である。
- **プラグインの不具合がホストを落とす構造**（2.1.289）。描画例外、高さゼロ領域、非同期例外、未知の枠線スタイル——**4件とも「plugin / mod が例外を投げたらその部分だけ失敗させ、セッションは生かす」方向へ寄せている。** 拡張機構を自作するときの設計方針（**障害の隔離境界をどこに置くか**）の実例として使える。
- **「既定モデルが使えないと全ターン失敗」から「1つ前のティアで再試行」への変更**（2.1.286）は、外部モデルに依存するシステムの可用性設計の型。**単一モデル指定は単一障害点である**という原則の具体例として短く示せる。**同じ週の Codex 0.159.1 が既定モデルを発表当日に入れ替えた**ことと並べると、**「固定しても固定しなくても、モデルは運用上の変数である」**という話に落とせる。
