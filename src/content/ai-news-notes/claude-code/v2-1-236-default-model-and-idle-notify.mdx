- `ANTHROPIC_DEFAULT_MODEL` は、ハーネスエンジニアリング教材の「設定をどこに置くか」の節に入れられる。設定ファイル（個人）→ 環境変数（配布可能）→ managed-settings（強制）という階層で、それぞれ何を置くべきかを整理する具体例になる。既定モデルは「チームの決定であって個人の好みではない」という主張を、この機能追加で裏付けられる。
- `notify_when_idle` は、複数セッション並行運用の教材に必要な部品。これまでポーリングで待つしかなかった構造が通知で置き換わる、という変化は、エージェント運用の設計パターンとして一般化できる（ポーリング → イベント駆動）。
- macOS サンドボックスのワイルドカード read-deny 修正は、セキュリティ設定の落とし穴の実例。「書いたつもりのルールが効いていなかった」状態が存在しえたということで、設定を書いたら効いていることを検証する手順まで教材に含める理由になる。修正で挙動が変わる方向（塞がる側）も明示する。
- print / SDK モードの SIGTERM 挙動変更は、CI 統合の教材で扱う。AI エージェントを CI に組み込むとき、正常終了とタイムアウト強制終了で後処理が変わる、という論点は見落とされやすい。バージョン更新時に1本パイプラインを流す、という運用習慣を教える動機付けになる。
- 「ほぼ毎日リリースが出るツールをどう追うか」という読み方の教材にできる。全部読むのではなく、環境変数・サンドボックス・シグナル処理のように「自分の設定と噛み合う領域」だけをフィルタする。バージョン単位の記事が並ぶ系列（2.1.234 / 2.1.235 / 2.1.236）を、テーマで束ね直す実演にも使える。
- VSCode のスクリーンリーダー対応は、アクセシビリティ要件が導入判断に関わる組織向けの論点。機能一覧では小さく見えるが、公共・教育・大企業の調達では可否を分ける項目になりうる。教材で「機能の重要度は読者の立場で変わる」例として使える。
- `/usage` 表示の Team / Enterprise メンバー向け変更は、プラン差の説明で使う。教材に画面例を載せるときは、どのプランで撮ったスクリーンショットかを明記しないと読者が混乱する、という運用ルールの根拠になる。
