- 権限チェックのバイパス修正は、`hooks.mdx` や `daily-operations.mdx` で「承認フローで危険なコマンドを止める」と説明している箇所の前提に関わる。教材本文の修正は不要だが、「承認フローは実装のバグで抜けうるので、バージョン更新を運用に組み込む」という一段上の話を補足として入れる候補。
- sandbox の `mode: "mask"` は、`deny` / 読ませる の二択しかなかった説明を三択に更新する必要がある。OS 差（macOS は `deny` フォールバック）まで含めて書かないと誤解を生むため、記述するなら OS 別の挙動表を作る。
- バックグラウンドセッションの commit / push 既定化は、CLAUDE.md の書き方教材（`claude-md-memory.mdx`）と結びつけやすい。「CLAUDE.md に git 運用を書いていないと既定挙動をそのまま受け入れることになる」という具体例として、CLAUDE.md を書く動機づけに使える。
- `/fork` の worktree 分離は `plan-mode-worktrees.mdx` の worktree 説明と接続する。ただし本リポジトリの `.claude/rules/branch-management.md` は「worktree は例外手段」という方針なので、教材化する場合は方針の違いを明示しないと混乱する。
- 講座の実演では Focus view が使いやすい。ツール実行ログを畳んだ画面のほうが受講者が話を追いやすいため、収録手順のメモとして残す。
