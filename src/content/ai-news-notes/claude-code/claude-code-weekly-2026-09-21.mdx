- **今週最大の教材は `npm pack --ignore-scripts` への変更である**（2.1.275）。修正の形を取っているが、**実質は「プラグインを入れる」という行為の意味が明文化された**ものである。install script が走っていたということは、**マーケットプレイスからプラグインを1つ入れるたびに、第三者のコードを自分の権限で実行していた。** サプライチェーンの話は抽象論になりやすいが、**受講者が実際に使っているツールで、先週まで起きていたこと**として始められる。教材の掴みとして今週いちばん強い。
- **棚卸しの手順まで書かないと片手落ちになる。** 更新しても、**すでに走った install script が何をしたかは戻らない。** 露出系・実行系の修正は (1) 更新、(2) いつ何を入れたかの洗い出し、(3) 影響しうる資格情報のローテーション、の3段構えになる。前週の資格情報露出（2.1.268）と同じ型で、**2週連続で同じ手順を要求されている**点を示すと、手順を定型化する動機になる。
- **URL 内の資格情報が3経路すべてに出ていた**（2.1.275）。メッセージ、ログ、`claude plugin marketplace list` の一覧表示。**「秘密情報を URL に入れない」という基本則が守られなかったとき、漏れる経路は1つではない。** 経路を全部塞ぐのが難しいからこそ、**そもそも入れない**という予防側に倒す、という順序で教える。VS Code のダイアログ側も別途直っている点が、経路の多さをさらに裏づける。
- **サブエージェント出力の枠付け**（2.1.277）は、プロンプトインジェクションの教材として構造が明快である。**「エージェントの出力を別のエージェントの入力に入れる」設計は、信頼境界がコードではなくテキストの中にある。** ヘッダとインデントで枠を付けるという対処は素朴に見えるが、**構造で塞ぐ**という原則の実装そのものである。マルチエージェント構成を勧める前に、この論点を必ず通す。
- **2.1.275 → 2.1.276 の3時間40分は、更新運用の教材になる。** 大型リリース（100項目超）の直後にゲートウェイ経由が全滅し、即日修正された。**「更新を止める」と「壊れたら更新して直す」は両立しない。** 前週の 2.1.269 → 2.1.270 と合わせ、**大型リリース直後に飛びつくと回帰を踏む確率が上がる**という観測が2週続いた。ステージングで1日置く、という運用則の根拠が揃った。
- **集中管理構成のほうが先に壊れる**（2.1.276）。ゲートウェイを挟むのはガバナンス上は正しいが、**ベンダーの検証が薄い経路でもある。** 同じ窓で Codex 0.155.0 も「非対応プロバイダで全拒否」を起こしており、**2社の独立した事例で同じ教訓が出た。** 企業導入の章で「統制と引き換えに、想定外経路を踏むリスクを取る」として扱う。
- **2.1.278 で、ゲートウェイの「透過性」が値段になった。** 未知のリクエストフィールド（`safeguards`）をそのまま通すかという実装品質が、**分類器ぶんの課金の有無に直結する。** LLM ゲートウェイの評価軸はこれまで統制・ログ・コスト可視化だったが、**パススルー適合が評価項目に加わった。** 選定チェックリストの具体項目として使える。**`CLAUDE_CODE_AUTO_MODE_SERVER=0` は公式が「一時的」と明記しているため、運用手順書へ固定値として書かない。**
- **「更新したのに安くならない」が起きる**（2.1.278）。対象アカウントでも、自社ゲートウェイが非対応なら課金は据え置かれ、**通知が出るだけ**である。原因が自社側にあるため、ベンダーへ問い合わせても解決しない。`/status` の `Auto mode server` 行で切り分ける、というところまでをセットで教える。
- **AGENTS.md 対応**（2.1.277）は、本リポジトリの構成に直接効く。CLAUDE.md / AGENTS.md / `.claude` をすべて `.agents/` へのシンボリックリンクにしているのは、**ツールごとに正本が分かれるのを避けるため**だった。公式が AGENTS.md を読むようになったことで、**回避策が要らなくなる方向へ一歩進んだ。** ハーネスエンジニアリング教材の「正本を1か所にする」節へ、実装が追いついた例として置ける。**Bedrock / Vertex / Foundry 未対応**という但し書きも一緒に教える。
- **TaskOutput の削除は「非推奨は本当に消える」の実例**（2.1.277）。`taskOutputMaxChars` が無効化されるため、**設定ファイルに書いてあるのに効かない**という状態が生まれる。設定の棚卸しを定期作業にする動機づけに使える。
- **統制設定が「効いていなかった」系の修正が今週も4系統**（2.1.271）。組織ポリシーのキャッシュ、`managed-mcp.json` の無視、`ANTHROPIC_UNIX_SOCKET` 経由のポリシー取得、そして 2.1.277 のサンドボックス除外 glob。**管理者が設定したはずの制限が効いていなかった期間がある。** 同じ週に n8n 側でも「declarative ノードで資格情報の許可ドメインが適用されていなかった」（1.123.80）が出ており、**製品をまたいで同じ型が3件**そろった。**統制は「入れた」で終わらず、「効いているか」を別の手段で確かめる**という手順の根拠になる。
- **最小権限の粒度が下がる動きが、今週は3製品で同時に出た。** Claude Code のコマンド単位 `allowed_domains`（2.1.271）、n8n のデータテーブル閲覧のプロジェクトロール化と API キーのフォルダスコープ（2.40.0）、GitHub Copilot の auto モデル選択ティア（コストの粒度）。**「セッション単位で開ける」から「必要な単位でだけ開ける」への移行**という一般則を、横断の実例で裏づけられる。
- **claude.ai のスキル・プラグインが端末へ同期される**（2.1.275）。**個人アカウントで有効化したものが手元の端末に降りてくる経路が増えた。** 組織の統制観点では新しい入口である。オプトアウト設定名（`syncClaudeAiSkills` / `syncClaudeAiPlugins`）は変わりうるため、恒久教材には「同期の向きと止め方を確認する」とだけ残す。
- **MCP の `timeout` が効いていなかった**（2.1.274）。サーバー別に長く設定しても約5分で切れていた。**設定値が実際に効いているかを確認する手順**を教える題材として素直である。設定画面に値が入っていることは、適用されている証拠にならない。
