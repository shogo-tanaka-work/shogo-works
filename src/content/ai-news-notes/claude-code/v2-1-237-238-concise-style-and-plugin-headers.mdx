- `headersHelper` は、ハーネスエンジニアリング教材の「配布経路をどう統制するか」の節に直結する。公開マーケットプレース依存の状態は、サプライチェーンの入口が組織の外にある状態である、という整理が核心。社内ホストへ移す具体的手段が公式に用意された、という事実で主張を裏づけられる。
- 配布側（`headersHelper` を与える）と受信側（workspace trust を必須にする）で方向が逆に見える変更が同じリリースに入っている点を、教材の題材にすると理解が深まる。「自分がホストする経路には手段を、リポジトリに紛れ込む設定には確認を」という非対称な設計が、信頼境界の引き方の実例になる。
- プロジェクト `.mcp.json` の `headersHelper` は、リポジトリを開くだけでコマンドが実行されうる構造だった。これはエディタ設定ファイル経由の攻撃（`.vscode/tasks.json` 等）と同型で、AI ツール固有の新しい脅威ではなく既知パターンの再来として説明できる。外部リポジトリを開く機会がある組織向けの運用ルール（バージョン下限を決める）まで落とせる。
- ゲートウェイ経由でプロンプトキャッシュが効いていなかった件は、コスト管理教材の実例。「アーキテクチャの選択がキャッシュの効き方を変える」という論点は見落とされやすく、監査やコスト集約のために挟んだ層がコストを増やしていた、という皮肉な構図が記憶に残る。更新前後で1〜2週間観測する、という検証手順まで教える。
- Concise 出力スタイルは、プロンプト設計とトークンコストの関係を教える素材。読み飛ばす出力にもトークンを払っている、という指摘は多くの読者にとって新しい視点になる。組み込みで提供されたことで、カスタム出力スタイルを書けない層にも届く。
- `--defer-shutdown-max-min` と `--proxy-authorization-command` / `--proxy-authorization-file` は、「AI エージェントの実行基盤も通常のインフラ運用の作法が要る」という主張の裏づけ。猶予付きシャットダウンは CI ランナーの設計と同型で、既存のインフラ知識が転用できることを示せる。認証情報を設定ファイルに直書きしない、という原則の適用例としても使える。
- 出力スタイルがセッション途中で既定へ戻る不具合は、「設定したつもりが効いていない」系の実例。2.1.236 の macOS サンドボックス修正と並べて、設定の効果を検証する手順まで教材に含める理由づけにできる。
- 長時間セッションのメモリリーク修正は、翌日の 2.1.239（`WebFetch` の期限切れページ保持）と合わせて扱う。2版続けて同方向の修正が入ることは、「セッションを閉じない」使い方が想定利用に入っている証拠として読める。バージョン単位の記事をテーマで束ね直す実演素材。
