- **「動いていたから正しい」は許可ルールでは成り立たない**、という一般則の実例として最良の教材。`Bash(git * main)` はサブコマンド前のオプションにもマッチする。**広すぎる許可は、問題が起きるまで問題として現れない**。ファイアウォールルールや IAM ポリシーの点検と同じ構造なので、他分野の経験がある受講者にも接続しやすい。
- **「無効化ではなく警告に留める」という判断**を、後方互換性の教材として扱える。壊さない代わりに、**気づいて直す人がいなければ状態は変わらない**。起動時メッセージは流れて消える。**警告は対応を保証しない**という点まで含めて教えると、運用設計の視点が育つ。点検を作業として割り当てる、という具体策まで落とす。
- **auto mode の classifier ルールが可視化された**ことは、ハーネスエンジニアリングのガードレール層の到達点として説明できる。自動承認は便利だが、**判定基準が見えないと監査で説明できない**。「なぜこの操作が自動承認されたか」に答えられる状態を、統制の最低ラインとして提示する。
- **第三者ゲートウェイ向けの API キーが別ホストへ送られていた不具合**は、資格情報のスコープ設計の教材になる。「どのホスト宛にどの資格情報を送るか」を明示的に管理していないと、こういう事故が起きる。**修正されても、修正前に送られた事実は消えない**——ローテーションの判断が必要という点まで教えると、インシデント対応の思考が身につく。
- **サブエージェントが `maxTurns` で止まったのに完了したように見えていた**問題は、「失敗を失敗として報告させる」原則の反例として強い。**中途半端な結果を「これで全部」として受け取っていた**可能性がある。無人実行のハーネス設計で、成功と部分成功と失敗を区別させることの重要性を、公式ツールの実例で示せる。
- **`/cd` で設定が効いていなかった問題**は、「ガードレールが効いていないことに気づかない」という最も危険な状態の実例。設定を配る運用は、配布より**効いているかの検証**が難しい。2.1.243 の `Skipped sources` と並べて、同じテーマの連続として教えると理解が定着する。
- **メモリリークの原因が「各行がトランスクリプト全体のコピーを保持していた」**という点は、設計ミスの分かりやすい実例。参照で足りるところをコピーで持つと、要素数に比例してメモリが増える。**AI ツールの中身も普通のソフトウェア**であり、性能問題は普通の原因で起きる、という当たり前の感覚を持たせるのに使える。
- **「公式ツールですらこの問題を抱えていて、修正されたのが今日」**という事実は、自作の自動化を点検する動機として、抽象的な注意喚起より強く働く。研修で行動を促すとき、**一般論ではなく直近の具体例を使う**ほうが効くという、教え方そのものの実例でもある。
