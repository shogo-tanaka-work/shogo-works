- **「サイレントに消える不具合」は、利用者が自力で気づけない**という点で教材価値が高い。`/clear` 後に MCP 定義が消えるのは、エラーも出ず、ただ機能が減る。**動いていないことに気づく仕組みを持つ**という運用設計の話へ接続できる。
- **`autoMode.hard_deny` は「分類器を信用しつつ、信用しない領域を明示する」設計**の実例。AI に判断を委ねる範囲と、絶対に委ねない範囲を分けて書けることが統制の要件になる、という説明に使える。
- **内部修正のみのパッチ（2.1.138）をどう扱うか**は、更新運用の判断材料として使える。変更点が読めないパッチは、単独で運用を変える根拠にならない。**再現していた不具合の確認とセットで上げる**という現実的な運用へ落とす。
- 週次でまとめると、**個々のパッチでは見えない「その週のテーマ」が見える**。この週は MCP の信頼性だった。日次の版数追跡と週次の傾向把握は別の作業である、という情報の扱い方そのものの教材になる。
