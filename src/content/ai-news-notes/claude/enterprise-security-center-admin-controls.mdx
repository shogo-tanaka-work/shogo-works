- **設定の棚卸しを「差分で見る」演習にする。** 全項目を読むのではなく、推奨とずれている項目だけを、「意図して変えた」「見落とし」に仕分ける。AI ツールに限らず、設定レビューの基本形になる。
- **「推奨どおり＝適合」ではない点を明示する。** 発表でも、保証ではなく目安と書かれている。自社の規程・取引先のチェックシートとの照らし合わせは人が行う。
- **退職者対応を例に、止まるものと止まらないものを分けさせる。** サインアウトでは API キー、実行中の処理、定期処理は止まらない。手順書に何を足すかを受講者に書かせる。
- **ベータ機能の扱いを論点にする。** 画面に出ていない機能は、設定ミスとは限らない。提供状況の確認先と、ベータを本番ルールに組み込む条件を決める。
- **受講者への問い**: 自社で AI ツールを使う人が辞めたとき、止めるべきものを全部挙げられるか。
- 恒久教材へ反映する場合は、**機能名やベータの状態を書かない**（変わる）。残すのは「推奨との差分で棚卸しする」「サインアウトと資格情報の停止は別の手順」の2点。
