- 「beta から GA へ」という遷移そのものを教材の題材にできる。機能自体は前から使えたのに、なぜ GA が意思決定を変えるのか。SLA、規制対応（HIPAA）、サポート、破壊的変更の扱いという4点で説明すると、企業の導入判断の実態に近い形になる。PoC 予算と本番予算の違いを説明する具体例としても使える。
- computer use の「1ターン複数アクション」は、エージェント設計の教材で**往復回数がコストと速度を支配する**という原則を教える最良の実例。フォーム5項目の入力に5往復かかる構造を図示し、往復を減らす設計（バッチ化、ツール設計、状態の持たせ方）へ話をつなぐ。
- browser use ツールの「座標ではなく構造」は、RPA との比較教材の核になる。座標ベース → DOM セレクタ → 構造読解 + LLM 判断、という3世代の変遷として整理すると、既存 RPA を持つ組織への説明がしやすい。ただし「壊れなくなる」ではなく「壊れにくくなる」であることを明示し、監視と失敗時の扱いを必ずセットで教える。
- Skills API は、ハーネスエンジニアリング教材の「暗黙知の配布」の節に直結する。社内 Wiki（読まれない）→ プロンプトへの貼り付け（属人化）→ スキルとしてバージョン管理（追跡可能）という段階で整理する。バージョン管理が API で提供されることの意味（どのエージェントが古い手順で動いているか追える）を強調する。
- Files API の 1TB とデータ自動有効期限は、AI ガバナンス教材の「保持ポリシーは設定で決まる」という論点。ポリシー文書を書いても、実際の保持期間は API の設定値が決める。ポリシーと実装の乖離を検出する仕組みまで教材に含める理由になる。
- Microsoft Foundry / Vertex AI 経由の提供差は、マルチクラウド前提の企業向け研修で使える。「同じ機能でも経路によって使える範囲が違う」という事実は、調達段階で見落とされやすい。今回は Skills API / Files API は Foundry で使えるが、computer use / browser use は Vertex AI に「近日」という非対称がある。表にして示すのが有効。
- 同日 GA した Cloudflare Browser Run の上限引き上げ（同時ブラウザ 120→200）と並べると、ブラウザ操作エージェントがモデル側と実行基盤側の両方から同時に整備されている状況を示せる。「モデルの性能ではなく基盤のクォータが上限になる」という設計演習の素材になる。
- HIPAA 対応は日本国内では直接効かないため、教材では「規制対象ワークロードに載る水準に達したという信号」として扱い、国内の相当物（医療情報システムの安全管理ガイドライン、個人情報保護法）に翻訳して説明する。海外基準をそのまま持ち込まない、という読み替えの練習にもなる。
