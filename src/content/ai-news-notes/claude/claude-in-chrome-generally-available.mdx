- **「禁止か許可か」ではなく「どのドメインを許可するか」という問いの立て方**は、AI ガバナンス教材の中心に置ける。二値で考えると必ず禁止側に倒れる。**中間の選択肢が製品側に用意されているのに、それを使わない意思決定**がなぜ起きるかを扱うと、組織論の題材にもなる。
- **プロンプトインジェクションの説明を「乗っ取られる」から「Web の文字列が指示として解釈される」へ言い換える**訓練は、そのまま演習にできる。前者は恐怖を生むだけだが、後者は「では外部から来る文書を読ませる用途は慎重に」という具体的な対策に接続する。**正確な比喩は対策を生み、雑な比喩は禁止を生む。**
- **3層防御の構造（訓練 / 検知プローブ / 実行前検証）**は、ハーネスエンジニアリングのガードレール層をそのまま体現している。モデルを賢くする層、入力を疑う層、出力（行動）を止める層。**どれか1つでは足りず、層を分けることに意味がある**という一般則の教材として使える。
- **ベンダー公表値をどう引用するか**は、AI 導入の説明責任の教材になる。「保護有効で成功0件」は事実だが、それは Anthropic の評価環境での測定である。**「ベンダーがこう測った」と「安全である」を混同しない**書き方を、稟議文の書き換え演習として扱える。
- **17.6% → 3.8% というモデル世代間の差**は、「安全性はモデル選定の要素である」という論点の具体例。同じ保護構成でも土台のモデルで結果が変わる。**モデル選定を性能とコストだけで語らない**根拠として数字を使える。
- **auto mode と同じ機構を流用している**点は、プロダクト設計の教材になる。Claude Code で検証済みの承認機構を、ブラウザという別の実行面へ持ち込んでいる。**制御機構を製品横断で1つにする**という発想は、社内の AI 利用ルール設計にも一般化できる。
- **自律実行の可否を「対象システムごとに決める」という粒度**は、研修で反復する価値がある。全社一律のポリシーは、必ず最も危険なシステムに合わせて設計され、結果として全体が使えなくなる。**リスクは対象ごとに違うのだから、ポリシーも対象ごとに持つ**という当たり前を、具体例で刷り込む。
