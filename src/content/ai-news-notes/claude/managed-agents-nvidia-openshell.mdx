- **「指示」と「強制」の区別**が、この記事のいちばん使える骨格。プロンプトで「本番DBに書くな」と書くのは指示。ランタイムで拒否するのは強制。**プロンプトインジェクションで壊れるのは指示のほうだけ**。この対比は、エージェント導入の相談を受けたときにそのまま使える。
- **既定拒否（default deny）という古典的な原則**が、エージェントの文脈で再登場している点を扱いたい。ファイアウォールでも権限設計でも昔から言われてきたこと。**新しい技術に、古い原則がそのまま効く**という例。「AIだから新しい考え方が要る」と言われがちな場面で、逆を示せる。
- **「数学的に検証できる」という主張の扱い方**を教材にする。強い主張だが、発表本文には手法の詳細がない。**強い主張ほど、根拠の粒度を確認する**という読み方の練習。鵜呑みにも全否定にもせず、「採用するなら実装を見る」という中間の態度。
- **層分離という設計パターン**は、Managed Agents を使わなくても持ち帰れる。エージェントループと実行サンドボックスを分ける、資格情報を vault に置く。**製品の紹介から、汎用の設計原則を抜き出す**読み方の訓練になる。
- **多くの内製エージェントが同じプロセスで資格情報を持っている**、という指摘は耳が痛い実例として効く。環境変数で API キーを渡す——**それは「エージェントから見えている」**。個人開発でも企業の内製でも普通にやっている。自分の構成を点検させる問いとして具体的。
- **「導入したから安全」にはならない**点を必ず添える。既定拒否型でも、ポリシーを緩く書けば広く通る。**仕組みは判断を代替しない**。セキュリティ製品全般に言える話で、ツール導入で安心してしまう組織の典型的な失敗。
- **Apache 2.0 という選択の意味**。セキュリティ製品がブラックボックスでないことの価値、ベンダーロックインの回避、自社ポリシーへの改変可能性。**ライセンスが採用判断に直結する**実例として説明しやすい。
- **競合が同じ方向を向いた、という事実の使い方**。Anthropic と NVIDIA が組んだ。報道では100社超が参画し OpenAI は不参加。**「業界の標準的な作法になりつつある」という傍証**は、提案の説得材料になる。ただし不参加の情報は公式未確認である点も、一次情報の扱いとしてセットで教える。
- **国内企業名（楽天）が事例に入っている**ことの実務的な価値。海外事例だけだと「うちとは違う」で止まる。**提案で使える具体性**という観点。
