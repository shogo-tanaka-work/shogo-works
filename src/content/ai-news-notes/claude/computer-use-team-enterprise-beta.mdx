- **設計の3点セットにする。** 「誰に（ロール）」「どのアプリで（許可・ブロックリスト）」「どの端末で（MDM）」を表に埋めさせる。導入の議論が「使う・使わない」の二択になりがちなので、段階の切り方を教える。
- **「効かない制限」を先に教える。** フォルダ制限と読み取り専用が Computer use に効かない点は、既存のファイル権限の感覚から外れる。**今までの制限が新機能にも及ぶと思い込まない**ことを演習にする。
- **サンドボックスなしの意味を図にする。** 画面上のメールや Web ページの文面が、そのまま操作の指示として働きうる流れを描かせ、プロンプトインジェクションの入口として説明する。
- **ブロックリストの穴を探す演習。** Chrome を禁止しても Claude in Chrome は止まらない、個人アカウントに切り替えれば組織のリストは外れる、といった抜け道を列挙させる。
- **反映の遅れ（約1時間）を運用に織り込む。** 緊急でオフにしたい場面を想定し、即時に止める手段（MDM など）と併用する考え方を示す。
- **有効化できない組織の条件は、規制対応の確認項目になる。** HIPAA、ZDR、CMEK、FERPA の組織は使えない。自社の契約や設定が該当しないかを、導入前の確認リストに入れさせる。
- 恒久教材へ反映する場合、**ベータ状態・展開時期・対応 OS のバージョンは書かない**（変わる）。残すのは「ロール・アプリ・端末の3層で制御する」「既存のフォルダ制限は及ばない」「画面上の内容が指示になりうる」の3点。
