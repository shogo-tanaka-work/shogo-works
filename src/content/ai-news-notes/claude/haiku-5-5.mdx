- **教材の軸は「単価の変化とトークン数の変化を分けて考える」に置く。** 単価10分の1、トークン数1.3倍、thinking トークンの追加。**この3つを合成しないと実質コストが出ない**という計算を、受講者に自分の手で1回やらせる価値が高い。AI の費用見積りで最も多い失敗が「公表単価をそのまま掛ける」ことなので、公式が同時に3つの変数を動かしたこの事例はちょうどよい練習台になる。
- **10万トークンの境界は「設計への投資が価格表で正当化された」事例として強い。** RAG で絞る設計は手間がかかるため「全部渡せばいい」に流れがちだが、ここで初めて**境界をまたぐと単価5倍という明示的なペナルティ**が付いた。設計コストと運用コストのトレードオフを、推測ではなく公式の価格表で説明できる教材は珍しい。
- **破壊的変更の棚卸しを「grep リスト」に変換する演習に使える。** `budget_tokens`、`temperature`、`top_p`、`top_k`、assistant prefill、`computer_20250124`、そして「応答の先頭ブロックを答えとして読む」コード。最後のものだけが grep で見つけにくい。**「機械的に探せる変更」と「読んで判断するしかない変更」を分類させる**と、移行計画の立て方そのものを教えられる。
- **`stop_reason: "refusal"` にサーバー側フォールバックがない点は、エラーハンドリング教材の具体例になる。** 「モデルが拒否する」という状態を正常系の分岐として設計する必要があり、例外として投げ捨てると本番で無言の失敗になる。
- **既存 Knowledge への最小反映が必要。** `claude/model-lineup-2026.mdx` はモデル一覧と使い分けを扱う教材で、**Haiku 枠が 4.5 のまま、価格も一律 $1 / $5 のままだと誤りになる。** プロンプト長段階価格は Claude 全体で初の体系なので、一覧表の構造自体に注記が必要。別 PR で「Haiku 5.5 の追加」と「段階価格という例外の明記」を最小差分で入れる。`claude/prompt-caching-guide.mdx` 側はキャッシュ読み取り $0.01 / $0.05 の追記だけで足りる。
- **Claude Code の既定 Haiku が静かに切り替わった点は、別の教材テーマに繋がる。** 「既定値の変更はリリースノートの1行に埋まる」という観測で、**消費量の計測基準をバージョン単位で持つ**という運用の必要性を教えられる。トークナイザが変わると前後比較が成立しないという具体的な理由まで示せる。
