- **「認証情報は守られるが、認可された操作は守られない」**という区別は、AI セキュリティ教材の核として使える。パスワードがモデルに渡らないことと、ログイン後にモデルが何をできるかは別問題である。**多くの人がこの2つを混同する**ため、具体例で分けて教える価値が高い。
- **Enterprise / Edu で使えず、Plus / Pro で使える**という提供範囲の逆転は、シャドー IT の教材として非常に良い。通常は「組織版のほうが機能が多い」と思われているが、**リスクの高い機能ほど組織版から外される**ことがある。結果として、会社では使えない機能が社員の個人契約では動く。この構造を理解していないと、統制の穴を見落とす。
- **「禁止か許可か」の前に実態把握、という順序**を教える題材。IP 制限がかかっているシステムはクラウドブラウザから弾かれるので影響がなく、外部からアクセスできる SaaS ほど通る。**保護されている範囲を先に確定させてから対策を考える**という手順は、セキュリティ対応の一般則としてそのまま転用できる。
- **Site tools（WebMCP）は「AI 向けインターフェースをサイトが提供する」という発想の転換点**。画面を見て操作する方式は UI 変更で壊れるが、サイト側がツールを定義すれば安定する。MCP の考え方が Web サイトへ広がった実例として、MCP 教材の応用編に置ける。**GPT-5.6 Sol / Terra が必要で Luna では動かない**という制約も、モデル選択が機能可用性を決める例として使える。
- **金銭が動くものと動かないものを分ける**という単純な線引きが、事故防止として実際に効く。エージェント活用の研修で、抽象的な「注意して使いましょう」ではなく、**判断基準を1つに絞って渡す**ほうが行動が変わる。
- **顧客の資格情報を第三者のクラウドブラウザに通してはいけない**、という論点は、フリーランス・受託向けの契約教材に組み込む価値がある。自分の情報を自分で扱うのと、預かった情報を扱うのは別の話であり、**便利さを理由に踏み越えると契約違反になりうる**。技術の話ではなく職業倫理の話として教える。
- **ブラウザ拡張の対応が4種増えたこと**は、統制対象の棚卸しという地味だが重要な作業の実例。Chrome だけ管理していれば済んだ構成が崩れる。**「対象が増える」タイプの更新は見落とされやすい**という一般則を教える材料になる。
