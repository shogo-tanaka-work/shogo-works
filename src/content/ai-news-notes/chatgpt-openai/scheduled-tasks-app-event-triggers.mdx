- **「呼んだら動く」から「起きたら動く」への転換**は、AI 自動化の教材で段階を示すのに使える。チャット（人が呼ぶ）→ 定期実行（時刻が呼ぶ）→ イベント駆動（事象が呼ぶ）という3段階で整理すると、自動化の成熟度が可視化できる。次の段階が何かも自然に見えてくる。
- **統制が効く設計と、効かない設計の対比**として、同日の「クラウドブラウザのサインイン」と並べると教材価値が高い。前者は個人が勝手に始められるが、後者は Slack チャンネルへのアプリ追加や GitHub のリポジトリアクセスという**管理者の承認を必ず通る**。同じベンダーの同じ日の発表で、統制構造が正反対である点は示唆に富む。
- **「チャンネルに入れる＝そのチャンネルの投稿が渡る」**という当たり前の事実を、申請の判断基準として言語化させる演習に使える。多くの組織はこの一文を書いていないため、申請が上がった時点で止まる。**チャンネル単位のホワイトリスト**という具体的な落とし所まで示すと実務に落ちる。
- **「後から絞るのは最初から絞るより難しい」**という原則を、GitHub の接続スコープで教えられる。全リポジトリ接続は楽だが、後で縮小するには影響調査が要る。最小権限の原則を抽象論ではなく、**手間の非対称性**として説明すると納得されやすい。
- **イベントがまとめられる挙動は、「1イベント1実行」前提の設計を壊す**。冪等性と取りこぼしの話を、身近な機能仕様として導入できる。**通知の取りこぼしを許容できない用途にはこの機能を使わない**という判断まで含めて教えると、ツール選定の視点が身につく。
- **時刻起動とイベント起動が併用できない制約**は、トレードオフを強制的に考えさせる良い題材。バッチ処理（件数が読める・反応が遅い）とイベント駆動（反応が速い・回数が読めない）の古典的な対比が、そのまま現れている。**コストと反応速度のどちらを取るか**をタスク単位で決める訓練になる。
- **「型を配る」という提供形態**は、AI 活用支援のビジネスモデルとして教える価値がある。プロンプトを文章で渡すのと、動くタスクを共有するのとでは実行率がまるで違う。**受け取り側が独立コピーを作る**設計なので、配布後の保守責任も切れている。教材やコンサルの成果物設計に応用できる。
- **Free 枠3件・1日1回まで**は、フリーミアム設計の実例。体験はできるが業務には足りない、という線引きの引き方は、自分がサービスを設計する側に回ったときの参考になる。研修の実習に無償枠を使うという実務的な活用法もセットで示せる。
