- **「古い判定結果が権限変更後も効く」（stale Guardian classifications）は、認可設計の教材としてほぼ完成形**。判定をキャッシュすると速いが、**権限状態の変化でキャッシュを無効化する経路を設計しないと、絞ったのに効かない**。RBAC、フィーチャーフラグ、CDN のキャッシュ無効化でも同じ形の事故が起きる。「無効化のトリガーを誰が引くか」を必ず設計に含める、という結論へ落とせる。
- **`/cd` がサンドボックス制限を弱められた**件は、「境界を決める操作」と「境界の中で動く操作」を混ぜると破れるという具体例。作業ディレクトリの変更が権限境界を動かしてよいかは、設計時に明示的に決める論点である。**同じ週に Claude Code もシンボリックリンク経由で同型の欠陥を直している**ので、2製品を並べて「境界の表現方法が文字列パスだと破れる」という共通構造を示せる。
- **拡張が MCP のツール結果をモデルへ渡す前に書き換えられる**のは、MCP の信頼境界を説明する最良の題材。マスキングや整形に使えば有用だが、**第三者製の拡張がモデルの入力を静かに書き換えられる**ことでもある。「拡張は便利機能」ではなく「入力経路に立つ中間者」として教える。
- **ネストしたサブエージェントのトークンがルート予算に算入されるようになった**点は、エージェント運用のコスト管理として重要。子が予算外だった状態は、階層が深いほど実コストが見えなくなる。**予算はツリー全体で1つ**という原則を、実際の修正で裏づけられる。
- **リモート compaction が画像をトークン予算に算入するようになった**（0.150.1）のは、「トークン予算の計算対象に何が入っているか」を疑う視点の実例。マルチモーダルなセッションでは、テキストだけを数える実装が実消費とずれる。自作エージェントでも同じ落とし穴が起きる。
- **0.149.1 は「バージョンは上がったが、何が変わったかは公式に書かれていない」**という状態。ここで compare リンクからコミット差分を読んで埋めないこと自体が、一次情報の扱い方の教材になる。差分から読める内容は「公式が説明した変更」とは別物である。
- **stable と alpha が並走し、alpha のほうが番号で先行する**（本窓では stable 0.151.0 に対し alpha は 0.152.0 系）。バージョン番号の大小だけで新しさや安定性を判断すると誤る。**同じ週に n8n の moving tag（`stable` が 2.36.8、`beta` が 2.37.4）でも同型の落とし穴が観測できる**ため、2例並べてバージョン管理の読み方として教えられる。
