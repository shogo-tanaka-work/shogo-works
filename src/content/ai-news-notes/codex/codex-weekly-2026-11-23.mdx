- **今週の最重要は「サンドボックス制限が引き継がれなかった」ことである（0.170.0）。** 権限更新時と子スレッドで、既存のサンドボックス制限が失われていた。**制限は、状態が変わる瞬間に落ちる。** 権限を更新した、スレッドを分けた、という「構成が変わるイベント」で引き継ぎが漏れていた。同じ週に「作業ディレクトリを変えても権限プロファイルが保たれる」修正（0.171.0）が入っており、**2週分で「状態遷移をまたぐ権限の引き継ぎ」が3箇所直っている**。セキュリティ設計を教えるときに、**チェックの正しさより引き継ぎの網羅性のほうが壊れやすい**と示せる具体例になる。
- **これは Claude Code 側の今週の話と同型である。** あちらは「作業ディレクトリの内外の判定が変わった」「相対 deny ルールが `cd` の後にプロジェクトを外れていた」（前週）。**基準ディレクトリが動くと権限判定が崩れる**という同じ構造が、2つの独立した製品で同じ時期に出ている。偶然ではなく、**「カレントディレクトリを前提にした権限判定」という設計自体の弱点**と読むのが妥当である。並べて説明する価値がある。
- **「遅延した完了イベントが新しいターンの承認を取り消さない」修正（0.171.0）は、承認の時間的整合性の話である。** 前のターンの完了通知が遅れて届き、新しいターンの承認を打ち消していた。**承認は「いつの、どの操作に対するものか」を持たないと、別の操作へ付け替わる。** CSRF やリプレイ攻撃と同型の構造で、エージェントの承認フローを自作するときの点検項目になる。「承認にターン ID を含める」という設計指針へ直接落ちる。
- **MCP OAuth の資格情報競合（0.170.0）は、Claude Code 側でも前週に出ていた。** あちらは「認証をクリアした直後にトークン更新が走ってサインインし直される」。今週の Codex は「取り消し・ログイン・ログアウト中の競合」と「古い資格情報の書き込みの上書き」。**MCP の OAuth 実装は、両製品で同じ時期に同じ種類の競合を踏んでいる。** トークンの保存を「最後に書いた人が勝つ」で実装すると、取り消しが上書きで復活する。**資格情報ストアは、取り消しを単調な操作として扱う**必要がある。
- **Linux サンドボックスの追加防御2件（`request_key` のブロック、x32 syscall の seccomp 制限）は、syscall フィルタの終わらなさを示す。** seccomp で許可リストを作っても、**x32 ABI のように「同じ syscall を別の番号空間から呼ぶ」経路**が残る。`request_key` はカーネルのキーリングへの入口である。**サンドボックスは列挙で守る仕組みであり、列挙は完成しない。** 前週の Claude Code の「ルールベースの権限チェックは入力言語が shell である限り原理的に未完成」という結論と、層が違うだけで同じ主張になる。多層防御を教える根拠として2例並べられる。
- **GPT-6.2 Sol がカタログの既定になった点は、運用側の確認事項である（0.171.0）。** 版を上げると既定のモデル選択が変わる。**モデルを固定している前提の自動化は、カタログ設定を見直す必要がある。** コストと挙動の両方が変わるため、「版を上げる＝モデルが変わる」という結びつきを運用手順に書いておく題材になる。同じ週に GitHub Copilot と Microsoft Copilot でも GPT-6.2 が入っており、**1つのモデル世代が3製品で同時に既定・選択肢へ入る**という観測点として記録しておく価値がある。
- **TUI ワークスペースが既定で有効になった点は、画面が変わるという素直な影響である。** 検索可能なドキュメントプレビュー、画像プレビュー、サブエージェントのトランスクリプトが本会話の横に並ぶ。**サブエージェントの出力を本会話と同じ画面で見せる**方向は、前週も「サイドチャットタブ」「エージェントコマンドセンター検索」として出ていた。Claude Code の Code Mode が「実行単位をコードへ上げる」方向だったのに対し、**Codex は「人間が複数のエージェントを見る画面」を作り込んでいる**。同じ課題への別解として対比できる。
- **`codex exec --remote` と `/rc` / `/remote`（0.171.0）は、実行場所の選択が運用の設計項目になったことを示す。** 既存の app server 上で非対話セッションを開始・再開できる。**手元で動かすか、サーバーで動かすかを、タスク単位で選べるようになった**という流れで、Claude Code のクラウドセッション・自己ホストランナーと対応する。CI へエージェントを入れる回で、両製品の選択肢を並べて示せる。
- **SPIFFE JWT-SVID 対応とマネージド CA 既定値（0.171.0）は、企業ネットワークへの適合である。** ワークロード ID 認証、Deno と Google Cloud SDK 向けの CA 既定値、ID トークンを refresh token なしで発行する IdP への対応。**「社内のプロキシと証明書と ID 基盤に合うか」がエージェント導入の実務的な障壁**であり、そこを埋める更新が続いている。導入支援の文脈では、機能比較より先にこの層を確認するという順序の根拠になる。
- **0.169.1 が Chores のみだった点も記録に意味がある。** ほぼ毎日リリースが出るツールでは、**内容のない版も混ざる**。版数の増加を進捗の指標にできない、という当たり前の注意を、週次ロールアップという形式そのものが示している。
- **最小限の Knowledge 反映案**: 既定スキップのままでよい。ただし Codex のサンドボックスや権限プロファイルを扱う教材があれば、**権限更新と子スレッドで制限が引き継がれない不具合が 0.170.0 で直った**こと、**作業ディレクトリ変更で権限プロファイルが保たれるようになった**ことを、下限バージョンの根拠として注記する。モデル一覧を扱う箇所には、**0.171.0 以降は GPT-6.2 Sol がカタログの既定**である点を記す。
