- **サンドボックス隔離の穴3件（0.156.0）は、「サンドボックスがあるから安全」という前提の危うさの実例**として使える。Windows の受信接続、Linux / macOS の特権ソケット、**読み取り専用として渡したファイルハンドル経由の書き込み。** 3つ目がとくに教材になる。**読み取り専用で渡したつもりのものが書き込み経路になっていた**のは、権限を「渡すもの」ではなく「その後どう使われうるか」で見る必要がある、という話に直結する。
- **サンドボックスを前提に権限を緩めている運用ほど影響が大きい**という因果を明示したい。**サンドボックスは統制を緩める根拠として使われる。** その根拠に穴があれば、緩めた分がそのまま露出する。**「守りを1枚入れたから他を緩める」という設計の連鎖リスク**として、企業導入の章に置ける。
- **既定値が2つ同時に変わった**（0.156.0 の音声会話と worktree）。**マイクが既定で使える状態になる**のは、組織によっては単独で導入判断を覆しうる変更である。**機能追加として書かれているが、実質は統制の前提が変わる変更。** リリースノートの見出しの分類と、実務上の重みが一致しない例として強い。
- **同じ週に Claude Code も既定モデルを変えており（Pro / Team Standard で Sonnet → Opus）、3件の既定値変更が並んだ。** **「更新すると挙動が変わる」と「更新しなくても挙動が変わる」を区別する**という原則を、1週間ぶんの実例だけで教えられる回。
- **レート制限時に安いモデルへ誘導する UI（0.156.1）は、コスト設計の教材**。利用者から見れば作業が止まらない利点があるが、**モデルが変わったことに気づかないまま出力品質が変わりうる。** **「親切な既定」が観測性を下げる**という構図で、切り替わりを認識できる運用にしておく、という注意点とセットで教える。
- **GPT-6 Sol / Luna の Bedrock 対応（0.157.0）は、「どのモデルが使えるかが契約経路で決まる」実例。** 技術的な優劣ではなく、**調達の都合でモデルが決まる**組織は多い。**同じ週に GitHub Copilot と Microsoft Copilot も同じ世代のモデルを追加しており、「同じモデルをどの経路から使うのが安いか」という比較軸**が実務の論点になっていることを示せる。
- **背景サーバーの自動起動（0.157.0）は、エージェントの実行場所がローカルから離れる流れの一部。** 同週の **GitHub Copilot の VS Code リモートエージェント実行（Dev Containers / SSH / Tunnel / WSL）**、**Claude Code の cloud sessions GA** と横に並べると、**「どのマシンで動いているか」を前提にした統制はいずれ効かなくなる**という一般則として提示できる。3社の独立した動きで裏づけられる回は珍しい。
- **`rust-v0.157.1` はリリース本文そのものが公開されていない**（"Release highlights could not be determined"）。**ページの読み込み失敗と、記載が無いことを区別した**のが今週の記録上の判断である。**日次で2回、週次で1回確認して、公式側に記載が無いと確定させた。** 「取得できていない」と「存在しない」を分けて記録する、という情報の扱い方の実例として使える。**推測で埋めない。**
- **alpha の積み上がり方（`0.155.0-alpha.16.x` から `0.158.0-alpha` 系まで4系列が並行）**は、リリースチャネルの読み方の教材。**alpha の本数を見て「更新が活発」と読むと実態を外す。** stable だけを追う運用と、alpha も見る運用で、そのツールの印象が変わる。**何を見て何を見ないかを決めるのが運用設計**という話へ繋げられる。
