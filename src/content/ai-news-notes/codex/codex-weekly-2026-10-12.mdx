- **今週の教材価値の中心は「公式が本文を書かなかったリリース」の処理である**（0.161.0）。GitHub Releases の本文が「Release 0.161.0」の1行だけで公開され、**翌日 `learn.chatgpt.com/docs/changelog` 側に内容が載った。** 中身は**既定モデルの GPT-6.1 Sol 化と GovCloud 対応**という重いものだった。**ここで二次ソースの要約を「公式の内容」として書いてしまうのが典型的な事故である。** 「版は出た。内容は未公開」と書き切れるかが調査の質を分ける。**同じ窓で n8n 1.123.84 も changelog 本文が無く、同じ症状が2ベンダーで出ている。**
- **既定モデルの変更が「bundled と Bedrock の両カタログで同時」だった点が、統制の教材になる。** 自社で Bedrock 経由に寄せていても、**既定モデルはツール側のリリースで動く。** モデルを明示指定していない構成は、**プロバイダーを自社管理下に置いても既定値は守れない。** 「モデル名を明示的に固定するか、変わることを前提に設計するか」の二択を迫る実例である。
- **0.162.1 の「互換性チェックを明示指定した override だけに絞る」修正は、設定の比較設計の原則そのものである。** 既定値まで含めて厳密一致を要求すると、**片方だけ更新したときに必ず壊れる。** 比較すべきは「ユーザーが意図的に指定した差分」だけ。**自社のツールで設定の互換性チェックを書くときに、そのまま流用できる原則**である。あわせて**バックグラウンドプロセスを残してクライアントだけ上げる構成**が、バージョン境界の不一致を生むという運用上の落とし穴も示せる。
- **managed Git worktree ツール（0.162.0）は、人間の運用ルールとエージェントの運用ルールが分岐する実例である。** 本リポジトリの `branch-management.md` は worktree を「並行作業が必要なときの例外手段」と位置づけているが、**エージェントが複数タスクを並行させる前提では、作業ツリーの分離は標準装備に寄る。** **同じ週に GitHub Copilot の VS Code 1.141 が「非アクティブなセッションの worktree のディスク使用量を見て掃除する」機能を入れた。** **エージェントが worktree を量産する前提で、掃除の仕組みが後から要る**という構図が2ベンダーで同期している。
- **カスタムプロバイダーの capability 設定（0.162.0）は、社内プロキシ経由で LLM を使う構成の教材に使える。** 「このプロバイダーはツール呼び出しに対応しない」を宣言できないと、**失敗してから気づく。** **能力の宣言を設定に持たせる**という設計は、自社のラッパーを書くときにも同じ項目が必要になる。**同じ週に GitHub Copilot CLI がローカル Ollama のモデル発見を入れ、tool calling と streaming の対応を要件として明記した。** 「ローカル / 自前のモデルがエージェント用途に使える最低条件」が2ベンダーで同じ形で出ている。
- **`SYSTEMROOT` / `TEMP` / `TMP` の保持（0.160.1）は、MCP のデバッグ手順の教材になる。** **MCP サーバーの起動環境は、クライアントの環境をそのまま継ぐわけではない。** OS 固有の環境変数が落ちると、原因が MCP 側か CLI 側か切り分けにくい症状になる。**MCP を扱う教材では、環境変数の引き継ぎ範囲を最初に確認させる手順を入れる。**
- **`/mcp login <name>`（0.161.0）は、MCP の認証がターミナル内で完結するようになった点が実務的である。** ブラウザとターミナルを往復しないで済む。**一方で、サインインの導線がツール内に閉じるほど、どのサーバーへ何の権限で繋いだかの記録が利用者の手元にしか残らない。** 組織として MCP を台帳管理する場合の論点になる。
- **`apply_patch` の CRLF 保持（0.162.0）は、Windows 混在チームの地味な落とし穴の実例である。** 改行コードが勝手に変わるとレビューの差分が膨らみ、**本来の変更が読めなくなる。** **Claude Code 2.1.296 の Shift-JIS 編集拒否と並べると、「エージェントがファイルを書き換えるとき、文字コードと改行コードの両方が壊れうる」**という1つの論点にまとまる。日本語・Windows 環境の案件では、どちらも事前の確認項目である。
