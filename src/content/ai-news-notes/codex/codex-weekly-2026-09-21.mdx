- **今週の中心教材は「既定値の変更が互換性を壊す」である**（0.155.0 → 0.155.1）。機能追加そのもの（推論サマリーの表示）には問題がなく、**それを既定で有効にしたこと**が、非対応プロバイダでの全拒否を生んだ。**新機能をオプトインにするかオプトアウトにするか**という設計判断の章に、そのまま置ける実例である。約21時間で既定が `none` へ戻された点まで含めると、**「迷ったらオプトイン」という結論の根拠**になる。
- **明示設定している環境は影響を受けなかった**、という非対称性も教える。**設定を書いている側が守られ、既定に任せている側が壊れる。** これは Codex に限らず一般的で、**「設定ファイルに明示する」ことが、便利さではなく変更耐性のために効く**という主張の裏づけになる。同じ窓で Claude Code 側も「モデルを固定していない環境ほど更新で挙動が変わる」系の話を繰り返している。
- **Claude Code v2.1.276 と並べると効果が大きい。** 同じ窓の中で、**両ツールとも「非標準のエンドポイント経由で使っている構成」が先に壊れ、即日〜翌日に修正されている。** ゲートウェイや代替プロバイダを挟む構成は統制上は正しいが、**ベンダーの検証が薄い経路である**という共通の教訓が、**2社の独立した事例で同時に裏づけられた。** 企業導入の章で使う素材として、今週はこれが最も強い。
- **MCP リクエストの Touch ID 検証**（0.155.0）は、単独で教材価値がある。**「エージェントが外部ツールを呼ぶ瞬間に人間の生体認証を挟む」**という統制の形で、他ツールへ波及しうる設計である。ただし**運用としては自動化と正面から衝突する**点を必ず添える。長時間の自律実行を前提にした使い方とは両立しないため、**どのツール呼び出しに対して要求するか**の線引きが実務の論点になる。
- **Windows サンドボックスの資格情報露出強化**（0.155.0）は、**プラットフォーム差がそのまま攻撃面になる**という論点の実例。同じ週に Claude Code 側でも sandboxed Bash が zsh で exit code 0 を返す問題（2.1.275）が直っており、**サンドボックスの実装はシェルと OS の差に足を取られ続ける**という共通の構図が見える。「サンドボックスがあるから安全」ではなく、**どの OS・どのシェルで検証されているかを確認する**という手順に落とす。
- **アカウント切り替え時のキャッシュ無効化**（0.155.0）は、Claude Code 2.1.271 の「組織ポリシーのキャッシュがアカウント切り替え後も再利用される」と**同じ型の不具合**である。**複数アカウント・複数テナントを行き来する使い方は、キャッシュの境界設計を壊しやすい。** 受託開発やコンサルのように、**顧客ごとにアカウントを切り替える働き方**では実害に直結するため、実務者向けの注意として具体性がある。
- **「9日間 alpha を回してから stable を出す」という開発プロセスの観測**は、ツール選定の材料になる。日次で版数を並べるのではなく、**安定版に到達するまでの期間と、その間の alpha の本数**を見ると成熟度と変更リスクの見積もりができる。窓の終端時点で `0.156.0` 系は alpha が積み上がったまま stable 化していない。
- **今週は Claude Code が8版、Codex が stable 2版だった。** 前週は Codex が stable 1版でロールアップ見送りになっている。**2ツールを併用している読者にとって、更新頻度の差は追随コストの差そのもの**である。「どちらが優れているか」ではなく、**どちらが運用の手間を多く要求するか**という軸で比較すると、実務の判断に接続できる。
- **`/voice` は実験的機能として扱いを分ける。** 対応ビルドに限られ、ライブ文字起こしとマイク操作を伴う。**音声入力は、機密情報の扱いと録音・文字起こしデータの保存先という別の論点を連れてくる。** 機能の紹介だけで終わらせず、**導入前に確認すべき項目（どこで文字起こしされ、どこに残るか）**をセットで示す。同じ週に xAI が Grok Voice Transcribe 2.0 を出しており、**音声を入口にするツールが増えている**という文脈で並べられる。
- **Bedrock 向けに「設定したコマンドから AWS 資格情報を取得する」**（0.155.0）は、資格情報の受け渡し設計として実務的である。**環境変数に置く / ファイルに置く / コマンドで都度取得する**という3択の比較に使える。コマンド取得は短命な資格情報と相性が良い反面、**そのコマンド自体が新しい信頼対象**になる点まで教える。
