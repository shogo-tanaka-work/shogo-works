- 権限プロファイルが resume / fork 時に復元されない不具合は、統制教材の核になる実例。**「設定した権限が、セッションを再開した瞬間に別のものになっていた」**という状態は、設定を書いたことと効いていることが別であるという原則そのもの。Claude Code 2.1.236 の macOS サンドボックス read-deny 修正と並べると、ベンダーを問わず同じ種類の穴が起きることを示せる。
- `codex agents` ダッシュボードは、「エージェントの並行数とレビュー可能な人数の比率」を教える題材。速度を上げる機能が、レビューのボトルネックを顕在化させる。ハーネスエンジニアリング教材の「AI の生産量に人間の検証能力が追いつかないとき何を捨てるか」の節に接続する。
- `codex queue` の「アイドルセッションを確実に起こす」修正は、非同期メッセージングの設計論として一般化できる。投げた側は成功したつもりで、受け側は動いていない。分散システムの教材で扱う配送保証の話が、そのままエージェント運用に現れている。
- `codex doctor` の診断拡大は、**サポート手順を設計する**教材に使える。「動きません」という報告から始める切り分けと、診断コマンドの出力を添えて始める切り分けでは、ヘルプデスクの負荷が桁で違う。社内手順に1行足すだけで効果が出る例として提示する。
- secure devcontainer の DNS エクスフィルトレーション文書化は、サンドボックスの信頼境界を教える最良の素材。「隔離した = 安全」という理解を崩す。ネットワークを遮断したつもりでも DNS が残る、という具体を出すと、境界を設計するとはどういうことかが伝わる。セキュリティ研修の演習問題にできる。
- SDK の reasoning effort（`max` / `ultra`）は、コスト設計の教材。**選択肢が増えることはコストが読めなくなることでもある**。呼び出し元で決めるか設定で固定するかという分岐は、組織のガバナンス設計そのもの。受託で納品する場合の仕様書記載項目としても扱える。
- 「stable と alpha が並行で出るツールをどう追うか」は、更新運用の教材に毎回使える。今回の窓では alpha が4件出ているが、追う必要はない。stable だけを見て、自分の構成と噛み合う領域（権限・サンドボックス・SDK 設定）を拾う、というフィルタの掛け方を教える。
- 外部コントリビューションを PR ではなく issue と設計議論に誘導する方針の明文化は、OSS 運営の教材として使える。AI でコードを書くコストが下がった結果、レビュー不能な量の PR が来る、という構造的な問題への対応と読める。「生成コストが下がったとき、ボトルネックはレビューへ移る」という主張の実例。
