- Amazon Bedrock の組み込みプロバイダー化は、企業導入教材で優先度が高い。「データを AWS 内に留めたい」という制約で Codex 導入を見送っていたケースが動く可能性がある。既存の Bedrock 権限設計に乗せられる点まで含めて説明する。
- Hooks から MCP ツールを呼べるようになった点は、単なる機能追加ではなく設計思想の変化として扱う。Hooks =「タイミングでコマンドを打つ仕組み」から「タイミングで任意の外部ツールを起動する仕組み」へ広がった。ハーネスエンジニアリングの自動化層の教材に追加できる。
- 非同期実行が同時に入ったことで「重い処理を Hooks に置ける」ようになった点はセットで説明しないと価値が伝わらない。同期実行のままでは MCP 呼び出しは実用にならなかった。
- `codex exec fork` は「文脈を保ったまま分岐する」という、AI エージェント運用固有の操作。Git の branch との対比で説明すると理解が速い。A 案 / B 案を同じ前提から比較する用途を具体例に。
- `/export` の Markdown 出力は、AI エージェントの作業ログ保全という監査論点に接続できる。「何を指示し何をさせたか」の記録要件は今後増える領域なので、AI ガバナンス教材の素材になる。
- コスト表示（`/status` / ステータスライン / ターミナルタイトル）は「eligible workspaces」限定。教材では条件を明示しないと、読者が自環境で見えないときに混乱する。
- Codex の記事は `codex-rust-v0-131-0` から継続的に出している系列。バージョン単位の記事が並ぶので、教材化するときは版ごとではなく「Hooks の進化」「プロバイダーの拡大」のようにテーマで束ねたほうが読める。
