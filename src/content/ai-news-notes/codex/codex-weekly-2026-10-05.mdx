- **今週いちばん強い教材は、既定モデルが発表当日に替わったこと**（0.159.1）。DevDay 2026 の発表と同日に、バンドルカタログと Bedrock カタログの既定が GPT-6.1 Sol になった。**「モデルを固定しない運用では、ベンダーの発表日が自社の挙動変化日になる」**という主張を、日付1つで示せる。**評価済みモデルの pin が必要だという結論を、1リリースで説明できる回**である。
- **ただし pin には裏がある、という話を同じ週の xAI と対で出せる。** xAI は **`grok-voice-transcribe-1.0` を 2026-10-02 で EOL にし、STT 既定を 2.0 へ切り替えた。** **既定指定のコードは自動で移り、pin していたコードだけが止まった。** **pin はバージョン固定の手段だが、EOL に対しては逆に脆い。** 「評価済みモデルを pin する」という推奨は、**pin した対象の EOL を自分で追う責任とセットでなければ成立しない**——ここまで言えると、運用ルールとして実装できる形になる。
- **資格情報ディレクトリの既定保護（`.aws`、0.159.0）は、ベンダー側の既定値が動いている実例**として強い。前日の 0.158.0 の「昇格権限に対するターミナル入力承認の既定有効化」と**同じ方向の変更が2版連続**で入っている。**同じ週に Claude Code 側でも資格情報のログ露出が5件塞がれた**ため、**2ツール・3領域で「資格情報を守る側へ既定が動いた週」**として並べられる。
- **exec-server の bearer token 保護（0.158.0）は、「自前で立てたものが無認証だった」型の教材。** ローカルだから、開発用だから、という理由で認証を省いた実行サーバーが、**サンドボックスの外側への入口になる。** 社内で MCP サーバーや実行基盤を自前運用するときの点検項目としてそのまま渡せる。
- **「ポリシーが許す場合」という条件つきの挙動変更**（0.160.0 のプロジェクト外セッション）は、**リリースノートを読まないと自社の設定次第で挙動が変わることに気づけない**型である。機能追加でもセキュリティ修正でもなく、**既存のポリシー設定の意味が変わる**。変更の分類として「条件つき挙動変更」という枠を持っておくと、読み落としが減る。
- **Guardian review がエージェント間の引き継ぎ文脈を含めるようになった**（0.160.0）。複数エージェントで分担すると、**後段のエージェントは前段の意図を知らないまま作業する。** **引き継ぎの情報落ちをレビュー工程で補う**という設計で、人間のチーム運営でも同じ構造の対処になる。マルチエージェント設計の章で、**「分担の副作用を工程で吸収する」**例として使える。
- **Windows のコンソール窓を3版にわたって直し続けている**（0.159.0 / 0.159.2 / 0.160.0）。単体では教材価値が薄いが、**同じ領域の修正が短期間に続くときは根本の設計が動いている**と読む——という**リリースノートの読み方そのもの**を教える材料になる。「社内標準バージョンを1〜2版待つ」判断の根拠として、n8n のキュー実行（2.41.4 / 2.42.2）と並べられる。
- **backport の方向から優先度を読む**（0.159.3）。alpha が 0.161 系まで進んでいる状態で、アカウントセキュリティ設定のリマインダーを **0.159 系へ戻して入れた。** **「待たせず配りたい」とベンダーが判断した**ことを意味する。**リリース番号の動きから優先度を読む**という読み方の練習材料になる。
- **`tui.prompt_suggestions` の廃止（0.159.0）は、CLI ツールを社内標準に据えるときの保守コストの実例。** 設定項目は増えるだけでなく消える。**手順書に書いた設定が、更新で無効になる。** 設定ファイルを配布している組織ほど、廃止の告知を追う必要がある。
- **`instant interrupt`（0.159.0）は「エージェントを止める手段」の教材。** 9月に相次いだ misalignment 報告（人間の中止指示が効かなかった事例）と並べると、**割り込み可能性を製品機能として実装する**流れが読める。**同じ週に Claude Code 側は auto mode を全プラン既定にしており、自動化を進める方向と止める手段を整える方向が同時に動いている。**
