# ナレッジ記事の書き方

既存の271本は3系統のフォーマットと、常体・敬体の混在を抱えている。**既存記事を一括で書き換えない**。触った記事だけをこの規約に寄せ、新規記事は最初からこれに従う。

## 文体

- **敬体（です・ます）に統一する。** 常体の既存記事を見つけても、その記事を編集する用事があるときだけ直す。
- 一人称は「私」。使わずに済むなら書かない。
- 読者への呼びかけは「あなた」ではなく、主語を省くか具体的な役割（担当者・開発者）で書く。
- 誇張しない。「劇的に」「圧倒的に」「革命的」は使わない。数字か具体例で示す。
- 「〜と言えるでしょう」「〜ではないでしょうか」で締めない。断定できないなら条件を書く。

## 記事フォーマット

用途ごとに3系統を使い分ける。混ぜない。

### 1. テーマ解説（prompt-engineering / context-engineering / harness-engineering）

```
## <テーマ>とは
## 具体例
### 例1 / 例2
## いつ使うべきか
## 注意点・限界
## 参考文献
```

### 2. 製品ドキュメント準拠（cloudflare / vercel / supabase / codex / claude-code）

```
## 一行サマリ
## 解決する課題（Why）
## 主要機能（What）
## いつ選ぶか
### 適しているシーン / 適していないシーン
## 競合・代替
## 料金モデルの要点
## 制限・注意点
## 参考リンク
```

### 3. カリキュラム（claude-code-curriculum）

```
## このレッスンでわかること
（本文）
## 実例：…
## やってみよう
## まとめ
## 理解度チェック
```

## 見出し

- `h2` から始める。`h1` はページタイトルが持つ。
- 見出しに記事タイトルを繰り返さない。
- 1つの `h2` の下が3000字を超えたら分割を検討する。

## タグ

タグは446個あり、その7割が1記事しか持たない。**新しいタグを増やす前に既存タグを探す。**

- 既存タグに同義のものがあればそれを使う（`/knowledge/tags` で確認できる）。
- 表記は既存の優勢な表記に合わせる（`Claude Code` / `Codex` / `MCP` など）。URL は自動で正規化されるが、表示ラベルは揃える。
- 1記事あたり3〜5個に収める。記事固有すぎる語をタグにしない。
- スラッシュを含む語（`CI/CD`）は使えるが、URL ではハイフンに畳まれる。

## frontmatter

- `updatedAt` は**内容を実際に改稿したときだけ**設定する。`createdAt` と同じ日付を入れない（情報がないのと同じ）。
- `sortOrder` は同じサブカテゴリ内で重複させない。tier の境界は `src/data/knowledgeTiers.ts` を参照する。
- `description` は一覧カードに出る。記事の要約であって、煽り文句ではない。

## リンク

- 内部リンクは `/knowledge/<category>/<subcategory>/<slug>` の形。**subcategory はディレクトリ名ではなく frontmatter の値**（`cloudflare-docs` ではなく `cloudflare`）。
- リンク切れは `tests/content/knowledgeIntegrity.test.ts` が検出する。
- 外部リンクは出典として意味のあるものだけ。URL をそのままリンクテキストにしない。
