# UIデザイン

UIを変更する前に `docs/DESIGN.md` を読む。機能・UX要件は `docs/SPEC.md`、ビジュアル表現は `docs/DESIGN.md` を正本とする。

## 必須ルール

- ページと通常セクションは、一枚のキャンバスとして同じ背景で扱う。
- 情報の階層は、余白、文字、配置、区切り線の順に表現する。
- 一覧は行と区切り線で表現し、安易にカード化しない。
- 通常領域の角丸は原則 `0` とする。`rounded-2xl` / `rounded-3xl` を新規に使わない。
- ボタン、入力欄、選択コントロールの角丸は `2px` から `6px` に留める。
- 影はモーダル、ドロワー、ポップオーバー、固定ナビゲーションなど、前面へ浮く要素に限定する。
- アクセントは teal 系1色。グラデーション（`gradient-text` / `gradient-border`）と `glass` / `glass-strong` を新規に使わない。
- 色値は `src/styles/global.css` の `@theme` トークンを参照し、コンポーネントへ生の色値を書かない。
- 入力欄と表ヘッダーには、識別に必要な淡い補助背景を使用できる。
- Grid/Flex の可変領域には `min-width: 0`（Tailwind では `min-w-0`）を設定する。
- 横スクロールを通常操作として発生させない。
- サイドバーを隠す幅では、同じ導線をセレクトまたはアコーディオンとして残す。

## 許可する例外

- 比較対象となるサマリー数値の細い外枠
- 状態を示すステータスバッジのピル形状
- 操作要素として必要なボタンと入力欄の小さな角丸
- モーダル、ドロワー、メニューなどオーバーレイの白背景と影
- エラー、警告、選択中を伝える意味のある状態色
- 記事本文（`.knowledge-prose`）のコードブロックと引用の背景

例外を使う場合も、同じ要素へ背景、枠線、角丸、影をすべて重ねない。

## 禁止事項

- セクションごとに同じ白いカードを量産する。
- カードの内側へ同じ見た目のカードを入れ子にする。
- 見た目を整える目的だけで角丸や影を追加する。
- 同じ階層のすべての要素を均一なカードグリッドへ変換する。
- グラデーション文字で見出しやCTAを強調する。
- セクション見出しの上に置く英字ラベルを装飾として増やす。
- PC用テーブルをスマートフォンで横スクロールさせる。
- `overflow: hidden` を安易に祖先要素へ指定し、スティッキー表示を壊す。
- フォーカス表示、エラー表示、選択状態、現在地表示を装飾削減と一緒に消す。

## 実装前チェック

1. 既存の `@theme` トークンと `src/components/ui/` で対応できるか確認する。
2. 変更する要素が閲覧情報、操作要素、オーバーレイのどれかを判定する。
3. 外枠ではなく余白や区切り線で表現できるか検討する。
4. PC、タブレット、スマートフォンへの影響を確認する。

## 実装後チェック

- カードの入れ子が増えていない。
- 通常コンテンツに新しい影が増えていない。
- 意味のない角丸が増えていない。
- ページ背景と主要表示領域が分断されていない。
- 横スクロールが発生していない。
- スティッキーヘッダーと固定ナビゲーションが重なっていない。
- キーボードフォーカス、選択状態、現在地、エラー状態を識別できる。
- `npm run build` が成功する。
