# コード設計

- 1ファイル1責務。200行を超えたら分割を検討し、300行を超えない。
- 1関数50行で分割を検討し、80行を超えない。
- 依存の方向を一方向に保つ（ページ → コンポーネント → ユーティリティ → データ）。
- ページは取得と組み立て、コンポーネントは表示、`src/utils/` は純粋な変換を担当する。
- 同じ判定や変換を複製せず、定数・型ガード・純粋関数へ集約する。
- 意味を持つ文字列（カテゴリ、ステータス、ツール名）は Union 型または定数から参照する。
- マジックナンバーを直書きしない。意図の分かる名前の定数として定義する。
- エラーは操作名を含む文脈付きメッセージとし、原因を握りつぶさない。空の catch を書かない。
- 外部サービス（Resend、外部フィード）へのアクセスはラッパー関数を介す。SDK を画面から直接呼ばない。
- 公開関数には JSDoc で1行の日本語説明を付ける。`@param`・`@returns` は型と重複するため書かない。
- コメントは「なぜ」を書く。「何を」はコードから読める。
- デバッグ用の出力はコミット前に削除する。
- 未使用の関数・型・import を残さない。

## 命名

- 変数・関数: camelCase
- 定数: UPPER_SNAKE_CASE
- 型・コンポーネント: PascalCase
- ファイル名: kebab-case（コンポーネントは PascalCase）
